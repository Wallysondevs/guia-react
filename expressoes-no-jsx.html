Expressões no JSX

A Ana descobriu ontem que dá para escrever código dentro do JSX: as chaves. Hoje ela quer usar isso para parar de fazer conta na cabeça — o preço de dois pacotes de pão de queijo, o estado da padaria, o nome do pão que está dentro de um objeto. Aos poucos vai aparecer o padrão: chaves são uma porta para o JavaScript, e do outro lado sai um valor que o React coloca na tela. Saber o que pode e o que não pode entrar por essa porta é o que separa "funcionou de primeira" de "a tela ficou em branco e eu não sei por quê".

Você vai aprender
  • O que é uma expressão e por que só ela entra nas chaves.
  • Mostrar variáveis, contas e texto montado.
  • Escolher entre duas opções com o ternário.
  • Mostrar ou esconder um pedaço com &&.
  • Por que objeto e função não aparecem na tela.
  • Como o painel mostra número, texto e o que é "invisível".

1. A cena: a conta feita na cabeça

O cardápio da Ana tinha duas linhas de preço. A primeira, o pacote de pão de queijo: seis reais. A segunda, dois pacotes: doze reais. Ela fez a conta na cabeça e digitou o doze. Funcionou por três dias — até o dia em que o preço subiu para sete reais e a segunda linha continuou dizendo doze.

O problema é o mesmo do cabeçalho repetido: um número que deveria ser consequência virou texto digitado. Se o doze fosse calculado a partir do seis, ele mudaria junto. É exatamente para isso que existem as chaves no JSX: elas permitem que a tela seja calculada em vez de digitada.

Antes de ver a solução, vale entender o que pode entrar por essa porta. É o resto da aula.

2. Expressão é o que vale um valor

Em JavaScript, as coisas se dividem em dois grupos: as que valem alguma coisa e as que mandam fazer alguma coisa. Uma conta vale um número. Uma variável vale o que está dentro dela. Já um if não vale nada: ele manda escolher um caminho. O JSX aceita o primeiro grupo e recusa o segundo, porque ele precisa de um valor para colocar no lugar das chaves.

Por isso {2 + 3} funciona e {if (x) ...} não. Não é implicância: o JSX vira uma chamada de função, e o miolo das chaves é um argumento dessa chamada. Argumento é valor. Quando você precisa decidir, decide com uma expressão que devolve a escolha — e as duas mais usadas são o ternário e o &&.

expressão
Qualquer coisa que produz um valor: 2 + 3, preco, aberto ? "sim" : "não".
chaves
O par { } que abre a porta para o JavaScript dentro do JSX. Sem elas, o texto é literal.
ternário
A escolha entre dois valores: condição ? seVerdadeiro : seFalso. Substitui o if dentro do JSX.
curto-circuito
O && que mostra algo só quando a condição é verdadeira. Cuidado com o valor zero.
renderizar
Transformar o que a expressão devolveu em conteúdo na tela. Nem todo valor vira conteúdo.

Uma distinção que parece detalhe e não é: o texto fora das chaves é literal — o React copia como está. O conteúdo das chaves é calculado — o React avalia e usa o resultado. Isso permite misturar os dois no mesmo parágrafo, e é o que faz "Preço:" ser fixo e o número ser variável.

3. Variáveis e contas

O caso mais comum é este: uma variável guarda um dado e a tela mostra o valor. Se a variável muda, a tela acompanha — sem você tocar no texto. E, como dentro das chaves é JavaScript, você pode fazer contas ali mesmo em vez de guardar o resultado em outra variável.

O segundo parágrafo foi digitado à mão e mostra o mesmo preço do primeiro. Troque o valor por uma conta dentro das chaves: {preco * 2}.

function App() {
  const preco = 6;
  return (
    <div>
      <h1>Pão de queijo</h1>
      <p>Um pacote: {preco} reais</p>
      <p>Dois pacotes: {preco} reais</p>
    </div>
  );
}
<div>
  <h1>Pão de queijo</h1>
  <p>Um pacote: 6 reais</p>
  <p>Dois pacotes: 6 reais</p>
</div>

function App() {
  const preco = 6;
  return (
    <div>
      <h1>Pão de queijo</h1>
      <p>Um pacote: {preco} reais</p>
      <p>Dois pacotes: {preco * 2} reais</p>
    </div>
  );
}

Depois de rodar, o segundo parágrafo mostra doze. Mude o preco para sete e rode de novo: as duas linhas mudam juntas, porque as duas vêm do mesmo lugar. Essa é a diferença entre uma tela calculada e uma tela digitada — e é o mesmo raciocínio do componente reaproveitado, só que aplicado a números.

Dentro das chaves cabem as quatro operações, o resto da divisão, parênteses para agrupar e chamadas de função. {2 + 3 * 4} dá 14, porque a multiplicação vem antes — o JavaScript de sempre, sem nenhuma regra nova. E cabem funções suas: {dobro(preco)} funciona, desde que dobro esteja definida antes do return.

Se quiser conferir uma conta antes de colocar na tela, o console do navegador é o lugar. Digite a mesma expressão e ele responde com o valor, sem mexer em nada da página:

> const preco = 6;
undefined
> preco * 2
12
> 2 + 3 * 4
14

A linha undefined não é erro: no console, toda declaração de variável responde com undefined porque ela não "vale" nada — só guarda. As duas linhas seguintes são o valor das expressões. Esse é o mesmo resultado que o React vai colocar na tela quando a expressão estiver entre chaves, o que faz do console um bom lugar para testar a conta antes de escrever o JSX.

Uma observação sobre o painel, que vale para toda a aula. Ele mostra o HTML gerado e, para ficar legível, separa os pedaços de texto com um espaço. Quando você escreve R$ {preco * 2},00, o painel pode exibir R$ 12 ,00, com um espaço antes da vírgula, enquanto na página de verdade o texto sai colado. Não é erro seu nem do React: é a forma de exibir do painel. Quando o texto colado importar, monte a string inteira em uma expressão só.

4. Número, texto e o que é invisível

Nem todo valor vira conteúdo. O React tem uma tabela mental simples: texto e número aparecem; true, false, null e undefined não aparecem — eles existem só para o componente decidir coisas. Quem vem do HTML estranha no começo, porque {false} literalmente não desenha nada, e isso é usado de propósito o tempo todo.

Dentro das chavesO que apareceExemplo

null e undefinednada{null}

Repare na diferença entre as duas últimas linhas do "nada": false e null são aceitos e simplesmente não desenham nada; objeto e função são recusados e derrubam o componente. É uma diferença importante, porque o sintoma na tela é parecido — não aparece nada — e a causa é oposta.

Quando o valor é undefined por acidente, o efeito é o mesmo: nada na tela. É o caso do nome digitado errado — a variável existe, mas o JavaScript procura por outro nome e não acha. O bloco some e o navegador reclama no console. Por isso, quando um pedaço do parágrafo desaparece, o primeiro lugar para olhar é o nome do que está entre chaves.

5. Escolher entre duas coisas: o ternário

A padaria abre e fecha, e o site precisa dizer qual dos dois. Dentro do JSX não cabe if, então usa-se o operador que escolhe entre dois valores em uma linha: condição ? valorSeVerdadeiro : valorSeFalso. O nome esquisito — ternário — vem de ele ter três partes.

A variável aberto vale true, mas o parágrafo diz "Fechado" porque o texto foi digitado. Use um ternário para escolher entre "Aberto agora" e "Fechado".

function App() {
  const aberto = true;
  return (
    <div>
      <h1>Padaria da Ana</h1>
      <p>Estado: Fechado</p>
    </div>
  );
}
<div>
  <h1>Padaria da Ana</h1>
  <p>Estado: Fechado</p>
</div>

function App() {
  const aberto = true;
  return (
    <div>
      <h1>Padaria da Ana</h1>
      <p>Estado: {aberto ? "Aberto agora" : "Fechado"}</p>
    </div>
  );
}

O painel mostra "Estado: Aberto agora". Troque o true para false e o mesmo parágrafo passa a dizer "Fechado" — a tela segue o dado. É a primeira vez no guia que você vê a lógica mudando o conteúdo, e é o alicerce do que vem depois: quando o dado vier de um clique, a tela vai mudar sozinha.

As aspas dentro do ternário são necessárias porque os dois lados são textos. Se fossem números, não precisariam: {quantidade ? quantidade : "esgotado"} é válido, e mistura número e texto sem problema. E se os dois lados forem elementos JSX, também vale — o ternário escolhe qual pedaço de tela entra.

O ternário é legível com duas opções; com três, vira um ninho difícil de ler. Nesse caso, calcule antes do return com um if normal e mostre uma variável só. O JSX não precisa saber da decisão, só do resultado.

6. Mostrar ou não: o &&

Quando uma das duas opções é "nada", o ternário fica desequilibrado: temPao ? <p>...</p> : null. Para esse caso existe um atalho. O && devolve o valor da direita se o da esquerda for verdadeiro, e devolve o da esquerda se ele for falso. Como falso não desenha nada, o resultado é "mostre o elemento só quando a condição for verdadeira".

function App() {
  const temPao = true;
  return (
    <div>
      <h1>Padaria da Ana</h1>
      {temPao && <p>Pão quentinho saindo do forno</p>}
    </div>
  );
}

Com temPao valendo true, o parágrafo aparece; valendo false, ele não existe no HTML gerado — nem como comentário, nem como espaço. É a forma mais comum de esconder um aviso, uma promoção ou uma mensagem de erro em React.

Tem uma armadilha famosa aqui, e ela vale o parágrafo. O && não devolve false quando o lado esquerdo é falso: devolve o próprio valor da esquerda. Se esse valor for 0, o React desenha o zero. Então {quantidade && <p>Restam</p>} mostra um "0" solto na tela quando a quantidade é zero. A correção é usar uma comparação explícita — quantidade > 0 && ... — que devolve true ou false, e falso não desenha nada.

7. Objetos, listas e funções

Objeto é o tipo que mais aparece no React — props são um objeto, estado com vários campos é um objeto — e é justamente o que o React se recusa a desenhar. A razão é que não existe uma forma óbvia de transformar { nome: "Pão francês", preco: 6 } em texto. Se o React escolhesse uma, ela estaria errada em algum caso.

O parágrafo tenta mostrar o objeto pao inteiro, e nada aparece. Mostre o nome em um parágrafo e o preço em outro: {pao.nome} e {pao.preco} reais.

function App() {
  const pao = { nome: "Pão francês", preco: 6 };
  return (
    <div>
      <h1>Cardápio</h1>
      <p>{pao}</p>
    </div>
  );
}
(o React não desenhou nada: o componente devolveu null?)

function App() {
  const pao = { nome: "Pão francês", preco: 6 };
  return (
    <div>
      <h1>Cardápio</h1>
      <p>{pao.nome}</p>
      <p>{pao.preco} reais</p>
    </div>
  );
}

No projeto de verdade, o navegador diz exatamente o que aconteceu. A mensagem aparece no console, em vermelho, e vale a leitura porque ela aponta o tipo do problema:

Objects are not valid as a React child (found: object with keys {nome, preco}).
If you meant to render a collection of children, use an array instead.

Traduzindo: "objetos não são um filho válido do React; encontrei um objeto com as chaves nome e preco". Repare que a mensagem já entrega a solução pela metade — ela lista as propriedades que existem dentro do objeto, que é justamente o que você precisa escrever depois do ponto. Para ver os valores, o caminho é o console:

> pao
{nome: 'Pão de queijo', preco: 6}
> pao.nome
'Pão de queijo'

Antes de rodar, o painel avisa que nada foi desenhado. É o sintoma de objeto dentro das chaves: o componente nem chega a terminar. Depois, com as propriedades, aparecem as duas linhas. A regra prática é simples: entre chaves, mostre texto ou número; para chegar a um deles a partir de um objeto, use a propriedade.

Listas têm um tratamento próprio: um array de elementos JSX é desenhado item por item, e essa é a base das listas com map, que tem aula própria. Array de números ou textos também é desenhado, mas sem separador — os itens saem colados, o que quase nunca é o que você quer. Função, por outro lado, não desenha nada e derruba o componente igual ao objeto.

E há as funções que você chama dentro das chaves: {formatarPreco(preco)} funciona, porque o que entra no JSX é o resultado da chamada, e o resultado é texto. Função como valor (sem parênteses) é o problema; função executada é solução. Guarde essa diferença, porque ela volta em eventos e em listas.

8. Pondo tudo junto em um cartão

Um cartão de produto usa três ou quatro expressões ao mesmo tempo, e é onde se vê por que as chaves são o coração do JSX. O código abaixo é o mesmo raciocínio da aula inteira em um bloco só:

function App() {
  const pao = { nome: "Pão de queijo", preco: 6 };
  const quantidade = 2;
  const temEstoque = quantidade > 0;

  return (
    <div>
      <h2>{pao.nome}</h2>
      <p>{quantidade} unidades</p>
      <p>Total: {pao.preco * quantidade} reais</p>
      {temEstoque ? <p>Pronto para retirar</p> : <p>Esgotado</p>}
    </div>
  );
}

Leia de cima para baixo. O objeto guarda os dados do pão. A quantidade é um número. O total é uma conta que usa os dois. E o último parágrafo é uma escolha entre dois elementos inteiros — não entre dois textos, entre dois pedaços de tela. Se você mudar a quantidade para zero, o total vira zero e o aviso troca sozinho.

Esse é o padrão que você vai repetir em todo componente: calcule antes, mostre depois. As contas e decisões ficam no topo da função, em JavaScript puro, onde são fáceis de ler e de testar. O return fica curto, com as chaves só buscando valores já prontos. Quem começa tende a fazer o contrário — contas gigantes dentro do JSX — e depois não consegue ler o próprio código.

OperadorExemploResultado
+ - * / %{preco * 2}a conta feita
? e :{aberto ? "Aberto" : "Fechado"}um dos dois valores
&&{temPao && <p>Tem pão</p>}o elemento ou nada
||{nome || "sem nome"}o segundo, se o primeiro for vazio
??{preco ?? "sem preço"}o segundo, só se o primeiro for nulo

A diferença entre || e ?? aparece quando o valor é zero. Com preco = 0, {preco || "sem preço"} mostra "sem preço", porque zero é considerado falso; já {preco ?? "sem preço"} mostra "0", porque o ?? só troca quando o valor é null ou undefined. Em preço, a diferença é a diferença entre um pão de graça e um pão sem preço.

9. Cenários do dia a dia

Cenário 1: o texto sumiu no meio do parágrafo

A Ana escreveu Preço: {preco}, mudou o nome da variável para valor e esqueceu de trocar no JSX. O resultado foi "Preço:" e nada depois. Erro de referência dentro do JSX derruba o componente, e o painel mostra o aviso de que nada foi desenhado. O conserto é conferir o nome — e o hábito que evita o problema é justamente o do fim da aula: calcular antes, com nomes claros, e usar no return só o que já existe.

Cenário 2: o zero que aparece sozinho

Ela usou {quantidade && <p>Restam unidades</p>} e, quando o estoque zerou, apareceu um "0" na tela. É o comportamento do &&, que devolve o valor da esquerda quando ele é falso. A correção é comparar explicitamente: {quantidade > 0 && ...}. O mesmo cuidado vale para || com preço zero, que desaparece como se não existisse.

Cenário 3: objeto entre chaves e a tela em branco

Tentar mostrar {pao} derruba o componente, e a tela fica vazia sem uma mensagem clara no painel. A causa é sempre a mesma: objeto não é conteúdo. A saída é escolher o que mostrar — o nome, o preço, os dois em parágrafos separados — e para inspecionar o objeto inteiro existe o console: console.log(pao) mostra tudo, e é assim que se descobre o nome exato de cada propriedade.

11. Resumo

As chaves do JSX são uma porta para o JavaScript, e por ela só passa expressão — algo que vale um valor. Variáveis, contas, textos, chamadas de função e escolhas com ternário entram; comandos como if e for ficam do lado de fora. O resultado é colocado no lugar das chaves, como se fosse texto.

Nem todo valor vira conteúdo: texto e número aparecem; true, false, null e undefined não desenham nada de propósito; objeto e função derrubam o componente. Para mostrar dados de um objeto, use a propriedade — {pao.nome}. Para escolher entre duas opções, ternário. Para mostrar ou esconder, &&, tomando cuidado com o zero que ele devolve.

E o hábito que organiza tudo: calcule antes do return, mostre depois. As contas e decisões ficam em JavaScript puro, com nomes claros; o JSX só busca valores prontos. Quem faz o contrário escreve uma tela que funciona e um código que ninguém consegue reler.

Na próxima aula o assunto é o outro lado dos atributos: os nomes que mudam em relação ao HTML, o className e os valores que precisam de chaves para funcionar.

Para lembrar

  • Chaves aceitam expressão, não comando.
  • {preco * 2} calcula; mude o dado e a tela acompanha.
  • Ternário escolhe entre dois valores: {cond ? "a" : "b"}.
  • && mostra ou esconde; com zero ele desenha o zero.
  • false, null e undefined não desenham nada.
  • Objeto e função entre chaves quebram o componente.
  • Use a propriedade: {pao.nome}, {pao.preco}.
  • Calcule antes do return e mantenha o JSX curto.
