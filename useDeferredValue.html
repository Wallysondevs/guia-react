O useDeferredValue

A Ana comprou um componente de busca pronto — uma caixa de texto que já vem com o seu próprio estado e devolve só o texto digitado. O componente é bom e ela não quer mexer nele. O problema é que a lista de dois mil pães, do lado de fora, filtra a cada letra e trava a digitação. Sem poder mudar o estado de dentro do componente, ela não tem como usar o useTransition. Nesta aula a Ana conhece o useDeferredValue: o hook que recebe um valor e devolve uma versão atrasada dele — a mesma ideia de prioridade, olhando pelo lado do valor em vez do lado da atualização.

Você vai aprender
  • O que é um valor adiado e quando ele chega.
  • Por que o React desenha duas vezes: uma urgente e uma adiada.
  • O valor inicial do useDeferredValue, no React 19.
  • Como usar o valor adiado no filtro de uma lista grande.
  • Por que ele não substitui debounce nem cache.
  • Como mostrar na tela que a lista está desatualizada.
  • Quando escolher useDeferredValue em vez de useTransition.

1. A cena: o valor que chega pronto de fora

O componente de busca da Ana é uma caixinha fechada: ela recebe o texto por prop e desenha o campo, com o useState dele lá dentro. O App só sabe o texto que chega. Para usar useTransition, ela precisaria do setState na mão — e não tem.

É aqui que entra o useDeferredValue. Ele recebe um valor qualquer e devolve uma cópia que pode ficar para trás: no primeiro momento, a cópia é o valor antigo; logo depois, o React desenha de novo com o valor novo. Quem usa a cópia — a lista grande, o gráfico, a tabela — espera. Quem usa o valor original — o campo, o título, o contador — responde na hora.

Repare que o hook não pergunta de onde veio o valor nem quem o mudou. Ele só precisa do valor. É por isso que ele funciona com prop, com resultado de contexto, com item de lista, com qualquer expressão. O useTransition precisa da função que muda o estado; o useDeferredValue precisa só do valor.

2. O que é um valor adiado

“Adiado” aqui não quer dizer errado nem velho para sempre: quer dizer que ele pode ficar atrás por alguns milissegundos, o tempo de o React preparar o desenho mais caro. Se nada urgente acontecer no meio, o atraso é imperceptível. Se a pessoa continuar digitando, o valor adiado persegue o atual e a lista pode ficar um pouco para trás — de propósito.

useDeferredValue
O hook que devolve o valor adiado: const atrasado = useDeferredValue(texto). Vem do React e, nas caixas, já está no escopo.
valor adiado
A cópia que o React entrega no desenho urgente enquanto prepara o desenho caro. Pode ser o valor anterior por um instante.
desenho urgente
O primeiro, com o valor novo no campo. É o que a pessoa vê primeiro e é o que não pode esperar.
desenho adiado
O segundo, com o valor adiado atualizado. É onde a lista, a tabela ou o gráfico são recalculados.
valor inicial
No React 19, o segundo argumento: useDeferredValue(texto, "carregando"). É o que aparece no primeiro desenho, antes de o valor de verdade existir.
atraso visível
Quando o valor adiado é diferente do atual: atrasado !== texto. Serve para esmaecer a lista ou mostrar “atualizando…”.

A comparação com o useTransition ajuda a fixar. O useTransition diz “esta atualização pode esperar”; o useDeferredValue diz “este valor pode chegar atrasado”. O primeiro age no momento em que o estado muda; o segundo age no momento em que o valor é usado. Os dois produzem o mesmo efeito na tela — o React faz um desenho urgente e um adiado — e a escolha entre eles é sobre onde você tem controle.

3. A caixa: dois desenhos, dois valores

A primeira caixa é um experimento, não uma tela bonita. O componente escreve no console o número do desenho e o valor adiado que recebeu. Sem o segundo argumento, o React desenharia duas vezes com o mesmo valor e não haveria nada para ver. Com "carregando" como valor inicial, o primeiro desenho mostra uma coisa e o segundo mostra outra — e o painel deixa os dois registros à vista.

Passe "carregando" como segundo argumento: useDeferredValue(texto, "carregando"). Rode e olhe o console do painel: ele mostra os dois desenhos.

let desenhos = 0;

function App() {
  const [texto] = useState("Pão de queijo");
  const atrasado = useDeferredValue(texto);
  desenhos = desenhos + 1;
  console.log("desenho " + desenhos + ": " + atrasado);
  return (
    <div>
      <p>Texto: {texto}</p>
      <p>Lista: {atrasado}</p>
    </div>
  );
}

O painel mostra o HTML final — “Texto: Pão de queijo”, “Lista: Pão de queijo” — e, embaixo, as duas linhas de console. A primeira diz carregando; a segunda, o valor de verdade. Isso é o React fazendo dois desenhos: o urgente, com o texto e o valor inicial; o adiado, com a lista atualizada.

Uma nota sobre o contador: ele é uma variável fora do componente, incrementada dentro do corpo. Em código de produção você não faz isso — é um truque de aula para mostrar quantas vezes o componente foi desenhado. Se quiser repetir o experimento no seu projeto, use um console.log no corpo e olhe a aba Console: cada par de linhas é uma atualização.

O que o HTML final não mostra é o instante do meio. Numa lista grande, é justamente esse instante que importa: a pessoa vê o campo com a letra nova e a lista ainda com o resultado anterior. Se você quiser avisar que a lista está velha, compare os dois valores:

const atrasado = useDeferredValue(texto);
const desatualizada = atrasado !== texto;
return (
  <ul className={desatualizada ? "lista apagada" : "lista"}>
    ...
  </ul>
);

Essa comparação é simples e funciona: enquanto a lista mostra o texto antigo, a classe muda e o CSS pode deixar o bloco mais claro. É o mesmo papel do pendente no useTransition, com a vantagem de não precisar de nenhum estado extra.

4. A caixa: a lista que espera

Agora o caso de verdade. O campo é controlado e atualiza o texto na hora; a lista grande deveria filtrar com o valor adiado. Na versão inicial, a lista mostra os três pães sempre — ninguém filtra nada — e a linha de resultados acompanha o texto. A missão é fazer o filtro e a linha usarem o valor adiado.

Crie const filtrados = paes.filter((p) => p.toLowerCase().includes(atrasado.toLowerCase())), desenhe filtrados no lugar de paes e troque a linha de resultados para Resultados para: {atrasado}.

function App() {
  const [texto, setTexto] = useState("");

  const paes = ["Pão francês", "Pão de queijo", "Baguete"];

      <label htmlFor="busca">Buscar pão</label>
      <input
        id="busca"
        value={texto}
        onChange={(e) => setTexto(e.target.value)}
      />
      <p>Resultados para: {texto}</p>
      <ul>
        {paes.map((p) => (
          <li key={p}>{p}</li>
        ))}
      </ul>
    </div>
  );
}

  const atrasado = useDeferredValue(texto);
  const paes = ["Pão francês", "Pão de queijo", "Baguete"];

      <input
        id="busca"
        value={texto}
        onChange={(e) => setTexto(e.target.value)}
      />

        ))}
      </ul>

Digite “queijo” e o painel mostra a linha “Resultados para: queijo” e uma lista com um item. Com três pães, o resultado é o mesmo que você teria filtrando pelo texto urgente; com dois mil, não é. A diferença é que, no desenho urgente, o React entrega o valor adiado antigo — a lista não é recalculada naquele instante — e a digitação não espera.

Esse detalhe tem uma consequência que confunde: a lista pode mostrar o resultado de um texto que já não está no campo. É o comportamento desejado. Se você mostrar “Resultados para: {atrasado}”, a frase conta a verdade sobre o que está na lista; se mostrar o texto atual, a frase mente por alguns milissegundos. Escolha uma das duas e seja coerente.

E o campo continua com value={texto}, não com value={atrasado}. Essa troca é o erro mais comum do hook: o campo passa a mostrar o valor adiado, e a pessoa sente a digitação travada — que é exatamente o que o hook deveria evitar.

5. O valor inicial do React 19

O segundo argumento é novidade do React 19 e resolve um problema específico: o primeiro desenho de um componente que ainda não tem o dado. Antes, o único jeito de o valor adiado diferir do atual era uma atualização; no primeiro desenho, os dois eram iguais. Agora você pode dizer o que aparece antes:

function Painel({ texto }) {
  const atrasado = useDeferredValue(texto, "carregando");
  return <p>Lista: {atrasado}</p>;
}

Esse valor inicial aparece uma vez, no primeiro desenho, e depois é substituído pelo valor de verdade. É útil quando o dado chega por uma leitura cara e você prefere mostrar um marcador em vez de uma lista vazia. Não é um estado de carregamento: não volta a aparecer se o valor mudar depois. Para carregamento de verdade, o caminho continua sendo um estado próprio, como em Carregando e Erro.

Se você escrever useDeferredValue(texto, ""), o primeiro desenho mostra a string vazia e o segundo mostra o texto. Isso evita o “pisca” de uma lista grande desenhada com o valor final antes de o navegador estar pronto. É um detalhe pequeno, e é a diferença entre uma tela que aparece e uma tela que aparece e se mexe.

6. Por que ele não substitui debounce nem cache

Aqui está o mal-entendido que mais custa caro. O useDeferredValue não reduz a quantidade de trabalho: ele só muda a prioridade. Cada letra digitada continua gerando um desenho urgente e um desenho adiado. Se há uma consulta ao servidor dentro de um efeito que depende do valor adiado, ela roda em toda letra — uma por letra.

A caixa seguinte conta as consultas. O useEffect depende de atrasado e soma um no contador a cada mudança. Digite “que” e veja o número: o contador começa em zero, o efeito soma um assim que a tela aparece e mais um a cada letra nova — quatro no total. É a prova de que adiar não é agrupar.

Faça o contador acompanhar o valor adiado: crie useEffect(() => { setBuscas((n) => n + 1) }, [atrasado]) no corpo do componente e digite “que” no campo, letra por letra.

function App() {
  const [texto, setTexto] = useState("");
  const atrasado = useDeferredValue(texto);
  const [buscas, setBuscas] = useState(0);

  return (
    <div>
      <input value={texto} onChange={(e) => setTexto(e.target.value)} />
      <p>Consultas: {buscas}</p>
    </div>
  );
}
<div>

Agora com debounce — um setTimeout que só dispara quando a digitação para, cancelado a cada tecla nova. As três letras viram uma consulta:

consulta 1: "que"

São ferramentas diferentes para problemas diferentes. O useDeferredValue cuida da prioridade do desenho; o debounce cuida do volume de chamadas. Um não substitui o outro, e o código que usa os dois é comum em busca de verdade: o valor adiado alimenta a lista, e o debounce decide quando perguntar ao servidor.

useEffect(() => {
  const id = setTimeout(() => {
    fetch("/api/paes?q=" + encodeURIComponent(texto))
      .then((r) => r.json())
      .then(setResultados);
  }, 300);

  return () => clearTimeout(id);
}, [texto]);

Nas caixas deste guia não há rede: fetch não funciona dentro do quadro. Quando o assunto for buscar dados, a espera é simulada com Promise mais setTimeout, e o código com fetch aparece no pre.file, como acima. O comportamento que importa — quantas vezes a função roda — é o mesmo.

7. useDeferredValue ou useTransition?

Os dois existem porque os dois lados do problema existem. A pergunta prática é uma só: você tem a função que muda o estado na mão?

o setState na mãofunciona, com uma variável a maisé o caso dele
uma ação que espera o servidornão cobre o awaito pendente cobre
um pedaço da tela que recebe textopasse o valor adiado e prontoprecisa subir o estado
um aviso de “está desatualizado”atrasado !== textopendente

Na prática, os dois aparecem juntos no mesmo projeto. O useTransition nas ações que você escreve — enviar encomenda, trocar de filtro salvo — e o useDeferredValue nos valores que chegam prontos e alimentam listas grandes. Trocar um pelo outro dá trabalho e não melhora nada.

Um critério de desempate: se o valor precisa ser lido por um componente que você não controla ou que recebe o dado por prop, o useDeferredValue é o único que funciona sem refatorar a árvore. É exatamente a situação da Ana no começo da aula.

8. Os cuidados que valem a pena

Quatro erros concentram as reclamações sobre este hook. Nenhum deles dá erro no console: todos aparecem como “não mudou nada” ou “ficou mais lento”.

O que você fezO que aconteceO conserto
usou o valor adiado no value do campoa digitação fica atrasadao campo usa o valor urgente
esperava menos consultas ao servidorcontinua uma por mudançadebounce no efeito
adiou um valor que alimenta pouca coisadois desenhos para nadatirar o hook

A terceira linha é a que menos aparece nas conversas e a que mais importa. Adiar custa: o componente é desenhado duas vezes, e o React guarda trabalho para depois. Se o pedaço caro é pequeno, o custo do mecanismo é maior que o ganho. O hook compensa quando há uma lista longa, um gráfico, uma tabela com cálculo — não para um parágrafo com três itens.

A quarta linha é a regra de sempre, e vale repetir porque o hábito escapa: useDeferredValue é hook como os outros, no topo do componente, sem condição. Se você precisa decidir se adia ou não, adie sempre e escolha o que fazer com o resultado no JSX. A aula As Regras dos Hooks explica o mecanismo por trás disso.

9. Cenários do dia a dia

Cenário 1: a caixa de busca que veio pronta

O componente de busca da Ana guardava o texto por dentro e devolvia por callback. Ela não podia usar useTransition porque não tinha o setState. Passou o texto por useDeferredValue e alimentou a lista com o valor adiado. O campo continuou instantâneo, e a lista passou a esperar.

Cenário 2: a tabela que piscava

A tabela de preços redesenha duzentas linhas a cada mudança de filtro, e a tela piscava. Com o valor adiado mais o valor inicial [], o primeiro desenho saiu com a tabela vazia e o segundo com o resultado — sem pisca e sem travar. O ganho veio da combinação: prioridade no desenho e um estado inicial honesto.

Cenário 3: o contador de consultas que não baixou

Ela adiou o valor e esperou ver menos requisições no painel do servidor. Continuou vendo uma por letra. A explicação está na seção 6: adiar não agrupa. Ela pôs um setTimeout com clearTimeout no efeito e manteve o valor adiado para a lista. As duas coisas juntas resolveram os dois problemas diferentes.

11. Resumo

O useDeferredValue recebe um valor e devolve uma versão que pode ficar para trás. O React desenha primeiro com o valor urgente — o campo, o título, o que a pessoa está mexendo — e depois com o valor adiado, que é onde a lista grande, a tabela e o gráfico são recalculados. Como não precisa da função que muda o estado, ele funciona com prop, com valor de contexto e com qualquer expressão.

No React 19, o segundo argumento define o valor do primeiro desenho: useDeferredValue(texto, "carregando"). É útil para evitar o pisca de uma lista montada com o valor final, e não substitui um estado de carregamento de verdade. Para saber se a lista está velha, compare atrasado !== texto e use isso no estilo ou na mensagem.

O hook não reduz trabalho: ele muda prioridade. Cada letra continua gerando um desenho urgente e um adiado, e cada mudança do valor adiado continua disparando os efeitos que dependem dele. Debounce, cache e cancelamento de requisição são outros assuntos, com outras ferramentas. E, como todo hook, ele fica no topo do componente — nunca dentro de um if.

Para lembrar

  • const atrasado = useDeferredValue(texto), no topo do componente.
  • O desenho urgente usa o valor atual; o adiado pode usar o anterior.
  • O campo de texto usa o valor urgente; a lista grande usa o adiado.
  • React 19: useDeferredValue(texto, "carregando") define o primeiro desenho.
  • atrasado !== texto avisa que a lista está desatualizada.
  • Não é debounce: não reduz consultas nem agrupa chamadas.
  • Não é cache: o valor adiado continua mudando a cada letra.
  • Funciona com valor que vem de prop, onde o useTransition não alcança.
  • Adiar custa dois desenhos: use onde o trabalho é grande de verdade.
  • Hook no topo, sem condição, como todos os outros.
