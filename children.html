O children

A Ana precisa do mesmo aviso em três páginas do site, com textos diferentes: na inicial, “encomendas até as 17h”; na lista de pães, “sai do forno às 6h”; no contato, “retire na loja até as 19h”. O formato da caixa é igual nos três — borda, cor de fundo, um respiro — e só o conteúdo muda. Ela já sabe mandar texto por prop, mas o texto do meio de um parágrafo, ou um parágrafo inteiro, não cabe bem num atributo. Nesta aula ela descobre que o React já reservou um lugar para isso: tudo o que você escreve entre as tags chega ao componente como children.

Você vai aprender
  • O que é children: o conteúdo que fica entre a tag de abertura e a de fechamento.
  • Como renderizar esse conteúdo com {children}.
  • Que children é uma prop como as outras, só com nome reservado.
  • O que chega quando há texto, um elemento ou vários elementos.
  • Quando usar children e quando usar uma prop com nome.
  • Como misturar children com as outras props no mesmo componente.
  • Por que esquecer a tag de fechamento quebra o código.

1. A cena: a mesma caixa, três textos

O aviso da padaria é sempre a mesma caixa: fundo claro, borda fina, texto pequeno. O que muda é o recado. Na primeira tentativa, a Ana fez o componente receber o texto por prop:

function Aviso({ texto }) {
  return <div className="aviso">{texto}</div>;
}

function App() {
  return <Aviso texto="Encomendas até as 17h" />;
}

Funciona para uma frase curta. Mas o recado de verdade tem negrito no meio, um link para o telefone, às vezes uma lista de horários. Colocar tudo isso dentro de um atributo é desconfortável: você teria de passar pedaços de HTML como texto ou inventar três props — texto, negrito, link — e o componente nunca mais seria simples.

O React resolve isso com uma ideia elegante: o conteúdo que fica entre a tag de abertura e a de fechamento não vira atributo nenhum. Ele é entregue ao componente numa prop especial chamada children. Ou seja, a posição já é a informação: o que está dentro é o conteúdo, e o componente decide onde encaixar.

Isso muda como você pensa componentes. Um componente deixa de ser só “uma caixa que recebe dados” e passa a ser também “uma moldura que recebe conteúdo”. É a diferença entre um cartão com texto fixo e um cartão que emoldura o que você quiser pôr dentro.

2. O conteúdo entre as tags

Quando você escreve <Caixa>Pão quentinho</Caixa>, o React monta o objeto de props com uma chave chamada children e o valor "Pão quentinho". Repare que a tag agora tem fechamento: sem ele, não há “entre”, e não há children. Uma tag escrita como <Caixa /> não tem conteúdo nenhum.

children
A prop que guarda o conteúdo escrito entre as tags. O nome é reservado pelo React: você não escolhe, e não precisa declarar na chamada.
tag de abertura
<Caixa>, com o sinal de maior no fim. É onde o conteúdo começa.
tag de fechamento
</Caixa>, com a barra antes do nome. Sem ela, o componente não tem filhos.
conteúdo
O que fica no meio: texto, um elemento, vários elementos, uma expressão com chaves.
moldura
O papel do componente que usa children: dar forma, borda e espaçamento a um conteúdo que ele não conhece.

O nome é emprestado do inglês: children quer dizer “filhos”. Em HTML, os elementos dentro de outro são chamados de filhos, e o React manteve a palavra. Não há nada de mágico no conceito — é uma chave do objeto de props como nome ou preco; o que ela tem de especial é ser preenchida pelo React, a partir da posição do conteúdo, e não por um atributo que você escreve.

Há um detalhe que confunde: children é uma prop, mas você não a escreve como atributo. Escrever <Caixa children="Pão" /> funciona, tecnicamente — o React aceita —, mas não é o costume e atrapalha quem lê. O jeito natural é o conteúdo entre as tags; o atributo fica reservado para os casos raros em que o conteúdo vem de uma variável.

3. Um espaço para o conteúdo

Veja o que acontece quando o componente não usa children: o React entrega o conteúdo, mas ninguém o coloca na tela. Ele some sem erro nenhum — o mesmo silêncio das props com nome errado.

O texto entre as tags não aparece, porque o componente não o renderiza. Coloque {children} dentro do div e clique em Rodar.

function Aviso({ titulo }) {
  return (
    <div className="aviso">
      <strong>{titulo}</strong>
    </div>
  );
}

function App() {
  return <Aviso titulo="Atenção">Encomendas até as 17h</Aviso>;
}
<div class="aviso"><strong>Atenção</strong></div>

function Aviso({ titulo, children }) {
  return (
    <div className="aviso">
      <strong>{titulo}</strong>
      {children}
    </div>
  );
}

function App() {
  return <Aviso titulo="Atenção">Encomendas até as 17h</Aviso>;
}

Duas coisas mudaram na solução: o conteúdo apareceu, e o componente passou a declarar children na assinatura. Essa segunda parte é opcional — {props.children} funcionaria igual —, mas declarar deixa claro, para quem lê, que aquele componente espera conteúdo. É a mesma ideia da aula de desestruturar: o que aparece no parâmetro é o contrato.

Repare também na ordem: o {children} foi colocado depois do título, e é ali que o texto aparece. O componente escolhe o lugar. Se você mover a linha para antes do strong, o conteúdo sobe na tela. children não é um bloco fixo no fim do componente: é um valor que você posiciona onde quiser.

4. children é uma prop como as outras

Chamada diferente, mesma mecânica. O que chega em props.children depende do que você escreveu no meio das tags, e o tipo acompanha o conteúdo. A tabela mostra os casos que aparecem no dia a dia.

Na chamadaO que chega em children
<Caixa>Pão quentinho</Caixa>o texto "Pão quentinho"
<Caixa><p>Pão</p></Caixa>o elemento p, inteiro
<Caixa><p>a</p><p>b</p></Caixa>uma lista com os dois elementos
<Caixa />undefined — nada aparece
<Caixa>{nome}</Caixa>o valor da variável nome
<Caixa>{2 + 1} pães</Caixa>o resultado e o texto: 3 pães

Para ver o que chegou, imprima. Quando o conteúdo é texto, a linha do console mostra a string inteira — é o jeito mais rápido de confirmar que a página mandou alguma coisa:

function Aviso({ titulo, children }) {
  console.log("children: " + children);
  return <div className="aviso">{children}</div>;
}
console: children: Sai às 6h

Se o conteúdo for um elemento em vez de texto, a concatenação com + não serve: o resultado vira [object Object]. Nesse caso, imprima children sozinho, sem montar string. É o mesmo cuidado que você viu com objetos na aula de props — e a mesma conclusão: para saber o que chegou, olhe o console antes de mexer no componente.

Duas consequências práticas. A primeira: {children} desenha qualquer coisa que o React saiba desenhar — texto, elemento, lista de elementos. Você não precisa tratar cada caso. A segunda: se não houver conteúdo, {children} vale undefined e simplesmente não desenha nada — sem erro, sem espaço sobrando.

Uma diferença em relação às props normais: quando há mais de um filho, o React entrega uma lista, e não um valor só. Você não precisa se preocupar com isso para renderizar — basta {children} —, mas precisa saber que existe, porque percorrer os filhos com map é uma técnica real e o tipo do valor muda conforme a chamada.

5. Texto, elemento ou vários

A caixa de aviso da Ana às vezes tem um parágrafo, às vezes dois. Como children aceita vários elementos, a mesma moldura serve para os dois casos — a página é que decide quantos parágrafos põe dentro.

A caixa é uma moldura que já renderiza children, mas a página só passa um parágrafo. Acrescente um segundo parágrafo com o texto Chega às 16h.

function Aviso({ children }) {
  return <div className="aviso">{children}</div>;
}

function App() {
  return (
    <Aviso>
      <p>Sai às 6h</p>
    </Aviso>
  );
}
<div class="aviso">
  <p>Sai às 6h</p>
</div>

function Aviso({ children }) {
  return <div className="aviso">{children}</div>;
}

function App() {
  return (
    <Aviso>
      <p>Sai às 6h</p>
      <p>Chega às 16h</p>
    </Aviso>
  );
}

O painel passa a mostrar dois parágrafos dentro do div, e a missão confere a contagem — dois p dentro de .aviso. Note que o componente não mudou uma linha. Quem decide o conteúdo é quem usa a moldura, e é por isso que children é a ferramenta certa para conteúdo variável: o componente não precisa saber quantos parágrafos existem.

Há também uma vantagem de manutenção que não aparece no primeiro dia. Quando o conteúdo está na página que usa o componente, mudar o recado não exige tocar no componente — e o contrário é verdadeiro: mudar a moldura não exige tocar em nenhuma das páginas. Cada arquivo cuida do que é seu. Isso parece pouco com três avisos e passa a valer muito quando são trinta.

Isso tem um limite saudável. Se o componente precisa controlar o conteúdo — mudar a cor de cada item, ordenar, numerar —, children não ajuda: ele só entrega o que veio. Nesse caso, o caminho é receber uma lista por prop e desenhar item por item, que é o assunto de Listas com map, mais adiante.

6. children ou prop com nome?

As duas formas mandam dados para dentro do componente. A diferença não é de poder, é de leitura: o que fica entre as tags é conteúdo livre; o que vai em atributo é valor com nome, que o componente pode usar em contas e decisões. A tabela resume a escolha.

SituaçãoMelhor caminhoPor quê
conteúdo que só quem usa conhecechildrena página manda o que quiser, inclusive links e listas
título curto e obrigatórioprop tituloo componente precisa dele em lugar fixo
parágrafo longo, com negritochildrenatributo não acomoda marcação
número usado em contaprop precoo componente calcula com valor, não com texto
rótulo de botãoas duas servemchildren se o rótulo pode ter ícone; prop se é sempre texto
lista de itensprop com listao componente precisa percorrer e desenhar cada um

Há um teste simples para decidir: o componente precisa olhar o conteúdo? Se ele só precisa colocar na tela, children. Se precisa comparar, contar, formatar ou decidir com base no valor, prop. Uma caixa que emoldura um aviso não olha o aviso; um cartão de preço olha o preço.

Na dúvida, comece com prop. É mais fácil transformar uma prop em children do que o contrário: quando o conteúdo passa a ter marcação, você muda a chamada de <Aviso texto="Sai às 6h" /> para <Aviso>Sai às 6h</Aviso> e o componente de {texto} para {children}. São duas edições pequenas e localizadas, e a tela continua igual — o que muda é o que passa a ser possível.

7. children junto com as outras props

O caso mais comum em projeto de verdade é a mistura: um título que o componente posiciona no topo e um conteúdo que ele emoldura embaixo. As duas coisas convivem na mesma chamada — os atributos viram props, o que está entre as tags vira children.

O título aparece, mas o conteúdo entre as tags não. Mostre os children dentro de um <p className="rodape">, depois do título.

function Cartao({ titulo }) {
  return (
    <div className="cartao">
      <h2>{titulo}</h2>
    </div>
  );
}

function App() {
  return <Cartao titulo="Pão do dia">Sai quentinho às 6h</Cartao>;
}
<div class="cartao">
  <h2>Pão do dia</h2>
</div>

function Cartao({ titulo, children }) {
  return (
    <div className="cartao">
      <h2>{titulo}</h2>
      <p className="rodape">{children}</p>
    </div>
  );
}

function App() {
  return <Cartao titulo="Pão do dia">Sai quentinho às 6h</Cartao>;
}

Essa é a forma que você vai usar em quase todo componente de layout: um ou dois valores por prop, para o que precisa ficar em lugar certo, e children para o miolo. E note que a chamada fica esquisita de ler se você não conhece a regra: titulo="Pão do dia" é atributo, e Sai quentinho às 6h é conteúdo. Duas coisas diferentes no mesmo lugar, cada uma com a sua porta de entrada.

Um detalhe de estilo: quando o componente recebe children e outras props, a ordem na assinatura não importa, mas o costume é deixar children por último — ele é o mais “especial” dos parâmetros. E não abrevie para kids ou filhos: o nome children é o que o React usa, e renomear só confunde quem lê.

8. Os tropeços de quem usa children

Como sempre, os erros são silenciosos ou de sintaxe. O silencioso é entregar conteúdo a um componente que não o renderiza; o de sintaxe é esquecer a tag de fechamento ou fechar com o nome errado. A tabela junta os dois tipos, com o conserto de cada um.

O que você escreveuO que aconteceO conserto

<Caixa> sem </Caixa>não compila: Unterminated JSX contentsfeche a tag

children="Pão" como atributofunciona, mas foge do padrãoescreva o texto entre as tags
Expected corresponding JSX closing tag for <Caixa>. (9:4)

Essa é a mensagem do terceiro caso, e ela é mais útil do que parece: diz qual tag ficou aberta e em que linha o compilador desistiu. O compilador do JSX trata as tags como um quebra-cabeça — cada abertura precisa de um fechamento com o mesmo nome, na ordem certa. Um </div> no lugar de </Caixa> não é “quase certo”: é outro fechamento.

Vale reparar no formato: a mensagem mostra a tag entre sinais de menor e maior, do jeito que você escreveu no código. É por isso que ela é tão específica — o compilador tem o seu texto na mão e aponta a peça que não encaixou.

9. Cenários do dia a dia

Depois que a ideia de moldura entra na cabeça, os componentes ficam menores e mais reutilizáveis. Os três cenários abaixo são as situações em que a Ana precisou de children de verdade.

Cenário 1: a caixa de aviso que servia para um texto só

O primeiro Aviso recebia texto por prop e funcionava para uma frase. Quando o recado passou a ter um telefone em negrito, ela trocou a prop por children e a chamada virou <Aviso>Ligue para <strong>11 5555-1234</strong></Aviso>. O componente ficou menor e passou a aceitar qualquer conteúdo.

Cenário 2: o conteúdo que sumiu na troca

Ela mudou a chamada para usar children e esqueceu de colocar {children} dentro do componente. A tela ficou sem o recado, e o console do navegador não reclamou de nada: para o React, o componente simplesmente não usou o que recebeu. O conserto é uma linha, e o sintoma — conteúdo que desaparece — vale memorizar.

Cenário 3: a tag fechada com o nome errado

Com pressa, ela fechou <Caixa> com </div>. O código não compilou, e a mensagem apontou a linha do fechamento errado com o nome da tag que ficou aberta. Conserto: </Caixa>. Em JSX, o nome da tag de fechamento não é decorativo — é verificação.

Quando o conteúdo não aparece, a ordem de conferência é curta. Primeiro, o componente renderiza {children} em algum lugar? Sem isso, nada chega à tela. Segundo, a chamada usa a tag com abertura e fechamento, e não a versão auto-fechada? Terceiro, o conteúdo está entre as tags certas — e não depois do fechamento, onde vira irmão do componente e aparece fora da moldura. Quatro em cada cinco casos caem no primeiro item.

Dica: é o nome que o React reserva para o que você escreve entre a tag de abertura e a de fechamento. Sem ele, o conteúdo não tem como chegar.

11. Resumo

Tudo o que você escreve entre as tags de um componente chega numa prop chamada children. O componente decide onde colocar — e, se não colocar, o conteúdo some em silêncio. É o que transforma um componente em moldura: a forma fica com ele, o conteúdo fica com quem usa.

children aceita texto, elemento, lista de elementos ou o resultado de uma expressão, e vale undefined quando não há conteúdo. Use children para o que o componente só precisa exibir; use prop com nome para o que ele precisa calcular, comparar ou posicionar com regra. E quando as duas coisas aparecem juntas, a chamada fica com atributos e conteúdo — cada um na sua porta.

Para lembrar

  • children é o conteúdo entre a tag de abertura e a de fechamento.
  • Renderize com {children}; o lugar no componente é escolha sua.
  • É uma prop como as outras, só com nome reservado e sem atributo.
  • Um filho ou vários: {children} desenha os dois casos.
  • Sem conteúdo, children é undefined e não aparece nada.
  • Componente que não usa {children} descarta o conteúdo, sem erro.
  • <Caixa /> não tem children; a tag precisa de abertura e fechamento.
  • Nome errado no fechamento não compila: Expected corresponding JSX closing tag.
