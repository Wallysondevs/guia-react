O Cleanup

A Ana escondeu o relógio da vitrine com um clique e reparou numa coisa estranha: o relógio sumiu da tela, mas continuou funcionando. O intervalo que ela ligou no efeito nunca foi desligado — e cada vez que ela esconde e mostra de novo, nasce mais um. Nesta aula ela aprende a devolver uma função no fim do efeito: o cleanup, que o React chama para desfazer o que o efeito fez antes de começar outro.

Você vai aprender
  • O que é a função de limpeza e como se devolve ela do useEffect.
  • As duas horas em que o cleanup roda: antes de cada nova execução e na desmontagem.
  • Como desligar um setInterval e um setTimeout.
  • Como cancelar uma assinatura quando o dado que ela usa muda.
  • Como cancelar o que ainda não aconteceu, com o exemplo do salvamento adiado.
  • Como ignorar a resposta de um pedido que ficou para trás — a corrida entre buscas.
  • Os erros comuns: esquecer o return, limpar o que não criou, limpar no lugar errado.

1. A cena: o relógio que continua andando

Na vitrine da Ana há um relógio que atualiza a hora a cada segundo. Ele vive em um componente chamado Relogio, e o componente de cima decide quando mostrá-lo: um botão "Mostrar ou esconder". Ao clicar, o React tira o Relogio da página — a desmontagem. O que a Ana não sabia é que desmontar não desliga nada que o componente tenha ligado por fora.

O setInterval que ela criou no efeito continua rodando, chamando setHora em um componente que não existe mais. Se ela esconde e mostra cinco vezes, ficam cinco intervalos rodando ao mesmo tempo — cinco atualizações por segundo em vez de uma, cada uma com um pedaço de memória preso. No começo ninguém nota. Depois de meia hora com a aba aberta, o notebook esquenta.

Esse é o problema que o cleanup resolve, e ele não é exclusivo de timer. Um listener de evento adicionado ao document fica escutando depois que o componente sai. Uma assinatura de notificação continua recebendo. Um pedido em andamento volta para ninguém. Todos esses casos têm a mesma forma: o efeito cria algo fora do React, e precisa de um lugar para desfazer aquilo.

2. O que é a função de limpeza

Para desfazer, o React dá ao efeito um canal de saída: o valor devolvido. Se a função do efeito devolver outra função, o React guarda essa segunda função e chama quando for hora de limpar. Essa segunda função é o cleanup. Não tem nome especial na hora de declarar, nem gancho próprio: é só um return.

useEffect(() => {
  const id = setInterval(() => setHora(new Date()), 1000);

  return () => {
    clearInterval(id);
  };
}, []);
cleanup
A função devolvida pelo efeito, que o React chama para desfazer o que ele fez. Em inglês, clean up: limpar.
desmontagem
O momento em que o componente sai da página — porque a condição que o mostrava ficou falsa, porque o pai trocou de tela, ou porque a aba fechou.
efeito sujo
Um efeito que cria algo por fora e não devolve nada para desfazer. É a causa da maioria dos vazamentos.
criar e desfazer
O par que sempre anda junto: setInterval com clearInterval, addEventListener com removeEventListener, fetch com abort.
corrida
Duas buscas em andamento em que a resposta mais antiga chega por último e sobrescreve a mais nova. O cleanup é a ferramenta para resolver.

Um detalhe de sintaxe que derruba muita gente: o return com a função de limpeza tem de estar dentro do corpo do efeito, e o corpo precisa estar entre chaves. Se você escrever useEffect(() => () => clearInterval(id), []), o efeito devolve a função direto e funciona — mas ninguém entende depois, e não há espaço para criar o intervalo no meio. Use as chaves e deixe o return explícito.

Outro detalhe: a função de limpeza não pode ser async. O React chama a limpeza e segue em frente; ele não espera. Se você precisa de await para limpar (fechar uma conexão, por exemplo), faça o trabalho assíncrono dentro de uma função chamada sem await.

3. Quando o cleanup roda

São dois momentos, e o segundo surpreende. O primeiro é a desmontagem: o componente sai da página e o React limpa o que ele havia criado. O segundo é antes de cada nova execução do efeito: se as dependências mudaram e o efeito vai rodar de novo, o React roda primeiro a limpeza da execução anterior. Sempre nessa ordem — limpa o velho, executa o novo.

Essa ordem é o que garante que o mundo de fora reflita o estado atual e nada mais. No caso da assinatura do jornal do bairro, o componente assina o Centro, a Ana muda para Vila Nova, e o React cancela a assinatura do Centro antes de assinar a da Vila Nova. Se você esquecer o cleanup, o componente fica com duas assinaturas e recebe o jornal de um bairro onde não mora mais.

Nas caixas desta aula você vai ver o cleanup acontecer por meio de um caderninho de registro: uma lista no estado do componente de cima, onde o efeito anota o que fez. O painel mostra o HTML gerado, então o caderninho aparece na tela — e a anotação "desliguei o intervalo" só existe se a limpeza realmente rodou. É a forma de provar o invisível.

4. O primeiro cleanup: o timer

Na caixa, o componente Relogio liga um intervalo e anota no caderninho. O efeito não devolve nada, então ninguém desliga o intervalo. A missão é devolver a função de limpeza: desligar e anotar.

O Relogio liga um intervalo e nunca o desliga. Faça o efeito devolver uma função que chama clearInterval(id) e anota desliguei o intervalo no caderninho. Depois clique em Mostrar ou esconder.

function Relogio({ anotar }) {
  useEffect(() => {
    anotar("liguei o intervalo");
    setInterval(() => {}, 1000);
  }, []);

  return <p>Relógio ligado</p>;
}

function App() {
  const [aberto, setAberto] = useState(true);
  const [registro, setRegistro] = useState([]);

  return (
    <div>
      <button onClick={() => setAberto(!aberto)}>Mostrar ou esconder</button>
      {aberto && <Relogio anotar={(m) => setRegistro((r) => [...r, m])} />}
      <ul>
        {registro.map((m, i) => (
          <li key={i}>{m}</li>
        ))}
      </ul>
    </div>
  );
}

O painel do código inicial termina com uma linha só no caderninho: "liguei o intervalo". Depois da missão e do clique, aparecem duas: "liguei o intervalo" e "desliguei o intervalo". O relógio saiu da tela e a limpeza rodou — a segunda linha é a prova.

Repare que a limpeza precisa do id que o setInterval devolveu. Esse id é criado dentro do efeito e capturado pela função de limpeza; é o mesmo mecanismo de closure que você já usa em qualquer função. Se você criar o intervalo no corpo do componente e tentar limpá-lo no efeito, o id não vai estar lá — e o conserto é sempre criar e desfazer no mesmo lugar.

5. O cleanup que roda antes da próxima execução

Agora o segundo momento do cleanup, aquele que surpreende. Na caixa, o componente assina o jornal de um bairro. Quando o bairro muda, o efeito roda de novo porque bairro está nas dependências. Sem cleanup, a assinatura antiga fica viva: o React não tem como saber que ela existia.

A assinatura do bairro antigo nunca é cancelada. Faça o efeito devolver uma função que anota cancelei o jornal do seguido do bairro. Depois clique em Mudei para a Vila Nova.

function Assinatura({ bairro, anotar }) {
  useEffect(() => {
    anotar("assinei o jornal do " + bairro);
  }, [bairro]);

  return <p>Assinatura ativa: {bairro}</p>;
}

function App() {
  const [bairro, setBairro] = useState("Centro");
  const [registro, setRegistro] = useState([]);

  return (
    <div>
      <Assinatura bairro={bairro} anotar={(m) => setRegistro((r) => [...r, m])} />
      <button id="vila" onClick={() => setBairro("Vila Nova")}>
        Mudei para a Vila Nova
      </button>
      <ul>
        {registro.map((m, i) => (
          <li key={i}>{m}</li>
        ))}
      </ul>
    </div>
  );
}

Rode a solução e clique em "Mudei para a Vila Nova": o caderninho passa a ter três linhas, nesta ordem — "assinei o jornal do Centro", "cancelei o jornal do Centro", "assinei o jornal do Vila Nova". A do meio é a prova de que o React limpou antes de recomeçar. E repare que a função de limpeza usou bairro: ela foi criada na execução antiga do efeito, então bairro ali é o valor antigo — o Centro. Isso é o que se quer: cancelar o que foi assinado antes, não o que está sendo assinado agora.

Essa é a razão pela qual o cleanup precisa estar na mesma execução do efeito. Cada execução cria a sua limpeza, com os valores daquele momento. É o React guardando um par (efeito, limpeza) para cada vez que roda — e chamando a limpeza certa na hora certa.

6. O cleanup que cancela o que ainda não aconteceu

Nem tudo o que um efeito agenda acontece logo. Um setTimeout de dois segundos é uma promessa para o futuro; se o valor mudou nesse meio-tempo, o que estava agendado não interessa mais. O cleanup cancela o agendamento. É assim que se escreve um debounce: esperar o leitor parar de digitar antes de salvar.

O efeito agenda o salvamento do texto e nunca cancela o agendamento antigo. Devolva uma função de limpeza que faz clearTimeout(id) e anota cancelei o salvamento anterior. Depois digite na caixa de texto.

function App() {
  const [texto, setTexto] = useState("pão francês");
  const [registro, setRegistro] = useState([]);

  useEffect(() => {
    setRegistro((r) => [...r, "agendei o salvamento"]);
    setTimeout(() => {
      setRegistro((r) => [...r, "salvei " + texto]);
    }, 40);
  }, [texto]);

  return (
    <div>
      <input value={texto} onChange={(e) => setTexto(e.target.value)} />
      <ul>
        {registro.map((m, i) => (
          <li key={i}>{m}</li>
        ))}
      </ul>
    </div>
  );
}
<div>

function App() {
  const [texto, setTexto] = useState("pão francês");
  const [registro, setRegistro] = useState([]);

  useEffect(() => {
    setRegistro((r) => [...r, "agendei o salvamento"]);
    const id = setTimeout(() => {
      setRegistro((r) => [...r, "salvei " + texto]);
    }, 40);

    return () => {
      clearTimeout(id);
      setRegistro((r) => [...r, "cancelei o salvamento anterior"]);
    };
  }, [texto]);

  return (
    <div>
      <input value={texto} onChange={(e) => setTexto(e.target.value)} />
      <ul>
        {registro.map((m, i) => (
          <li key={i}>{m}</li>
        ))}
      </ul>
    </div>
  );
}

No código inicial, cada letra digitada agenda um salvamento e nenhum é cancelado: quem digita "pão de queijo" faz o sistema salvar uma vez por tecla, cada uma com um pedaço do texto. Na solução, cada nova digitação cancela o agendamento anterior, e só o último sobrevive — o caderninho mostra "cancelei o salvamento anterior" no meio do caminho.

Com dois segundos no lugar de 40 milissegundos, esse é o comportamento que o cliente espera: parar de digitar, esperar um instante e ver "salvo". O mesmo desenho serve para a busca que só consulta o servidor quando o leitor para de digitar — e aí o cleanup também evita uma enxurrada de pedidos.

7. A corrida dos pedidos

Falta o caso mais importante, e o mais invisível: o pedido que volta depois. A Ana digita "pão", o pedido sai, ela digita "queijo" e outro pedido sai. O segundo pode responder antes do primeiro — e quando o primeiro chegar, sobrescreve a lista com o resultado errado. A tela mostra os pães de uma busca que já não interessa.

O cleanup resolve com uma variável combinada: cada execução do efeito marca que está viva, e a limpeza marca que não está mais. O código que recebe a resposta confere a marca antes de chamar o set:

useEffect(() => {
  let ativo = true;

  async function carregar() {
    const resposta = await fetch("https://loja.test/api/paes?busca=" + termo);
    const lista = await resposta.json();
    if (ativo) {
      setPaes(lista);
    }
  }

  carregar();

  return () => {
    ativo = false;
  };
}, [termo]);

A variável ativo não é estado: é uma variável comum dentro do efeito, que a função de limpeza enxerga pela closure. Quando o termo muda, a limpeza da execução antiga roda e coloca ativo = false. A resposta que chegar depois encontra a marca desligada e não faz nada. Cada execução tem a sua própria variável, então a marca de uma não interfere na outra.

A outra forma é abortar o pedido de verdade, com o AbortController do navegador. A diferença é que o pedido é interrompido na rede em vez de só ser ignorado na chegada — mais econômico, e o erro que aparece é um AbortError, que você precisa saber ignorar:

useEffect(() => {
  const controle = new AbortController();

  fetch("https://loja.test/api/paes?busca=" + termo, { signal: controle.signal })
    .then((resposta) => resposta.json())
    .then((lista) => setPaes(lista))
    .catch((e) => {
      if (e.name !== "AbortError") setErro(e.message);
    });

  return () => controle.abort();
}, [termo]);

Sem o filtro do AbortError, o cancelamento vira mensagem de erro na tela — e o cliente vê "deu ruim" quando, na verdade, tudo funcionou como planejado. Detalhe que confunde: se você checar resposta.ok depois de um abort, o erro que aparece não é o de status, é o da requisição cancelada. Por isso o catch precisa olhar o nome do erro antes de decidir o que mostrar.

DOMException: The user aborted a request.
Uncaught (in promise) DOMException: The user aborted a request.

8. Os erros comuns do cleanup

O primeiro é esquecer o return. O efeito cria o timer, o listener ou a assinatura e termina sem devolver nada; o React não tem o que chamar e o recurso fica vivo. O sintoma é sempre cumulativo: uma vez não incomoda, dez vezes trava. Quando o componente "fica mais lento cada vez que abre", desconfie disso.

O segundo é limpar o que não foi criado. Se o efeito não criou o timer, ele não deve clearInterval em nada — e, pior, não deve limpar um recurso que pertence a outro efeito. Cada efeito limpa o que ele mesmo criou, nem mais nem menos. É o mesmo princípio de "um efeito por assunto" da primeira aula.

O terceiro é o lugar da limpeza. A função de limpeza tem de ser devolvida, não chamada no fim do efeito: return () => clearInterval(id), nunca clearInterval(id); return;. A segunda forma desliga o intervalo imediatamente, no instante em que o efeito começa, e o timer nunca chega a funcionar. O sintoma é um efeito que "não faz nada", e a causa está na última linha.

O quarto é o esquecimento na desmontagem por causa de uma condição. Se o componente aparece e desaparece conforme um if, ele desmonta de verdade e o cleanup roda. Mas se ele fica na árvore com display: none (via CSS), nada desmonta e nada é limpo — o componente continua montado, com efeito rodando. Trocar CSS por renderização condicional é o que faz a diferença entre esconder e desmontar.

Os quatro cabem em uma tabela de consulta, com o sintoma de cada um e o conserto:

9. Cenários do dia a dia

Cenário 1: o console mostra "montei" e "limpei" em pares

No modo de desenvolvimento, com StrictMode, cada efeito roda, é limpo e roda de novo. O console mostra a sequência "montei, limpei, montei" — o que parece errado e é de propósito. O React quer ver se o seu efeito sabe se limpar: se o segundo "montei" encontrar o mundo ainda sujo, é sinal de vazamento. As caixas deste guia não usam StrictMode, então você vê cada linha uma vez. No navegador, o console fica assim:

montei o relógio
limpei o relógio
montei o relógio

Cenário 2: a lista pisca com dados de uma busca anterior

É a corrida. A busca antiga responde depois e sobrescreve. O conserto é a marca ativo ou o AbortController, os dois desta aula. Enquanto o conserto não vem, um paliativo é limpar a lista no começo do efeito — mas isso troca o problema por outro: a tela fica vazia entre uma digitação e outra, o que incomoda mais do que parece.

Cenário 3: o timer do forno dispara depois que a tela mudou

A Ana agenda um aviso de "pão pronto" em cinco minutos e troca de tela. O aviso dispara na tela nova, em cima de outro conteúdo. Com clearTimeout na limpeza, o aviso é cancelado junto com a saída do componente. É a mesma regra do intervalo: quem cria, desfaz — e o efeito é o dono do que cria.

11. Resumo

O cleanup é a função que o efeito devolve. Ele roda em dois momentos: quando o componente desmonta e antes de cada nova execução do efeito. Sua função é desfazer o que o efeito fez — desligar o setInterval, remover o addEventListener, cancelar o setTimeout, abortar o fetch — para que o mundo de fora reflita o estado atual e nada mais.

O par é sempre criar e desfazer no mesmo efeito, com o mesmo id ou a mesma referência. A limpeza é criada junto com o efeito e guarda os valores daquela execução, o que é exatamente o que se precisa para cancelar o que foi criado. Devolver a função é diferente de chamá-la: chamar desfaz na hora, e aí não há nada para limpar depois.

Com timers, assinaturas e pedidos limpos, o componente pode montar e desmontar quantas vezes for sem deixar rastro. E o relógio que continuava andando depois de sumir da tela? Agora ele para — e a próxima aula é sobre os timers em si: como usar setTimeout e setInterval dentro do React sem cair nas armadilhas de estado velho.

Para lembrar

  • Cleanup é a função que o efeito devolve: return () => { ... }.
  • Roda na desmontagem e antes de cada nova execução do efeito.
  • Cada execução tem a sua própria limpeza, com os valores daquele momento.
  • Quem cria, desfaz: setInterval com clearInterval, listener com removeEventListener.
  • Cancelar o que ainda não aconteceu: clearTimeout no debounce.
  • Pedido que voltou tarde: marque ativo = false na limpeza e confira antes do set.
  • AbortController aborta de verdade; o AbortError não é erro de verdade.
  • Devolver a limpeza é diferente de chamá-la no fim do efeito.
  • Cada efeito limpa só o que ele criou.
  • Com StrictMode, o par efeito/limpeza roda duas vezes: é teste, não bug.
