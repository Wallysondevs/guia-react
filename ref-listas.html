Listas

Toda lista em React é a mesma conta: um array de dados entra, um array de elementos sai. O que muda de uma tela para outra são as decisões em volta — de onde vem a chave, o que fazer quando o filtro não deixa nada, como ordenar sem estragar o array original. A Ana chega aqui quando a vitrine da padaria passa de três pães para trezentos. Esta página é a consulta: cada seção responde uma pergunta e aponta para a aula que a destrincha.

Como usar esta página

  • As tabelas são o resumo; o texto em volta explica o porquê e aponta a aula completa.
  • As duas caixas rodam com React 19 de verdade: edite, clique em Rodar e leia o painel.
  • Os trechos de arquivo mostram o código como ele fica no projeto, com import e export.

1. A conta que está por trás de toda lista

React não tem um componente de lista. O que existe é JavaScript: um array de dados, uma chamada de .map que transforma cada dado em JSX e um key que diz qual elemento é qual. O resultado é um array de elementos, e o React aceita arrays dentro do JSX — ele desenha cada item na ordem.

export function Vitrine({ paes }) {
  return (
    <ul>
      {paes.map((pao) => (
        <li key={pao.id}>{pao.nome}</li>
      ))}
    </ul>
  );
}

Três coisas acontecem nesse bloco, e vale separá-las porque cada erro de lista é um erro em uma delas. Primeiro, o array é percorrido pelo map, que devolve um array novo do mesmo tamanho. Segundo, cada item percorrido vira um elemento React com o seu key. Terceiro, o array de elementos é entregue ao <ul> como filho, e o React o desenha item por item.

lista
Um array de dados (pães, pedidos, clientes) que o componente recebe ou monta. Não é estado por natureza: pode ser prop, constante ou resultado de um filtro.
item
Um elemento do array. Pode ser texto, número ou objeto — se for objeto, você escolhe quais campos aparecem na tela.
map
O método que percorre o array e devolve outro array, com um elemento React por item. É a ponte entre dado e tela.
key
A identidade do item para o React: uma string ou número único dentro da lista, estável entre desenhos. Não é prop e não chega ao componente.
lista derivada
O array que você calcula no desenho a partir do original: filtrado, ordenado, cortado, somado. Não vai para o estado.
vazio
O caso em que a lista não tem item nenhum. É uma tela legítima, com mensagem própria, e não um erro.

Se o array vier de uma API, o mesmo desenho vale — muda só a origem. O que o React precisa é que, a cada desenho, o array exista. Se ele ainda não chegou, você não tem uma lista vazia: você tem uma lista desconhecida, e isso é a seção 5. A aula Listas com map constrói esse primeiro exemplo linha por linha.

2. O map: três formas de escrever o mesmo

O map tem uma particularidade que pega todo mundo: a função passada para ele precisa devolver o JSX. Se você abre chaves para escrever um corpo, precisa de um return explícito. Se usa parênteses, o retorno é implícito. As duas formas são certas; misturar as duas é o erro.

FormaComo ficaQuando usar
parênteses (retorno implícito)paes.map((p) => (<li key={p.id}>{p.nome}</li>))um elemento só, curto — o padrão do guia
chaves com returnpaes.map((p) => { return <li key={p.id}>{p.nome}</li>; })quando há cálculo antes do JSX
corpo de componentefunction Item({ p }) { return <li>{p.nome}</li>; }quando o item tem estado ou lógica própria — As Regras dos Hooks

A terceira linha é a saída para itens que guardam estado — o “curtir” de cada pão, o campo de quantidade de cada pedido. Hook não pode ficar dentro do map; ele fica dentro do componente que o map desenha. É o mesmo motivo pelo qual a key vai no componente: quem tem ficha própria é o componente, não o item do array.

A lista tem três pães e o <li> está escrito à mão. Troque por paes.map((pao) => (...)) com key={pao.id}, mostrando nome e preço.

function App() {
  const paes = [
    { id: 1, nome: "Pão francês", preco: 1 },
    { id: 2, nome: "Pão de queijo", preco: 3 },
    { id: 3, nome: "Baguete", preco: 6 },
  ];

  return (
    <ul>
      <li>Pão francês — R$ 1</li>
    </ul>
  );
}

</ul>

Dois tropeços aparecem no painel com mensagens bem diferentes. Se você usar chaves sem return, a lista sai vazia e sem erro — a função devolve undefined para cada item. Se você esquecer de escolher o campo e desenhar o objeto inteiro, o React reclama com a mensagem da seção 8. Nos dois casos, o conserto está na forma, não no dado.

Um detalhe de leitura: o map devolve um array, e o JSX aceita array. Você não precisa de join, não precisa transformar em string e não precisa de dangerouslySetInnerHTML. Se o resultado na tela estiver certo mas com vírgulas entre os itens, é porque alguém converteu o array em texto antes de entregar — sinal de que o map foi parar dentro de um molde de string.

3. A key: a identidade do item

O key não é enfeite para calar o console. Quando a lista muda — um item entra, outro sai, dois trocam de lugar —, o React compara a lista nova com a antiga e decide o que reaproveitar. A comparação é pelo key. Sem ele, o React usa a posição, e a posição não é identidade: o terceiro item de hoje pode ser o segundo de amanhã.

De onde vem a keyExemploVeredito
id do dadokey={pao.id}o certo, sempre que existir
campo único do dadokey={pao.slug}vale, se for único e estável
combinação de camposkey={pedido.mesa + "-" + pedido.hora}aceitável em lista sem id
índice do mapkey={indice}só em lista fixa, que nunca reordena — Chaves Estáveis
sorteiokey={Math.random()}nunca: remonta tudo a cada desenho — Chaves Estáveis

A chave precisa ser única entre irmãos e estável entre desenhos. Única entre irmãos porque o React procura o par; estável porque é isso que permite reconhecer o mesmo item depois. Se a chave muda, o React entende que o item é outro: desmonta o antigo e monta o novo, perdendo estado, foco e o que estava digitado.

O caso do índice merece uma frase própria. Ele funciona enquanto a lista não muda de ordem nem ganha itens no meio. No dia em que a Ana ordena por preço, o item que estava na posição 3 vira posição 1 — e o estado que morava na posição 3 vai junto para o item errado. A aula Chaves Estáveis mostra o bug acontecendo; a regra prática é: índice só para lista gerada, fixa e sem estado por item.

Quem usa o key é o React, não o seu componente. Ele não chega por props: se você escrever function Item(props) e tentar props.key, recebe undefined. Para usar o id dentro do componente, passe-o como prop com outro nome: <Item key={p.id} id={p.id} />.

No modo de desenvolvimento, esquecer a chave produz um aviso no console do navegador. Ele não impede a página de rodar, e por isso é fácil ignorar:

Warning: Each child in a list should have a unique "key" prop.

Esse aviso é um dos poucos que valem conserto imediato: o problema que ele aponta aparece depois, como estado no item errado ou campo que perde o foco ao digitar. A aula Listas Aninhadas cobre o caso de duas listas na mesma tela, em que cada nível precisa da sua própria chave.

4. Filtrar, ordenar e contar: derive antes de desenhar

A regra que resolve a maior parte das dúvidas de lista: o array que você desenha é uma conta feita no desenho, não um estado paralelo. Filtro, ordem, corte e contagem saem do array original mais os valores de estado que descrevem a escolha (o texto da busca, a categoria, a direção da ordenação).

PerguntaDerivar no desenhoGuardar no estado
quais itens aparecem?paes.filter(...) com o filtro que é estadonunca: a lista filtrada envelhece — Filtrar
em que ordem?[...paes].sort(...) ou paes.toSorted(...)nunca: a ordem é conta — Ordenar
quantos são?visiveis.lengthnunca: é o tamanho da derivada
qual é o total?reduce no desenhonunca: refaça a conta — Estado Derivado
o que o usuário escolheu?—sim: texto, categoria, ordem, página

Guardar a lista filtrada em useState cria duas verdades: a original e a filtrada. Na primeira vez em que uma delas mudar sozinha — um item novo chega, um item é apagado —, elas discordam. O sintoma é “o item novo não aparece até eu recarregar”. A aula Estado Derivado trata exatamente desse desencontro.

Os botões mudam filtro, mas a lista ignora. Filtre com paes.filter((p) => filtro === "todos" || p.tipo === filtro) e mostre a mensagem Nenhum pão com esse filtro quando não sobrar nenhum.

function App() {
  const [filtro, setFiltro] = useState("todos");
  const paes = [
    { id: 1, nome: "Pão francês", tipo: "salgado" },
    { id: 2, nome: "Pão de queijo", tipo: "salgado" },
    { id: 3, nome: "Croissant", tipo: "doce" },
  ];
  const visiveis = paes;

  return (
    <div>
      <button className="doces" onClick={() => setFiltro("doce")}>Doces</button>
      <button className="sem-acucar" onClick={() => setFiltro("sem-acucar")}>Sem açúcar</button>
      <p>Visíveis: {visiveis.length}</p>
      <ul>
        {visiveis.map((p) => (
          <li key={p.id}>{p.nome}</li>
        ))}
      </ul>
    </div>
  );
}

function App() {
  const [filtro, setFiltro] = useState("todos");
  const paes = [
    { id: 1, nome: "Pão francês", tipo: "salgado" },
    { id: 2, nome: "Pão de queijo", tipo: "salgado" },
    { id: 3, nome: "Croissant", tipo: "doce" },
  ];
  const visiveis = paes.filter(
    (p) => filtro === "todos" || p.tipo === filtro
  );

  return (
    <div>
      <button className="doces" onClick={() => setFiltro("doce")}>Doces</button>
      <button className="sem-acucar" onClick={() => setFiltro("sem-acucar")}>Sem açúcar</button>
      <p>Visíveis: {visiveis.length}</p>
      {visiveis.length === 0 ? (
        <p>Nenhum pão com esse filtro</p>
      ) : (
        <ul>
          {visiveis.map((p) => (
            <li key={p.id}>{p.nome}</li>
          ))}
        </ul>
      )}
    </div>
  );
}

Repare que a contagem (visiveis.length) sai da mesma derivada que a lista. Contar à parte é a origem do “aqui diz 12 e embaixo tem 11”. E note que o filtro é comparado com o valor do estado, nunca com o texto digitado direto no value: quem manda no desenho é o estado.

A ordenação tem um cuidado próprio: sort altera o array original. Se o array veio de prop, alterar é efeito colateral fora do componente — o pai não sabe. Use [...paes].sort(...) ou paes.toSorted(...), que devolve uma cópia. Para texto, compare com localeCompare; para número, subtraia. A aula Ordenar traz o comparador completo, com desempate e ordem crescente/decrescente; a aula Filtrar cobre o filtro que combina categoria e texto.

5. Lista vazia, primeira vez e carregando

São três telas diferentes, e misturá-las é o erro mais comum de uma lista que vem da rede. Lista vazia: o dado chegou e não tem nada — pode ser a loja sem promoção do dia ou o filtro sem resultado. Primeira vez: o dado ainda não chegou e ninguém pediu nada. E carregando: já pedimos, ainda não voltou. Cada uma pede uma mensagem diferente.

O teste do vazio é length === 0, e não a lista “falsa”. Cuidado com o atalho que parece elegante e imprime um zero na tela: {itens.length && <ul>...</ul>} desenha o número 0 quando a lista está vazia, porque 0 é um valor que o React mostra. Compare com zero, e o problema desaparece.

if (itens.length === 0) {
  return <p>Hoje não tem pão de queijo. Volte às 15h.</p>;
}

return <ul>{itens.map((p) => <li key={p.id}>{p.nome}</li>)}</ul>;

A frase da mensagem é parte do produto, não do código. “Nenhum resultado” diz o que aconteceu; “Nenhum pão com esse filtro. Limpar filtro” diz o que fazer. A aula Estados Vazios compara os tipos de vazio — primeira vez, filtro, erro — e a Estados de Carregamento mostra o esqueleto que evita a tela piscando.

Uma armadilha de condicional em lista: o ? dentro do map é permitido, o if dentro do map também (dentro de um corpo com chaves), mas o return antecipado fora do map não pode ficar depois de um hook. Regra curta: condicional para decidir o que desenhar, nunca se um hook existe. A aula Renderização Condicional cobre os três operadores com exemplos curtos.

6. Listas aninhadas e tabelas

Quando cada item tem a sua própria lista — pedido com itens, categoria com produtos —, o map aparece duas vezes. Cada nível precisa da sua chave, e a chave só precisa ser única entre os irmãos daquele nível. Duas listas diferentes podem usar key={1} sem conflito; dois itens da mesma lista, não.

export function Pedidos({ pedidos }) {
  return (
    <ul>
      {pedidos.map((pedido) => (
        <li key={pedido.id}>
          <strong>{pedido.cliente}</strong>
          <ul>
            {pedido.itens.map((item) => (
              <li key={item.id}>{item.nome}</li>
            ))}
          </ul>
        </li>
      ))}
    </ul>
  );
}

Se você se pegar com três map aninhados, provavelmente a tela quer ser uma lista só. Achatar antes de desenhar — transformar a árvore em uma lista de pares “cliente + item” — costuma dar um componente menos profundo e uma chave por linha. A aula Listas Aninhadas mostra as duas versões.

Tabela é uma lista com roupa diferente: um <tr> por item, com o key na linha, nunca na célula. O cabeçalho fica fora do map, e o scope="col" ajuda o leitor de tela a anunciar a coluna. Para números, alinhe à direita; para texto, à esquerda. A aula Tabela de Dados traz o exemplo com ordenação pelo cabeçalho.

7. Quando a lista é grande

Lista grande não é um problema de map: é um problema de quantos elementos existem no DOM. Antes de otimizar, meça. As três saídas que resolvem quase tudo, em ordem de custo:

Desenhar menos. Paginação ou “carregar mais” corta o array antes do map. É a solução mais simples e a que o leitor entende — a aula Paginação faz a conta do corte. Desenhar por perto. Janela virtual: só os itens visíveis viram DOM, com um trilho do tamanho total para a barra de rolagem não mentir. A aula Listas Grandes implementa a janela. Desenhar sem recalcular. Se a lista é derivada de um cálculo caro, useMemo guarda o resultado entre desenhos; se cada item é um componente, memo evita redesenhar os que não mudaram — mas só funciona com chave estável, senão tudo remonta.

O que não resolve: passar a lista por contexto, mudar de biblioteca ou adicionar useDeferredValue sem motivo. O custo está no número de nós e no trabalho de cada desenho, e as duas coisas se medem. A página Performance reúne as técnicas com o critério de quando usar; a aula Medindo Performance mostra como ler o tempo antes de mexer no código.

8. Erros comuns e o que cada mensagem quer dizer

Quase todo defeito de lista aparece como uma destas cinco coisas. A tabela serve para ir do sintoma ao conserto sem reler a página inteira.

SintomaCausaConserto
nada aparece e não há errochaves no map sem returntrocar por parênteses ou escrever o return — Listas com map
aviso de key no consolefalta a chave em algum itemkey={item.id} no elemento raiz do item
estado no item errado depois de reordenarkey é o índiceusar o id do dado — Chaves Estáveis
o item novo não aparecelista filtrada guardada em estadoderivar no desenho — Estado Derivado
o array original muda de ordem sozinhosort sem cópia[...lista].sort(...) — Ordenar

A mensagem mais confusa é a do objeto desenhado sem escolher o campo. Ela não fala de lista, fala de “objeto”:

Uncaught Error: Objects are not valid as a React child (found: object with keys {nome, preco}).

Traduzindo: “objetos não são filhos válidos do React”. Você entregou {pao} onde precisava de {pao.nome}. Para inspecionar um objeto na tela, use JSON.stringify(pao); para mostrar o dado, escolha os campos. A aula Erros Comuns reúne essa e outras mensagens com a tradução e a aula Depurando no Navegador mostra como chegar até a linha.

Um último erro que não dá mensagem: desenhar a lista a partir de uma cópia feita uma vez só. Se você guarda const [lista, setLista] = useState(paes) e depois altera paes por fora, a tela não acompanha — o React não é avisado. Estado é dono do dado; se ele vem de fora, ou entra por prop e é desenhado direto, ou é copiado no momento em que algo acontece, nunca por referência compartilhada.

Resumo

Lista em React é array.map(dado => JSX) com um key que vem do dado. A chave é identidade, não posição: use id sempre que existir e o índice só em lista fixa. O que a tela mostra é uma derivada — filtro, ordem, corte — calculada no desenho a partir do array original mais os valores de estado que descrevem a escolha; a lista filtrada nunca vira estado.

Lista vazia não é erro: é uma tela com mensagem própria, e o teste é length === 0. Lista aninhada pede uma chave por nível; tabela é lista de linhas, com a chave no <tr>. Quando a lista cresce, o caminho é desenhar menos (paginação), desenhar por perto (janela) ou desenhar sem recalcular (useMemo e memo) — nessa ordem, e só depois de medir.

Para lembrar

  • map devolve array: com parênteses, retorno implícito; com chaves, return.
  • key vem do dado, é única entre irmãos e estável entre desenhos.
  • key não chega por props: repasse o id com outro nome se precisar.
  • Filtro, ordem e contagem são contas do desenho — não estado.
  • sort altera o array: copie antes ou use toSorted.
  • Vazio se testa com length === 0, nunca com length &&.
  • Cada nível de lista pede a sua própria chave.
  • Estado por item exige componente próprio — hook não mora no map.
  • Lista grande: paginar, virtualizar, memoizar — nessa ordem.
  • Objeto na tela precisa de campo escolhido, não do objeto inteiro.
