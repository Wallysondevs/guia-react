Efeitos

Efeito é o lugar onde o componente conversa com o mundo fora do React: buscar dados, ligar um timer, escutar o redimensionamento, mexer no título da aba. O useEffect roda depois que a tela apareceu e pode devolver uma função de limpeza. Esta página é a consulta rápida: a forma do hook, os três formatos do array de dependências, o cleanup, a busca de dados sem corrida e — o mais importante — quando o efeito não devia existir. A Ana usa efeitos no painel da padaria desde o relógio da vitrine; aqui está o resumo que ela consulta antes de escrever mais um.

Como usar esta página
  • A tabela da seção 3 é a das dependências; a da seção 7 é a do "não use efeito".
  • As caixas rodam React 19: edite, clique em Rodar e leia o painel.
  • Se o efeito roda sem parar, comece pela seção 8; se a tela pisca, pela seção 4.

1. O que é um efeito

Efeito é a ponte entre o componente e o que não é React. O render calcula o JSX; o efeito cuida do resto: chamar a rede, abrir um intervalo, adicionar um listener no window, gravar no localStorage, ajustar o título do documento. Tudo isso são ações que acontecem fora da árvore de elementos e que o React não controla.

O useEffect não é um método de ciclo de vida com outro nome. Ele é uma forma de dizer: "depois que a tela refletir este estado, faça isto; e, quando os valores mudarem, desfaça o anterior e faça de novo". Pensar em sincronização, e não em "montou/desmontou", evita a maior parte dos bugs.

function Vitrine() {
  const [aberta, setAberta] = useState(false);

  useEffect(() => {
    document.title = aberta ? "Padaria aberta" : "Padaria fechada";
  }, [aberta]);

  return <p>{aberta ? "Aberto" : "Fechado"}</p>;
}

O efeito acima sincroniza o título da aba com um estado. Cada vez que aberta muda, o efeito roda de novo e o título acompanha. Não há botão, não há evento: a tela mudou, o mundo de fora acompanha. Esse é o desenho típico.

efeito
O código que sincroniza o componente com algo fora do React: rede, timer, DOM global.
dependências
O array que decide quando o efeito roda de novo. Comparado item por item com o render anterior.
cleanup
A função que o efeito devolve. Desfaz o que ele criou: limpa timer, remove listener, aborta requisição.
montagem
A primeira vez que o componente aparece na tela. É quando o efeito com [] roda.
corrida
Duas respostas chegando fora de ordem. A antiga pode sobrescrever a nova se ninguém descartar.

Uma coisa que efeito não é: lugar de calcular. Total, lista filtrada, mensagem de erro e texto derivado se calculam no corpo do componente. Se o valor sai do que você já tem, não precisa de efeito — e a seção 7 é sobre esse instinto.

Vale separar efeito de evento. Evento é algo que a pessoa fez: clique, tecla, envio. Efeito é a consequência de o componente estar na tela: o timer que precisa existir enquanto ele existe, o listener que precisa acompanhar a janela, o título que precisa refletir o estado. Se a ação nasce de um gesto, o lugar dela é o handler; se nasce da tela montada, é o efeito.

2. A forma do useEffect

A chamada tem duas partes: uma função e um array. A função é o trabalho; o array diz quando repetir. A função pode devolver outra função — o cleanup —, que roda antes da próxima execução e quando o componente sai da tela.

useEffect(() => {
  const id = setInterval(() => setHora(new Date()), 1000);

  return () => clearInterval(id);
}, []);

O React executa os efeitos depois de pintar a tela. Isso significa que, dentro do efeito, o DOM já existe: dá para medir, focar e ler. E significa que o efeito não pode preparar dados para o render que já aconteceu — ele roda depois. Quando você precisa medir antes da pintura, o hook é useLayoutEffect.

Com mais de um efeito, eles rodam na ordem em que foram declarados, de cima para baixo, sempre depois do render. A ordem ajuda a ler o console, mas não é uma garantia para construir lógica: se um efeito depende do outro, o desenho está errado.

O console mostra a sequência em cada render: primeiro o corpo do componente, depois o efeito.

render: 1
efeito: 1
render: 2
efeito: 2

Se o efeito aparece antes do render no seu log, provavelmente ele está sendo chamado no lugar errado — ou o log está dentro de uma função que roda antes, como um evento.

A promoção nunca é preenchida. Escreva um useEffect com [] que chama setPromocao("pão de queijo pela metade do preço") uma vez, na montagem.

function App() {
  const [promocao, setPromocao] = useState("");

  return (
    <div>
      <h1>Padaria da Ana</h1>
      <p>promoção: {promocao}</p>
    </div>
  );
}

O efeito roda depois do primeiro desenho, chama o setter e provoca um segundo render com a promoção preenchida — é por isso que o painel mostra a frase, e não a tela vazia. O [] garante que isso aconteça uma vez; sem ele, o efeito rodaria em todo render e o setter criaria um laço.

3. O array de dependências

Três formatos, três comportamentos. O array vazio roda uma vez, na montagem. Com valores, roda na montagem e sempre que algum deles mudar. Sem array, roda depois de todo render. A comparação é de identidade, item por item, com Object.is.

ArrayQuando o efeito rodaUse paraAula
[]uma vez, na montageminicialização que não depende de nadaO useEffect
[busca]na montagem e quando busca mudaacompanhar um valorAs Dependências
[a, b]quando qualquer um mudadois valores na mesma sincronizaçãoAs Dependências
sem arraydepois de todo renderquase nunca; causa laço se muda estadoAs Dependências
objeto criado no renderem todo render (identidade nova)nunca; liste os campos lidosAs Dependências

O array precisa listar tudo o que o efeito lê de dentro do componente: estado, props e funções declaradas ali. Faltar um valor produz o bug mais silencioso do React — o efeito guarda uma versão velha da variável e age com ela. O ESLint avisa no editor:

React Hook useEffect has a missing dependency: 'busca'.
Either include it or remove the dependency array.
  react-hooks/exhaustive-deps

Há duas saídas legítimas e uma errada. Incluir a dependência é a primeira. Mover para dentro do efeito o que você criou fora é a segunda — uma função usada só ali pode ser declarada ali. A saída errada é desligar o aviso e seguir: o código passa no teste e quebra quando o valor muda.

Existe um terceiro caminho que resolve muitos casos: tirar a dependência do array porque ela não precisa estar ali. Se o efeito usa uma função que você criou no componente, declare a função dentro do efeito — ela deixa de ser dependência e o efeito passa a rodar só quando os dados mudarem. O mesmo vale para um objeto montado ali dentro: crie dentro, não fora.

4. Cleanup: desfazer o que o efeito fez

Todo efeito que cria algo precisa desfazer. Timer aberto continua rodando depois que o componente sai; listener no window continua chamando uma função que já não existe; requisição em voo pode chegar depois e gravar em um componente desmontado. O cleanup é a função devolvida pelo efeito.

useEffect(() => {
  function aoTeclar(e) {
    if (e.key === "Escape") setAberto(false);
  }

  window.addEventListener("keydown", aoTeclar);

  return () => {
    window.removeEventListener("keydown", aoTeclar);
  };
}, []);

O React chama o cleanup em dois momentos: antes de rodar o efeito de novo (quando uma dependência mudou) e quando o componente é removido. No caso do listener, isso evita duplicar o registro a cada mudança; no caso do timer, evita dois intervalos somando. Sem cleanup, o sintoma é sempre o mesmo: o trabalho acontece mais vezes do que devia.

Um detalhe que engana em desenvolvimento: o Strict Mode monta, desmonta e monta de novo para denunciar efeitos sem cleanup. O console mostra o efeito rodando duas vezes e parece bug — é o teste funcionando. Em produção, o componente monta uma vez.

Para remover um listener, a função precisa ser a mesma que foi registrada. Por isso ela é declarada com nome dentro do efeito e usada nas duas chamadas; uma arrow escrita direto no addEventListener não tem como ser removida depois, porque ninguém guardou a referência. O mesmo raciocínio vale para setInterval: guarde o id devolvido para poder cancelar.

Efeito que não cria nada não precisa de cleanup: escrever no localStorage, ajustar o título ou chamar um console.log não deixam nada pendente. A pergunta é sempre "o que eu criei que continua vivo depois daqui?". Se a resposta for nada, não há o que devolver.

5. Buscar dados sem corrida

Buscar dados é o efeito mais comum e o mais fácil de errar. A chamada é assíncrona: o efeito começa, termina, e a resposta chega depois. Se o componente mudou de estado nesse meio-tempo — outra busca, outro item, saiu da tela —, a resposta antiga pode sobrescrever a nova. Isso é a corrida.

useEffect(() => {
  setCarregando(true);
  let ativo = true;

  buscarPaes(termo)
    .then((dados) => {
      if (!ativo) return;          // resposta velha: descarta
      setPaes(dados);
      setCarregando(false);
    })
    .catch((erro) => {
      if (!ativo) return;
      setErro(erro.message);
      setCarregando(false);
    });

  return () => {
    ativo = false;                 // desliga este efeito
  };
}, [termo]);

A flag ativo resolve a corrida sem cancelar a requisição. Se você quer cancelar de verdade, use AbortController: crie no efeito, passe o signal para o fetch e chame abort() no cleanup. O catch precisa ignorar o erro de cancelamento. A aula de abortar um pedido mostra o código completo.

Nos três estados, o padrão é sempre o mesmo: carregando, dados e erro, com o render escolhendo o que mostrar. A caixa abaixo simula a rede com Promise e setTimeout, porque o quadro do guia não tem servidor — o fetch de verdade entra no projeto, e o resto do componente fica igual.

O efeito busca uma vez só, então a resposta não acompanha a busca. Coloque busca nas dependências: digite "queijo" e confira o resultado.

const PAES = ["pão francês", "pão de queijo", "sonho"];

function App() {
  const [busca, setBusca] = useState("");
  const [resultado, setResultado] = useState("");

  useEffect(() => {
    const achado = PAES.find((p) => p.includes(busca)) || "nada";
    new Promise((ok) => setTimeout(() => ok(achado), 30)).then(setResultado);
  }, []);

  return (
    <div>
      <label htmlFor="busca">Busca</label>
      <input
        id="busca"
        value={busca}
        onChange={(e) => setBusca(e.target.value)}
      />
      <p>resultado: {resultado}</p>
    </div>
  );
}

Com [], digitar "queijo" não muda o resultado: o efeito já rodou e não roda mais. Com [busca], cada tecla dispara uma busca nova e o painel acompanha. Na vida real, entrar e sair do campo rápido cria a corrida da seção anterior — e é aí que a flag ou o AbortController entram.

6. Timers, listeners e o mundo global

Três famílias de efeito aparecem sempre. Timer, para o que muda com o tempo; listener, para o que acontece no navegador; armazenamento, para o que precisa durar mais que a aba. Todas têm a mesma estrutura: cria, devolve o cleanup.

Para quêComo se fazCleanupAula

tamanho da janelaaddEventListener("resize")removeEventListenerO Cleanup

Para o relógio, um cuidado de leitura de estado: dentro do intervalo, prefira a forma de função do setter — setHora((h) => new Date()) ou setSegundos((s) => s + 1) —, porque a função guardada enxerga o valor do render em que nasceu. Sem isso, o contador pode ficar repetindo o mesmo número.

Para armazenamento, o efeito é de mão única: escrever no localStorage quando o estado muda. Ler dali é trabalho do valor inicial do useState, com a forma de função (useState(() => lerDoStorage())), e não de um efeito que copia o valor depois — o efeito rodaria tarde demais para o primeiro render.

Um caso que mistura os dois: sincronizar entre abas. O evento storage avisa quando outra aba gravou, e o efeito é o lugar certo para escutá-lo — com cleanup, como qualquer listener. Já a leitura inicial continua sendo do useState. Separar "ler uma vez" de "acompanhar mudanças" é o que mantém o componente previsível.

7. Quando não usar efeito

Esta é a seção que economiza mais código. A maior parte dos efeitos que se escreve por aí não precisava existir: era conta que podia ser feita no render, reação que pertencia ao evento, ou estado que podia ser derivado.

SituaçãoO que se costuma fazerO que fazerAula
total, filtro, validaçãoefeito que chama setTotalcalcular no renderEstado Derivado
reagir a um cliqueefeito que observa uma flagagir no próprio handlerEventos e onClick
copiar prop para estadoefeito de sincronizaçãousar a prop, ou uma chave no componenteEstado Derivado
enviar dados ao servidor ao mudarefeito que observa o estadoenviar no evento que mudouQuando Não Usar Efeito
ajustar estado a partir de estadoefeito com dependência no estadocalcular na hora do setterQuando Não Usar Efeito

O teste é uma pergunta: "isto precisa acontecer depois que a tela apareceu?". Se a resposta for não, não é efeito. Calcular acontece no render; reagir a um clique acontece no handler; sincronizar com fora acontece no efeito. Efeito é a exceção, não o lugar padrão.

Quando o efeito muda um estado que ele mesmo observa, o resultado é o laço: efeito roda, estado muda, render acontece, efeito roda de novo. O React interrompe com "Maximum update depth exceeded". A correção nunca é desligar o aviso do ESLint: é tirar a dependência que muda a cada volta ou trocar o efeito por uma conta.

O último caso tem uma explicação simples: o efeito pode devolver uma função de cleanup, e uma função async devolve sempre uma Promise. O React não sabe o que fazer com ela. A saída é declarar a função assíncrona dentro do efeito e chamá-la sem await no corpo do efeito.

useEffect(() => {
  async function carregar() {
    const dados = await buscarPaes(termo);
    setPaes(dados);
  }
  carregar();
}, [termo]);

Com o tempo, o padrão fica automático: todo efeito que cria algo devolve o cleanup; todo efeito que lê um valor lista esse valor; todo valor que sai de outro valor nem vira efeito. Os três hábitos cobrem quase tudo o que esta página descreve.

Se o efeito está difícil de escrever, geralmente o problema não é o hook: é o desenho. Um efeito que precisa de cinco dependências, que muda três estados e que depende da ordem dos outros costuma indicar que aquele trabalho pertence a um evento, a um hook próprio ou a um componente separado. Simplificar o desenho resolve mais do que ajustar o array.

Resumo

useEffect sincroniza o componente com o que está fora do React e roda depois da pintura. A forma é uma função e um array: [] na montagem, com valores quando algo muda, sem array em todo render. O array precisa listar tudo o que o efeito lê, e a comparação é de identidade — objeto criado no render conta como novo.

Todo efeito que cria algo devolve o cleanup: timer, listener e requisição. O React chama essa função antes da próxima execução e na saída de tela. Buscar dados pede três estados e um descarte de resposta velha, com flag ou AbortController, para não deixar a resposta antiga sobrescrever a nova.

E o hábito que mais economiza código: antes de escrever um efeito, pergunte se o valor não é conta, se a reação não pertence ao evento e se o estado não é derivado. Efeito é para o que acontece depois da tela — não para tudo o que muda.

Para lembrar

  • useEffect roda depois da pintura; useLayoutEffect, antes.
  • [] uma vez; [valor] quando muda; sem array, todo render.
  • Liste tudo o que o efeito lê; o ESLint avisa.
  • Objeto ou função nas dependências faz o efeito rodar sempre.
  • Quem cria, limpa: devolva a função de cleanup.
  • Busca de dados: carregando, dados e erro; descarte a resposta velha.
  • Não use efeito para total, filtro ou validação.
  • Reagir a clique é no handler, não no efeito.
  • Efeito com async direto não pode: declare a função dentro.
  • Laço infinito é dependência ou efeito que muda o que observa.
