Props com Objetos

O cartão da Ana já recebe o nome e o preço por props, e isso resolveu metade do problema. A outra metade apareceu quando ela quis mostrar também a descrição, a validade e se o pão é integral: a chamada virou uma linha comprida, com cinco atributos, repetida para cada pão da vitrine. Pior, quando um pão ganhou um campo novo, ela teve de editar todas as chamadas. Nesta aula ela manda um objeto no lugar de cinco props soltas — e aprende a ler os valores que estão dentro dele.

Você vai aprender
  • Como passar um objeto como uma única prop, e por que aparecem duas chaves.
  • Como ler valores dentro do objeto: props.pao.nome.
  • A diferença entre passar um objeto escrito na hora e passar um objeto que já existe numa variável.
  • Como o objeto aparece no console, com as chaves aninhadas.
  • O que os três pontos fazem: <Cartao {...pao} />.
  • Por que o mesmo objeto chega em todos os cartões e por que não se altera.
  • Os tropeços de quem esquece uma chave ou lê no nível errado.

1. A cena: cinco props para o mesmo pão

O cartão da vitrine cresceu. Além do nome e do preço, que chegaram por props na aula anterior, a Ana quis mostrar a descrição, o peso e se o pão é integral. A chamada ficou assim:

<Cartao
  nome="Pão de queijo"
  preco="R$ 3,50"
  descricao="Assado na hora, com queijo da serra"
  peso="80 g"
  integral={false}
/>

Funciona. Mas repare no que aconteceu: cinco atributos para descrever um pão, repetidos em cada cartão da vitrine. Quando ela resolveu acrescentar “sem lactose”, precisou abrir todas as chamadas do site. E cada chamada é uma oportunidade de errar o nome de uma chave.

O dado já andava junto: nome, preço e descrição são todos do mesmo pão. O JavaScript tem uma caixa feita para isso — o objeto —, e o React aceita essa caixa como prop. Em vez de cinco atributos soltos, um atributo só, com tudo dentro. A diferença parece cosmética e não é: o objeto pode ser montado em outro lugar, guardado numa variável, vindo de uma lista, e a chamada continua curta.

Um aviso antes de seguir: nesta aula você vai ver chaves duplas, parênteses e três pontinhos. Nada disso é invenção do React — é JavaScript comum. A boa notícia é que são só três ideias, e cada uma tem a sua seção.

2. As peças: objeto, chave e caminho

Um objeto é uma lista de pares: um nome e um valor. Em JavaScript, escreve-se entre chaves, com dois-pontos entre o nome e o valor e vírgula entre os pares. O nome é a chave. Para chegar ao valor, usa-se o ponto: pao.nome.

objeto
Uma caixa com pares de chave e valor: { nome: "Pão", preco: "R$ 1,20" }. Serve para agrupar dados que descrevem a mesma coisa.
chave
O nome de um campo do objeto: nome, preco. No console aparece entre aspas, mas no código se escreve sem aspas.
literal
O objeto escrito na hora, com as chaves e os valores na mão — em oposição ao objeto que vem de uma variável.
caminho
A sequência de pontos até o valor: props.pao.nome quer dizer “dentro de props, o campo pao; dentro dele, o campo nome”.
espalhar
Usar ... para abrir um objeto em pedaços: {...pao} entrega cada chave como uma prop separada.

Com esse vocabulário, a chamada da Ana fica curta e o componente recebe tudo de uma vez. O preço é que a leitura dentro do componente fica com um ponto a mais: não é mais props.nome, é props.pao.nome. Um nível a mais de profundidade, e é aí que a maioria dos iniciantes se perde.

3. O objeto literal e as duas chaves

Vamos escrever o objeto na própria chamada. Repare nas chaves duplas — e na explicação logo abaixo, porque elas são a parte que mais confunde:

O objeto pao só tem o nome, então o preço sai vazio. Acrescente preco: "R$ 1,20" dentro do objeto e clique em Rodar.

function Cartao(props) {
  return (
    <div className="cartao">
      <h2>{props.pao.nome}</h2>
      <p>{props.pao.preco}</p>
    </div>
  );
}

function App() {
  return <Cartao pao={{ nome: "Pão francês" }} />;
}
<div class="cartao">
  <h2>Pão francês</h2>
  <p></p>
</div>

function Cartao(props) {
  return (
    <div className="cartao">
      <h2>{props.pao.nome}</h2>
      <p>{props.pao.preco}</p>
    </div>
  );
}

function App() {
  return <Cartao pao={{ nome: "Pão francês", preco: "R$ 1,20" }} />;
}

As duas chaves não são um enfeite: são duas coisas diferentes. A de fora é a porta do JSX — a mesma que você usa para mostrar um valor, {props.nome}. A de dentro é o objeto em si, escrito em JavaScript. Se você usar só uma, o código nem compila: o compilador entende que ali começa um bloco e reclama do dois-pontos. Na seção 9 tem a mensagem exata.

Da mesma forma que no caso de uma prop só, o valor pode misturar texto e outros tipos: nome e preço como texto, integral: false como booleano, peso: 80 como número. O que muda é que agora todos viajam juntos, dentro de props.pao. E se um deles faltar, o valor é undefined — que no JSX aparece como nada, um espaço em branco.

4. Ler dentro do objeto

Cada ponto é um passo para dentro. O componente recebe props, que é um objeto; dentro dele, a chave pao guarda outro objeto; dentro desse, as chaves do pão. Errar o caminho é o equivalente a procurar o preço na gaveta errada: o valor não existe e a tela fica vazia.

A terceira linha merece atenção, porque o sintoma é estranho: a tela não mostra o objeto, mostra nada. O React só sabe desenhar texto, número e elementos; um objeto não é nenhum dos três. No navegador, a mensagem Objects are not valid as a React child aparece no console do DevTools e aponta o componente. Aqui no painel, o trecho simplesmente fica vazio.

A quarta linha é o erro mais comum de todos: quando se passa um objeto, todo valor está um nível abaixo. props.nome procura nome no primeiro nível, onde só existe pao. Se você acabou de transformar cinco props em um objeto, essa é a linha que precisa revisar em cada ponto do componente.

O caminho pode ter mais de dois pontos, e a lógica é sempre a mesma: cada ponto é uma camada que você abre. Se a página passasse pedido={{ pao: { nome: "Pão francês" }, quantidade: 2 }}, a leitura seria props.pedido.pao.nome e props.pedido.quantidade. Funciona, e ao mesmo tempo é um sinal de alerta: quando o caminho chega a três níveis, o componente fica difícil de ler e de usar. Na prática, agrupar em um nível resolve quase tudo; se você precisou de dois, vale perguntar se o componente não deveria receber só a parte que ele usa.

5. O objeto que vem de uma variável

Escrever o objeto na chamada serve para dois ou três cartões. Quando o dado já existe numa variável — porque veio de uma lista, de um arquivo, de um cálculo —, você passa a variável. Note que o atributo e a variável podem ter o mesmo nome sem confusão: o da esquerda é o nome da prop, o da direita é o valor.

O objeto pao está pronto na variável, mas a chamada não passa nada. Entregue-o na prop pao, escrevendo pao={pao}.

function Cartao(props) {
  return (
    <div className="cartao">
      <h2>{props.pao.nome}</h2>
      <p>{props.pao.preco}</p>
    </div>
  );
}

function App() {
  const pao = { nome: "Pão de queijo", preco: "R$ 3,50" };
  return <Cartao />;
}
(o React não desenhou nada: o componente devolveu null?)

function Cartao(props) {
  return (
    <div className="cartao">
      <h2>{props.pao.nome}</h2>
      <p>{props.pao.preco}</p>
    </div>
  );
}

function App() {
  const pao = { nome: "Pão de queijo", preco: "R$ 3,50" };
  return <Cartao pao={pao} />;
}

Esse é o formato que você vai ver em código de verdade. O objeto nasce antes do return, a chamada fica curta, e a página pode montar o objeto como quiser — inclusive a partir de dados que o navegador buscou na rede. O componente não sabe nem se importa de onde veio: ele recebe uma caixa com nome e preco e desenha.

Uma vantagem prática de ter o objeto numa variável: você pode usá-lo em mais de um lugar. Dois cartões com o mesmo pao={pao} mostram o mesmo pão, o que faz sentido num destaque “pão do dia” repetido em duas seções. O objeto é o mesmo; o React chama o componente uma vez por cartão.

6. O que chega, de verdade

Quando o assunto é objeto, o console deixa de ser luxo e passa a ser necessidade. Imprimir props mostra a estrutura completa, com as chaves aninhadas — e é assim que você descobre se o problema é o nome da prop ou o nome da chave dentro dela.

function Cartao(props) {
  console.log(props);
  return <h2>{props.pao.nome}</h2>;
}
console: {"pao":{"nome":"Pão francês","preco":"R$ 1,20"}}

Leia de fora para dentro: o objeto de props tem uma chave, pao. O valor dessa chave é outro objeto, com duas chaves: nome e preco. É exatamente o caminho que o componente percorre com os pontos. Se você passasse também destaque na chamada, ele apareceria no primeiro nível, ao lado de pao, e não dentro.

Compare com o que você viu na aula de props: lá, o objeto tinha as chaves no primeiro nível ({"nome":...,"preco":...}). Aqui há um nível a mais. Guardar essa diferença na cabeça resolve a maior parte dos cartões em branco: o erro nunca é “o React perdeu o dado”, é “o caminho está errado”.

Quando o objeto tem muitas chaves, imprimir tudo vira parede de texto. Aí vale imprimir só o pedaço que interessa: console.log(props.pao) mostra o objeto do pão, e console.log(props.pao.preco) mostra o valor final. Comece pelo valor que devia aparecer na tela; se sair undefined, suba um nível por vez até achar onde a chave deixa de existir. É uma busca curta e sempre termina.

7. Espalhar com três pontos

Existe um atalho quando o objeto tem exatamente as chaves que o componente espera como props separadas. Os três pontos, chamados de spread, abrem o objeto e entregam cada chave como um atributo. <Cartao {...pao} /> é o mesmo que <Cartao nome={pao.nome} preco={pao.preco} />.

O componente espera as props nome e preco soltas, mas a chamada mandou o objeto inteiro dentro de pao. Espalhe o objeto com {...pao} para o cartão aparecer.

function Cartao(props) {
  return (
    <div className="cartao">
      <h2>{props.nome}</h2>
      <p>{props.preco}</p>
    </div>
  );
}

function App() {
  const pao = { nome: "Pão francês", preco: "R$ 1,20" };
  return <Cartao pao={pao} />;
}
<div class="cartao">
  <h2></h2>
  <p></p>
</div>

function Cartao(props) {
  return (
    <div className="cartao">
      <h2>{props.nome}</h2>
      <p>{props.preco}</p>
    </div>
  );
}

function App() {
  const pao = { nome: "Pão francês", preco: "R$ 1,20" };
  return <Cartao {...pao} />;
}

Depois da correção, as props chegam no primeiro nível: props.nome funciona de novo. Repare que o componente não mudou — quem mudou foi a forma de entregar. Os dois estilos são legítimos e a escolha é de contrato: se o componente diz “eu quero um pão”, passe pao={pao}; se ele diz “eu quero nome e preço”, espalhe.

Um cuidado com o espalhamento: ele passa todas as chaves, inclusive as que o componente não usa. Num objeto de dez campos, o componente recebe dez props e ignora oito. Isso não quebra nada, mas dificulta descobrir o que ele realmente precisa quando você lê a chamada. Use espalhamento quando o objeto foi feito para aquela chamada; use a prop única quando o objeto é um dado maior, com vida própria.

8. O objeto é o mesmo, não uma cópia

Há um detalhe do JavaScript que aparece em projeto grande: quando você passa pao={pao}, o componente recebe o mesmo objeto, não uma cópia. Se dois cartões usam o mesmo objeto, os dois apontam para a mesma caixa. Alterar um campo em um lugar aparece no outro.

É por isso que a regra da aula anterior continua valendo, agora com mais força: não altere o objeto que chegou por prop. Quem altera um objeto compartilhado não consegue prever quem mais vai ver a mudança. No React, o costume é criar um objeto novo quando algo muda, em vez de mexer no antigo — assim cada renderização recebe um retrato diferente e o React consegue perceber a diferença.

Na prática, para esta aula, basta uma disciplina: leia com pontos, mostre no JSX, e não escreva no objeto. Quando você precisar de um valor derivado — o preço com desconto, o peso em quilos —, calcule numa variável antes do return e mostre a variável. O objeto que veio de fora fica intacto do começo ao fim do componente.

Essa é a mensagem do primeiro caso: uma chave só. O compilador leu pao={ e começou um bloco, encontrou nome: e não soube o que fazer. A linha e a coluna apontam para o dois-pontos, que é onde o problema realmente está. Quem já viu essa mensagem uma vez não erra mais: se aparecer Unexpected token logo depois de uma chave, olhe se não faltou a segunda.

Cenário 1: o cartão sem preço

A Ana passou pao={{ nome: "Pão francês" }} e o preço saiu vazio. O componente pedia props.pao.preco, e a chave preco não existia no objeto. O React não reclama de chave faltando: o valor é undefined e o JSX desenha nada. O conserto é acrescentar a chave — e, no dia a dia, conferir com console.log(props).

Cenário 2: o objeto que não devia ir para a tela

Com pressa, ela escreveu <p>{props.pao}</p> para “ver o que tinha dentro”. A tela ficou vazia e o console do navegador avisou que objeto não é filho válido. Para espiar o conteúdo, o lugar certo é o console; para mostrar na tela, é preciso escolher uma chave: {props.pao.nome}.

Cenário 3: o espalhamento que não espalhou nada

Ela escreveu <Cartao {...pao} /> e o cartão veio em branco. O objeto existia, mas com outro nome — const paoDoDia = {...} —, e pao valia undefined. Espalhar undefined não dá erro: simplesmente não passa prop nenhuma. O sintoma é idêntico ao de uma prop com nome errado, e é por isso que o console é o primeiro passo.

Exercício: o objeto do dia

O componente Cartao lê props.pao.nome e props.pao.preco. Crie a variável pao com o nome “Brioche” e o preço “R$ 4,00” e passe-a na chamada. Depois responda: qual é a chave que guarda o nome dentro do objeto?

function App() { const pao = { nome: "Brioche", : "R$ 4,00" }; return <Cartao pao={pao} />; }

Dica: o componente pede props.pao.preco. A chave tem de se chamar exatamente assim, sem acento e sem maiúscula.

11. Resumo

Quando os dados descrevem a mesma coisa, agrupe-os num objeto e passe uma prop só: pao={{ nome: "Pão francês", preco: "R$ 1,20" }}. As chaves de fora abrem o JavaScript; as de dentro criam o objeto. Para ler, siga o caminho com pontos: props.pao.nome — um nível a mais do que na aula anterior, e é esse nível que a maioria esquece.

O objeto pode vir de uma variável, e é assim que ele aparece em projeto de verdade. O console mostra a estrutura aninhada e é o melhor amigo do diagnóstico. E os três pontos, {...pao}, abrem o objeto em props separadas, o que serve quando o componente espera os campos soltos.

Para lembrar

  • Objeto como prop: pao={{ chave: "valor" }} — duas chaves, dois papéis.
  • Ler um nível abaixo: props.pao.nome.
  • Objeto não vai para a tela; escolha uma chave para mostrar.
  • Objeto de variável: const pao = {…} e pao={pao}.
  • Espalhar: {...pao} entrega cada chave como prop separada.
  • O objeto é compartilhado, não copiado: não altere o que veio por prop.
  • Chave faltando vale undefined e aparece como nada — sem erro.
  • Faltou uma chave na chamada? Unexpected token, expected “}”.
