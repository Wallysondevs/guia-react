JSX

JSX é a escrita que parece HTML e vira JavaScript. Esta página é a consulta rápida do assunto: as cinco regras que o compilador cobra, o que cabe dentro das chaves, os atributos que mudam de nome, listas com key, condicionais e as mensagens de erro mais comuns. 1. O que é JSX, em uma frase

JSX é uma escrita parecida com HTML que o compilador transforma em chamadas de função. Não é HTML, não é texto e não é template string: é JavaScript com uma cara mais confortável. Quando você escreve <h1>Pão</h1>, o compilador do projeto — no Vite com React, o Babel — troca isso por React.createElement("h1", null, "Pão"). O navegador nunca vê JSX; ele vê o resultado dessa transformação.

Essa troca explica tudo o que parece estranho no começo. Um elemento JSX é um objeto, não uma string, então dá para guardá-lo numa variável, devolvê-lo de uma função, passá-lo como argumento e colocá-lo dentro de um array. É por isso que componente é função que devolve JSX: o retorno é um valor como outro qualquer.

function App() {
  const titulo = <h1>Padaria da Ana</h1>;
  const aviso = <p>Aberto das 6h às 18h</p>;

  return (
    <div>
      {titulo}
      {aviso}
    </div>
  );
}

O JSX acima é a receita; o que o compilador produz é a chamada de função. Para um elemento simples, a conversão é literal:

React.createElement("h1", null, "Padaria da Ana")
React.createElement("p", null, "Aberto das 6h às 18h")

O primeiro argumento é o tipo (a tag ou o componente), o segundo são as props — null quando não há nenhuma — e o terceiro em diante são os filhos. Um <div> com dois filhos vira uma chamada com dois argumentos a mais. Entender essa forma ajuda a ler mensagens de erro que falam de "elemento" e de "filho" em vez de tag.

Duas consequências práticas. Primeira: como é JavaScript, você pode usar variáveis, contas e funções dentro das chaves — o assunto da seção 3. Segunda: como o resultado é um objeto, o React consegue comparar, guardar e reaproveitar elementos sem tocar no DOM até a hora de desenhar. O JSX é a superfície; o objeto é o que circula por dentro.

Vale saber que JSX é opcional: o mesmo componente pode ser escrito com React.createElement direto. Ninguém faz isso no dia a dia — a escrita fica ilegível —, mas saber que o JSX é só açúcar ajuda quando você vê a saída do compilador ou uma biblioteca que gera elementos por função.

JSX
A escrita parecida com HTML dentro do JavaScript. Não é string nem HTML: é sintaxe transformada no build.

O objeto que o JSX representa: tipo, props e filhos. É o que o React compara e desenha.

Qualquer coisa que produza um valor e possa ficar entre chaves: {preco * 2}.

2. As cinco regras que o compilador cobra

São poucas e sempre as mesmas. Quem aprende estas cinco para de brigar com o compilador.

1. Toda tag fecha. <br>, <img> e <input> viram <br />, <img /> e <input />. Em JSX não existe tag aberta sem fechamento, mesmo as que o HTML aceita vazias.

2. Um pai só. O return devolve um elemento. Para mostrar dois irmãos, embrulhe em <div> ou em <>...</> — o fragmento, que não cria nó no HTML. É o erro "Adjacent JSX elements must be wrapped in an enclosing tag".

3. Aspas para texto, chaves para JavaScript. nome="Ana" passa a string "Ana"; preco={2.5} passa o número. A regra vale para atributos e para filhos: texto solto é texto; {expressao} é JavaScript.

4. Os nomes não são os do HTML. className, htmlFor, onClick, tabIndex, style com objeto. O React usa camelCase porque esses nomes são propriedades de um objeto JavaScript, não atributos de uma string de HTML.

5. Comentário é chaves com barra e asterisco. {/* assim */} dentro do JSX; // e /* */ valem fora dele. Um comentário HTML <!-- --> aparece na tela como texto.

function Cartao() {
  const preco = 2.5;

  return (
    <>
      <h2 className="titulo">Pão de queijo</h2>
      <label htmlFor="qtd">Quantos?</label>
      <input id="qtd" type="number" defaultValue={1} />
      <img src="pao.png" alt="Pão de queijo na cesta" />
      <p style={{ fontWeight: "bold" }}>R$ {preco}</p>
      {/* o fragmento <> não cria nó no HTML */}
    </>
  );
}

Repare que aria-* e data-* ficam como estão: são atributos livres, sem tradução. O que muda é só o que colide com palavra reservada do JavaScript ou com a API do DOM.

3. O que cabe dentro das chaves

Dentro de { } cabe uma expressão: qualquer coisa que produza um valor. Nome de variável, conta, chamada de função, acesso a propriedade, ternário, comparação, template string, map. Não cabe comando: if, for, return, declaração de variável. Se você precisa de um if, calcule antes do return ou use um ternário.

Dentro de { }ExemploResultadoAula

map{lista.map((p) => ...)}uma lista de elementosListas com map

O caso do objeto merece atenção porque o erro é claro mas o motivo não: o React aceita texto, número, elemento, array e null como filho. Um objeto não tem como ser desenhado — quais campos apareceriam? — então ele reclama. Para mostrar um objeto, escolha os campos: {pedido.nome}.

Outro detalhe que pega iniciante: 0 e "" são filhos válidos. Em {quantidade && <p>itens</p>}, quando a quantidade é zero o React desenha o número 0 na tela, porque 0 é o valor da expressão. Use {quantidade > 0 && ...} quando o zero não deve aparecer.

O total está escrito à mão e o nome aparece em minúsculas. Use expressões: {pao.toUpperCase()} no produto e {preco * quantidade} no total.

function App() {
  const pao = "pão de queijo";
  const preco = 2.5;
  const quantidade = 3;

  return (
    <div>
      <h1>Padaria da Ana</h1>
      <p>produto: {pao}</p>
      <p>total: R$ 0</p>
    </div>
  );
}

O painel mostra o texto final, não a expressão. Essa é a leitura mais útil do JSX: você escreve a conta, o React escreve o resultado no DOM. Se o número sair com muitas casas decimais, formate antes — {(preco * quantidade).toFixed(2)} —, porque o JSX não arredonda nada por você.

4. Atributos: aspas, chaves e os nomes que mudam

A regra é a mesma dos filhos: aspas entregam texto, chaves entregam JavaScript. id="nome" é string; value={nome} é a variável; preco={2.5} é número; itens={lista} é array. Misturar os dois é o erro mais comum: preco="{2.5}" entrega a string "{2.5}", com chaves no meio.

Atributos booleanos têm atalho: disabled sozinho vale true, e disabled={false} desliga. O mesmo vale para required, checked e hidden. checked e value são especiais em formulário: sem onChange, o campo fica travado — o React avisa no console.

function Botao(props) {
  return (
    <button
      type="button"
      className="primario"
      disabled={props.carregando}
      aria-label="Salvar pedido"
      onClick={props.aoClicar}
    >
      {props.carregando ? "Salvando..." : "Salvar"}
    </button>
  );
}

// spread: repassa todas as props de uma vez
<Botao {...props} />

O style é o único atributo que sempre pede objeto: as chaves são as propriedades CSS em camelCase, e os valores são strings ou números. style={{ marginTop: 8 }} vira margin-top: 8px. Para várias classes condicionais, monte a string: className={"card " + (destaque ? "card--destaque" : "")}.

Por último, o key. Ele aparece no JSX como atributo, mas não chega ao componente como prop: o React o usa para identificar o item na lista e o remove do objeto de props. Se você precisa do identificador dentro do componente, passe-o com outro nome — id={pedao.id} — e deixe a key só para a lista.

Um par de atributos que confunde na consulta: value e defaultValue. Com value, o campo é controlado e precisa de onChange; sem ele, o campo fica travado e o React avisa no console. Com defaultValue, o valor é só o ponto de partida e o navegador cuida do resto — o campo não controlado. O mesmo par existe em checked e defaultChecked para caixas e rádios, e a escolha entre os dois é o assunto da aula controlado e não controlado.

5. Listas com map e a key

Lista em JSX é map. O map devolve um array de elementos, e o React sabe desenhar um array de filhos. Cada elemento precisa de uma key única entre os irmãos, para o React reconhecer quem é quem entre um desenho e outro.

const PAES = [
  { id: 1, nome: "pão francês", preco: 0.9 },
  { id: 2, nome: "pão de queijo", preco: 2.5 },
];

function Lista() {
  return (
    <ul>
      {PAES.map((pao) => (
        <li key={pao.id}>
          {pao.nome} — R$ {pao.preco.toFixed(2)}
        </li>
      ))}
    </ul>
  );
}

A key certa é o identificador estável do dado: o id que veio do banco, o código do produto, o e-mail. Índice do array só serve para lista fixa, que nunca muda de ordem nem ganha item no meio — e, mesmo assim, é melhor evitar. Com índice, remover o primeiro item faz o React achar que todos mudaram, e o estado de cada linha vai para o vizinho errado.

O aviso "Each child in a list should have a unique key" só aparece em desenvolvimento; em produção, a lista sem key desenha, mas perde a otimização e pode trocar estados de lugar. Vale tratar como erro. Outro detalhe: key não é prop e não aparece no HTML gerado — no painel, você vê o li sem nenhum atributo.

Se a lista vem de um filtro ou de uma ordenação, a key continua sendo o id do dado, nunca a posição. E se o item é um componente, a key vai no componente: <Linha key={p.id} pedido={p} />.

6. Condicionais: três formas de escolher

Como if não cabe dentro das chaves, o JSX resolve escolha de três jeitos: ternário para duas opções, && para mostrar ou não, e return antecipado para sair do componente antes de desenhar.

O && tem uma pegadinha que vale decorar: ele devolve o valor da esquerda quando ela é falsa. Com 0, "" ou NaN, esse valor aparece na tela. Por isso a comparação explícita — {itens.length > 0 && ...} — é mais segura do que {itens.length && ...}. Com null, undefined, false e true, nada é desenhado.

A lista mostra os dois pães, mas não avisa qual acabou. Use {!pao.pronto && "(esgotado)"} dentro do li e clique em Rodar.

const PAES = [
  { id: 1, nome: "pão francês", pronto: true },
  { id: 2, nome: "pão de queijo", pronto: false },
];

function App() {
  return (
    <ul>
      {PAES.map((pao) => (
        <li key={pao.id}>{pao.nome}</li>
      ))}
    </ul>
  );
}

No painel, o segundo li mostra "pão de queijo (esgotado)". O primeiro não mostra nada porque !true é false, e false não vira texto. Se você quisesse escrever "disponível" no primeiro, o ternário seria a escolha: {pao.pronto ? "(disponível)" : "(esgotado)"}.

7. As mensagens de erro mais comuns

Quase todo erro de JSX cai em uma destas linhas. O painel do guia mostra a mensagem do compilador quando o código não compila; o console do navegador mostra as do React em desenvolvimento.

Mensagem ou sintomaCausaConsertoAula
"Adjacent JSX elements must be wrapped in an enclosing tag"dois elementos soltos no mesmo returnembrulhar em <div> ou <>...</>O Fragment
"Objects are not valid as a React child"{pedido} em vez de {pedido.nome}escolher os campos que aparecemProps com Objetos
"Unterminated JSX contents"tag sem fechamento ou chave sem parfechar a tag, contar as chavesAs Regras do JSX
"Expected corresponding JSX closing tag"abriu <section> e fechou </div>casar abertura e fechamentoAs Regras do JSX
"Invalid DOM property class. Did you mean className?"atributo com nome do HTMLusar o nome do ReactAtributos e className

Um erro de objeto em filho, no console do navegador, aparece assim:

Objects are not valid as a React child (found: object with keys {nome, preco}).

A leitura é direta: alguém tentou desenhar um objeto inteiro. O React lista as chaves justamente para você reconhecer qual objeto era. O conserto quase sempre é apontar o campo certo, e o resto da mensagem — "use an array instead" — só se aplica quando você realmente queria uma lista.

Duas mensagens não impedem a página de rodar: o aviso de class e o de key são avisos de desenvolvimento. O atributo é ignorado e a lista desenha; o problema aparece depois, em comportamento estranho. Já erro de sintaxe — tag sem fechar, chave sem par — impede a compilação e o painel mostra "não compilou".

8. JSX no projeto: do arquivo ao DOM

Em um projeto com Vite, o JSX vive em arquivos .jsx e é transformado no build. O navegador recebe JavaScript comum. Por isso o JSX nunca aparece numa string, num innerHTML ou num arquivo .html: ele precisa passar pelo compilador antes.

import { createRoot } from "react-dom/client";
import App from "./App.jsx";

createRoot(document.getElementById("raiz")).render(<App />);

O App é um componente, e <App /> é a chamada dele. Essa é a única linha que o projeto precisa para começar: o resto é componente chamando componente. Nas caixas deste guia, o motor já renderiza <App /> e remove import e export default, então você escreve só a função.

Três hábitos que evitam a maior parte dos problemas. Primeiro: mantenha um componente por arquivo e o JSX do return com recuo consistente — erro de tag fechada aparece na hora. Segundo: extraia um componente quando o JSX passa de umas trinta linhas ou quando o mesmo bloco se repete. Terceiro: quando o painel mostrar um HTML diferente do que você esperava, compare com o JSX e procure a expressão que devolveu outro valor; o JSX não erra sozinho, ele desenha o que você pediu.

Resumo

JSX é JavaScript com roupa de HTML: o compilador troca cada tag por uma chamada React.createElement, e o que circula são objetos. As cinco regras são tag fechada, um pai só, aspas para texto e chaves para JavaScript, nomes em camelCase e comentário entre chaves. Dentro das chaves cabe expressão — variável, conta, ternário, &&, map, chamada de função —, nunca comando como if ou for.

Listas saem de map com uma key estável, de preferência o id do dado. Condicionais saem de ternário, de && ou de um return antecipado, e o && pede comparação explícita quando o valor pode ser zero. As mensagens de erro falam de elementos adjacentes, objeto como filho, tag sem fechar e key ausente — cada uma aponta para uma regra desta página.

Para consultar rápido: se o JSX não compila, é sintaxe (tag, chave, irmãos soltos). Se compila e a tela mostra outra coisa, é expressão. Se compila e o console reclama, é nome de atributo ou key. Com essas três perguntas, você resolve a maior parte sem abrir a documentação.

Para lembrar

  • JSX vira React.createElement(tipo, props, filhos) no build.
  • Toda tag fecha; irmãos soltos pedem <div> ou <>...</>.
  • Aspas = texto; chaves = JavaScript; className e htmlFor substituem class e for.
  • Nas chaves cabe expressão, não comando.
  • Objeto não é filho válido: mostre {objeto.campo}.
  • 0 e "" aparecem na tela; false, null e undefined não.
  • map precisa de key estável; índice só em lista fixa.
  • key não chega como prop.
  • style é objeto com camelCase.
  • Erro de sintaxe impede compilar; aviso de atributo ou key só reclama no console.
