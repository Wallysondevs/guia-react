Glossário

Toda profissão tem um vocabulário, e React não é diferente: componente, prop, estado, hook, efeito, chave, build. A maior parte da confusão de quem começa não é de lógica — é de palavra usada em dois sentidos. A Ana anota aqui os termos do jeito que o guia os usa, com sinônimo em inglês, a aula onde o assunto é ensinado e o exemplo mínimo.

Como usar esta página
  • Os termos estão agrupados por assunto, na ordem em que aparecem no guia — não em ordem alfabética.
  • Cada verbete tem o termo, a definição curta e, quando importa, o sinônimo em inglês.
  • A tabela da seção 1 traduz o vocabulário que aparece em mensagem de erro e em documentação.
  • As duas caixas mostram três palavras do glossário funcionando juntas: prop, estado e valor derivado.

1. Como ler este glossário

Uma palavra por vez, e sempre no sentido que o guia dá a ela. Quando um termo tem tradução consagrada em português, o guia usa a tradução; quando a tradução atrapalha, mantém o inglês e explica. “Desenho” é o caso do primeiro tipo: quase todo material chama de render, e aqui a palavra é desenho porque é o que o React faz — pega o que o componente devolveu e põe na tela.

Três palavras deste glossário têm sentido mais estreito do que na conversa do dia a dia. Desenho não é o resultado visual: é a execução do corpo do componente. Atualização não é o valor novo: é o pedido de mudança. E efeito não é consequência: é o trecho que roda depois do desenho. Guardar esses três sentidos resolve metade das dúvidas de leitura de código alheio.

2. Componentes, JSX e props

O vocabulário da tela. Tudo o que aparece aqui é sobre o que o React desenha e de onde vêm os dados que ele usa.

componente
Função com nome em maiúscula que devolve JSX. O React chama a função e desenha o resultado: function Cartao() { ... }. Aula: O Primeiro Componente.
JSX
A escrita parecida com HTML dentro do JavaScript. Não é HTML nem texto: é traduzida para chamadas que criam elementos. Aula: As Regras do JSX.
elemento
O que o JSX representa: a tag, os atributos e os filhos. Um elemento é uma descrição; o nó no DOM é o resultado de desenhá-lo.
prop
Dado que chega ao componente pela chamada: <Cartao nome="Ana" />. Somente leitura. Aula: As Props.
children
A prop especial que carrega o que foi escrito entre as tags. Serve para compor sem saber o que vem dentro. Aula: O children.
composição
Montar telas juntando componentes em vez de herdar comportamento. Aula: Composição.

Uma diferença que vale fixar no vocabulário: JSX parece HTML, mas obedece a regras do JavaScript. Os atributos são camelCase (onClick, tabIndex), a classe se escreve className e o rótulo de formulário usa htmlFor. Toda tag fecha, inclusive as vazias (<br />, <img />). E comentário é {/* … */}, porque <!-- --> não existe dentro de expressão.

O resto do vocabulário desta família, em definições curtas:

expressão
Tudo o que vai entre chaves no JSX e é avaliado como JavaScript: {preco * 2}, {nome}, {itens.length}.
atributo de JSX
O que vira atributo no HTML. A maioria tem o mesmo nome; duas exceções importam: className em vez de class e htmlFor em vez de for.
renderização condicional
Escolher o que desenhar com ?, && ou if antes do return. Aula: Renderização Condicional.
fragmento
Casca invisível para devolver vários irmãos sem criar nó: <>...</> ou Fragment. Aula: O Fragment.
prop drilling
Passar a mesma prop por níveis que não a usam, só para ela chegar lá embaixo. Aula: Props Drilling.
valor padrão de prop
O que o componente usa quando a prop não vem: function Botao({ tipo = "submit" }). Aula: Props Padrão.

3. Estado, eventos e atualizações

O vocabulário do que muda. Estado é o dado que o componente guarda; atualização é o pedido de mudança; desenho é a consequência.

estado
Dado que nasce dentro do componente e sobrevive entre desenhos. Declarado com useState. Aula: O useState.
função de troca
O segundo item do useState: setNome. Chama-se setter na documentação. Chamar essa função agenda uma atualização.
atualização
O pedido de mudança de estado. Não muda a variável na hora: o valor novo chega no próximo desenho.
desenho
A execução do corpo do componente. Todo desenho lê o estado atual e devolve JSX novo.
batching
Agrupar várias atualizações do mesmo evento em um único desenho. Aula: Batching.
estado derivado
Valor calculado a partir de estado existente, sem useState próprio. Aula: Estado Derivado.
elevar o estado
Mover o estado para o ancestral comum de quem precisa dele. Aula: Elevando o Estado.
evento sintético
O objeto que o React entrega no manipulador, imitando o evento do navegador: onClick, onChange, onSubmit. Aula: Eventos e onClick.
manipulador
A função que responde ao evento. Vai como referência (onClick={somar}), não chamada.

Três palavras do glossário no mesmo componente: nome é prop, paes é estado e total é valor derivado — só que está fixo em 2. Troque por const total = paes * 2; e clique duas vezes em “Somar pão”.

function Resumo({ nome }) {
  const [paes, setPaes] = useState(0);
  const total = 2;

  return (
    <div>
      <p>Cliente: {nome}</p>
      <button onClick={() => setPaes(paes + 1)}>Somar pão</button>
      <p>Pães: {paes}</p>
      <p>Total: R$ {total}</p>
    </div>
  );
}

function App() {
  return <Resumo nome="Ana" />;
}
<div>
  <p>Cliente: Ana</p>
  <button>Somar pão</button>
  <p>Pães: 0</p>
  <p>Total: R$ 2</p>
</div>

O botão muda o estado, o estado muda o desenho e o desenho recalcula o derivado. Nenhuma das três coisas precisa de hook extra: total não é estado, é conta. Guardar total em um useState seria a segunda fonte de verdade da qual a seção 3 fala.

4. Hooks

Hook é a função do React que dá um recurso ao componente: memória, efeito, contexto, identidade. Todos começam com use e todos obedecem à mesma regra de lugar.

Três deles são confundidos com frequência porque o nome é parecido e a diferença é de alvo: useMemo guarda valor, useCallback guarda função e useRef guarda uma caixa cujo conteúdo muda sem disparar desenho. E há o par que não é hook: memo é um embrulho de componente, não uma chamada dentro do corpo. Se a dúvida for de desempenho, a consulta é Performance.

hook
Função do React chamada no topo de um componente ou de outro hook. Não é classe, não é método e não existe fora do desenho.
regra dos hooks
Mesma quantidade e mesma ordem em todo desenho: nada de if, laço ou return antes. Aula: As Regras dos Hooks.
efeito
Trecho que roda depois do desenho, para sincronizar com algo de fora: rede, título da aba, timer. Aula: O useEffect.
dependências
A lista que decide quando o efeito roda de novo. Aula: As Dependências.
cleanup
A função devolvida pelo efeito, que desfaz o que ele fez antes do próximo ciclo. Aula: O Cleanup.
useRef
Guarda um valor entre desenhos sem disparar desenho novo; também dá acesso a um nó do DOM. Aula: O useRef.
useMemo
Guarda o resultado de um cálculo até as dependências mudarem. Aula: O useMemo.
useCallback
Guarda a identidade de uma função entre desenhos. Aula: O useCallback.
useReducer
Troca o par valor/setter por estado mais dispatch, com a regra em um reducer. Aula: O useReducer.
useContext
Lê o valor do provider mais próximo de um canal. Aula: O useContext.
useId
Gera um id único e estável para ligar rótulo e campo. Aula: O useId.
useTransition
Marca uma atualização como não urgente e informa se ela está em curso. Aula: O useTransition.
useDeferredValue
Devolve uma versão atrasada de um valor, para a parte cara da tela esperar. Aula: O useDeferredValue.
hook próprio
Função com nome use... que chama outros hooks e devolve o que o componente precisa. Aula: Hooks Próprios.

Hook não é palavra do JavaScript: é do React, e por isso precisa ser importado no topo do arquivo. Nas caixas deste guia os hooks já estão no escopo, mas no projeto cada um vem de "react". Esquecer o import produz a mensagem mais direta do vocabulário:

Uncaught ReferenceError: useState is not defined

“useState não foi definido” quer dizer, quase sempre, “falta o import”. O conserto é a linha import { useState } from "react" — e, se o aviso persistir, confira se o nome está escrito igual ao do import, com maiúscula no lugar certo.

5. Listas, chaves e dados

O vocabulário de transformar array em tela. Quase tudo aqui é JavaScript comum; o React só pede a chave.

lista
Array de dados desenhado item por item. Pode vir de prop, de estado ou de constante. Consulta: Listas.
map
Método que transforma cada item em JSX e devolve um array de elementos. Aula: Listas com map.
chave
A identidade do item para o React, escrita em key. Vem do dado, não da posição. Aula: Chaves Estáveis.
índice
A posição do item no array. Serve como chave só em lista fixa, que nunca reordena.
derivar
Calcular a lista visível no desenho: filtrar, ordenar, cortar. Não vai para o estado. Aulas: Filtrar e Ordenar.
vazio
Lista sem item. É tela legítima, com mensagem própria, testada com length === 0. Aula: Estados Vazios.
paginação
Desenhar um pedaço por vez, com controle de página. Aula: Paginação.
virtualização
Desenhar só os itens visíveis, mantendo a rolagem do tamanho total. Aula: Listas Grandes.

A lista está vazia e um 0 aparece na tela: itens.length vale zero, e o && desenha esse zero. Troque por itens.length === 0 ? <p>Hoje não tem pão de queijo</p> : <ul>…</ul>.

function App() {
  const [itens] = useState([]);

  return (
    <div>
      <h1>Vitrine</h1>
      {itens.length && (
        <ul>
          {itens.map((p) => (
            <li key={p}>{p}</li>
          ))}
        </ul>
      )}
    </div>
  );
}
<div>
  <h1>Vitrine</h1>
  0
</div>

function App() {
  const [itens] = useState([]);

  return (
    <div>
      <h1>Vitrine</h1>
      {itens.length === 0 ? (
        <p>Hoje não tem pão de queijo</p>
      ) : (
        <ul>
          {itens.map((p) => (
            <li key={p}>{p}</li>
          ))}
        </ul>
      )}
    </div>
  );
}

6. Formulários e acessibilidade

O vocabulário do dado digitado e do dado anunciado. As duas coisas andam juntas: um campo sem rótulo é um campo que metade das pessoas não consegue usar.

Acessibilidade não é um assunto separado — é vocabulário. Rótulo, descrição, estado de erro e ordem de foco são atributos do mesmo componente que você já está escrevendo. Um formulário “pronto” sem label ligado não está pronto: está funcionando para quem enxerga a tela e tem mouse.

campo controlado
Campo cujo valor vem do estado, via value, e cuja mudança volta por onChange. Consulta: Formulários.
não controlado
Campo em que o DOM guarda o valor; o React só lê no envio. Valor inicial em defaultValue. Aula: Controlado e Não Controlado.
evento de mudança
onChange, que no React dispara a cada tecla. O valor está em e.target.value.
rótulo
O <label> ligado ao campo por htmlFor e id. Sem ele, o campo não tem nome para quem usa leitor de tela. Aula: Formulário Acessível.
descrição
O texto que explica o campo, ligado por aria-describedby: formato esperado, mensagem de erro.
validação
Conferir o dado antes de enviar. A do navegador é declarativa (required); a do componente guarda a mensagem em estado. Aula: Validação.
envio
O evento onSubmit do <form>, com e.preventDefault() na primeira linha. Aula: Envio de Formulário.

7. Rede, assincronia e erros

O vocabulário do dado que demora e do dado que falha. É onde o estado de carregamento nasce.

Três palavras desta seção não são sinônimos e viram três telas: carregando é “pedi e ainda não voltou”; vazio é “voltou e não tem nada”; erro é “voltou quebrado”. Desenhar a mesma mensagem nos três casos é o defeito mais comum de tela que busca dados — e o conserto é sempre separar os estados, não melhorar o texto.

fetch
A função do navegador que faz requisição HTTP e devolve uma promessa. Aula: Fetch.
promessa
Objeto que representa um valor futuro: pendente, resolvida ou rejeitada. Aula: Async/Await.
estado de carregamento
O booleano ou texto que diz “estou buscando”. Sem ele, a tela parece travada. Aula: Estados de Carregamento.
erro de execução
Exceção lançada durante o desenho ou em um evento. A mensagem vai para o console. Consulta: Mensagens de Erro.
error boundary
Componente que captura o erro dos filhos e desenha uma tela de desculpa. Aula: Tratamento de Erro.
lazy e Suspense
Carregar um componente só quando ele é necessário, com uma tela de espera enquanto chega. Aula: Lazy e Suspense.

8. Ferramentas, build e produção

O vocabulário de fora do código: o programa que junta os arquivos, o comando que roda a versão de desenvolvimento e o que vai para o servidor no fim.

Duas ideias resolvem a maior parte da confusão desta seção. A primeira: o que vai para o servidor é a pasta dist, gerada pelo build — não é o seu src, e não é o node_modules. A segunda: desenvolvimento e produção são programas diferentes, com avisos diferentes. Um erro que só aparece em produção quase sempre é aviso de desenvolvimento que ninguém consertou.

Vite
A ferramenta que cria e serve o projeto React neste guia: desenvolvimento rápido e build no fim. Aula: Criar o Projeto com Vite.
bundler
O programa que junta os módulos em poucos arquivos e traduz JSX. O Vite usa um por baixo.
build de produção
A versão final, empacotada e minificada, gerada por npm run build. Aula: Build de Produção.
modo de desenvolvimento
A versão com avisos e verificações extras, servida por npm run dev. Não é a que vai ao ar.
StrictMode
O embrulho que faz o React desenhar duas vezes em desenvolvimento para revelar efeitos mal feitos. Aula: Strict Mode.
DevTools
As ferramentas do navegador, com o painel do React para ver componentes, props e desenhos. Aula: Depurando no Navegador.
ESLint
O verificador de estilo e de regras que avisa antes de rodar — inclusive as regras dos hooks.
deploy
Publicar o build em um servidor ou serviço. Aula: Publicando.

No terminal, a mensagem de comando errado é curta e específica. Ela aparece quando o package.json não tem o script que você pediu — comum em projeto criado com outro modelo, em que o comando de desenvolvimento tem outro nome:

npm ERR! Missing script: "dev"

“Script dev faltando.” A lista do que existe está no package.json, na seção scripts; a aula Scripts do package.json mostra os quatro do Vite e como criar os seus. E se o terminal disser que não achou package.json, você está na pasta errada: o comando roda dentro da pasta do projeto.

Resumo

O vocabulário do guia cabe em seis palavras: componente (função que devolve JSX), prop (dado que desce), estado (dado que nasce dentro e muda), desenho (execução do componente), efeito (o que roda depois) e hook (a função que dá o recurso). Tudo o mais — lista, chave, contexto, transition, build — é uma combinação dessas seis.

Quando uma palavra parecer ambígua, procure o par: estado e prop, controlado e não controlado, desenho e efeito, memo e useMemo. A confusão quase sempre está em usar o mesmo nome para o pedido de mudança e para o valor novo. As duas caixas desta página mostram três termos juntos — prop, estado e valor derivado — e o resto do guia mostra cada um em uso.

Para lembrar

  • Componente é função; JSX é a escrita que devolve elementos.
  • Prop desce, estado fica: prop é somente leitura.
  • Atualização é o pedido; o valor novo aparece no próximo desenho.
  • Desenho executa o componente; efeito roda depois dele.
  • Hook começa com use e fica no topo, sempre na mesma ordem.
  • Chave de lista vem do dado e é estável entre desenhos.
  • Lista visível é derivada: filtrar e ordenar não viram estado.
  • Campo controlado é value mais onChange.
  • Carregamento, vazio e erro são três telas diferentes.
  • Desenvolvimento avisa; produção só entrega — build é outro programa.
