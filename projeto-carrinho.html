Carrinho de Compras

A padaria agora vende pelo site, e a Ana precisa resolver uma pergunta que parece simples: quando o cliente clica duas vezes em "Pão de queijo", o que acontece? Um item repetido na lista ou um item com quantidade 2? E o total, quem calcula? Neste projeto ela monta o carrinho do zero: o catálogo, a lista de itens com quantidade, as contas de subtotal, frete e total, o dinheiro formatado em reais e a mensagem do carrinho vazio. Cada caixa roda uma parte do app com o React de verdade.

Você vai aprender
  • Como separar o catálogo (dado fixo) do carrinho (estado).
  • Como somar o mesmo produto em vez de repetir a linha.
  • Como aumentar a quantidade com map sem mutar o item.
  • Como calcular subtotal, frete e total no render.
  • Como formatar dinheiro em reais sem erro de arredondamento.
  • Como mostrar o carrinho vazio e limitar a quantidade.
  • Como remover um item com filter.
  • O que quebra quando o preço chega como texto.

1. A cena e as decisões do carrinho

O carrinho tem duas listas, e confundi-las é o primeiro erro do projeto. A primeira é o catálogo: os produtos que a padaria vende, com preço fixo. A segunda é o carrinho: o que aquele cliente escolheu, com quantidade. O catálogo é dado de partida e não muda; o carrinho é estado e muda a cada clique.

A segunda decisão é o que um item do carrinho guarda. Guardar o produto inteiro copiado é cômodo e perigoso: se o preço mudar no catálogo, o item fica com o preço velho. Guardar só o id obriga a buscar o produto a cada conta. Neste projeto o item guarda uma cópia mínima — id, título e preço — porque o preço do momento da compra é justamente o que interessa num carrinho.

A terceira decisão é sobre dinheiro. Preço em reais com centavos é número decimal, e decimal em JavaScript tem fama ruim: 0.1 + 0.2 não dá exatamente 0.3. Para um app de padaria, guardar reais e arredondar na hora de mostrar resolve. Para um sistema financeiro, o caminho é guardar centavos inteiros e dividir só na exibição.

O escopo: catálogo, adicionar, aumentar, diminuir, remover, subtotal, frete e total. Fora: cupom, pagamento, estoque real. O frete é uma regra simples — grátis a partir de R$ 20, senão R$ 5 — e serve para mostrar que nem toda conta precisa de estado.

2. Os dados: produto e item

São dois formatos parecidos e com papéis diferentes. O produto é o que a loja oferece; o item é o que o cliente levou. O produto tem preço unitário; o item tem quantidade. Os dois têm id, e é o id que permite encontrar o mesmo produto nas duas listas.

produto
O que está na vitrine: { id, titulo, preco }. O preço é o valor unitário, em reais.
item do carrinho
O que o cliente escolheu: { id, titulo, preco, quantidade }. O id é o mesmo do produto.
quantidade
Quantas unidades daquele produto. Começa em 1 e sobe com o botão de mais.
subtotal
A soma de preco * quantidade de todos os itens, antes do frete.
total
Subtotal mais o frete. É o número que o cliente paga e o que aparece em destaque.

Com os formatos definidos, os dados ficam legíveis:

const produtos = [
  { id: "pao-frances", titulo: "Pão francês", preco: 1.0 },
  { id: "pao-queijo", titulo: "Pão de queijo", preco: 1.5 },
  { id: "bolo-cenoura", titulo: "Bolo de cenoura", preco: 12.0 },
  { id: "cafe", titulo: "Café coado", preco: 2.5 },
];

Repare que o preço é número, não texto: 1.5, e não "1,50". Guardar texto obrigaria a converter em toda conta e abriria espaço para "1,5" + "2" virar "1,52". A conversão para o formato brasileiro acontece só na hora de mostrar, com uma função pequena.

DecisãoCaminho fácilO que custa depois
preço como texto"R$ 1,50"toda conta precisa converter; a soma concatena
copiar o produto inteiro no item{ ...produto, quantidade: 1 }o item carrega campos que não usa e pode ficar velho
guardar o total no estadoconst [total, setTotal]é preciso atualizar em cada mudança de quantidade
calcular o total no rendercarrinho.reduce(...)nada: é sempre a soma do carrinho atual

A última linha é a regra do projeto inteiro: o total não é um dado novo, é uma conta. Guardar o total num useState significa lembrar de recalculá-lo em adicionar, aumentar, diminuir e remover — e um dia esquecer. A conta feita no render nunca esquece.

3. O catálogo na tela

A vitrine é a parte fácil: um map sobre produtos, um cartão por produto, com título, preço formatado e o botão de adicionar. O botão ainda não faz nada nesta etapa — ele ganha a função no próximo passo. Separar as etapas é o que permite testar uma coisa de cada vez.

A vitrine mostra dois produtos escritos à mão. Gere um div.produto para cada item de produtos, com key, título, preço em reais e o botão Adicionar.

O painel mostra quatro cartões com o preço já no formato brasileiro. A função reais faz duas coisas: toFixed(2) garante duas casas e replace(".", ",") troca o ponto pela vírgula. Sem o toFixed, o preço apareceria como 1 ou 1.5; sem o replace, apareceria como R$ 1.50 — que o cliente brasileiro lê errado.

Note que a função está fora do componente. Ela não usa estado nem props, então não precisa ser recriada a cada desenho. O mesmo vale para produtos: é dado fixo, não estado. Só o carrinho vai mudar com o tempo.

Para conferir os dados, um console.log mostra o catálogo e o tipo do preço:

typeof produtos[1].preco: number

Se o seu typeof der string, o preço veio com aspas em algum lugar — e a primeira conta vai concatenar em vez de somar. Vale conferir antes de seguir.

4. Adicionar o mesmo produto duas vezes

Aqui está a decisão que separa um carrinho de uma lista de compras: clicar duas vezes no mesmo produto não cria duas linhas, aumenta a quantidade da linha existente. O código precisa procurar o produto no carrinho antes de decidir entre somar e acrescentar.

Na caixa abaixo, o adicionar sempre empilha um item novo. Clique duas vezes no segundo produto e veja duas linhas de "Pão de queijo". Conserte com find e map:

Clicar duas vezes no mesmo produto cria duas linhas. Se o produto já estiver no carrinho, aumente a quantidade com map; se não estiver, acrescente com spread.

const produtos = [
  { id: "pao-frances", titulo: "Pão francês", preco: 1.0 },
  { id: "pao-queijo", titulo: "Pão de queijo", preco: 1.5 },
  { id: "bolo-cenoura", titulo: "Bolo de cenoura", preco: 12.0 },
  { id: "cafe", titulo: "Café coado", preco: 2.5 },
];

function App() {
  const [carrinho, setCarrinho] = useState([]);

  function adicionar(produto) {
    setCarrinho([
      ...carrinho,
      {
        id: produto.id,
        titulo: produto.titulo,
        preco: produto.preco,
        quantidade: 1,
      },
    ]);
  }

  return (
    <div>
      <h2>Vitrine</h2>
      <div className="produtos">
        {produtos.map((produto) => (
          <div key={produto.id} className="produto">
            <p>{produto.titulo}</p>
            <button onClick={() => adicionar(produto)}>Adicionar</button>
          </div>
        ))}
      </div>
      <h3>Carrinho</h3>
      <ul>
        {carrinho.map((item) => (
          <li key={item.id}>
            {item.quantidade} × {item.titulo}
          </li>
        ))}
      </ul>
    </div>
  );
}

Depois do conserto, dois cliques no "Pão de queijo" deixam uma linha, com 2 × Pão de queijo. O find responde se o produto já está lá; o map devolve um carrinho novo, trocando só o item que combina. É a mesma receita do "concluir tarefa": procurar pelo id e devolver um objeto novo com o campo alterado.

Três detalhes merecem atenção. O primeiro é que o map precisa devolver item sem alteração nos outros casos — esquecer o : item transforma todos os itens em undefined. O segundo é o spread no item que muda: sem ele, você perde título e preço. O terceiro é que o else é obrigatório: sem ele, o item novo seria acrescentado mesmo quando já existe.

O console mostra o carrinho depois dos dois cliques, com um item só:

carrinho.length: 1
carrinho[0].quantidade: 2
carrinho[0].preco: 1.5

Se o seu carrinho.length for 2, o find não achou o item — quase sempre porque o id comparado é do produto e o guardado é outro, ou porque a comparação usa == com tipos diferentes.

5. Aumentar, diminuir e remover

Dentro do carrinho, as três operações são variações da mesma ideia: encontrar o item pelo id e devolver um carrinho novo. Aumentar e diminuir trocam a quantidade; remover tira a linha. O erro clássico é mutar o item e entregar o mesmo array ao set.

O botão de mais muda o objeto no lugar e a tela não atualiza. Troque por um map que devolve { ...item, quantidade: item.quantidade + 1 } para o item clicado.

const reais = (valor) => "R$ " + valor.toFixed(2).replace(".", ",");

function App() {
  const [carrinho, setCarrinho] = useState([
    { id: "pao-frances", titulo: "Pão francês", preco: 1.0, quantidade: 1 },
  ]);

  function aumentar(id) {
    const item = carrinho.find((i) => i.id === id);
    item.quantidade = item.quantidade + 1;
    setCarrinho(carrinho);
  }

  const total = carrinho.reduce(
    (soma, item) => soma + item.preco * item.quantidade,
    0
  );

  return (
    <div>
      <h3>Carrinho</h3>
      <ul>
        {carrinho.map((item) => (
          <li key={item.id}>
            {item.quantidade} × {item.titulo}
            <button className="mais" onClick={() => aumentar(item.id)}>+</button>
          </li>
        ))}
      </ul>
      <p>Total: {reais(total)}</p>
    </div>
  );
}

Clique no +: a linha passa a "2 × Pão francês" e o total para R$ 2,00. O total é reduce — ele percorre o carrinho somando preco * quantidade, começando em 0. Como é uma conta feita no render, ela acompanha a quantidade sem nenhum setTotal.

adicionar
Recebe o produto do catálogo. Decide entre somar a quantidade do item existente e acrescentar um item novo.
aumentar
Recebe o id do item. Devolve o carrinho com quantidade + 1 no item certo.
diminuir
Recebe o id. Devolve quantidade - 1 e remove o item que chegar a zero.
remover
Recebe o id. Devolve o carrinho sem aquele item, com filter.
reais
Recebe um número e devolve o texto formatado: R$ 8,00. Usada só na exibição.

Para diminuir, a diferença é o limite: a quantidade não pode ficar abaixo de 1. Quando chega em 1, o botão de menos deve remover o item, não mostrar "0 ×". Uma condição resolve:

function diminuir(id) {
  setCarrinho(
    carrinho
      .map((item) =>
        item.id === id
          ? { ...item, quantidade: item.quantidade - 1 }
          : item
      )
      .filter((item) => item.quantidade > 0)
  );
}

O map diminui a quantidade e o filter tira quem chegou a zero. Repare que o filter vem depois, sobre o resultado do map — e não antes. Essa ordem importa: é o item já atualizado que precisa ser testado.

Remover é só o filter, sem map:

function remover(id) {
  setCarrinho(carrinho.filter((item) => item.id !== id));
}

As três funções têm a mesma forma: recebem um id, devolvem um carrinho novo, nunca tocam no array antigo. Quando você sentir que está repetindo código, é sinal de que dá para extrair uma função atualizarQuantidade(id, delta) — mas só depois de as três funcionarem.

6. Subtotal, frete e total

O carrinho tem três números e nenhum deles é estado. O subtotal soma os itens; o frete depende do subtotal; o total soma os dois. Todos são contas feitas no render, a partir do carrinho. A tabela mostra a regra de cada um:

NúmeroComo se calculaCuidado
subtotalreduce de preco * quantidadecomeçar em 0, senão o primeiro item quebra a conta
freteR$ 5, ou R$ 0 a partir de R$ 20carrinho vazio não cobra frete
totalsubtotal + fretesomar depois de arredondar, não antes
exibiçãoreais(total)formatar só na tela; guardar número

A regra do frete é uma expressão condicional simples e merece um cuidado: carrinho vazio não paga frete. Sem essa condição, o cliente abre o site e vê "Total: R$ 5,00" sem ter escolhido nada — um dos bugs mais constrangedores de loja pequena.

const subtotal = carrinho.reduce(
  (soma, item) => soma + item.preco * item.quantidade,
  0
);
const frete = carrinho.length === 0 || subtotal >= 20 ? 0 : 5;  // vazio ou acima de 20: grátis
const total = subtotal + frete;

Quando o subtotal chega a R$ 20, o frete vira zero e o total é só o subtotal. O cliente vê "Frete: grátis" em vez de "Frete: R$ 0,00" — detalhe de redação que faz diferença na percepção. Uma condicional no texto resolve:

<p>Frete: {frete === 0 ? "grátis" : reais(frete)}</p>
<p>Total: {reais(total)}</p>

O console é o melhor lugar para conferir as contas antes de confiar na tela:

subtotal: 1
frete: 5
total: 6
reais(total): "R$ 6,00"

Se o total vier com muitas casas decimais — 7.999999999 —, é o tal do decimal binário. Não arredonde no meio da conta: arredonde só na exibição, com toFixed(2), e o cliente vê o valor certo. Guardar centavos inteiros é a solução definitiva, para quando o app crescer.

7. Carrinho vazio, limites e o que remove

O carrinho vazio não é um erro: é o estado inicial e o estado depois de remover o último item. A tela precisa dizer o que fazer, não ficar em branco. E o texto muda conforme o motivo: na primeira visita, "Seu carrinho está vazio. Escolha um pão na vitrine."; depois de remover, a mesma frase serve, porque o carrinho realmente está vazio.

Os limites são a outra metade do acabamento. Quantidade máxima por item evita pedidos de 300 pães por engano; quantidade mínima 1 evita linha com zero. O frete grátis é um limite de outra natureza — é uma regra de negócio que muda o total, não a lista. Todos os três são condições calculadas, não estados.

const limite = 10;

function aumentar(id) {
  setCarrinho(
    carrinho.map((item) =>
      item.id === id && item.quantidade < limite
        ? { ...item, quantidade: item.quantidade + 1 }
        : item
    )
  );
}

if (carrinho.length === 0) {
  return <p>Seu carrinho está vazio. Escolha um pão na vitrine.</p>;
}

O return antecipado do vazio é uma escolha legível: quando não há carrinho, não há o que calcular. Cuidado apenas com a ordem dos hooks — todos os useState precisam vir antes de qualquer return condicional. Se você devolver cedo demais, o React reclama que a quantidade de hooks mudou entre um desenho e outro.

SituaçãoRegraO que a tela faz
carrinho sem itenscarrinho.length === 0mostra a mensagem de vazio e não cobra frete
menos no item de quantidade 1quantidade > 0 depois do mapo item sai da lista
mais no item de quantidade 10quantidade < limiteo botão não faz nada, e o número não sobe
subtotal de R$ 20 ou maissubtotal >= 20frete zero, exibido como "grátis"

Um detalhe de acessibilidade que vale desde já: o botão de aumentar deve dizer o que aumenta. Um + sozinho é lido como "mais" e não diz de qual produto. Um aria-label resolve sem mudar o visual: aria-label={"Aumentar " + item.titulo}. O mesmo vale para o botão de remover.

8. Cenários do dia a dia

Cenário 1: o total fica um clique atrás

A Ana atualizava a quantidade com item.quantidade += 1 e o total só mudava no clique seguinte. O array era o mesmo objeto, então o React não redesenhava; o segundo clique mudava o número de novo, e a tela mostrava o valor anterior. Com map e um objeto novo, cada clique desenha uma vez e o total acompanha.

Cenário 2: o preço virou texto e o total concatenou

O preço chegou de um catálogo em JSON como "1.50", e o reduce começou a colar textos: "01.501.50". O conserto foi converter na entrada — Number(produto.preco) — e manter número no estado. Se o valor vier do servidor como texto, converta uma vez, no lugar em que ele entra, e não em cada conta.

Cenário 3: o carrinho cobra frete sem ter item

Ela calculou o frete só pela regra do valor e esqueceu o carrinho vazio: o subtotal era 0, então a condição do frete grátis falhava e o total aparecia como R$ 5,00 na primeira visita. A correção foi testar carrinho.length === 0 antes da regra de valor. Regra de negócio precisa considerar o estado vazio, não só o número.

Exercício: somar o carrinho

Complete a conta que soma preco * quantidade de todos os itens. Escreva só o método do array:

const subtotal = carrinho.( (soma, item) => soma + item.preco * item.quantidade, 0 );

Dica: é o método que percorre a lista acumulando um valor só. O segundo argumento, 0, é o valor inicial do acumulador. Com map você teria uma lista de subtotais, não um total.

10. Resumo

O carrinho tem duas listas: o catálogo, que é dado fixo, e o carrinho, que é estado. Cada item guarda id, título, preço e quantidade — o preço como número, não como texto. Adicionar procura o produto com find: se existe, map aumenta a quantidade; se não, spread acrescenta o item novo. Aumentar, diminuir e remover devolvem sempre um carrinho novo.

Subtotal, frete e total são contas feitas no render, com reduce e uma condicional. O formato brasileiro aparece só na exibição, com toFixed(2) e replace. O carrinho vazio tem mensagem própria, e a quantidade tem limite mínimo e máximo. Nenhum desses números precisa de useState.

O projeto anterior, a galeria de fotos, usa a mesma base de listas com filtro e um detalhe que abre — vale comparar. O próximo projeto usa a mesma base com um ingrediente novo: dados que chegam de uma "API" e mudam de status. O painel de pedidos junta o carrinho, o status e o carregamento numa tela só. Se quiser revisar as contas com calma, a aula de estado derivado tem os mesmos exemplos isolados.

Para lembrar

  • Catálogo é dado fixo; carrinho é estado.
  • Item do carrinho: { id, titulo, preco, quantidade }.
  • Adicionar: find decide entre map e spread.
  • Aumentar: map com { ...item, quantidade: item.quantidade + 1 }.
  • Remover: filter pelo id.
  • Subtotal: reduce começando em 0.
  • Frete: condicional no subtotal e no carrinho vazio.
  • Total: subtotal + frete, calculado no render.
  • Dinheiro: número no estado, reais() na tela.
  • Carrinho vazio merece mensagem e não cobra frete.
