JSON: os dados em texto

A Ana clicou em “preços” no painel da padaria e viu uma parede de texto na tela do navegador: {"nome":"Pão francês","preco":1.2}. Ela tentou dados.nome no console e recebeu undefined. O texto parece um objeto, tem chaves e valores e até aspas — mas é uma string, e string não tem propriedade. Para virar objeto de verdade, esse texto precisa passar por uma função que o traduz. Essa tradução, e o caminho de volta, é o assunto desta aula.

Você vai aprender

  • As regras da sintaxe JSON — as que quebram o programa quando violadas.

  • JSON.stringify: de objeto para texto, para mandar de volta.
  • Como ler JSON aninhado, com listas dentro de objetos.
  • O que resposta.json() faz e por que ele precisa de await.
  • As mensagens de erro mais comuns e o que cada uma aponta.

1. A cena: o pedido que chegou como texto

Na aula de buscar dados, a Ana aprendeu a pedir a lista de preços e guardar a resposta no estado. Funcionou. Semana depois, ela quis mostrar o nome do primeiro pão e escreveu dados[0].nome — e a tela ficou em branco. No console, console.log(dados) imprimiu uma linha enorme, cheia de chaves, que ela confundiu com um objeto:

{"cliente":"Ana","itens":[{"pao":"brioche","qtd":2}],"total":9}

Só que aquilo é texto. A pista está nas aspas que envolvem tudo, nas chaves entre aspas e na ausência de espaços decorativos. Um objeto JavaScript impresso no console aparece como { cliente: 'Ana', ... }, com aspas apenas nos textos e sem aspas nos nomes das chaves. A diferença parece cosmética e é fundamental: dados.cliente funciona no segundo caso e devolve undefined no primeiro.

Esse formato tem nome: JSON, sigla de JavaScript Object Notation. Ele existe porque dois programas escritos em linguagens diferentes não conseguem passar objeto um para o outro diretamente — mas conseguem passar texto. Então a regra é sempre a mesma: quem envia transforma o objeto em texto JSON; quem recebe transforma o texto de volta em objeto. No meio do caminho, tudo é texto.

Vale dizer o que JSON não é, porque a confusão aparece cedo. Ele não é um banco de dados, não é um protocolo e não é uma biblioteca: é só um jeito de escrever dados em texto, com regras fixas. Um arquivo .json no projeto é exatamente isso — texto salvo em disco. E o nome tem “JavaScript” porque a sintaxe foi inspirada na linguagem, não porque só o JavaScript entende: Python, PHP, Go e praticamente tudo que conversa com servidor lê e escreve JSON.

2. JSON é texto, não é objeto

Vale fixar a ideia com duas linhas lado a lado. A primeira é JavaScript, com um objeto de verdade. A segunda é a mesma informação em JSON — perceba as aspas em volta dos nomes das chaves:

const paoObjeto = { nome: "Pão francês", preco: 1.2 };

const paoTexto = '{"nome": "Pão francês", "preco": 1.2}';

paoObjeto nasceu objeto: dá para acessar paoObjeto.nome, mudar paoObjeto.preco, passar em prop. paoTexto nasceu string: dá para medir o tamanho, procurar um pedaço com includes, cortar com slice — e nada mais. Ele tem { e }, mas para o JavaScript são só caracteres, do mesmo jeito que um desenho de pão numa folha não se come.

Por isso a leitura de qualquer API tem sempre dois passos, e é comum ver gente travada no primeiro achando que já fez o segundo. Passo um: buscar o texto. Passo dois: transformar o texto em objeto. Na aula de busca, o .json() já fazia o passo dois escondido — é o que a seção 7 detalha. Antes disso, vale conhecer as duas funções que fazem a tradução à mão, porque é com elas que você vai depurar qualquer resposta estranha.

JSON
Formato de texto para trocar dados entre programas. Nasceu do JavaScript, mas é lido por todas as linguagens — é por isso que ele existe.
parse
“Traduzir para a estrutura da linguagem”. JSON.parse recebe texto e devolve objeto, array, número, booleano ou null.
stringify
O caminho de volta: JSON.stringify recebe valor JavaScript e devolve o texto JSON.
serializar
O nome técnico dos dois sentidos: transformar estrutura em sequência de caracteres (e desserializar, ao contrário).
Response
O objeto que o fetch devolve. Tem .json(), .text(), .status e o corpo ainda não lido.

3. As regras da sintaxe

JSON é um formato pequeno: sete tipos de valor e quatro regras. Os valores são texto (entre aspas duplas), número, true, false, null, objeto (pares de chave e valor) e array (lista ordenada). Não existe função, não existe undefined, não existe comentário, não existe data — data vai como texto, geralmente no formato "2026-03-14".

As regras que mais derrubam iniciante são as de pontuação. Toda chave é texto, com aspas duplas obrigatórias. Todo texto usa aspas duplas — aspas simples são erro. Vírgula separa itens e nunca sobra depois do último. E o arquivo inteiro é um valor só: não dá para ter dois objetos soltos lado a lado.

Repare na linha do undefined: é a única em que o JSON “perde” informação sem reclamar. Se um campo obrigatório desaparece do texto, muitas vezes a causa está no objeto de origem, com undefined em vez de um valor. E repare também que JSON não tem tipo para data: o new Date() virou uma string ISO, e quem recebe precisa saber disso para exibir a data.

4. Do texto ao objeto: JSON.parse

A função que traduz texto JSON em objeto chama-se JSON.parse. Ela recebe uma string e devolve o valor que a string descreve. O caso abaixo tem a resposta de uma API que a Ana colou no arquivo para testar o componente sem depender de rede:

O parágrafo mostra o texto cru, porque resposta é string. Use JSON.parse para virar objeto e mostre o nome e o preço no formato Pão francês — R$ 1,20 (duas casas decimais, vírgula no lugar do ponto).

const resposta = '{"nome": "Pão francês", "preco": 1.2}';

function App() {
  return (
    <p className="preco">{resposta}</p>
  );
}
<p class="preco">{"nome": "Pão francês", "preco": 1.2}</p>

const resposta = '{"nome": "Pão francês", "preco": 1.2}';

function App() {
  const pao = JSON.parse(resposta);
  return (
    <p className="preco">{pao.nome} — R$ {pao.preco.toFixed(2).replace(".", ",")}</p>
  );
}

Depois do JSON.parse, pao é objeto: pao.nome funciona, pao.preco é número e aceita toFixed. O toFixed(2) garante duas casas decimais e o replace(".", ",") troca o ponto decimal pela vírgula brasileira — detalhe de formatação, não de JSON, mas que aparece em toda vitrine.

A função também serve para valores soltos, não só para objetos: JSON.parse("42") devolve o número 42, JSON.parse("true") devolve o booleano, JSON.parse('"pão"') devolve o texto (sim, com aspas dentro da string), e JSON.parse("null") devolve null. Isso importa porque uma API pode responder só null para dizer “não achei”.

Um detalhe que engana: JSON.parse não sabe nada sobre o seu componente. Ele não devolve JSX, não sabe de estado, não avisa a tela. Ele só converte um valor em outro, e é por isso que ele cabe numa linha antes do return — ou, melhor ainda, fora do componente, quando o texto é fixo, para não repetir a conversão a cada desenho.

E o que acontece quando o texto está quebrado? JSON.parse não devolve undefined nem tenta consertar: ele lança um erro. Isso é bom, porque um erro tem mensagem. A seção 8 mostra as duas mensagens que você vai encontrar mais.

5. Aninhado: listas dentro de objetos

Resposta de API raramente é plana. O pedido da padaria, por exemplo, tem um cliente, uma lista de itens e cada item tem nome e quantidade:

{
  "cliente": "Ana",
  "itens": [
    { "pao": "brioche", "qtd": 2 },
    { "pao": "sonho", "qtd": 1 }
  ]
}

Depois do parse, esse objeto tem a mesma forma do JSON: pedido.itens é um array, pedido.itens[0] é um objeto, pedido.itens[0].pao é texto. O caminho é lido da esquerda para a direita, ponto por ponto — e a lista é percorrida com map, como qualquer array. Não há nada de especial em JSON aninhado: o aninhamento é só a forma do dado.

O componente já tem o pedido em objeto, mas só mostra a quantidade de itens. Desenhe a lista ul.itens com um li por item, no formato 2× brioche.

const texto = '{"cliente": "Ana", "itens": [{"pao": "brioche", "qtd": 2}, {"pao": "sonho", "qtd": 1}]}';

function App() {
  const pedido = JSON.parse(texto);
  return (
    <div>
      <h2>Pedido de {pedido.cliente}</h2>
      <p>itens: {pedido.itens.length}</p>
    </div>
  );
}
<div>
  <h2>Pedido de Ana</h2>
  <p>itens: 2</p>
</div>

const texto = '{"cliente": "Ana", "itens": [{"pao": "brioche", "qtd": 2}, {"pao": "sonho", "qtd": 1}]}';

function App() {
  const pedido = JSON.parse(texto);
  return (
    <div>
      <h2>Pedido de {pedido.cliente}</h2>
      <ul className="itens">
        {pedido.itens.map((item) => <li key={item.pao}>{item.qtd}× {item.pao}</li>)}
      </ul>
    </div>
  );
}

Quando o aninhamento fica fundo, a leitura fica frágil: um ?.pedido?.itens? cheio de interrogações é sinal de que você não sabe se aquele pedaço existe. Nesse ponto vale dividir: uma função que recebe o JSON e devolve só o que a tela precisa, achatado. O componente fica simples e a tradução fica num lugar só.

6. Do objeto ao texto: JSON.stringify

O caminho de volta é JSON.stringify. Ele recebe um objeto (ou array, ou número) e devolve o texto JSON correspondente. É o que acontece quando você envia um pedido para o servidor: o corpo do POST é texto JSON, não é objeto.

O pre mostra [object Object], porque objeto não vira texto sozinho. Troque por JSON.stringify(pedido, null, 2) para o JSON aparecer indentado, com "cliente": "Ana" e "paes": 2.

function App() {
  const pedido = { cliente: "Ana", paes: 2, obs: undefined };
  return <pre className="json">{String(pedido)}</pre>;
}
<pre class="json">[object Object]</pre>

function App() {
  const pedido = { cliente: "Ana", paes: 2, obs: undefined };
  return <pre className="json">{JSON.stringify(pedido, null, 2)}</pre>;
}

O nome “stringify” vem de string, texto: a função devolve uma string. Por isso ela é a parceira obrigatória do envio de dados. Quando a Ana for implementar o botão de enviar o pedido, o corpo da requisição vai ser JSON.stringify(pedido) — não o objeto. Mandar o objeto direto faz o navegador converter para algo inútil como [object Object], que é exatamente o que o pre da caixa mostra antes da correção.

O segundo argumento é o “substituto” e fica null quando você não quer filtrar chaves. O terceiro é o espaçamento: 2 usa dois espaços por nível e deixa o texto legível; JSON.stringify(pedido) sem ele devolve tudo numa linha só, que é o formato econômico para viajar pela rede. Repare também que a prop obs com undefined sumiu do texto — a mesma regra da tabela da seção 3.

console: {"nome":"Ana"}

Essa linha saiu de console.log(JSON.stringify({ nome: "Ana", obs: undefined, f: () => 1 })): o objeto tinha três chaves e o JSON ficou com uma. Função também desaparece, porque JSON não tem tipo função. Saber disso economiza meia hora de depuração quando um campo “não chega no servidor”.

7. resposta.json(): o parse que já vem feito

Voltando ao começo: se o fetch devolve texto, por que o código da aula de busca nunca chamou JSON.parse? Porque o objeto que o fetch devolve, a Response, tem um método que faz isso: .json(). Ele lê o corpo da resposta e devolve o valor já traduzido — com uma diferença importante: como a leitura do corpo leva tempo, .json() devolve uma Promise.

useEffect(() => {
  async function carregar() {
    const resposta = await fetch("https://loja.test/api/paes");
    const dados = await resposta.json();
    setPaes(dados);
  }
  carregar();
}, []);

Os dois await são obrigatórios e cada um resolve um problema diferente. O primeiro espera a resposta chegar. O segundo espera o corpo ser lido e traduzido. Sem o segundo, dados é uma Promise: dados.map não existe, e a tela fica vazia com o painel reclamando que o componente não desenhou nada. É o tropeço número um de quem está começando com rede.

Um jeito de não esquecer: conte os await como conta os tempos da frase. “Vou buscar a resposta” (primeiro await) e “vou ler o corpo dela” (segundo await). São duas esperas porque são duas coisas diferentes acontecendo em momentos diferentes — o servidor primeiro responde o cabeçalho, depois manda o corpo. Em respostas pequenas quase sempre chegam juntos, e é justamente por isso que o erro de esquecer o segundo passa despercebido em teste rápido e aparece em produção.

Existe também resposta.text(), para quando o corpo não é JSON — um recibo em texto puro, um CSV, uma página HTML de erro. Nesse caso você recebe a string e faz o que quiser. Se o servidor responde HTML em vez de JSON (acontece quando a URL está errada e o servidor devolve a página de “não encontrado”), .json() falha com erro de sintaxe — e a mensagem parece um problema do seu código, quando o problema é a URL.

8. Os tropeços com JSON

O tropeço mais comum é a vírgula sobrando. Ela é permitida em objeto JavaScript desde sempre e é erro em JSON. A mensagem do navegador aponta a posição exata:

Expected double-quoted property name in JSON at position 23 (line 1 column 24)

Traduzindo: “esperava um nome de propriedade entre aspas duplas na posição 23”. Se você contar 23 caracteres no texto, vai cair justamente no } que veio depois da vírgula. A mensagem é feia, mas é precisa — e sempre aponta o caractere onde o parser desistiu, não o começo do JSON. O segundo tropeço é o par de aspas simples, que dá uma mensagem parecida:

Expected property name or '}' in JSON at position 1 (line 1 column 2)

A posição 1 é o começo do objeto: o ' depois da chave. Trocar por aspas duplas resolve. O terceiro tropeço não dá erro nenhum: é chamar JSON.parse num valor que já é objeto. O parser espera texto, recebe objeto, e reclama de um token inesperado — o famoso Unexpected token o. Se a resposta já veio com .json(), não há o que parsear de novo.

Há ainda um quarto tropeço, mais sutil: confiar no JSON para carregar o que ele não carrega. Datas viram texto, undefined desaparece, número grande perde precisão em casos extremos e Map ou Set viram {}. Na dúvida, imprima o texto cru com console.log(texto) antes de parsear: ver o que chegou é metade do conserto.

9. Cenários do dia a dia

Cenário 1: o preço que aparecia como texto

A Ana recebeu {"preco": "1.20"} — note as aspas no número — e a conta de três pães saiu como 1.202.202.20: string somada com string concatena. O conserto foi no servidor, que passou a mandar número; no componente, uma defesa simples é Number(pao.preco) antes de calcular. JSON não garante tipo: quem envia decide se o número vai com aspas ou sem.

Cenário 2: o pedido que chegou pela metade

Um campo opcional do pedido vinha undefined e o servidor recebia o JSON sem ele, gravava nulo e a nota saía sem o endereço de entrega. Depois de entender que undefined some no stringify, ela passou a mandar null explícito para “vazio de propósito”, e o servidor começou a distinguir “não enviado” de “enviado vazio”.

Cenário 3: o JSON guardado no navegador

A lista de encomendas fica também no localStorage, que só aceita texto. Por isso o JSON.stringify aparece de novo lá, na aula de localStorage: gravar é objeto para texto, ler é texto para objeto. Mesmo par de funções, mesmo cuidado com aspas e com datas.

Exercício: o texto que precisa virar objeto

A resposta da API está guardada numa constante de texto, e o componente precisa mostrar o nome do primeiro pão. Complete a chamada que transforma o texto em objeto:

const resposta = '{"paes": [{"nome": "brioche"}]}'; function App() { const dados = JSON.(resposta); return <p>Primeiro pão: {dados.paes[0].nome}</p>; }

Dica: o caminho de ida (objeto para texto) tem o nome que lembra “string”, e o de volta tem o nome que lembra “parsear”. Aqui o texto já existe e você quer o objeto.

11. Resumo

JSON é texto com formato combinado, e é assim que dados viajam entre programas. Ele aceita texto, número, booleano, null, objeto e array — nada de função, comentário, aspas simples ou vírgula sobrando. JSON.parse transforma texto em objeto; JSON.stringify faz o contrário e é o que se envia num POST.

Resposta de API chega como texto, e o .json() da Response faz o parse por você, devolvendo uma Promise — daí o await. Aninhamento é só a forma do dado: ponto para descer, map para percorrer. E quando o parse falha, a mensagem aponta a posição exata do caractere problemático: leia a posição, não o começo da mensagem.

Para lembrar

  • JSON é string; objeto é objeto. dados.nome só funciona no segundo.
  • Chave e texto sempre com aspas duplas; sem vírgula sobrando; sem comentário.
  • JSON.parse(texto) devolve objeto; JSON.stringify(objeto) devolve texto.
  • stringify(objeto, null, 2) deixa o JSON indentado e legível.
  • undefined e função somem no stringify; em array viram null.
  • resposta.json() já parseia: precisa de await.
  • Erro de parse aponta posição e coluna: é lá que está o caractere errado.
  • Número com aspas é texto: "1.20" concatena em vez de somar.
