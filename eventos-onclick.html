Eventos e onClick

O botão da Ana existe, o texto muda quando o estado muda, e mesmo assim o clique não faz nada. Falta o fio que liga o navegador ao componente: o evento. Nesta aula ela entende o que o onClick espera receber, por que os parênteses são a pegadinha número um do React, como passar um argumento para o manipulador e o que vem dentro do objeto do evento.

Você vai aprender
  • O que é um evento e quem o dispara.
  • Por que onClick={somar} funciona e onClick={somar()} não.
  • Como passar um argumento para o manipulador dentro de uma lista.
  • O que é o objeto do evento: type, target, preventDefault.
  • Quais eventos existem além do clique.
  • Por que um div clicável não substitui um button.

1. A cena: o botão que não faz nada

A placa do site da Ana já vira: o estado aberto está lá, o texto muda quando ele muda. O que falta é o clique chegar até a função. Ela escreveu o botão, escreveu a função, e o botão continua inerte — como uma campainha instalada mas não ligada no fio.

Ligar esse fio é o assunto desta aula. No React, a ligação é um atributo que começa com on: onClick, onChange, onSubmit. Você escolhe o evento pelo nome do atributo e entrega uma função. O React se encarrega de conversar com o navegador, ouvir o evento e chamar a sua função na hora certa.

Parece simples, e é. A confusão toda mora em uma pergunta de sintaxe: o que exatamente vai entre as chaves? Uma função ou o resultado de uma chamada? A diferença são dois parênteses, e ela muda o comportamento do componente inteiro.

2. O que é um evento

Um evento é um aviso do navegador de que algo aconteceu: o leitor clicou, digitou, enviou um formulário, apertou uma tecla, passou o mouse, saiu do campo. Cada tipo de acontecimento tem um nome, e o React usa versões com on na frente para dizer "escute este aqui".

Atributo no JSXDispara quandoOnde costuma aparecer
onClicko elemento é clicadobotões, links, cartões
onChangeo valor de um campo mudainputs, selects, checkboxes
onSubmitum formulário é enviadoformulários
onKeyDownuma tecla é pressionadacampos de busca, atalhos
onFocus / onBluro campo recebe ou perde o focovalidação, dicas
onMouseEntero mouse entra no elementomenus, cartões

O onClick é o mais usado e o melhor para aprender, porque o efeito é imediato e visível. Mas tudo o que vale para ele vale para os outros: o atributo recebe uma função, o React chama essa função quando o evento acontece, e o que a função fizer com o estado é o que muda a tela.

Por baixo, o React não coloca um ouvinte em cada botão. Ele escuta os eventos lá na raiz da aplicação e, quando um deles acontece, descobre qual elemento da sua árvore foi o alvo e chama o manipulador correspondente. O objeto que chega ao seu código é um embrulho do evento do navegador, com as mesmas informações que você usaria no JavaScript puro. Você não precisa saber disso para usar onClick, mas vale saber que o comportamento é o mesmo de sempre: clicou, disparou, subiu pela árvore até alguém escutar.

evento
O aviso de que algo aconteceu no navegador: um clique, uma tecla, um envio de formulário.
manipulador
A função que você escreve para reagir ao evento: somar, fechar, registrar.
ouvinte
O React, no meio do caminho: ele registra o ouvinte no elemento e chama o seu manipulador.
objeto do evento
O que o React passa para o manipulador: type, target, preventDefault e mais.
callback
Uma função entregue para ser chamada depois, por outra pessoa. O manipulador é um callback.

3. onClick recebe uma função

Esta é a frase que resolve metade dos bugs de iniciante: onClick recebe uma função, não o resultado dela. Você entrega a função ao React e ele a chama quando o clique acontecer. Se você entregar o resultado, o React não tem o que chamar depois — e a função já rodou, cedo demais, durante o desenho.

Os dois botões estão desligados: nenhum tem onClick. Ligue o + ao manipulador somar e o botão "Zerar" ao manipulador zerar, entregando a função (sem parênteses).

function App() {
  const [total, setTotal] = useState(0);

  function somar() {
    setTotal((atual) => atual + 1);
  }

  function zerar() {
    setTotal(0);
  }

  return (
    <div>
      <h1>Padaria da Ana</h1>
      <p>Total: {total}</p>
      <button className="mais">+</button>
      <button className="zerar">Zerar</button>
    </div>
  );
}
<div>
  <h1>Padaria da Ana</h1>
  <p>Total: 0</p>
  <button class="mais">+</button>
  <button class="zerar">Zerar</button>
</div>

    </div>
  );
}

Sem onClick, o botão é um enfeite: existe, recebe clique, não avisa ninguém. Com onClick={somar}, você entrega a referência da função — o nome dela, sem chamar. O React guarda essa referência e a executa no clique. Repare que a função somar não recebe parâmetro nenhum: ela só precisa do estado, que já está no escopo.

Também funciona declarar a função na hora, dentro do atributo:

<button onClick={() => setAberto(!aberto)}>Virar a placa</button>

Aqui a seta cria uma função nova a cada desenho, e é essa função que o React chama no clique. A conta !aberto só acontece quando alguém clica — não no desenho. É a forma mais comum quando a função tem uma linha e não é usada em outro lugar.

4. O erro dos parênteses

O tropeço clássico é escrever onClick={somar()}. Com os parênteses, você não está entregando a função: está chamando ela naquele instante, durante o desenho, e entregando o que ela devolver. Como somar não devolve nada, o atributo recebe undefined, e o React não tem o que chamar no clique.

function somar() {
  setTotal(total + 1);
}

<button onClick={somar()}>+</button>

No caso acima o estrago é maior: somar() roda durante o desenho e chama o setter. O React desenha de novo, roda o componente, chama somar() outra vez, e assim por diante. O componente não termina de desenhar, e a tela fica vazia. É por isso que esse erro assusta: não aparece mensagem nenhuma na página, só um buraco onde o componente deveria estar.

Dá para flagrar o erro com uma linha de log. O código abaixo tem um manipulador que só escreve no console, e mesmo assim a linha aparece antes de qualquer clique:

function avisar() {
  console.log("avisar rodou no desenho");
}

<button onClick={avisar()}>Avisar</button>
avisar rodou no desenho

Se você vir uma linha dessas ao abrir a página, sem ter clicado em nada, o culpado está encontrado: algum onClick do projeto está com parênteses. O log não é um efeito colateral inofensivo — é a prova de que a função rodou na hora errada.

Há um caso em que os parênteses são legítimos: quando a função devolve outra função. Isso é usado em bibliotecas e em padrões avançados, e o nome é "currying" — não é o que você quer aqui. Para quem está começando, a regra é simples: dentro do onClick, ou vai o nome da função sem parênteses, ou vai uma seta que a chama.

5. Passar argumentos para o manipulador

Uma função sem parâmetros resolve o botão único. Quando são vários botões e cada um precisa dizer algo diferente para a mesma função — o pão escolhido, o item removido, o passo do formulário —, o caminho é embrulhar a chamada numa seta.

Todos os botões pedem "pão francês", porque o argumento está escrito à mão. Faça cada botão pedir o seu próprio pão, usando o valor de p dentro de uma seta.

function App() {
  const [pedido, setPedido] = useState("nenhum");
  const paes = ["pão francês", "broa", "croissant"];

  function pedir(nome) {
    setPedido(nome);
  }

  return (
    <div>
      <h1>Padaria da Ana</h1>
      <p>Pedido: {pedido}</p>
      <ul>
        {paes.map((p) => (
          <li key={p}>
            <button onClick={() => pedir("pão francês")}>{p}</button>
          </li>
        ))}
      </ul>
    </div>
  );
}

      <ul>

      </ul>
    </div>

}

A seta existe para adiar a chamada. Sem ela, pedir(p) rodaria no desenho, uma vez para cada pão, e o último a rodar venceria — além de chamar o setter durante o desenho, o que trava o componente. Com ela, cada botão guarda uma função que só chama pedir quando aquele botão for clicado, com o p daquele item.

Repare que o key={p} continua ali: são assuntos diferentes. A key é a identidade do item para o React; a seta é o que permite cada botão carregar o seu argumento. Um não substitui o outro, e os dois aparecem juntos em quase toda lista de botões.

6. O objeto do evento

Quando o React chama o seu manipulador, ele passa um argumento: o objeto do evento. É um objeto cheio de informação sobre o que aconteceu, e três propriedades resolvem quase tudo no dia a dia.

PropriedadeO que temPara que serve
evento.typeo nome do evento: "click", "change"descobrir o que aconteceu quando o mesmo manipulador serve a vários eventos
evento.targeto elemento que disparousaber qual botão foi clicado, ler o valor de um campo
evento.preventDefault()a função que cancela o comportamento padrãoevitar que um formulário recarregue a página, que um link navegue

Os botões não têm manipulador. Ligue os dois ao mesmo registrar, que descobre qual foi clicado pelo texto do alvo: depois de clicar em "Abrir", o painel precisa mostrar Último clique: Abrir.

function App() {
  const [ultimo, setUltimo] = useState("nenhum");

  function registrar(evento) {
    setUltimo(evento.target.textContent);
    console.log("tipo: " + evento.type + ", alvo: " + evento.target.textContent);
  }

  return (
    <div>
      <h1>Padaria da Ana</h1>
      <p>Último clique: {ultimo}</p>
      <button>Fechar</button>
      <button>Abrir</button>
    </div>
  );
}

    </div>

}

Um manipulador, dois botões, e nenhum argumento escrito à mão: quem diz qual foi o botão é o próprio evento. No console do navegador, depois do clique em "Abrir", aparece a linha que o código escreveu:

tipo: click, alvo: Abrir

evento.type confirma que foi um clique; evento.target é o elemento que recebeu o clique, e textContent é o texto dele. O mesmo manipulador poderia ler evento.target.value se fosse um campo de texto, ou evento.target.id se você preferisse identificar cada botão por id.

O preventDefault merece um exemplo próprio, porque é o que salva os formulários. Quando um formulário é enviado, o navegador recarrega a página por padrão — e no React isso apaga todo o estado. Chamar evento.preventDefault() no início do manipulador cancela esse comportamento e deixa você cuidar do envio:

function Formulario() {
  function enviar(evento) {
    evento.preventDefault();
    console.log("enviado sem recarregar a página");
  }

  return (
    <form onSubmit={enviar}>
      <input name="cliente" />
      <button type="submit">Enviar</button>
    </form>
  );
}

A mesma ideia vale para links: um <a href="#"> com onClick precisa de preventDefault se você não quiser que a página pule para o topo. Quando o assunto é formulário de verdade, com campos controlados e validação, há aulas próprias no Nível 2 — aqui basta reconhecer a chamada quando ela aparecer.

7. Um botão de verdade, não uma div

É comum ver <div onClick={...}> por aí. Funciona no mouse e falha em todo o resto: não recebe foco pelo Tab, não é acionada pelo Enter nem pelo espaço, não é anunciada como botão pelo leitor de tela. O elemento button já vem com tudo isso pronto, e o React só acrescenta o onClick.

<button type="button" onClick={virar}>Virar a placa</button>

O type="button" evita um acidente clássico: dentro de um formulário, um botão sem tipo é tratado como submit e envia o formulário quando clicado. Se a intenção era só virar a placa, o formulário é enviado sem querer e a página recarrega. Escrever o tipo é barato e evita uma tarde de depuração.

Dois atributos que combinam com botão: disabled, que desliga o clique e o foco, e aria-pressed, que diz ao leitor de tela se o botão está ligado ou desligado — útil para botões de alternar, como o da placa. Nenhum dos dois substitui a lógica: o disabled precisa refletir o estado, e o aria-pressed também.

<button
  type="button"
  onClick={virar}
  aria-pressed={aberto}
  disabled={carregando}
>
  {aberto ? "Fechar a loja" : "Abrir a loja"}
</button>

Se por algum motivo você precisar de um elemento que não é botão, o mínimo é dar a ele role="button", tabIndex={0} e um manipulador de teclado para o Enter. É mais código do que usar o botão. Na prática, use o botão.

8. Nomes de manipulador que ajudam

A convenção da comunidade é começar o nome com handle quando ele é passado como atributo e descrever a ação: handleClick, handleSubmit, handleChange. Em português, nomes como virar, somar, enviar e registrar dizem a mesma coisa e são mais legíveis para quem está começando. O importante é que o nome diga o que acontece, não o que foi clicado.

function App() {
  const [aberto, setAberto] = useState(true);

  function virar() {
    setAberto((atual) => !atual);
  }

  return (
    <button onClick={virar}>
      {aberto ? "Fechar a loja" : "Abrir a loja"}
    </button>
  );
}

Nomes assim também ajudam a separar responsabilidades. virar não sabe nada sobre botões; ela só troca um booleano. Quem decide que ela será chamada no clique é o onClick. No dia em que o mesmo virar precisar rodar depois de um envio de formulário, ele continua servindo — porque não está preso ao clique.

Repare que o texto do botão muda com o estado, e a função é a mesma. Um botão que diz o que vai fazer — "Fechar a loja" quando está aberto — é mais claro do que um botão fixo "Alternar", e o leitor de tela agradece. O onClick não sabe nem se importa com o texto; ele só chama a função.

9. Cenários do dia a dia

Cenário 1: o clique que roda duas vezes

Ela escreveu onClick={() => somar()} dentro de um map e o contador subia dois por clique. O culpado era o botão dentro de outro elemento com onClick: o clique subia pela árvore e disparava os dois. O conserto foi evento.stopPropagation() no manipulador interno — ou, melhor, repensar a estrutura para não ter dois cliques no mesmo caminho.

Cenário 2: o formulário que recarregava

O botão de enviar recarregava a página e o estado voltava a zero. Faltava evento.preventDefault() no início do manipulador de onSubmit. É um erro que parece do React e é do navegador: formulário enviado recarrega, a menos que alguém cancele o padrão.

Cenário 3: o botão que só funcionava no mouse

O cartão de produto era uma div com onClick. No mouse, abria; no teclado, nada. A troca por button resolveu foco, Enter, espaço e leitura por leitor de tela de uma vez. Quando o elemento é acionável, o elemento certo é o botão.

Os três cenários têm uma coisa em comum: o React estava fazendo exatamente o que foi escrito, e o problema estava no que o navegador faz por padrão ou no elemento escolhido. Antes de culpar o onClick, vale perguntar: quem mais está ouvindo esse clique? O elemento é o certo? O comportamento padrão foi cancelado? Três perguntas resolvem quase tudo.

11. Resumo

Evento é o aviso de que algo aconteceu; manipulador é a função que reage. No React, a ligação é um atributo com on na frente, e ele recebe sempre uma função. onClick={somar} entrega a referência; onClick={() => somar()} entrega uma função que chama. As duas funcionam. onClick={somar()} chama na hora do desenho — e é o erro que deixa o botão inerte ou o componente em branco.

Para passar um argumento, embrulhe a chamada numa seta: onClick={() => pedir(p)}. A seta adia a chamada até o clique e leva junto o valor daquele item. O React entrega ao manipulador o objeto do evento, com type, target e preventDefault — o suficiente para saber o que aconteceu e para impedir que o navegador faça o que faria por conta própria, como recarregar o formulário.

E o conselho que vale para todo o resto do guia: use button para o que é clicável. O elemento certo já traz teclado e leitor de tela; o React só acrescenta o comportamento. Com estado, condição, lista e evento, você já tem as quatro peças de qualquer tela interativa — e é hora de juntá-las numa entrada de texto controlada, que é o assunto da próxima aula.

Para lembrar

  • Evento é aviso; manipulador é a função que reage a ele.
  • onClick recebe função: onClick={somar}, não onClick={somar()}.
  • Parênteses chamam na hora do desenho: o clique fica sem manipulador.
  • Seta para passar argumento: onClick={() => pedir(p)}.
  • Um manipulador pode servir a vários botões: use evento.target.
  • evento.preventDefault() cancela o padrão do navegador (formulário, link).
  • onChange, onSubmit, onKeyDown seguem a mesma regra.
  • Use button, não div clicável: teclado e leitor de tela agradecem.
  • type="button" evita envio acidental de formulário.
  • Nome do manipulador diz o que acontece: virar, enviar, somar.
