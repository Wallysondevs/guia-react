O Contador

A Ana quer contar quantos pães cada cliente leva, sem papel e sem calculadora. Um número na tela, um botão que soma, um que subtrai — e a tela acompanhando. O contador é o menor programa React que faz alguma coisa de verdade, e é por isso que ele ensina tanto: estado, manipulador, limite e reaproveitamento cabem em vinte linhas.

Você vai aprender
  • As três partes de um contador: o valor, o botão que soma e o botão que subtrai.
  • Como impedir que o contador fique negativo.
  • Como zerar o valor sem olhar para o que estava antes.
  • Por que dois contadores na mesma tela precisam de estados separados.
  • Como escrever botões que o leitor de tela entende.
  • O que um contador ensina sobre qualquer pedaço de estado que você fizer depois.

1. A cena: o papel de pão e o número na tela

Na vitrine, a Ana anota cada pão num papelzinho e, no fim do dia, soma. Funciona até o dia em que o papel molha. Ela quer o mesmo gesto no site: um número grande, um botão de somar e um de subtrair. Cada clique muda o número, e o número muda a tela — nada de recarregar página.

O contador é o exercício clássico de React porque ele tem tudo o que um componente interativo tem, em escala mínima: um estado que guarda um número, dois manipuladores que mudam esse número e um pedaço de JSX que mostra o resultado. Quem entende um contador entende o esqueleto de um carrinho de compras, de um formulário com passos e de um painel de pedidos.

Contador aparece em mais lugares do que parece: quantidade no carrinho, número de convidados, passo do formulário, estoque que entra e sai, nota de avaliação. Todos têm a mesma forma, e todos compartilham os mesmos riscos: ficar negativo, esquecer de redesenhar, guardar duas cópias do número. Por isso vale construir um com calma, entendendo cada linha, em vez de copiar um pronto.

Nesta aula o contador é construído em pedaços. Primeiro o valor e o botão de somar, que já estão prontos no exemplo. Depois o limite, para o pão não ficar negativo. Depois o botão de zerar. No fim, o mesmo contador aparece duas vezes na tela — um para pães, outro para cafés — sem um atrapalhar o outro.

2. O desenho do contador

Um contador tem quatro peças. O estado guarda a quantidade. O texto mostra o estado. O botão de somar chama o setter com o valor mais um, e o botão de subtrair chama o setter com o valor menos um. Repare que não existe uma quarta variável guardando "o total": o texto lê o estado direto, e é por isso que ele nunca fica desatualizado.

function Contador() {
  const [paes, setPaes] = useState(0);

  return (
    <div>
      <p>Pães: {paes}</p>
      <button onClick={() => setPaes(paes + 1)}>+</button>
      <button onClick={() => setPaes(paes - 1)}>−</button>
    </div>
  );
}

O + e o − nos botões são só o texto visível. O que importa é o onClick: uma função que será chamada quando o clique acontecer. A forma () => setPaes(paes + 1) é uma função de uma linha; a aula de eventos vai destrinchar todas as maneiras de escrever isso, incluindo os casos em que a função é declarada antes com um nome.

Um detalhe que costuma passar batido: o texto é {paes}, e não uma variável total que você atualiza junto. Guardar o texto à parte seria criar duas fontes para a mesma verdade — e a segunda sempre atrasa. O estado é a fonte; a tela é a leitura dele.

3. O botão que soma

O botão de somar é o mais simples dos dois: pega o valor atual, soma um e entrega ao setter. Se o valor for 3, o setter recebe 4, o React desenha de novo e o texto passa a mostrar 4. Cada clique é um ciclo completo — não existe "somar na tela"; existe pedir um novo desenho com outro número.

Vale reparar que a conta é feita com o paes do desenho atual. Isso dá o resultado certo para um clique por vez. Se dois cliques acontecerem antes de o React desenhar, os dois usam o mesmo valor antigo e o resultado é um a menos do que você espera. Esse caso tem nome, atualização em lote, e uma aula própria mais adiante — por enquanto, um clique de cada vez funciona.

Quem chama a função é o navegador, no momento do clique — não o seu código. Isso é o que onClick={somar} significa: "guarde esta função e execute quando alguém clicar". Você não está chamando somar ali; está entregando ela. A diferença entre entregar e chamar é o assunto da aula de eventos, e é uma das confusões mais comuns de quem começa: com parênteses, a função roda na hora do desenho, e o clique fica sem nada para fazer.

Também vale saber por que não usamos paes++. O ++ muda a variável e devolve o valor antigo: o setter receberia o número de antes e a tela não mudaria. Em React, toda atualização é um valor novo entregue ao setter, não uma instrução que mexe na variável. É setPaes(paes + 1), sempre.

4. O limite: não existe pão negativo

O botão de subtrair funciona, mas funciona demais. Se a Ana clicar duas vezes com o valor em 1, a tela mostra -1, e não existe cliente devolvendo pão que ela não vendeu. Um contador de coisas físicas precisa de um piso: em zero, o botão não faz nada.

O botão de menos não tem freio: dois cliques levam o contador a -1. Faça o manipulador parar no zero, para o painel mostrar Pães: 0 depois dos dois cliques.

function App() {
  const [paes, setPaes] = useState(1);

  console.log("pães na tela: " + paes);

  function somar() {
    setPaes(paes + 1);
  }

  function subtrair() {
    setPaes(paes - 1);
  }

  return (
    <div>
      <h1>Padaria da Ana</h1>
      <p>Pães: {paes}</p>
      <button className="mais" onClick={somar}>+</button>
      <button className="menos" onClick={subtrair}>−</button>
    </div>
  );
}

      <p>Pães: {paes}</p>

      <button className="menos" onClick={subtrair}>−</button>
    </div>
  );
}

A solução tem duas partes e uma ideia: o limite mora no manipulador, não no JSX. Dá para conferir e simplesmente não chamar o setter quando o valor já é zero. Também dá para escrever setPaes(Math.max(0, paes - 1)), que devolve o maior entre zero e o resultado — mesma decisão, em uma linha. Escolha a forma que você lê melhor; o importante é que a regra esteja no código, não na cabeça de quem clica.

O console.log que ficou no corpo do componente ajuda a acompanhar o efeito do limite: ele está fora dos manipuladores, então quem escreve é o desenho, não o clique. É a diferença entre "o botão foi clicado" e "o componente foi desenhado de novo" — e, nesta altura, você já sabe que a segunda é a que muda a tela.

Cada desenho do componente escreve uma linha, e a sequência no console do navegador conta a história do limite:

pães na tela: 1
pães na tela: 0

A primeira linha é o desenho inicial, com 1 — é a que aparece também no painel da caixa, logo depois do HTML. A segunda é o desenho depois do primeiro clique, já com 0, e só aparece no console do navegador, porque acontece depois do desenho. O segundo clique não escreveu nada, porque o manipulador não chamou o setter: sem mudança de estado, não há desenho, não há log. Ver a ausência da linha é tão informativo quanto ver a linha.

5. O botão de zerar

No fim de cada cliente, a Ana zera a conta. Zerar é o exemplo mais claro de atualização que não depende do valor anterior: o novo valor é zero, sempre. Por isso o setter pode receber o número direto, sem conta nenhuma: setPaes(0).

Falta o botão de zerar a conta. Acrescente um <button className="zerar">Zerar</button> que chame o setter com zero e rode: dois cliques no mais, depois um no zerar, e a tela precisa voltar a "Pães: 0".

function App() {
  const [paes, setPaes] = useState(0);

  return (
    <div>
      <h1>Padaria da Ana</h1>
      <p>Pães: {paes}</p>
      <button className="mais" onClick={() => setPaes(paes + 1)}>+</button>
      <button className="menos" onClick={() => setPaes(paes - 1)}>−</button>
    </div>
  );
}

Repare que o botão de zerar poderia chamar setPaes(paes - paes), e funcionaria. Mas escrever a conta para chegar a zero é contar uma história mais complicada do que a verdade: o novo valor é zero. Código que diz o que quer dizer é mais fácil de manter — e, quando alguém ler daqui a três meses, não vai precisar fazer a conta.

Com os três botões, o contador está completo. O que falta é a pergunta que todo componente reutilizável enfrenta: e se a padaria vender café também?

6. O mesmo contador em dois lugares

A Ana quer dois contadores na tela: um de pães e um de cafés. O caminho natural é transformar o contador num componente com uma prop de nome e usar duas vezes. O tropeço é onde guardar o número: se o estado ficar no App e for passado para os dois, os dois mostram o mesmo valor — clicar num mexe no outro.

Os dois contadores compartilham o mesmo estado: clique no + dos pães e os cafés sobem junto. Mova o useState para dentro do componente Contador, para cada um ter a sua própria memória.

function Contador({ id, nome, qtd, somar }) {
  console.log(nome + " = " + qtd);

  return (
    <section id={id}>
      <p>{nome + ": " + qtd}</p>
      <button className="mais" onClick={somar}>+</button>
    </section>
  );
}

Três linhas, dois componentes, um desenho novo. A primeira dupla é do primeiro desenho, quando os dois nasceram com zero. A terceira é do desenho seguinte, e só o contador de pães foi chamado — o de cafés continua com o mesmo nó e o mesmo zero. Quando o React desenha um componente, ele chama a função dele; os irmãos que não mudaram não são recriados.

7. Rótulos que explicam o botão

Os botões do contador mostram + e −, o que é ótimo para quem vê e péssimo para quem ouve. Um leitor de tela anuncia "botão, mais" e "botão, menos" sem dizer de quê. A solução é dar um nome acessível ao botão, que não muda o visual:

function Contador() {
  const [paes, setPaes] = useState(0);

  return (
    <div>
      <p aria-live="polite">Pães: {paes}</p>
      <button aria-label="Somar um pão" onClick={() => setPaes(paes + 1)}>+</button>
      <button aria-label="Subtrair um pão" onClick={() => setPaes(paes - 1)}>−</button>
      <button onClick={() => setPaes(0)}>Zerar</button>
    </div>
  );
}

aria-label substitui o texto do botão para quem usa leitor de tela — o + continua na tela, mas o nome falado é "Somar um pão". E aria-live="polite" no parágrafo faz o leitor anunciar o número novo quando ele muda, sem interromper o que a pessoa estava ouvindo. São dois atributos, nenhum JavaScript, e a página fica utilizável para muito mais gente.

O terceiro botão não precisa de aria-label: "Zerar" já é um nome bom. A regra é simples: se o texto visível não diz o que o botão faz, dê um nome com aria-label; se diz, deixe como está. Botão com nome claro também ajuda quem usa o site pelo teclado, porque o foco chega nele e o navegador mostra o nome.

8. Três decisões que valem para qualquer contador

O contador é pequeno, mas as decisões que ele exige aparecem em todo estado que você fizer daqui para frente. A primeira: uma fonte da verdade. O número fica no estado, e o texto lê o estado. Nada de guardar o número em dois lugares — a cópia sempre atrasa. A segunda: a regra no manipulador. O limite de zero, a validação, o "não pode" moram na função que muda o estado, não no CSS nem no bom senso de quem clica. A terceira: o estado o mais perto possível de quem usa. Se só o contador precisa do número, o estado é dele; se a nota precisa, sobe.

Há ainda uma decisão de tipo que vale registrar. O contador guarda número, e número em React não formata sozinho: {paes} mostra 3. Quando precisar de "3 pães" no singular ou plural, calcule na hora — {paes === 1 ? "1 pão" : paes + " pães"} — em vez de guardar o texto no estado. Estado é dado; texto é leitura.

Se você guardar "3" (texto) por engano, o botão de somar vai concatenar e virar "31". Por isso useState(0) com zero de verdade, e não useState("0"). Quando o valor vem de um campo de formulário — que sempre entrega texto —, converta antes de guardar: Number(valor) ou parseInt(valor, 10).

function Quantidade({ paes }) {
  const rotulo = paes === 1 ? "pão" : "pães";
  return <p>{paes} {rotulo}</p>;
}

Esse componente é burro de propósito: recebe o número e devolve o texto certo. Se amanhã a padaria vender "broa" e "broas", você acrescenta uma prop e o resto continua igual. Separar o dado da apresentação é o que permite reaproveitar — e é o mesmo motivo pelo qual o contador de pães e o de cafés compartilham o componente.

9. Cenários do dia a dia

Cenário 1: o contador que pula de dois em dois

A Ana clicou rápido e o número subiu dois de uma vez. O culpado era paes++ no manipulador: ele altera a variável e devolve o valor antigo, então o setter recebia o mesmo número. Trocar por setPaes(paes + 1) resolveu. Em React, atualizar estado é entregar o valor novo, não modificar o que já existe.

Cenário 2: o botão de menos que não faz nada

Depois de colocar o limite, o botão de menos parecia morto quando o valor era zero — e era mesmo: o manipulador confere e não chama o setter. Isso é o esperado, mas é bom avisar quem usa: desabilitar o botão com disabled={paes === 0} deixa a regra visível na tela, e não só no clique. Aí o leitor entende antes de tentar.

Cenário 3: o total que não batia

Ela mostrava o total da venda somando os dois contadores no papel, e um dia a conta não fechou. O motivo: os dois contadores tinham estados independentes, e o total era digitado à mão em outro lugar. Enquanto o total for um número escrito em outro canto, ele vai divergir. Quando isso importar, o caminho é elevar o estado e calcular o total a partir dele — nunca manter duas cópias.

11. Resumo

Um contador é um estado numérico, dois botões que chamam o setter com o valor novo e um parágrafo que lê o estado. O limite mora no manipulador — if (paes > 0) ou Math.max(0, paes - 1) — e o zerar entrega o zero direto, sem conta. O texto nunca guarda cópia do número: ele lê a fonte.

Quando o mesmo contador aparece duas vezes, o estado vai para dentro do componente. Cada instância tem a sua memória, e um clique em um não mexe no outro. Se um dia o total dos dois precisar aparecer junto, o estado sobe para o pai — mas sobe uma vez, para uma fonte só.

O contador também ensina o que nenhum texto ensina: que o React redesenha o componente inteiro a cada mudança de estado, que a conta é feita com o valor do desenho atual e que atualizar estado é substituir, não modificar. Na próxima aula, a pergunta que ficou no ar: e quando o valor novo depende de duas mudanças na mesma função? Aí a forma de função do setter entra em cena.

Para lembrar

  • Contador = estado + texto que lê o estado + botões que chamam o setter.
  • Some com setPaes(paes + 1); paes++ entrega o valor antigo.
  • Limite e validação ficam no manipulador, não no CSS.
  • Zerar é setPaes(0): valor direto, sem conta.
  • Cada componente tem o seu estado: dois contadores, duas memórias.
  • Estado no pai compartilha o número entre os filhos; estado no filho isola.
  • O estado mora o mais perto possível de quem usa; sobe só quando precisa.
  • Botão só com símbolo pede aria-label.
  • aria-live="polite" anuncia a mudança para o leitor de tela.
  • Número é dado; o texto "3 pães" é calculado na hora.
