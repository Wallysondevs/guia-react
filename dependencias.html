As Dependências

A Ana acertou o efeito: ele roda, calcula o total da encomenda e mostra na tela. Só que agora ela aumentou o preço do pão e o total continuou o mesmo. A tela está desatualizada, e o culpado é o segundo argumento do useEffect — o array que ela copiou de um exemplo sem entender. Nesta aula ela descobre que esse array não é enfeite: é a lista de tudo o que o efeito lê, e é ele que decide quando o efeito roda de novo.

Você vai aprender
  • O que o array de dependências significa, em palavras simples.
  • O comportamento de cada formato: sem array, [] e [valor].
  • Por que o valor "velho" aparece na tela quando falta uma dependência.
  • Que o array lista tudo o que o efeito lê: estado, props e variáveis de fora.
  • Por que objeto, array e função recriados a cada render bagunçam a conta.
  • Como reconhecer um laço infinito pelo erro do React.
  • O que o aviso exhaustive-deps está tentando dizer.

1. A cena: o total que não acompanha o preço

A padaria vende encomendas de três pães. O componente tem dois estados: o preço de cada pão e o total da encomenda. O total é calculado por um efeito, porque na cabeça da Ana aquilo era "uma conta que acontece depois". Ela copiou o [] de um exemplo da internet, rodou, viu o total certinho e foi tomar café.

No dia seguinte o preço do pão subiu. Ela mudou o preço, olhou a tela e o total continuou o mesmo. Conferiu a conta no papel: estava certa. O problema não era a multiplicação — era o array. Com [], o efeito roda uma vez, na montagem do componente, e nunca mais. Ele calculou o total com o preço que existia naquele instante e nunca ficou sabendo que o preço mudou.

Esse é o mal-entendido central desta aula: o array de dependências não é uma formalidade para o React parar de reclamar. Ele é a resposta para a pergunta "quando este efeito precisa rodar de novo?". Errar a resposta dá dois sintomas opostos: efeito que roda de menos (tela com valor velho) e efeito que roda demais (laço, pedidos repetidos, contas dobradas). Os dois nascem do mesmo lugar.

2. O que o array quer dizer

O segundo argumento do useEffect é um array de valores que o React observa. Antes de rodar o efeito, o React compara os valores do array com os do render anterior, um por um, usando comparação de igualdade (===). Se todos forem iguais aos de antes, ele pula o efeito. Se algum for diferente, ele roda o efeito de novo, depois de desenhar a tela.

A leitura correta do array é: "estes são os valores de fora que este efeito usa". O React não tem como descobrir isso sozinho, porque o JavaScript não deixa ninguém olhar dentro de uma função para ver quais variáveis ela usa. Quem informa é você. É por isso que o array é uma responsabilidade do programador — e por isso que esquecer um item é o erro mais comum de todos.

dependência
Cada valor dentro do array. Se o efeito lê preco, então preco é uma dependência dele.
array de dependências
O segundo argumento do useEffect: [], [preco], [preco, quantidade].
valor velho
O que acontece quando o efeito não roda e a tela continua mostrando o resultado de uma conta antiga.
laço infinito
Efeito que muda estado, que pede render, que roda o efeito de novo — até o React parar com "Maximum update depth exceeded".
identidade
O "mesmo" objeto. Um objeto novo, ainda que com o mesmo conteúdo, tem outra identidade e conta como mudança para o React.

Antes dos formatos, uma imagem que a Ana usou para entender: o array é a lista de assuntos sobre os quais o efeito quer ser avisado. [] é "não me avise de nada, faça uma vez e pronto". [preco] é "me avise quando o preço mudar". E não ter array é "me avise de tudo, sempre" — o que raramente é o que se quer.

FormatoQuantas vezes rodaFrase que resume
useEffect(f)uma vez por render"me chame sempre, eu decido o que fazer"
useEffect(f, [])uma vez, na montagem"não dependo de nada que mude"
useEffect(f, [a])na montagem e quando a mudar"me avise quando a mudar"
useEffect(f, [a, b])na montagem e quando a ou b mudar"me avise quando qualquer um dos dois mudar"

3. Sem array: depois de todo render

Quando você chama useEffect(funcao) sem o segundo argumento, o efeito roda depois de todo render — o primeiro e todos os seguintes. Isso é útil para acompanhar mudanças, e perigoso se o efeito mexer no estado, porque cada execução cria um novo render. O exemplo a seguir é o laço clássico; não precisa rodar, ele trava a caixa:

useEffect(() => {
  setTotal(total + 1);   // muda o estado a cada execução
});                      // sem array: roda em todo render

O React percebe depois de algumas dezenas de tentativas e interrompe com uma mensagem que você vai ver cedo ou tarde. Ela não fala de array; fala de profundidade de atualização, o que soa assustador e significa apenas "tem coisa se atualizando em círculo aqui":

Maximum update depth exceeded. This can happen when a component
repeatedly calls setState inside useEffect, but useEffect either
doesn't have a dependency array, or one of the dependencies changes
on every render.

A mensagem lista as duas causas possíveis, e as duas são desta aula. A primeira é o efeito sem array que muda estado. A segunda é uma dependência que muda a cada render — um objeto, um array ou uma função criada dentro do componente, que ganha identidade nova sempre. Voltamos a ela na seção 7.

Existe um uso legítimo para o efeito sem array: acompanhar algo que muda a cada render sem mexer no estado. Um console.log de depuração, por exemplo. Mas, como você já sabe, o console do navegador no modo de desenvolvimento mostra tudo em dobro — e aí a leitura fica confusa. Na prática, o efeito sem array é raro e quase sempre é sinal de que faltou pensar.

4. Com []: uma vez, na montagem

O array vazio diz "este efeito não depende de nada que mude". Ele roda uma vez, quando o componente entra na tela, e não roda mais — nem quando o estado muda, nem quando uma prop muda. É o formato certo para carregar dados uma vez, registrar um aviso de entrada ou preparar algo global. E é o formato errado para qualquer efeito que precise acompanhar um valor.

Na caixa a seguir, o efeito calcula o total com []. Rode o código inicial e clique em Rodar: o total é 6, porque a encomenda é de três pães a 2 reais. Agora clique em Aumentar o preço dentro da prévia: o preço vai para 3 e o total continua 6. A missão é fazer o total acompanhar.

A encomenda é sempre de três pães e o total é calculado por um efeito. Clique em Aumentar o preço e veja que o total não muda. Acrescente preco ao array de dependências para o total acompanhar.

function App() {
  const [preco, setPreco] = useState(2);
  const [total, setTotal] = useState(0);

  useEffect(() => {
    setTotal(preco * 3);
  }, []);

  return (
    <div>
      <p>Preço do pão: {preco} reais</p>
      <p>Total da encomenda: {total} reais</p>
      <button onClick={() => setPreco(preco + 1)}>Aumentar o preço</button>
    </div>
  );
}
<div>
  <p>Preço do pão: 2 reais</p>
  <p>Total da encomenda: 6 reais</p>

</div>

Com [preco], o efeito roda na montagem e roda de novo depois do render em que o preço mudou. O React não "chama o efeito quando você clica": ele desenha a tela com o preço novo e, no fim desse render, compara o array. Como preco era 2 e agora é 3, o efeito roda, calcula 9 e chama setTotal. Um terceiro render acontece com o total novo, e o painel mostra o resultado final.

Repare que o painel da caixa já mostra o estado depois do clique — é o mesmo mecanismo de prova que você viu na aula de estado. E repare também que o efeito não roda de novo só porque total mudou: total não está no array. Se estivesse, e se o efeito também lesse total para calcular, aí sim teríamos um laço.

5. Com valores: quando algum deles muda

Um array pode ter várias dependências, e cada uma delas é um gatilho. O erro comum aqui é lembrar de uma e esquecer a outra — e o sintoma é sempre o mesmo: a tela mostra uma conta que não fecha, feita com um dos valores antigos.

O total depende do preço e da quantidade, mas o array só lista o preço. Clique em Mais um pão e veja o total parado. Acrescente a quantidade ao array.

function App() {
  const [preco, setPreco] = useState(2);
  const [quantidade, setQuantidade] = useState(1);
  const [total, setTotal] = useState(2);

  useEffect(() => {
    setTotal(preco * quantidade);
  }, [preco]);

  return (
    <div>
      <p>Total: {total} reais</p>
      <button id="mais-pao" onClick={() => setQuantidade(quantidade + 1)}>
        Mais um pão
      </button>
    </div>
  );
}

A regra que fecha essa seção é curta: o array lista tudo o que o efeito lê. Não é "tudo o que eu quero que dispare o efeito", é tudo o que aparece dentro da função do efeito e vem de fora dela. Se você lê preco e quantidade, os dois entram. Se lê uma prop chamada bairro, ela entra. Se lê uma constante global que nunca muda, ela pode ficar de fora — o React só precisa das coisas que podem mudar.

Há um caso especial que vale conhecer: mudar o tamanho do array entre um render e outro. Se em um render o array é [] e no seguinte é [preco], o React avisa que não sabe se deve rodar o efeito e não tem como comparar. Na prática, o array precisa ter sempre o mesmo número de itens, na mesma ordem.

6. De onde vêm as dependências: as props também contam

Até agora as dependências vieram do useState. Mas um componente também recebe dados por props, e o efeito que lê uma prop tem a mesma obrigação de listá-la. Este é o caso que mais escapa, porque a prop não foi escrita naquele arquivo: alguém de fora manda, e o efeito calcula com base naquilo.

Na caixa, a padaria cobra uma taxa de entrega que depende do bairro. O bairro chega por prop, o efeito da taxa tem [], e o resultado é a taxa antiga grudada na tela enquanto o bairro muda.

A taxa de entrega é calculada por um efeito que lê a prop bairro, mas o array está vazio. Clique em Mudar de bairro e veja a taxa não acompanhar. Acrescente bairro ao array.

function Entrega({ bairro }) {
  const [taxa, setTaxa] = useState(0);

  useEffect(() => {
    setTaxa(bairro === "Centro" ? 5 : 12);
  }, []);

  return (
    <p>Taxa de entrega: {taxa} reais</p>
  );
}

function App() {
  const [bairro, setBairro] = useState("Centro");

  return (
    <div>
      <p>Bairro: {bairro}</p>
      <Entrega bairro={bairro} />
      <button onClick={() => setBairro("Vila Nova")}>Mudar de bairro</button>
    </div>
  );
}

Duas coisas para levar daqui. A primeira: dependência é valor lido, venha ele de estado ou de prop. A segunda: quando a prop muda, o componente Entrega é chamado de novo pelo pai, com o bairro novo, e o efeito compara bairro com o do render anterior. A comparação é do React, não sua — você só informa o que observar.

Se a confusão é sobre como as props chegam, vale reler a aula de props antes de seguir; o mecanismo do efeito em cima delas é exatamente o mesmo do estado. A diferença é que quem muda a prop é o componente de cima, e quem precisa avisar o efeito é o array do componente de baixo.

7. As armadilhas: objeto novo, função nova, laço infinito

A comparação do React é de identidade, não de conteúdo. Dois objetos com os mesmos campos são objetos diferentes. Isso importa porque, dentro de um componente, um objeto ou um array criado no corpo da função é recriado a cada render. Se ele for para o array de dependências, o React olha os dois e diz "mudou" — e o efeito roda sempre.

function App() {
  const [paes, setPaes] = useState(["francês"]);

  // objeto novo a cada render: nunca é igual ao anterior
  const filtro = { tipo: "pão" };

  useEffect(() => {
    console.log("filtrei por " + filtro.tipo);
  }, [filtro]);   // roda em todo render, mesmo que o conteúdo seja o mesmo
}

O mesmo vale para funções. Uma função declarada dentro do componente é uma função nova a cada render. Se o efeito depende dela, ele roda sempre. A solução para os dois casos é não colocar dentro do array um valor que você mesmo recriou — ou criar o objeto e a função dentro do efeito (o que quase sempre dá certo, porque o efeito já roda quando precisa) — ou, no caso de funções que vêm do pai, envolver a função em useCallback, um assunto do Nível 2.

E aqui está o laço infinito mais chato de achar: um efeito que lê um objeto recriado a cada render e muda um estado na mesma execução. Cada render cria o objeto, o efeito vê "mudou", roda, muda o estado, o que provoca outro render, que cria outro objeto — e o React para com a mesma mensagem de profundidade máxima da seção 3. O erro não está no objeto em si, está em usá-lo como dependência e como gatilho de estado ao mesmo tempo.

Números, textos e booleanos não têm esse problema: 2 é igual a 2, e "Centro" é igual a "Centro". Por isso as dependências mais tranquilas são justamente as mais comuns: preço, quantidade, bairro, termo de busca, se está aberto ou fechado. Quando você se pegar colocando um objeto inteiro no array, pergunte se não dá para listar os campos que o efeito realmente lê.

8. O aviso do ESLint e como ler

O projeto criado pelo Vite vem com o ESLint configurado para o React, e uma das regras dele olha exatamente para o array de dependências. O nome da regra é react-hooks/exhaustive-deps, e o aviso aparece no editor, sublinhado em amarelo, antes de você rodar qualquer coisa:

React Hook useEffect has a missing dependency: 'preco'.
Either include it or remove the dependency array.
  react-hooks/exhaustive-deps

A tradução é direta: "o seu efeito usa preco e o array não lista preco". Note que o aviso oferece duas saídas — incluir a dependência ou remover o array. As duas são legítimas, e a escolha depende do que o efeito faz. Se ele deve acompanhar o preço, inclua. Se ele deveria rodar uma vez só e o preço entrou ali por acidente, o conserto é outro: tire o preço de dentro do efeito, não o array.

Há uma terceira saída que o aviso nem menciona, e que é a melhor na maioria das vezes: perceber que aquilo não precisava de efeito. Um total que é preco * quantidade pode ser calculado direto no corpo do componente, sem estado e sem efeito — nada para o array observar. A aula Quando Não Usar Efeito é sobre esse instinto, mas ele já vale aqui: antes de brigar com o array, confira se o efeito devia existir.

9. Cenários do dia a dia

Cenário 1: a tela mostra o valor antigo por um instante

Com duas fontes de verdade — o preço no estado e o total calculado por um efeito —, existe sempre um render em que o preço é novo e o total ainda é velho. O olho atento vê um piscar. Quando a conta é derivada, calcule no render; quando o valor vem de fora, aí sim o efeito é a ferramenta certa e o "instante desatualizado" é inevitável.

Cenário 2: o efeito roda duas vezes e faz dois pedidos

No modo de desenvolvimento, o StrictMode monta o componente duas vezes, então o efeito com [] roda duas vezes e dois pedidos saem. Não é o array errado: é o React testando se o seu efeito sabe se limpar. A resposta certa é a aula de cleanup, que vem depois de buscando dados — e a solução prática é cancelar o pedido anterior na função de limpeza.

Cenário 3: o array com um item que nunca muda

A Ana colocou [3] no array, achando que era "o número de pães". O efeito rodou uma vez e nunca mais, porque o número dentro do array é sempre o mesmo — não é uma variável, é um valor escrito ali. Dependência tem de ser algo que possa mudar entre um render e outro: uma variável de estado, uma prop, um cálculo a partir delas. Constante não é dependência.

Exercício: o total que acompanha os dois valores

O efeito calcula preco * quantidade e já lista o preço. Complete o array com o que falta para o efeito rodar quando a quantidade mudar.

useEffect(() => { setTotal(preco * quantidade); }, [preco, ]);

Dica: é o outro valor que o efeito lê. Sem ele, o total fica parado quando a quantidade muda.

11. Resumo

O array de dependências é a lista de tudo o que o efeito lê de fora da própria função. Sem array, o efeito roda depois de todo render; com [], roda uma vez na montagem; com valores dentro, roda na montagem e de novo sempre que algum deles mudar. O React compara os valores com os do render anterior usando igualdade, e roda o efeito só quando a comparação falha.

Esquecer uma dependência produz o valor velho na tela: o efeito não roda, a conta não é refeita, e o número antigo fica convivendo com o dado novo. Incluir demais produz efeito demais: pedidos repetidos, contas dobradas e, se houver mudança de estado dentro do efeito, o laço que o React interrompe com "Maximum update depth exceeded".

A regra de ouro é listar o que se lê, e a pergunta de ouro vem antes: este efeito precisa existir? Se o valor pode ser calculado no render, não há array para acertar. As próximas aulas usam essa base para o caso em que o efeito é realmente necessário — buscar dados fora do componente — e para o caso em que ele precisa desfazer o que fez.

Para lembrar

  • Sem array: roda depois de todo render. Com []: só na montagem.
  • Com [a, b]: roda na montagem e quando a ou b mudar.
  • O array lista tudo o que o efeito lê: estado, props e variáveis de fora.
  • O React compara por identidade: objeto, array e função recriados contam como mudança.
  • Dependência que nunca muda (um número escrito no array) não faz nada.
  • Faltando dependência, o sintoma é valor velho na tela.
  • Sobrando efeito, o sintoma é laço: "Maximum update depth exceeded".
  • O aviso react-hooks/exhaustive-deps aponta a dependência que falta.
  • Antes de acertar o array, pergunte se o efeito devia existir.
  • Valor derivado de estado se calcula no render; efeito é para o que vem de fora.
