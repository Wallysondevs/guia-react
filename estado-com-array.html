Estado com Array

A Ana agora tem uma fila de encomendas: cada pedido que chega entra na lista, cada pedido entregue sai dela, e o pão que ficou pronto muda de estado. Ela escreveu pedidos.push(novo) e a lista continuou com os mesmos itens na tela. Escreveu pedidos.splice(0, 1) e nada saiu. Nesta aula ela aprende a guardar uma lista no estado e a mudá-la do jeito que o React percebe: construindo uma lista nova.

Você vai aprender
  • Como guardar uma lista num estado e desenhá-la com map.
  • Acrescentar um item com [...lista, novo].
  • Remover um item com filter, de preferência pelo id.
  • Trocar um item com map, sem mutar os outros.
  • Quais métodos de array mudam a lista no lugar — e por que evitá-los no estado.
  • Ordenar sem estragar a lista original.
  • As receitas prontas de cada operação de lista.

1. A cena: a fila de encomendas

A padaria da Ana passou a receber encomendas por telefone, e ela quer uma tela com a fila. Cada pedido tem um nome e uma situação: na fila ou pronto. Quando chega um pedido, entra na lista; quando o cliente leva, sai; quando o pão sai do forno, muda de situação.

O primeiro instinto é o que todo mundo tem: a lista é um array, array tem push para acrescentar e splice para remover. Ela escreveu pedidos.push(novoPedido) e o item entrou — no array. Na tela, nada. Depois chamou setPedidos(pedidos) para "avisar o React", e nada de novo: o setter recebeu exatamente o mesmo array que já estava no estado.

É o mesmo problema da aula de estado com objeto, com outra roupagem. O React compara a referência: se o array é o mesmo, ele conclui que nada mudou e não redesenha. push, splice, sort e reverse alteram a lista no lugar, sem criar outra. E o estado precisa receber uma lista nova.

A solução não é complicada, e o React tem uma vantagem a oferecer: quando a lista é nova, o React consegue comparar item por item e atualizar só o que mudou na tela. Uma lista construída com calma é também uma tela mais rápida.

2. A lista no estado

Guardar uma lista num estado é igual a guardar qualquer outra coisa: o valor inicial é [] ou um array com itens. Para desenhar, usa-se map, que transforma cada item num pedaço de JSX; cada pedaço recebe uma key estável, para o React saber qual é qual.

function App() {
  const [pedidos, setPedidos] = useState([
    { id: 1, nome: "Pão francês", pronto: false },
    { id: 2, nome: "Pão de queijo", pronto: true }
  ]);

  return (
    <ul>
      {pedidos.map((pedido) => (
        <li key={pedido.id}>
          {pedido.nome} — {pedido.pronto ? "pronto" : "na fila"}
        </li>
      ))}
    </ul>
  );
}

Se a lista estiver vazia, o map devolve uma lista vazia e nada é desenhado — a ul fica sem filhos. Vale tratar esse caso na tela, porque uma área em branco não diz se o site está carregando, se deu erro ou se não há pedidos. Um {pedidos.length === 0 && <li>Nenhum pedido na fila</li>} dentro da lista resolve a dúvida do cliente sem nenhum estado extra.

O estado é um array de objetos. O map percorre e devolve uma lista de elementos li; o React desenha essa lista. A key é o id, e não o índice: o índice muda quando a lista muda, e aí o React reaproveita o elemento errado — a aula A key entra nesse detalhe.

array
Uma lista ordenada de valores, escrita entre colchetes: ["pão", "bolo"]. No estado, começa vazio ([]) e vai crescendo.
item
Um elemento da lista. Numa fila de pedidos, cada item é um objeto com id, nome e pronto.
índice
A posição do item: 0 para o primeiro, 1 para o segundo. Muda quando você remove ou ordena — por isso não serve de identidade.
id
Um valor que não muda e não se repete: 1, 2, 3 ou um número gerado na hora. É o que identifica o item em qualquer posição.
lista nova
Um array recém-criado, com os itens que você quer. É o único jeito de o React perceber a mudança: referência nova, render novo.

3. Acrescentar: uma lista nova com o item no fim

O push acrescenta no fim da lista existente. O spread faz o mesmo sem tocar na lista original: ele copia os itens para um array novo, e você escreve o item novo logo depois.

O botão usa push e a tela não muda. Acrescente o pedido construindo uma lista nova. A missão clica no botão e confere que apareceram dois itens, um deles "Pão de mel".

function App() {
  const [pedidos, setPedidos] = useState(["Pão francês"]);

  function acrescentar() {
    pedidos.push("Pão de mel");
    setPedidos(pedidos);
  }

  return (
    <div>
      <button onClick={acrescentar}>Novo pedido</button>
      <ul>
        {pedidos.map((pedido) => (
          <li key={pedido}>{pedido}</li>
        ))}
      </ul>
    </div>
  );
}
<div>
  <button>Novo pedido</button>
  <ul>
    <li>Pão francês</li>
  </ul>
</div>

function App() {
  const [pedidos, setPedidos] = useState(["Pão francês"]);

  function acrescentar() {
    setPedidos([...pedidos, "Pão de mel"]);
  }

  return (
    <div>
      <button onClick={acrescentar}>Novo pedido</button>
      <ul>
        {pedidos.map((pedido) => (
          <li key={pedido}>{pedido}</li>
        ))}
      </ul>
    </div>
  );
}

O spread resolve os dois requisitos de uma vez: os itens antigos vão para a lista nova (nada se perde) e o array é outro objeto (o React percebe). A ordem dos elementos no spread é a ordem final na tela — [...pedidos, novo] põe no fim, [novo, ...pedidos] põe no começo.

Um detalhe que confunde: push devolve o novo tamanho da lista, não a lista. Escrever setPedidos(pedidos.push(novo)) guarda o número 2 no estado, e a tela quebra no map com "pedidos.map is not a function". Se você vir esse erro, procure um set que recebeu o retorno de um método em vez da lista.

Coloque um console.log no handler e você vê o desencontro: o array do estado cresceu, mas o componente não rodou de novo, então a tela ficou como estava. O painel da caixa só muda quando há render.

no console: pedidos: ["Pão francês","Pão de mel"]
na tela:    1 pedido

4. Remover: filter devolve só o que fica

Para remover, a pergunta muda de lado: em vez de dizer o que sai, você diz o que fica. O filter percorre a lista e devolve uma lista nova com os itens para os quais a sua função respondeu true. O item removido simplesmente não entra.

O "Remover" usa splice e a lista continua com dois itens. Remova o pedido sem mutar a lista. A missão clica no primeiro Remover e confere que sobrou um item.

function App() {
  const [pedidos, setPedidos] = useState([
    { id: 1, nome: "Pão francês" },
    { id: 2, nome: "Pão de queijo" }
  ]);

  function remover(id) {
    const i = pedidos.findIndex((p) => p.id === id);
    pedidos.splice(i, 1);
    setPedidos(pedidos);
  }

  return (
    <ul>
      {pedidos.map((p) => (
        <li key={p.id}>
          {p.nome} <button onClick={() => remover(p.id)}>Remover</button>
        </li>
      ))}
    </ul>
  );
}

function App() {
  const [pedidos, setPedidos] = useState([
    { id: 1, nome: "Pão francês" },
    { id: 2, nome: "Pão de queijo" }
  ]);

  function remover(id) {
    setPedidos(pedidos.filter((p) => p.id !== id));
  }

  return (
    <ul>
      {pedidos.map((p) => (
        <li key={p.id}>
          {p.nome} <button onClick={() => remover(p.id)}>Remover</button>
        </li>
      ))}
    </ul>
  );
}

p.id !== id lê como "todo pedido cujo id é diferente do que eu quero remover". A função devolve false justamente para o pedido clicado, e o filter o deixa de fora. Não há splice, não há índice, não há mutação — só uma lista nova.

lista antiga: ["Pão francês","Pão de queijo"]
lista nova:   ["Pão de queijo"]

A lista antiga continua existindo, com os dois itens, porque nada nela foi alterado. A lista nova é outro array, com o pedido que sobrou. É essa diferença que o React compara: referências diferentes, render novo.

E por que remover pelo id e não pela posição? Porque a posição muda. Se a lista estiver ordenada por nome ou se um item já tiver saído, o índice que você viu na tela pode não ser o mesmo do array no momento do clique. O id viaja com o item e não se confunde.

5. Trocar um item: map com comparação

Atualizar um item é o caso mais interessante, porque a lista muda e o item também. A receita é map: para cada pedido, se for o do id clicado, devolva uma versão nova; se não, devolva o mesmo. A lista nova tem os mesmos itens, menos um — que é outro objeto.

O botão muda a propriedade dentro do objeto e a tela não reage. Troque o item por um objeto novo, dentro de uma lista nova. A missão clica em Marcar e confere que aparece pronto na lista.

function App() {
  const [pedidos, setPedidos] = useState([
    { id: 1, nome: "Pão francês", pronto: false },
    { id: 2, nome: "Pão de queijo", pronto: false }
  ]);

  function marcar(id) {
    const pedido = pedidos.find((p) => p.id === id);
    pedido.pronto = true;
    setPedidos(pedidos);
  }

  return (
    <ul>
      {pedidos.map((p) => (
        <li key={p.id}>
          {p.nome + " — " + (p.pronto ? "pronto" : "na fila")}{" "}
          <button onClick={() => marcar(p.id)}>Marcar</button>
        </li>
      ))}
    </ul>
  );
}
<ul>

    <button>Marcar</button>
  </li>
  <li>

function App() {
  const [pedidos, setPedidos] = useState([
    { id: 1, nome: "Pão francês", pronto: false },
    { id: 2, nome: "Pão de queijo", pronto: false }
  ]);

  function marcar(id) {
    setPedidos(
      pedidos.map((p) => (p.id === id ? { ...p, pronto: true } : p))
    );
  }

  return (
    <ul>
      {pedidos.map((p) => (
        <li key={p.id}>
          {p.nome + " — " + (p.pronto ? "pronto" : "na fila")}{" "}
          <button onClick={() => marcar(p.id)}>Marcar</button>
        </li>
      ))}
    </ul>
  );
}

A expressão tem três partes: p.id === id escolhe o item; { ...p, pronto: true } cria uma versão nova dele, sem perder o nome nem o id; : p devolve os outros intactos. Duas aulas se encontram aqui: o spread do objeto e a lista nova do array.

A key do item continua a mesma depois da troca, e é por isso que o React atualiza aquele li em vez de apagar e criar outro. Se o key fosse o índice ou o texto visível, o React perderia a referência: criaria um elemento novo e, num formulário dentro da linha, o foco e o texto digitado iriam embora. Chave estável é o que permite atualizar no lugar.

Note que os itens não alterados são os mesmos objetos de antes — e isso é bom, é o que permite ao React concluir que eles não precisam ser redesenhados. Só o item clicado é novo.

6. Os métodos que mudam a lista no lugar

JavaScript tem dois tipos de método de array: os que alteram o array original e os que devolvem um array novo. No estado, só os segundos servem. Vale colar esta tabela em algum lugar da memória, porque o erro que os primeiros causam é sempre o mesmo: a tela parada.

MétodoAltera a lista original?Devolve
push, pop, shift, unshiftsimo novo tamanho ou o item retirado
splicesima lista dos itens removidos
sort, reverse, fillsimo próprio array, já alterado
map, filter, slice, concatnãoum array novo
toSorted, toReversed, toSplicednãouma cópia já alterada (JavaScript moderno)

Quando você precisa de um método da primeira linha, o caminho é copiar antes: [...lista] cria uma cópia rasa, e aí o sort pode trabalhar nela sem estragar o estado. As versões toSorted e companhia já fazem essa cópia por dentro, e funcionam nos navegadores atuais e no Node 22.

Um aviso sobre a cópia rasa: [...lista] copia a lista, não os itens. Os objetos de dentro continuam sendo os mesmos — o que é exatamente o que queremos no map da seção 5, mas não protege ninguém de uma mutação feita direto no item.

7. Ordenar sem estragar a lista

A Ana quis mostrar a fila por ordem alfabética e escreveu setPedidos(pedidos.sort()). Duas coisas erradas de uma vez: o sort altera o array no lugar, então o estado muda sem o React saber; e o setter recebe o mesmo array, então nada é redesenhado. Na tela, a ordem antiga; no estado, a nova. Pior: qualquer render posterior mostra a lista embaralhada, e a origem do bug fica invisível.

const ordenados = [...pedidos].sort((a, b) => a.nome.localeCompare(b.nome));
setPedidos(ordenados);

O spread cria a cópia; o sort trabalha nela; o setter recebe um array novo. A função de comparação é necessária porque o sort padrão compara como texto, e "10" vem antes de "2". O localeCompare compara com as regras do português, acentos incluídos.

Dá para evitar o spread usando pedidos.toSorted((a, b) => ...), que devolve a cópia ordenada e deixa a original em paz. Os dois jeitos estão certos; o primeiro funciona em qualquer navegador, o segundo é mais curto e mais novo.

Uma alternativa que muita gente prefere: guardar a ordem como um estado separado, e ordenar só na hora de desenhar, com [...pedidos].sort(...) dentro do JSX. A lista original continua na ordem em que os pedidos chegaram, e a tela mostra o que você escolheu. Esse é um caso de dado derivado — assunto da próxima aula.

8. As receitas de cada operação

Com o tempo, essas operações viram reflexo. Vale ter a tabela à mão nas primeiras semanas, porque a diferença entre a versão que funciona e a que não funciona é pequena — e o sintoma é sempre "a tela não mudou".

O que você querComo se escreveO que acontece
Acrescentar no fimsetLista([...lista, novo])lista nova com o item no fim
Acrescentar no começosetLista([novo, ...lista])lista nova com o item na frente
Remover pelo idsetLista(lista.filter((x) => x.id !== id))lista nova sem o item
Trocar um itemsetLista(lista.map((x) => x.id === id ? { ...x, campo } : x))lista nova com um item novo
EsvaziarsetLista([])lista nova, vazia
OrdenarsetLista([...lista].sort(fn))lista nova na ordem pedida

Repare que todas as linhas que funcionam têm uma coisa em comum: produzem um array novo. É o mesmo princípio do estado com objeto — o valor que vai para o setter nunca é o que já estava lá, é sempre um valor novo, construído a partir do antigo.

Cada item também precisa de um id que não mude. Se você cria os itens na hora, um valor como Date.now() serve para um pedido por vez; para uma sequência de vários no mesmo milissegundo, o ideal é um contador. O importante é que o id acompanhe o item para sempre: é ele que o key usa e é por ele que você remove e atualiza.

9. Cenários do dia a dia

Cenário 1: a tela com dois itens e o estado com um

A Ana chamou setPedidos([...pedidos]) logo depois do push e a tela passou a mostrar o item novo. Parece resolvido, mas o hábito é ruim: a lista é mutada antes de ser copiada, e qualquer outro componente que estivesse segurando a lista antiga vê o item aparecer sem aviso. Copiar no mesmo passo — setPedidos([...pedidos, novo]) — produz o mesmo resultado sem efeito colateral.

Cenário 2: "pedidos.map is not a function"

Um clássico. Ela escreveu setPedidos(pedidos.push(novo)), e o estado passou a guardar o número 2, que é o que o push devolve. No render seguinte, o map não existe num número e a caixa mostra o erro. Quando aparecer essa mensagem, olhe o que foi entregue ao setter: tem de ser um array, não o retorno de um método.

Cenário 3: o item errado saiu da lista

Ela removeu pela posição, com filter((p, i) => i !== 0), para tirar "o primeiro da tela". Só que a lista estava ordenada por nome e o primeiro da tela não era o primeiro do array: saiu o pedido errado, e o certo continuou lá. Remover pelo id do item clicado não depende de ordem nenhuma. Posição serve para desenhar; identidade serve para agir.

setPedidos([, novo]); setPedidos(pedidos.((p) => p.id !== id)); setPedidos(pedidos.((p) => p.id === id ? { ...p, pronto: true } : p));

Dica: a primeira linha copia a lista com os três pontinhos; as outras duas usam métodos que devolvem lista nova — um escolhe o que fica, o outro transforma cada item.

11. Resumo

Uma lista no estado é um valor como outro qualquer, e a regra é a mesma dos objetos: nunca altere o que já está lá. push, splice, sort e reverse mexem na lista original e deixam o React sem motivo para redesenhar. O caminho é sempre construir uma lista nova — com spread para acrescentar, filter para remover e map para trocar um item.

Os itens precisam de identidade: um id que não muda serve de key no map e de critério na hora de remover ou atualizar. Posição serve para desenhar, não para agir. E cada operação tem uma receita curta: [...lista, novo], lista.filter((x) => x.id !== id), lista.map((x) => x.id === id ? { ...x, campo } : x).

Com isso, a Ana já consegue manter a fila de encomendas viva na tela: entra pedido, sai pedido, muda situação. O que ainda falta é não guardar o que pode ser calculado — quantos pedidos estão na fila, quanto vai render o dia, qual item aparece primeiro. Guardar esses números em estados separados é o próximo tropeço, e é o assunto da aula seguinte.

Para lembrar

  • Lista no estado: useState([]); desenhe com map e uma key estável.
  • Acrescentar: [...lista, novo]; no começo: [novo, ...lista].
  • Remover: lista.filter((x) => x.id !== id).
  • Trocar um item: lista.map((x) => x.id === id ? { ...x, campo } : x).
  • push, splice, sort e reverse mutam: evite no estado.
  • push devolve o tamanho — setLista(lista.push(x)) guarda um número.
  • Ordenar: [...lista].sort(fn) ou lista.toSorted(fn).
  • O spread copia a lista, não os objetos de dentro.
  • Remova e atualize pelo id, nunca pela posição.
  • Lista nova, render novo: referência nova é o que o React compara.
