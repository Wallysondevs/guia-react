O useTransition

A Ana pôs uma busca na loja: você digita “queijo” e a lista se filtra na hora. Com trinta pães, perfeito. Com os dois mil itens que ela cadastrou no estoque, cada letra digitada travava o campo por meio segundo — a pessoa digitava “q”, “u”, “e” e as letras apareciam atrasadas, uma por uma. Nesta aula a Ana aprende o useTransition: como dizer ao React “esta parte pode esperar, mas o que a pessoa está digitando não pode” — e como mostrar um aviso enquanto a parte lenta trabalha.

Você vai aprender
  • O que é uma transição e o que muda quando uma atualização entra nela.
  • Como usar const [pendente, iniciar] = useTransition().
  • Por que o campo de texto precisa continuar urgente.
  • O que o pendente mede, quando ele vira true e quando volta.
  • Como rodar uma ação assíncrona dentro da transição, no React 19.
  • Como desabilitar um botão enquanto a ação está em curso.
  • O que o useTransition não faz: não é debounce, não cancela promessa.

1. A cena: a busca que engasga a digitação

O campo de busca da Ana é controlado: cada letra vira estado, o estado filtra a lista, a lista aparece. Enquanto a lista tinha trinta itens, tudo acontecia no mesmo instante. Com dois mil itens, o filtro passou a custar caro — e o custo cai justamente na letra que a pessoa acabou de digitar. O navegador fica ocupado filtrando, e o campo não redesenha até terminar.

O sintoma é fácil de reconhecer: você digita rápido e as letras aparecem com atraso, como se o teclado estivesse com preguiça. Não é a rede, não é o computador: é a ordem em que o React foi obrigado a trabalhar. Toda atualização de estado era tratada como urgente, inclusive a que recalcula a lista inteira.

A ideia do useTransition é separar essas duas coisas. A letra digitada é urgente: tem de aparecer no campo agora. A lista filtrada pode esperar um pouco, e o React pode até interromper o trabalho dela se outra letra chegar. Quem decide o que é urgente é você, e a ferramenta para isso é uma transição.

2. O que é uma transição

Uma transição é um jeito de marcar uma atualização de estado como não urgente. O nome vem da ideia de passagem: o React prepara a tela nova em segundo plano e troca quando ela está pronta, mantendo a antiga visível no meio do caminho. Se uma atualização urgente chegar durante o preparo, ela passa na frente.

transição
Uma atualização de estado marcada como não urgente. Pode ser interrompida e não bloqueia a digitação.
useTransition
O hook que devolve o par: const [pendente, iniciar] = useTransition(). Vem do React e, nas caixas, já está no escopo.
iniciar
A função que recebe o trabalho: iniciar(() => setFiltro(valor)). Tudo o que for atualizado dentro dela é transição.
pendente
O isPending: true enquanto a transição não terminou. Serve para mostrar “filtrando…”, desabilitar botão, esmaecer a lista.
atualização urgente
O que precisa aparecer na hora: a letra no campo, o clique no botão, o checkbox marcado. Fica fora da transição.
ação assíncrona
No React 19, a função passada para iniciar pode ser async: o pendente continua verdadeiro até depois do await.

Antes de ver código, vale entender o que a transição não é. Ela não adia a chamada de setFiltro: a função roda na hora, o estado novo é agendado na hora. O que muda é a prioridade com que o React desenha o resultado. É como pedir uma pizza e continuar conversando: o pedido foi feito, a conversa não para.

Também não é mágica de desempenho. Se o seu filtro leva dois segundos de cálculo puro, a transição não faz esse cálculo ficar rápido — ela faz o campo continuar respondendo enquanto o cálculo acontece. Para ficar rápido de verdade, o caminho é reduzir o trabalho: filtrar menos itens, paginar, memoizar. A transição cuida da sensação; o algoritmo cuida do tempo.

3. A caixa: a lista que espera

A caixa simula uma busca no servidor. Como não há rede aqui dentro, a espera é feita com new Promise((ok) => setTimeout(ok, 3000)) — a mesma forma que você usaria para simular qualquer chamada. A versão inicial busca, mas não avisa nada: durante três segundos, a tela fica igual, e a pessoa clica de novo achando que o botão não funcionou. A missão é marcar a busca como transição e mostrar “Buscando no forno…” enquanto ela não termina.

Chame const [pendente, iniciar] = useTransition() no topo e envolva o trabalho do buscar com iniciar(async () => { ... }). Enquanto a promise não resolve, mostre "Buscando no forno…" em vez de “Lista pronta”.

function App() {
  const [lista, setLista] = useState(["Pão francês"]);

  async function buscar() {
    await new Promise((ok) => setTimeout(ok, 3000));
    setLista(["Pão francês", "Pão de queijo bom"]);
  }

  return (
    <div>
      <button onClick={buscar}>Buscar pães de queijo</button>
      <p>Lista pronta</p>
      <ul>
        {lista.map((p) => (
          <li key={p}>{p}</li>
        ))}
      </ul>
    </div>
  );
}

function App() {
  const [pendente, iniciar] = useTransition();
  const [lista, setLista] = useState(["Pão francês"]);

  function buscar() {
    iniciar(async () => {
      await new Promise((ok) => setTimeout(ok, 3000));
      setLista(["Pão francês", "Pão de queijo bom"]);
    });
  }

  return (
    <div>
      <button onClick={buscar}>Buscar pães de queijo</button>
      <p>{pendente ? "Buscando no forno…" : "Lista pronta"}</p>
      <ul>
        {lista.map((p) => (
          <li key={p}>{p}</li>
        ))}
      </ul>
    </div>
  );
}

Rode a solução, clique em “Buscar pães de queijo” e olhe o painel nos primeiros instantes: o parágrafo muda para “Buscando no forno…” e a lista continua com um item. Três segundos depois, o segundo pão aparece. É a assinatura de uma transição: a tela antiga fica no lugar, o aviso mostra que tem coisa acontecendo, e a troca só ocorre quando o resultado chega.

Repare na diferença de estrutura entre as duas versões. Antes, buscar era uma função async que esperava e mexia no estado. Agora, buscar é uma função comum que chama iniciar com uma função async dentro. Quem sabe que existe uma transição em curso é o React; quem mostra isso é o pendente.

E por que a ação precisa estar dentro do iniciar, e não só o setLista? Porque o pendente fica verdadeiro do começo ao fim do que estiver lá dentro — inclusive durante o await. Se você deixar a espera fora e marcar só a atualização final, o aviso aparece por um instante no fim, que é exatamente quando ninguém precisa dele.

4. Urgente e não urgente

O caso mais comum de transição não é a busca, é o filtro. A regra é simples de dizer e fácil de errar na prática: o estado que alimenta o campo de texto é urgente; o estado que alimenta a lista é transição. Se os dois forem a mesma coisa, o campo espera o filtro. Se os dois forem transição, o campo também espera.

O campo guarda o texto, mas a lista nunca filtra: falta alimentar filtro. Dentro de aoDigitar, chame setTexto(valor) e depois iniciar(() => setFiltro(valor)).

function App() {
  const [texto, setTexto] = useState("");
  const [filtro, setFiltro] = useState("");
  const [pendente, iniciar] = useTransition();
  const paes = ["Pão francês", "Pão de queijo", "Baguete"];

  function aoDigitar(e) {
    const valor = e.target.value;
    setTexto(valor);
  }

  const filtrados = paes.filter((p) =>
    p.toLowerCase().includes(filtro.toLowerCase())
  );

  return (
    <div>
      <label htmlFor="busca">Buscar pão</label>
      <input id="busca" value={texto} onChange={aoDigitar} />
      {pendente && <p>Filtrando…</p>}
      <ul>
        {filtrados.map((p) => (
          <li key={p}>{p}</li>
        ))}
      </ul>
    </div>
  );
}

  const [filtro, setFiltro] = useState("");
  const [pendente, iniciar] = useTransition();

    const valor = e.target.value;
    setTexto(valor);
    iniciar(() => setFiltro(valor));
  }

    p.toLowerCase().includes(filtro.toLowerCase())
  );

        ))}
      </ul>
    </div>
  );
}

Digite “queijo” e o painel mostra o campo com o texto e a lista com um item só. Com três pães a diferença de velocidade é invisível — o valor da caixa é mostrar a estrutura, que é a mesma quando a lista tem dois mil itens. Aí a transição ganha o direito de ser interrompida: se a pessoa digitar outra letra antes de o filtro terminar, o React descarta o trabalho antigo e começa de novo com o texto novo.

Esse descarte é o que muda a sensação de uso. Sem transição, o React termina o filtro de “que” para só depois começar o de “quei”. Com transição, ele pode abandonar o primeiro no meio e atender o segundo. A pessoa não vê trabalho jogado fora: vê o campo respondendo.

Duas armadilhas aqui. A primeira: esquecer o setTexto fora do iniciar — o campo passa a mostrar o valor antigo enquanto o filtro roda, e parece que o teclado não funciona. A segunda: pôr tudo na transição, inclusive o estado do campo, e depois estranhar a lentidão. Urgente é o que a pessoa está fazendo agora; o resto é transição.

5. O pendente: o que ele mede e onde ele mora

O pendente é um booleano que começa falso, vira verdadeiro quando uma transição é iniciada e volta a falso quando as atualizações dela foram desenhadas. Ele não mede “a promessa terminou”: mede “a tela ainda não mostrou o resultado”. A diferença aparece quando a promessa termina e o desenho ainda não aconteceu — nesse intervalo, o pendente continua verdadeiro, e é isso que você quer.

No console do seu projeto, com um console.log no começo e no fim da ação, a sequência é assim:

buscando...
pendente: true
2 pães encontrados
pendente: false

O pendente mora no componente que chamou o hook. Se você chamar useTransition dentro de um componente e ler pendente em outro, o valor não chega lá: hooks não compartilham estado entre componentes. Para usar o aviso em outro lugar, passe o booleano por prop ou ponha o hook no componente que precisa dele.

O botão pode ser clicado várias vezes enquanto a encomenda é enviada. Use o pendente para desabilitar o botão e trocar o rótulo: disabled={pendente} e {pendente ? "Enviando…" : "Enviar encomenda"}.

function App() {
  const [pendente, iniciar] = useTransition();
  const [recado, setRecado] = useState("");

  function enviar() {
    iniciar(async () => {
      await new Promise((ok) => setTimeout(ok, 2000));
      setRecado("Encomenda registrada");
    });
  }

  return (
    <div>
      <button onClick={enviar}>Enviar encomenda</button>
      <p>{recado || "Nada enviado"}</p>
    </div>
  );
}

}

Clique e olhe o painel antes dos dois segundos: o botão aparece com disabled e o rótulo muda para “Enviando…”. Isso resolve um problema real — o clique duplo em formulário de encomenda, que gera dois pedidos e uma conversa chata no balcão. O disabled não é enfeite: é a interface dizendo “já recebi”.

Note que o pendente não substitui o estado de carregamento do seu formulário. Ele é o estado de carregamento da transição. Se você tiver uma requisição que pode falhar, continue precisando de um estado para o erro, como em Carregando e Erro. O pendente cobre o “está indo”, não o “deu errado”.

6. Ações assíncronas e o servidor

Até o React 18, a função passada para iniciar era síncrona: o pendente voltava a falso antes de qualquer await. No React 19 ela pode ser async, e o pendente acompanha a espera inteira. É essa mudança que fez o useTransition virar a base das “ações” de formulário do React 19: enviar, esperar, mostrar o resultado.

Nas caixas deste guia não há rede, então a espera é simulada. No projeto da Ana, a função chama o servidor de verdade:

import { useState, useTransition } from "react";

export function BuscaDePaes() {
  const [pendente, iniciar] = useTransition();
  const [texto, setTexto] = useState("");
  const [resultados, setResultados] = useState([]);

  function aoDigitar(e) {
    const valor = e.target.value;
    setTexto(valor);

    iniciar(async () => {
      const resposta = await fetch("/api/paes?q=" + encodeURIComponent(valor));
      const dados = await resposta.json();
      setResultados(dados);
    });
  }

  return (
    <div>
      <input value={texto} onChange={aoDigitar} />
      {pendente ? <p>Buscando…</p> : null}
      <ul>
        {resultados.map((pao) => (
          <li key={pao.id}>{pao.nome}</li>
        ))}
      </ul>
    </div>
  );
}

Esse código funciona, e tem um problema que a transição não resolve: cada letra dispara uma requisição. Com “queijo”, são seis chamadas ao servidor, e a resposta que chega por último pode não ser a da última letra. Transição não é debounce. Se você quiser uma chamada por pausa de digitação, precisa de um setTimeout cancelado no useEffect — o assunto de Timers — ou de uma biblioteca de busca. O useTransition cuida da prioridade do desenho; quem cuida do volume de requisições é você.

Ainda sobre o projeto: useTransition é importado do React, como todos os hooks. E existe também a função startTransition, importada à parte, para quando a transição acontece fora de um componente. Copiar um exemplo da documentação sem o import dá um erro fácil de reconhecer:

Uncaught ReferenceError: startTransition is not defined

Se você vir isso, o problema não é a transição: é a linha de import que falta. Nas caixas deste guia, use sempre o iniciar que vem do hook — é o que está no escopo e é o que você vai usar em noventa por cento dos casos.

7. O que o useTransition não resolve

Como toda ferramenta nova, o useTransition atrai usos para os quais não foi feito. Quatro aparecem sempre:

Você querO useTransition resolve?O que fazer
a digitação não travarsim, é o caso clássicocampo urgente, lista na transição
uma chamada por pausa de digitaçãonãodebounce com setTimeout no efeito
cancelar a requisição antiganãoAbortController ou ignorar a resposta velha
mostrar erro de envionãoestado de erro separado, com try/catch
deixar um cálculo pesado mais rápidonãofiltrar menos, paginar, useMemo

A linha do erro merece atenção, porque é a que mais surpreende. Se a função async dentro de iniciar lançar uma exceção, o React não tem para onde mostrá-la: não existe “tela de erro da transição”. Você continua precisando de try/catch e de um estado para a mensagem. O pendente volta a falso, e a interface fica como estava — o que pode parecer que nada aconteceu.

Também vale resistir à tentação de envolver tudo. Uma transição a mais não deixa o site mais rápido; ela só muda a prioridade de um desenho. Se o trabalho é pequeno, marcar como transição não muda nada na prática — e adiciona uma linha que alguém vai ter de entender depois. Use onde a diferença aparece: listas grandes, cálculos de filtro, ações que esperam o servidor.

8. useTransition ou useDeferredValue?

Os dois hooks resolvem o mesmo desconforto — a tela travando por causa de trabalho pesado — e escolhem lados diferentes da mesma moeda. O useTransition marca a atualização como não urgente; o useDeferredValue marca um valor como atrasado. A pergunta que separa os dois é: você controla a função que muda o estado?

SituaçãouseTransitionuseDeferredValue

Na prática, a escolha quase sempre é óbvia pelo lugar do código. Se o estado nasce no componente que você está escrevendo, useTransition. Se o texto chega por prop e você só quer que a lista grande espere, useDeferredValue. A próxima aula é exatamente sobre ele, e mostra o mesmo problema resolvido pelo outro lado.

9. Cenários do dia a dia

Cenário 1: os dois mil itens do estoque

O filtro do estoque da Ana rodava a cada letra e travava o campo. Ela separou o estado do texto (urgente) do estado do filtro (transição) e a digitação voltou a responder. O trabalho de filtro continuou igual; o que mudou foi a ordem em que o React o fez.

Cenário 2: o botão de enviar que virava dois pedidos

O formulário de encomenda aceitava clique duplo, e o servidor recebia o pedido duas vezes. Com disabled={pendente} no botão e o rótulo mudando para “Enviando…”, o segundo clique deixou de existir. O pendente funcionou como trava de interface, sem precisar de estado extra.

Cenário 3: o aviso que não aparecia

Ela pôs a espera fora do iniciar: fez await na função do clique e chamou a transição só no fim. O aviso aparecia por um piscar de olhos, já com o resultado pronto. Mover o await para dentro de iniciar(async () => ...) fez o pendente cobrir a espera inteira — e o aviso passou a servir para alguma coisa.

11. Resumo

O useTransition separa o que é urgente do que pode esperar. O campo de texto, o clique e o checkbox ficam urgentes; a lista filtrada, o cálculo pesado e a busca no servidor entram na transição. O hook devolve [pendente, iniciar], e tudo o que acontece dentro de iniciar é marcado como não urgente e pode ser interrompido por uma nova digitação.

No React 19, a função passada para iniciar pode ser async, e o pendente acompanha o await — é o que permite mostrar “enviando…” durante uma requisição de verdade e travar o botão para evitar clique duplo. O aviso vive no componente que chamou o hook; para outro componente, vai por prop.

E o que ele não faz: não é debounce, não cancela requisição, não trata erro e não deixa cálculo pesado rápido. Cada uma dessas necessidades tem a sua ferramenta, e misturar as duas coisas é o caminho mais curto para uma tela que parece quebrada. Quando o valor chega de fora e você só quer atrasar o desenho, o hook da próxima aula é o mais direto.

Para lembrar

  • const [pendente, iniciar] = useTransition(), no topo do componente.
  • iniciar(() => setLista(...)): atualização não urgente.
  • O campo de texto fica fora da transição: urgente é o que a pessoa está fazendo.
  • React 19: iniciar(async () => ...) e o pendente cobre o await.
  • pendente é verdadeiro até o resultado aparecer na tela.
  • disabled={pendente} evita clique duplo em envio.
  • O pendente mora no componente que chamou o hook.
  • Não é debounce, não cancela promessa e não mostra erro.
  • Cálculo pesado continua pesado: transição muda prioridade, não custo.
  • Valor que vem de prop: prefira useDeferredValue.
