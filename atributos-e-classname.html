Atributos e className

A Ana copiou para o JSX o cartão que já existia no site da padaria — o mesmo HTML de sempre, com class, style e um botão desabilitado. Na tela, o cartão apareceu sem a moldura, o preço saiu preto em vez de vermelho e o botão de comprar nasceu travado. Nada disso era erro de digitação: eram atributos escritos do jeito do HTML, num lugar onde o React lê atributos do jeito dele. Esta aula é sobre essa tradução — o que muda de nome, o que muda de tipo e o que continua igual.

Você vai aprender
  • Como um atributo do HTML vira uma prop do React.
  • Por que className e não class.
  • Quando o valor vai entre aspas e quando vai entre chaves.
  • Por que style precisa de objeto.
  • A diferença entre disabled="false" e disabled={false}.
  • Atributos que não mudam de nome: data-*, aria-*, href.

1. A cena: o cartão que perdeu a moldura

O cartão da padaria, no site antigo, era um div com a classe cartao. O CSS dava a ele moldura, sombra e um respiro interno. No React, o mesmo class="cartao" deveria bastar. A Ana colou o bloco no return do componente, salvou e voltou ao navegador: o texto estava lá, mas sem moldura nenhuma, encostado na margem.

Ela abriu o inspetor do navegador e viu o culpado: o div não tinha classe. O React não tinha aplicado o atributo. E o motivo não é capricho — no JSX, o que fica entre o nome da tag e o > não é um atributo de HTML: é uma prop, um dado que o React vai entregar ao elemento. O elemento que representa uma tag comum repassa essas props para o DOM, mas com os nomes que ele conhece.

Por isso a aula tem duas metades. A primeira é o nome: alguns atributos mudam de nome no JSX, e o caso mais famoso é o da classe. A segunda é o tipo do valor: alguns atributos que no HTML aceitam qualquer texto, no React esperam um valor de outro tipo — e aí a string silenciosamente não serve.

2. Atributo, prop e o que o React faz com eles

Um componente é uma função, e as props que ele recebe são um objeto. Quando você escreve <div className="cartao">, o React monta { className: "cartao" } e entrega ao elemento div. O elemento sabe quais props viram atributos de HTML, quais viram propriedades do DOM e quais ele deve tratar de um jeito especial. className vira class; style vira um conjunto de propriedades de estilo; onClick vira um ouvinte de evento.

prop
O dado que você passa para um componente ou elemento, escrito como nome=valor dentro da tag.
atributo
O que aparece no HTML final, dentro da tag: class="cartao", href="...".
className
A prop do React que corresponde ao atributo class do HTML.
valor literal
Texto entre aspas duplas: "cartao". Vai para o atributo como está.
expressão
Valor entre chaves: {cor}. O React calcula e usa o resultado.

A consequência prática é que você pode fazer com atributos tudo o que já sabe fazer com expressões: usar variável, fazer conta, escolher com ternário. className={ativo ? "cartao ativo" : "cartao"} funciona, e é assim que se muda a aparência de um item selecionado. Só que a porta das chaves só existe no lado do React — no HTML puro, atributo é sempre texto.

3. className, o nome que o React usa

O motivo histórico é curto: class é palavra reservada do JavaScript, e o JSX é traduzido para JavaScript. Cem anos de código React usaram className por isso, e é o nome que documentação, exemplos e bibliotecas usam até hoje. Desde o React 19, escrever class em uma tag comum também chega ao DOM — o React passou a repassar atributos desconhecidos —, mas o nome oficial continua sendo className, e é ele que você deve usar.

A missão abaixo é curta de propósito: o cartão precisa de duas classes, e o valor precisa entrar pela porta do React.

O cartão tem só a classe cartao, e ela está escrita do jeito do HTML. Use className e acrescente a classe destaque: className="cartao destaque".

function App() {
  return (
    <div class="cartao">
      <h1>Padaria da Ana</h1>
      <p>Pão quentinho saindo do forno</p>
    </div>
  );
}
<div class="cartao">
  <h1>Padaria da Ana</h1>
  <p>Pão quentinho saindo do forno</p>
</div>

function App() {
  return (
    <div className="cartao destaque">
      <h1>Padaria da Ana</h1>
      <p>Pão quentinho saindo do forno</p>
    </div>
  );
}

A prévia desta página não carrega o CSS da padaria, então o cartão não fica com moldura nem aqui nem lá — o que se confere é o atributo no HTML gerado, e é isso que o painel mostra. Esse é um bom hábito: quando o visual não muda, olhe o HTML antes de suspeitar do CSS.

<div class="cartao destaque">
  <h1>Padaria da Ana</h1>
  <p>Pão quentinho saindo do forno</p>
</div>

Repare no que o painel exibe: className virou class. A tradução acontece na hora de desenhar. Se você inspecionar o elemento no navegador, vai ver a mesma coisa — e é por isso que o CSS antigo continua válido, sem uma linha de mudança.

Uma sutileza que vale guardar: className é uma prop como qualquer outra. Se o valor vier de uma variável, use chaves: className={classe}. Se vier vazio, o atributo desaparece do HTML em vez de virar class="" — comportamento diferente de className="", que produz um atributo vazio. E um número entre chaves é convertido para texto: className={2} gera class="2".

4. A tabela de conversões

Poucos atributos mudam de nome, e os que mudam são justamente os mais usados. A tabela abaixo cobre os que aparecem em qualquer projeto; o resto continua igual e você pode escrever como sempre escreveu.

No HTMLNo JSXPor quê
classclassNameclass é palavra reservada do JavaScript
forhtmlFormesma razão: for também é do JavaScript
tabindextabIndexatributos compostos viram camelCase
maxlengthmaxLengthidem, e vale para readOnly, autoComplete

data-* e aria-*igualo React repassa como estão
href, src, alt, idigualnomes simples não mudam

O critério para decorar é simples: se o nome é uma palavra do JavaScript (class, for) ou é composto por mais de uma palavra (tabindex, maxlength), ele muda. Se é uma palavra só e não é reservada, fica igual. E os que começam com data- ou aria- são uma exceção explícita à regra do camelCase: eles foram feitos para serem escritos com hífen, e o React os respeita.

Um atalho para quem está convertendo uma página inteira de HTML para JSX: traduza só três nomes — class, for e style — e rode. O que estiver errado no resto costuma aparecer no painel com o número da linha. Fazendo isso em uma página de cada vez, o trabalho rende e você não precisa decorar a tabela de uma vez: depois de três ou quatro conversões, className sai sem pensar.

O caso dos eventos merece um aviso, porque a falha é silenciosa: onclick="..." com texto é descartado, e onclick={() => ...} com a letra minúscula também. O React só reconhece o nome onClick, com C maiúsculo, recebendo uma função. O comportamento em si tem aula própria mais adiante; aqui basta saber que este é um atributo em que errar a caixa da letra custa o evento inteiro.

5. Valor com aspas ou valor com chaves

Toda prop tem um valor, e esse valor pode chegar de dois jeitos. Entre aspas, ele é texto e vai como está: alt="Pão quentinho". Entre chaves, ele é JavaScript e o React usa o resultado: alt={descricao}. A regra é essa e não tem exceção — inclusive para números, que precisam de chaves (tabIndex={2} produz tabindex="2").

Três detalhes economizam depuração. Primeiro: aspas dentro de aspas não funcionam; se o texto tem aspas, use chaves com uma string: title={"O pão d'água"}. Segundo: chaves com texto precisam das aspas da string dentro delas — className={"cartao"} é válido, e className={cartao} procura uma variável chamada cartao. Terceiro: valor booleano não precisa de nada, disabled sozinho já significa verdadeiro — como no HTML.

Há um caso em que a diferença entre os dois jeitos é visível: atributo vazio. alt="" é texto vazio e produz alt="" no HTML, o que é correto para imagem decorativa. Já alt={undefined} faz o atributo desaparecer. São intenções diferentes, e o navegador trata as duas de forma diferente também — leitor de tela ignora a imagem decorativa e reclama da imagem sem descrição.

6. style é um objeto, não uma string

Este é o atributo que mais derruba iniciante, porque a falha é total: a tela fica vazia. No HTML, style é texto com declarações CSS. No React, style é um objeto JavaScript em que cada chave é uma propriedade de estilo. Passar texto não é convertido: o componente quebra, e o painel avisa que nada foi desenhado.

O parágrafo do preço usa style="color: red", do jeito do HTML, e a prévia fica em branco. Troque por um objeto: style={{ color: "red" }}.

function App() {
  return (
    <div>
      <h1>Padaria da Ana</h1>
      <p id="alvo" style="color: red">Pão quentinho</p>
    </div>
  );
}
(o React não desenhou nada: o componente devolveu null?)

function App() {
  return (
    <div>
      <h1>Padaria da Ana</h1>
      <p id="alvo" style={{ color: "red" }}>Pão quentinho</p>
    </div>
  );
}

As duas chaves duplas não são um operador novo: são as chaves do JSX (esta prop recebe um valor calculado) envolvendo as chaves do objeto (o valor é um objeto). Ler como "entregue este objeto" resolve o susto. As chaves do objeto são nomes de propriedade CSS em camelCase: backgroundColor, fontSize, borderRadius. O valor é texto, com unidade: "12px", "1rem", "50%".

Sobre números: quando a propriedade aceita comprimento, o React acrescenta px sozinho. style={{ width: 100 }} vira width: 100px; já style={{ opacity: 0.5 }} não ganha unidade, porque opacidade é um número puro. Na dúvida, escreva a unidade você mesmo — é o que todo exemplo da documentação faz, e não deixa ambiguidade.

> document.querySelector("#alvo").style.color
'rgb(255, 0, 0)'
> document.querySelector("#alvo").getAttribute("style")
'color: red;'

O console mostra as duas caras do mesmo estilo: a propriedade do DOM devolve o valor normalizado pelo navegador, e o atributo devolve o texto que o React escreveu. As duas linhas provam que o objeto virou declaração CSS de verdade.

Uma vantagem do objeto que o texto não tem: ele aceita variável de CSS. As chaves de costume são propriedades do CSS em camelCase, mas nomes que começam com dois hífens passam como estão — style={{ "--cor": cor, color: "var(--cor)" }} grava a variável no elemento e a usa na linha seguinte. É o jeito mais direto de deixar uma cor vir de um dado sem escrever uma folha de estilo para cada combinação.

Quando usar style? Em casos pontuais, que dependem de dado: a cor de um selo calculada a partir de um estado, a largura de uma barra de progresso, uma animação simples. Para o visual do dia a dia, classe em folha de estilo é melhor: reaproveita, não polui o JSX e permite :hover, media query e transição. E existe um limite honesto: style não escreve pseudo-classe nem media query, então o que precisa dessas coisas tem de ser classe.

7. Atributos que ligam e desligam

Alguns atributos do HTML não carregam informação, apenas estado: disabled, required, readOnly, hidden. A presença vale mais que o valor — o botão está desabilitado, ponto. É aí que a string atrapalha: disabled="false" não significa "não desabilitado", significa "o atributo está aqui", e o botão fica travado do mesmo jeito.

O botão de comprar nasceu travado. O código diz disabled="false", mas o atributo presente já desabilita. Troque por disabled={false} para que o botão funcione.

function App() {
  return (
    <div>
      <h1>Padaria da Ana</h1>
      <button disabled="false">Comprar pão</button>
    </div>
  );
}
<div>
  <h1>Padaria da Ana</h1>
  <button disabled="">Comprar pão</button>
</div>

function App() {
  return (
    <div>
      <h1>Padaria da Ana</h1>
      <button disabled={false}>Comprar pão</button>
    </div>
  );
}

Com chaves, o React olha o valor booleano: false remove o atributo, true o coloca. É esse mecanismo que permite ligar e desligar o botão a partir de um dado — estoque vazio, pedido já enviado, formulário incompleto. Com string, essa possibilidade não existe, porque toda string é verdadeira, inclusive "false".

O mesmo raciocínio vale para required em campo de formulário e para readOnly em campo preenchido pelo sistema. E vale também para o contrário: para ligar o estado, escrever o nome sozinho é o atalho (<button disabled>), e é equivalente a disabled={true}. Escrever disabled="disabled", como se fazia no HTML antigo, também funciona, mas é ruído.

8. Os que não mudam e os que enganam

A maior parte dos atributos atravessa o JSX sem tradução. href, src, alt, title, id, lang, target, placeholder, type — todos iguais. Os que começam com data- e aria- também, e isso é sorte: são justamente os que carregam dado extra e informação de acessibilidade, e mudar de nome neles quebraria bibliotecas inteiras.

Agora a parte que engana. O React 19 repassa atributos desconhecidos para o DOM, então um erro de digitação no nome não gera erro: ele vira um atributo esquisito no HTML e a classe não é aplicada. O inspetor mostra clases="cartao" e o CSS não tem o que fazer com isso. É a falha mais difícil de achar, porque o código parece certo e nada reclama.

> document.querySelector("button").getAttribute("onclick")
null
> document.querySelector("div").getAttribute("clases")
'cartao'

A primeira linha mostra o onclick escrito como texto sendo descartado — o React não cria atributo de evento; ele espera a prop onClick com uma função. A segunda mostra o erro de digitação preservado no DOM. As duas lições: confira o nome no HTML gerado, e desconfie de atributo que existe no inspetor mas não faz efeito.

Um último cuidado com acessibilidade, porque é barato e faz diferença: aria-label não é enfeite. Um botão que mostra só um ícone precisa de nome, e o nome vem daí. Um campo precisa de label ligado por htmlFor ao id do campo — no React o atributo do rótulo é htmlFor, e é o único lugar em que for aparece com outro nome.

Por fim, três props que nunca viram atributo: key, children e ref. Elas são do React, não do HTML. children é o conteúdo entre as tags; key identifica itens de lista, e o React a consome sem escrever nada no elemento; ref guarda uma ligação direta com o elemento do DOM. Procurar key="1" no inspetor é perda de tempo — ele está no React, não no HTML.

9. Cenários do dia a dia

Cenário 1: a classe que não chega no componente

A Ana criou um componente Cartao e usou <Cartao className="cartao" />. Nada mudou na tela. O motivo não é o nome: className é uma prop, e o componente precisa repassá-la ao elemento que desenha — com <div className={props.className}> ou com <div {...props}>. Sem isso, a prop chega e morre. É a diferença entre um atributo de tag comum, que o React aplica sozinho, e uma prop de componente, que é decisão de quem escreveu o componente.

Cenário 2: o preço que sumiu junto com o parágrafo

Ela colou style="color: red" no parágrafo do preço e a página inteira ficou vazia. Não é o CSS que está errado: o componente quebra antes de desenhar, porque style com texto não é aceito. O conserto é trocar por objeto — style={{ color: "red" }} — e o hábito que evita o susto é conferir o painel depois de colar código de outro lugar: HTML copiado costuma trazer class e style no formato antigo.

Cenário 3: o botão que nunca habilita

O código já calculava o estoque e escrevia disabled={quantidade === 0}, mas o botão continuava travado. A causa estava uma linha acima: o valor chegava como texto, vindo de um formulário, e "0" === 0 é falso em JavaScript. Com o tipo certo, o botão passou a responder. Atributo booleano só funciona com booleano de verdade — e o caminho até o booleano é conferir o tipo do dado, não o atributo.

Exercício: traduzir o atributo

O HTML antigo da padaria tinha <div class="cartao">. No JSX, o nome da prop muda. Complete com o nome correto:

<div ="cartao">Pão quentinho</div>

Dica: é className, com C e N maiúsculos, sem hífen e sem ponto. O valor continua sendo texto entre aspas, e no HTML final o atributo aparece como class="cartao".

11. Resumo

Atributo no JSX é prop, e prop tem nome e tipo. O nome muda em três situações: palavra reservada (class vira className, for vira htmlFor), nome composto (tabindex vira tabIndex, maxlength vira maxLength) e evento (onclick vira onClick, com função em vez de texto). Os que começam com data- ou aria- não mudam, e os nomes simples também não.

O tipo depende de como o valor é escrito. Entre aspas, é texto literal. Entre chaves, é JavaScript calculado — e isso vale para número, variável, ternário e string montada. Dois atributos têm tipo obrigatório: style quer um objeto com propriedades em camelCase, e atributo de estado (disabled, required, readOnly) quer booleano de verdade, porque "false" é texto e texto presente já liga o estado.

E a armadilha que fecha a aula: o React 19 é tolerante com atributo desconhecido e o repassa ao DOM. Um nome digitado errado não dá erro — vira atributo inútil, e o CSS não acha a classe. Quando o visual não responde, a ordem de investigação é HTML gerado, depois tipo do valor, e só então o CSS.

Para lembrar

  • class no HTML é className no React.
  • for vira htmlFor; compostos viram camelCase.
  • Aspas para texto, chaves para valor calculado.
  • style recebe objeto: {{ color: "red" }}.
  • Número em estilo ganha px quando faz sentido.
  • disabled="false" ainda desabilita; use {false}.
  • data-* e aria-* ficam iguais.
  • Prop de componente só chega ao DOM se for repassada.
