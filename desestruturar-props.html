Desestruturar Props

O cartão da Ana já recebe um objeto com nome, preço, descrição e peso. Funciona, mas o componente ficou cheio de props.pao.nome, props.pao.preco, props.pao.descricao — a palavra props aparece em toda linha e o olho não encontra mais o que importa. Nesta aula ela aprende o atalho que o JavaScript oferece: pegar as chaves do objeto de uma vez, no próprio parâmetro da função, e usar só os nomes nus dentro do componente. É menos letra, mesma tela.

Você vai aprender
  • O que é desestruturar um objeto, com um exemplo fora do React.
  • Como fazer isso no parâmetro: function Cartao({ nome, preco }).
  • Por que o contrato com quem chama continua igual.
  • Como desestruturar um nível mais fundo: { pao: { nome } }.
  • Como renomear uma prop na entrada: { nome: titulo }.
  • Quando desestruturar no corpo da função, em vez do parâmetro.
  • Os tropeços de quem mistura props com os nomes nus.

1. A cena: a palavra props em toda linha

Este é o componente da Ana depois da aula de objetos. Ele funciona perfeitamente, e é cansativo de ler:

function Cartao(props) {
  return (
    <div className="cartao">
      <h2>{props.pao.nome}</h2>
      <p>{props.pao.descricao}</p>
      <p>{props.pao.peso} · {props.pao.preco}</p>
    </div>
  );
}

Conte as vezes em que props.pao aparece: quatro. Agora imagine o cartão de um produto de verdade, com doze campos. A palavra se repete doze vezes, e cada repetição é uma chance de errar uma letra. Pior: o que muda de um campo para outro — nome, descricao, peso — fica escondido no meio do caminho.

Há também um custo que não aparece na tela: reler. Semana que vem, quando o cartão tiver um campo novo, você vai passar os olhos por essas linhas procurando onde mexer. Cada props.pao. no meio do caminho é ruído igual, e o cérebro gasta energia para ignorá-lo. Código que se lê rápido é código que se corrige rápido — e essa economia vale mais do que parece quando o projeto cresce.

O JavaScript tem um recurso feito exatamente para isso, e ele não é do React: chama-se desestruturação. A ideia é pegar um objeto e “abrir” as chaves em variáveis, de uma vez só. Em vez de escrever o caminho completo a cada uso, você declara uma vez quais campos quer e usa os nomes direto. O componente fica mais curto e mais fácil de ler.

E tem um efeito colateral bom: quando as props aparecem no começo da função, quem lê o componente sabe imediatamente o que ele espera receber. É a documentação que não desatualiza, porque está no lugar onde o código roda.

2. Desestruturar, sem React no meio

Antes de aplicar no componente, veja o mecanismo sozinho. Um objeto com dois campos:

const pao = { nome: "Pão francês", preco: "R$ 1,20" };

const { nome, preco } = pao;
console.log(nome);   // Pão francês
console.log(preco);  // R$ 1,20

A linha const { nome, preco } = pao; diz: “crie duas variáveis, nome e preco, e preencha cada uma com o valor da chave de mesmo nome dentro de pao”. As chaves da esquerda não são um objeto sendo criado — são uma lista de nomes sendo declarada. É por isso que não há dois-pontos nem vírgula depois do último nome.

desestruturar
Abrir um objeto (ou lista) em variáveis. const { nome } = pao cria a variável nome com o valor de pao.nome.
lista de nomes
O que vai entre as chaves: { nome, preco }. Cada nome vira uma variável, na ordem que você quiser.
renomear
Usar dois-pontos para dar outro nome à variável: { nome: titulo } lê a chave nome e guarda em titulo.
aninhado
Desestruturar dentro de outro objeto: { pao: { nome } } pega props.pao.nome direto em nome.
parâmetro
O que a função recebe. No React, o parâmetro é o objeto de props — e pode ser desestruturado ali mesmo.

Três detalhes de comportamento que evitam dúvida. A ordem dos nomes não importa: { preco, nome } produz as mesmas duas variáveis. Chave que sobra no objeto é simplesmente ignorada — desestruturar { nome } de um objeto com dez campos não dá erro nenhum. E você pode declarar só o que vai usar: não é preciso listar tudo. A desestruturação não valida nada; ela só copia, por nome, o que você pediu.

Uma consequência que vale guardar: a desestruturação procura a chave pelo nome. Se o objeto não tem aquela chave, a variável existe e vale undefined — não dá erro. É o mesmo comportamento que você já viu com props.nome, e é a origem de metade dos cartões em branco desta aula.

3. Desestruturar no parâmetro

O parâmetro da função é um objeto, então pode ser desestruturado como qualquer outro. A escrita é a mesma: chaves no lugar do nome do parâmetro. E aqui aparece o primeiro tropeço de quem faz a troca pela metade — a assinatura muda, o corpo continua falando de props.

A assinatura já desestrutura nome, mas o corpo ainda usa props.nome, que não existe mais. Use o nome nu dentro do JSX.

function Cartao({ nome }) {
  return (
    <div className="cartao">
      <h2>{props.nome}</h2>
      <p>R$ 1,20</p>
    </div>
  );
}

function App() {
  return <Cartao nome="Pão francês" />;
}
(o React não desenhou nada: o componente devolveu null?)

function Cartao({ nome }) {
  return (
    <div className="cartao">
      <h2>{nome}</h2>
      <p>R$ 1,20</p>
    </div>
  );
}

function App() {
  return <Cartao nome="Pão francês" />;
}

Antes da correção, o painel avisa que o React não desenhou nada — é o sintoma de um erro que aconteceu antes do return. E não é por causa da desestruturação: é porque props deixou de existir. Quando o parâmetro é { nome }, não há nenhuma variável chamada props dentro da função — só nome. O React não sabe que você quis dizer “as props”; o JavaScript procura uma variável com esse nome, não encontra e para a execução. No navegador, o console do DevTools mostra a mensagem exata: props is not defined.

Essa é a diferença entre os dois estilos, em uma frase: com props, você percorre o objeto com pontos; com { nome }, você já tem os valores soltos. Os dois mostram a mesma coisa na tela. O segundo é mais curto e é o que você vai encontrar em quase todo código React moderno.

Se você está convertendo um componente agora, faça em dois passos e rode depois de cada um. Primeiro troque a assinatura; o painel vai ficar vazio, e isso é esperado. Depois troque os usos dentro do JSX. Dois passos pequenos com uma conferência no meio acham o erro mais rápido do que uma edição grande com três mudanças de uma vez.

4. O contrato com quem chama não mudou

Talvez a parte mais importante desta aula: desestruturar não muda a forma de chamar o componente. A página continua escrevendo nome="Pão francês", e a chave continua se chamando nome. O que mudou foi só como o componente lê o que chegou.

A tabela é a ponte entre as duas aulas anteriores e esta. A coluna do meio é a única que muda; as outras duas continuam iguais. Guarde a leitura: o nome à esquerda dos dois-pontos é sempre a chave que existe no objeto, e o nome à direita é a variável que você vai usar no código.

Vale notar que a escolha é local, por componente. O mesmo objeto de props pode ser lido com pontos num componente e desestruturado no outro, na mesma página. Não existe um “jeito certo” global: existe o jeito que deixa aquele componente legível. Em código de equipe, o mais comum é padronizar — e o padrão moderno é desestruturar no parâmetro quando o componente usa poucas props.

É por isso que a desestruturação é segura de adotar aos poucos. Você pode converter um componente hoje e deixar o vizinho do jeito antigo — os dois funcionam na mesma página, porque a chamada não muda. E se um dia cansar, dá para voltar: é só trocar a assinatura por props e os nomes nus por props.nome.

5. Um nível mais fundo

Quando a prop é um objeto, a desestruturação pode descer junto. Em vez de receber pao e depois andar com pontos, você declara o caminho inteiro de uma vez. É o caso mais comum em projeto de verdade, porque quase todo dado chega agrupado.

A página passa pao={{ nome: "Pão francês" }}, mas a assinatura procura uma prop nome que não existe. Desestruture um nível: { pao: { nome } }.

function Cartao({ nome }) {
  return (
    <div className="cartao">
      <h2>{nome}</h2>
      <p>R$ 1,20</p>
    </div>
  );
}

function App() {
  return <Cartao pao={{ nome: "Pão francês" }} />;
}
<div class="cartao">
  <h2></h2>
  <p>R$ 1,20</p>
</div>

function Cartao({ pao: { nome } }) {
  return (
    <div className="cartao">
      <h2>{nome}</h2>
      <p>R$ 1,20</p>
    </div>
  );
}

function App() {
  return <Cartao pao={{ nome: "Pão francês" }} />;
}

Leia a assinatura em voz alta: “recebo um objeto; dele, quero a chave pao; dentro dela, quero a chave nome; guarde em nome”. O dois-pontos aqui não renomeia — ele entra no objeto. É a mesma ideia do caminho com pontos, escrita de uma vez só.

Vale saber o risco: se a prop pao não vier, a desestruturação de dentro quebra, porque não há objeto para abrir. O sintoma é o mesmo de sempre — tela vazia, sem mensagem clara no painel. Nas primeiras semanas, prefira desestruturar um nível ({ pao } e {pao.nome}) e desça mais só quando o componente já estiver funcionando. Menos elegante, mais fácil de consertar.

6. Renomear com dois-pontos

Às vezes a chave tem um nome que não serve dentro do componente. Pode ser um nome reservado, um nome comprido ou simplesmente um nome que colide com outra variável. A desestruturação permite ler a chave e guardar com outro nome — e é aí que o dois-pontos aparece com o segundo significado dele.

A chamada passa fundo="amber", mas a assinatura procura cor com o nome fundo. Alinhe a assinatura com a chamada, mantendo o uso de fundo.

function Etiqueta({ texto, cor: fundo }) {
  return <span className={"etiqueta " + fundo}>{texto}</span>;
}

function App() {
  return <Etiqueta texto="Novo" fundo="amber" />;
}
<span class="etiqueta undefined">Novo</span>

function Etiqueta({ texto, fundo }) {
  return <span className={"etiqueta " + fundo}>{texto}</span>;
}

function App() {
  return <Etiqueta texto="Novo" fundo="amber" />;
}

Antes, a classe saía como etiqueta undefined, porque cor não existia no objeto e fundo ficava sem valor. A missão confere o atributo class do span, e não só o texto: é o jeito de provar que o valor chegou de verdade.

Repare que a missão podia ser resolvida dos dois lados: mudando a assinatura para { fundo } ou mudando a chamada para cor="amber". As duas funcionam. O que não funciona é deixar um lado com cor e o outro com fundo — e é exatamente esse desencontro que a variante cor: fundo produz quando a chave não existe: a variável é criada, mas vazia.

Quando renomear ajuda? Quando a prop se chama className e você quer usar classe; quando o dado se chama nome e dentro do cartão você quer titulo; quando duas props trariam variáveis de mesmo nome. A regra de leitura é uma só: à esquerda, a chave que veio; à direita, o nome local. Se os dois nomes forem iguais, não precisa de dois-pontos.

7. No parâmetro ou no corpo?

Há duas formas de desestruturar, e as duas são válidas. No parâmetro, como você viu:

function Cartao({ nome, preco }) {
  return <h2>{nome}</h2>;
}

E no corpo da função, logo depois da abertura:

function Cartao(props) {
  const { nome, preco } = props;
  return <h2>{nome}</h2>;
}

A diferença prática é o que fica disponível. No parâmetro, você perde a referência ao objeto props inteiro — o que quase nunca faz falta, mas faz quando você precisa repassar todas as props para outro componente. No corpo, o objeto continua ali: dá para desestruturar algumas chaves, usar Object.keys(props) para conferir o que chegou e repassar o resto adiante.

O segundo estilo tem uma vantagem prática que o primeiro não tem: depois de pegar as chaves que interessam, você ainda pode guardar o resto. Os três pontos, do lado esquerdo da desestruturação, fazem o papel inverso do espalhamento da aula anterior — juntam o que sobrou num objeto novo. É útil quando o componente repassa as props para um filho sem saber quais são.

function Cartao({ nome, ...resto }) {
  console.log("resto: " + JSON.stringify(resto));
  return <h2>{nome}</h2>;
}

Numa chamada com três props, o nome sai separado e o resto vira um objeto com as duas que sobraram: resto vale {"preco":"R$ 1,20","peso":"80 g"}. É a prova de que a desestruturação não perde nada — o que você não pediu continua disponível, agrupado. Essa é a base dos componentes que repassam props: pegam o que precisam e espalham {...resto} no filho.

console: nome: Pão francês, preco: R$ 1,20

A linha acima veio de um componente que recebeu props e desestruturou no corpo: const { nome, preco } = props; seguido de um console.log com os dois valores. É o mesmo resultado de desestruturar no parâmetro — a diferença é que aqui a função ainda tem acesso ao objeto inteiro, caso precise conferir ou repassar.

Escolha pelo tamanho. Componente pequeno, que só usa duas ou três props: no parâmetro, e o código começa mais limpo. Componente que precisa inspecionar o objeto, repassar tudo ou aplicar valores padrão mais elaborados: no corpo, com a desestruturação na primeira linha. E não misture os dois no mesmo componente sem motivo — é a receita para ler props.nome num lugar onde a variável se chama nome.

8. Os tropeços de quem desestrutura

Quase todos os problemas desta aula vêm de uma confusão só: o que existe dentro da função depois da assinatura. Com props, existe o objeto; com { nome }, existem as variáveis soltas e mais nada. Trocar a assinatura sem trocar o corpo é o erro número um.

9. Cenários do dia a dia

Os três cenários abaixo são a mesma história contada de três jeitos: a assinatura e a chamada precisam combinar. Quando não combinam, a tela fica vazia e o console fica limpo — o pior par possível.

Cenário 1: a assinatura mudou e o corpo não

A Ana trocou function Cartao(props) por function Cartao({ nome }) e esqueceu o {props.nome} da linha seguinte. A tela ficou em branco. O conserto foi apagar o props. — depois disso, o componente passou a mostrar o nome e ficou três letras mais curto em cada linha.

Cenário 2: o cartão que esperava dois níveis

Ela aprendeu a desestruturar e fez { pao: { nome, preco } } num componente que recebia as props soltas, sem pao. O React não reclamou de nada, mas a tela ficou vazia e o console do navegador apontou o erro ao abrir o objeto. O conserto foi voltar para { nome, preco }.

Cenário 3: o nome que não casava

A chamada passava fundo="amber" e a assinatura pedia cor, renomeando para fundo. Resultado: a classe saiu como etiqueta undefined e a etiqueta ficou sem cor. O conserto foi um dos dois: mudar a chamada para cor="amber" ou a assinatura para { fundo }. O importante é que os dois lados usem a mesma palavra.

Um roteiro para quando o componente desestruturado não mostra nada. Primeiro, confira se a chamada passa a chave que a assinatura pede — é o caso mais comum. Segundo, imprima o valor com console.log; se sair undefined, o nome está diferente em algum lugar. Terceiro, reduza: volte a assinatura para props e leia com pontos. Se funcionar assim, o problema é só de nomes; se não funcionar, o problema nunca foi a desestruturação. Esse último passo evita horas perdidas com a suspeita errada.

11. Resumo

Desestruturar é abrir um objeto em variáveis. No React, o objeto é sempre o de props, e o lugar mais comum de abrir é o parâmetro: function Cartao({ nome, preco }). Dentro do componente, você usa nome e preco direto, sem props. na frente — e sem a variável props, que deixa de existir.

Para descer um nível, { pao: { nome } }. Para renomear, { nome: titulo }. A chamada do componente não muda em nada: o contrato é o mesmo, só a leitura ficou mais curta. Quem está começando deve desestruturar um nível por vez e conferir a tela a cada passo.

Para lembrar

  • function Cartao({ nome }) abre a prop nome em variável.
  • Com a assinatura desestruturada não existe props dentro da função.
  • Chamada igual, leitura mais curta: o contrato não muda.
  • Nível a mais: { pao: { nome } }.
  • Renomear: { nome: titulo } — esquerda é a chave, direita é a variável.
  • Chave que não veio vale undefined: aparece como nada, sem erro.
  • Também dá para desestruturar no corpo: const { nome } = props;.
  • Assinatura muda, corpo tem de mudar junto.
