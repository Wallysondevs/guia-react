Listas com map

A vitrine da Ana tem quatro pães hoje, e ela digitou os quatro à mão: um <li> por linha, com o nome copiado e colado. Na sexta-feira chegaram dois pães novos, e ela esqueceu de acrescentar um deles — a vitrine ficou um dia inteiro sem o croissant, e ninguém entendeu por quê. O problema não é a digitação: a lista de pães já existe em algum lugar, num array, e a tela deveria ser consequência dela. Nesta aula ela conhece o map, a ferramenta que transforma um array de dados numa lista de elementos.

Você vai aprender
  • O que o map faz com um array, sem React no meio.
  • Como escrever {lista.map(...)} dentro do JSX.
  • Como cada item vira um <li> — e como vira um cartão com nome e preço.
  • Por que a função com chaves esconde o resultado e deixa a lista vazia.
  • O que fazer com lista vazia, com a contagem e com o número zero.
  • O primeiro contato com a key, que ganha aula própria depois desta.
  • As mensagens de erro que aparecem quando o map é escrito no lugar errado.

1. A cena: a vitrine escrita à mão

O componente da vitrine da padaria está assim:

function App() {
  return (
    <ul className="vitrine">
      <li>Pão francês</li>
      <li>Brioche</li>
      <li>Sonho</li>
      <li>Pão de queijo</li>
    </ul>
  );
}

Quatro linhas quase idênticas. Funciona, e por isso mesmo engana. A Ana copiou a primeira linha e colou três vezes, trocando só o texto. Quando o pão do dia muda, ela edita o componente. Quando um pão acaba, ela edita o componente. Quando entra um pão novo, ela precisa lembrar de editar o componente — e foi exatamente esse lembrete que falhou no dia do croissant.

O que a Ana tem de verdade é um dado: a lista dos pães da vitrine. Num arquivo de JavaScript, essa lista se escreve assim:

const paes = ["Pão francês", "Brioche", "Sonho", "Pão de queijo", "Croissant"];

Uma linha, cinco pães, e a ordem é a do array. Se a tela fosse desenhada a partir desse array, o croissant apareceria sozinho no dia em que entrou — sem ninguém editar JSX. O trabalho, então, é um só: pegar cada item do array e transformá-lo num <li>. Quem faz esse trabalho é o map, e ele não tem nada de React.

2. O map, sem React no meio

map é um método de array. Ele percorre o array e devolve um array novo, do mesmo tamanho, em que cada posição é o resultado da função que você entregou, aplicada ao item daquela posição. A função que você entrega é chamada de callback, e é escrita quase sempre como arrow function:

const precos = [1.2, 4.5, 3.0];

const comAumento = precos.map((preco) => preco + 0.3);

console.log(comAumento);

Três coisas aconteceram. O map pegou o 1.2, aplicou a função e guardou 1.5. Depois o 4.5, guardou 4.8. Depois o 3.0, guardou 3.3. O array precos continua exatamente como estava; o que mudou foi o array novo, comAumento. Essa parte de “não mexer no original” vale a pena guardar: no React, o array de dados costuma ser a fonte da verdade, e estragar ele no meio da renderização é uma fonte clássica de bug.

Três propriedades do map explicam todo o resto da aula. Primeira: ele devolve sempre um array do mesmo tamanho do original — cinco itens entram, cinco saem. Segunda: o que sai é o que a função devolveu, item por item; se a função não devolve nada, o array novo fica cheio de undefined, sem erro nenhum. Terceira: ele só existe em array — em objeto não há map, e isso rende uma das mensagens de erro mais confusas para quem está começando.

MétodoO que devolveServe para montar lista no JSX?
maparray novo, do mesmo tamanho, com cada item transformadosim: é o método das listas
forEachundefined — ele só executa a função, não junta resultadonão: o JSX recebe undefined e não desenha nada
filterarray novo só com os itens aprovados pela funçãosim, e costuma vir antes do map
findum item só, o primeiro aprovadonão para listas: é para achar um item
Object.keys(objeto)array com os nomes das chavessim: é o jeito de percorrer objeto

A linha do forEach merece um comentário, porque é a confusão mais comum de quem vem de tutoriais antigos: forEach serve para fazer algo com cada item (imprimir, somar, chamar uma API), não para devolver algo. Lista na tela é devolver, então é map.

3. Cada item vira JSX

Com o map na mão, o componente fica assim:

function App() {
  return (
    <ul className="vitrine">
      {paes.map((pao) => <li>{pao}</li>)}
    </ul>
  );
}

Vale ler essa linha por partes, porque ela concentra a sintaxe toda:

  • As chaves { e } dizem “aqui dentro é JavaScript, não texto”. Tudo que aparece entre elas é uma expressão, e o valor dela é o que o React desenha naquele ponto.
  • paes.map(...) chama o método no array dos pães. O resultado é um array de elementos <li> — e o React sabe desenhar array de elementos.
  • (pao) => é a função que recebe cada item, um de cada vez. O nome pao é escolha da Ana; podia ser item, nome ou paoDaVez. Ele existe só dentro do parêntese e do que vem depois da seta.
  • <li>{pao}</li> é o molde que o map repete. O {pao} lá dentro é outra expressão, agora para o conteúdo daquele item.

A vitrine mostra só o primeiro pão, porque alguém escreveu paes[0]. Use o map para desenhar os três — e dê a cada <li> uma key com o próprio nome do pão.

const paes = ["Pão francês", "Brioche", "Croissant"];

function App() {
  return (
    <ul className="vitrine">
      <li>{paes[0]}</li>
    </ul>
  );
}
<ul class="vitrine">
  <li>Pão francês</li>
</ul>

const paes = ["Pão francês", "Brioche", "Croissant"];

function App() {
  return (
    <ul className="vitrine">
      {paes.map((pao) => <li key={pao}>{pao}</li>)}
    </ul>
  );
}

O HTML que sai no painel é o mesmo da versão escrita à mão, com uma diferença que muda tudo: agora a tela segue o array. Sexto pão no array, sexto <li> na tela. Nenhuma linha do componente é editada.

Antes de seguir, um detalhe da função (pao) => <li>{pao}</li>: ela não tem chaves, não tem return e mesmo assim devolve o <li>. Chama-se retorno implícito, e é só uma forma curta de escrever. Guarde essa palavra, porque a próxima seção é justamente sobre o que acontece quando a Ana coloca chaves.

array
A lista de dados — paes, com um texto por posição. O React não desenha array; ele desenha o que o map devolve a partir dele.
map
Método de array que percorre os itens e devolve um array novo do mesmo tamanho, com cada item transformado pela função que você entrega.
callback
A função entregue ao map: no exemplo, (pao) => <li>{pao}</li>. Ela roda uma vez para cada item.
retorno implícito
Quando a arrow function não tem chaves, o que vem depois da seta é devolvido automaticamente — sem return. Com chaves, o return volta a ser obrigatório.
expressão
Qualquer coisa que produza um valor: paes.map(...), {pao}, pao.preco. Entre chaves, no JSX, só entra expressão.
key
Marca única de cada elemento da lista, para o React saber qual é qual. Não aparece na tela. É o assunto da aula seguinte, A key.

4. A lista de objetos: cada pão virou um cartão

Texto puro resolve vitrine simples. Na padaria, cada pão tem nome e preço, então o array deixa de ser de textos e passa a ser de objetos:

const paes = [
  { nome: "Pão francês", preco: "R$ 1,20" },
  { nome: "Brioche", preco: "R$ 4,50" },
  { nome: "Sonho", preco: "R$ 3,00" }
];

Dentro do map, o callback recebe um objeto por vez, e não mais um texto. Então {pao} não serve: objeto não é filho válido de elemento. O que vai para a tela é o que você escolhe do objeto — {pao.nome}, {pao.preco} — exatamente como se lê prop de objeto em Props com Objetos.

A vitrine mostra apenas o primeiro pão, escrito com paes[0]. Troque pela lista inteira: um <li> por pão, com nome, travessão e preço — e key={pao.nome} em cada um.

const paes = [
  { nome: "Pão francês", preco: "R$ 1,20" },
  { nome: "Brioche", preco: "R$ 4,50" },
  { nome: "Sonho", preco: "R$ 3,00" }
];

function App() {
  return (
    <ul className="vitrine">
      <li>{paes[0].nome} — {paes[0].preco}</li>
    </ul>
  );
}
<ul class="vitrine">
  <li>Pão francês — R$ 1,20</li>
</ul>

const paes = [
  { nome: "Pão francês", preco: "R$ 1,20" },
  { nome: "Brioche", preco: "R$ 4,50" },
  { nome: "Sonho", preco: "R$ 3,00" }
];

function App() {
  return (
    <ul className="vitrine">
      {paes.map((pao) => <li key={pao.nome}>{pao.nome} — {pao.preco}</li>)}
    </ul>
  );
}

O map não mudou: continua transformando cada item no molde que você escreveu. O que mudou foi o molde. Dá para ir mais longe e usar uma <div className="cartao"> em vez do <li>, com nome, preço e um botão de encomendar dentro — o map não se importa com o tamanho do molde.

Com o JSX crescendo, aparecem três lugares onde a mesma lista pode ser escrita. Nenhum é “o certo”; todos funcionam, e a escolha depende do tamanho do molde e de quantas vezes ele reaparece:

Onde fica o mapComo ficaQuando usar
direto no JSX{paes.map((pao) => <li key={pao.nome}>{pao.nome}</li>)}molde de uma linha, uma lista só na página
numa variável antes do returnconst itens = paes.map(...) e depois {itens}quando precisa filtrar, ordenar ou contar antes de desenhar
dentro de um componente{paes.map((pao) => <Item key={pao.nome} pao={pao} />)}molde com várias linhas, ou reaproveitado em outra página

A terceira linha é a que mais rende: o componente Item recebe um pão por prop e cuida do próprio desenho, e o map só decide quantas vezes ele aparece. Repare que a key vai no componente <Item>, não na <div> de dentro dele — quem repete é o map, então é o elemento repetido que precisa da marca.

5. A armadilha do return

A primeira vez que a Ana precisou de mais de uma linha no molde, ela abriu chaves. Era o que fazia em qualquer função JavaScript. O resultado foi uma vitrine em branco:

function App() {
  return (
    <ul className="vitrine">
      {paes.map((pao) => {
        <li key={pao}>{pao}</li>;
      })}
    </ul>
  );
}

Nada de erro no painel: a lista simplesmente saiu vazia, como <ul class="vitrine"></ul>. A explicação está na seção 3. Chaves, numa arrow function, significam bloco de código — e bloco de código só devolve o que tem return. Sem return, a função devolve undefined para cada item, o map devolve um array de undefined, e o React não desenha undefined. Não é bug do React: é a regra da linguagem.

A função do map abre chaves e não devolve nada, então os dois pães sumiram. Faça o map devolver o <li> — troque as chaves por parênteses, ou escreva o return.

const paes = ["Pão francês", "Sonho"];

function App() {
  return (
    <ul className="vitrine">
      {paes.map((pao) => {
        <li key={pao}>{pao}</li>;
      })}
    </ul>
  );
}
<ul class="vitrine"></ul>

const paes = ["Pão francês", "Sonho"];

function App() {
  return (
    <ul className="vitrine">
      {paes.map((pao) => (
        <li key={pao}>{pao}</li>
      ))}
    </ul>
  );
}

As duas saídas são boas e você vai ver as duas em código alheio. A dos parênteses troca chaves por parênteses — e parêntese só agrupa, não cria bloco, então o retorno volta a ser implícito. A do return mantém as chaves e escreve a palavra:

      {paes.map((pao) => {
        return <li key={pao}>{pao}</li>;
      })}

Na prática, os parênteses servem para molde de uma expressão só, mesmo que ela ocupe várias linhas fisicamente. O return aparece quando há trabalho antes dele: calcular a classe do pão quente, formatar o preço, decidir se mostra o botão de encomendar. Aí o corpo cresce e o return fica no fim, devolvendo o JSX. Um console.log dentro das chaves, antes do return, é uma boa forma de ver o item chegando.

6. A key que o React pede

Todos os exemplos até aqui escrevem key={...} no elemento que o map repete. A aula inteira é sobre map, então cabe a explicação curta — o assunto completo fica em A key.

  • A key não vira atributo no HTML e não aparece na tela. É um recado para o React.
  • Ela identifica cada elemento da lista, para que o React saiba qual é qual quando a lista muda.
  • O valor precisa ser único dentro daquela lista: o nome do pão serve, o preço não (dois pães podem custar o mesmo).
  • A regra prática desta aula: sempre que o map devolve um elemento por item, dê uma key a esse elemento.

Quando a key falta, o painel daqui não acusa nada — a lista aparece igual. O aviso existe, mas é do console do navegador de verdade, e o custo dele aparece depois, quando a lista muda e o React começa a reaproveitar o elemento errado. Como este guia usa listas que mudam a partir da aula seguinte, vale pegar o hábito agora, enquanto o molde é pequeno.

7. Lista vazia, contagem e o zero

Array vazio não é erro. O map de um array vazio devolve um array vazio, e o React não desenha nada: a <ul> sai com zero <li>. É o comportamento correto — mas é feio na tela, então quase sempre a página diz alguma coisa no lugar da lista:

const paes = [];

function App() {
  return (
    <div>
      <h2>Vitrine</h2>
      <p>{paes.length} pães</p>
      {paes.length === 0 && <p className="aviso">Nenhum pão na vitrine.</p>}
      <ul className="vitrine">
        {paes.map((pao) => <li key={pao}>{pao}</li>)}
      </ul>
    </div>
  );
}

No painel, esse componente desenha o título, o parágrafo 0 pães, o aviso e uma <ul class="vitrine"></ul> vazia no fim. paes.length é a contagem, e está disponível em qualquer array. O && é a condição curta: se a esquerda for verdadeira, desenha a direita. Isso é renderização condicional, e voltaremos lá com calma.

Uma pegadinha dessa contagem: o número 0 aparece na tela. Se a Ana escrevesse {paes.length && <p>Nenhum pão</p>}, com a lista vazia sairia um 0 solto antes do aviso — porque 0 é um valor desenhável. Já null, false e undefined não desenham nada. Confundir “falso” com “invisível” é a origem de um 0 perdido no meio da página.

console: quantidade: 3
console: nomes: ["Pão francês","Brioche","Sonho"]

Essas duas linhas saíram de um console.log("quantidade:", paes.length) e de um console.log("nomes:", paes.map((pao) => pao.nome)) colocados no começo do componente. É um bom jeito de conferir a lista antes de culpar o JSX: se o array já vem certo, o problema está no molde; se vem vazio, o problema está na origem do dado. E se a lista chega por prop, lembre de props padrão: { paes = [] } evita o erro de percorrer undefined.

8. O que não funciona

Três tropeços aparecem sempre, e cada um tem uma mensagem própria. O primeiro é de compilação: o molde abre <li> e fecha </ul>. Repare que o erro aponta a linha do map, não a linha do </ul>:

      {paes.map((pao) => <li key={pao}>{pao}</ul>)}
Erro: não compilou: /App.jsx: Expected corresponding JSX closing tag for <li>. (6:44)

A leitura é literal: “esperava a tag de fechamento correspondente para <li>”. O 6:44 é linha e coluna — linha 6, coluna 44 —, e a linha que começa com > na mensagem completa é a que tem o problema. Conserto: fechar </li> e fechar o </ul> fora do map.

O segundo tropeço não é erro de JSX, é erro de tipo: chamar map em objeto. O componente para no meio da renderização, e o painel mostra a mensagem genérica de render vazio:

const pao = { nome: "Pão francês", preco: "R$ 1,20" };

function App() {
  return <ul className="vitrine">{pao.map((item) => <li>{item}</li>)}</ul>;
}
(o React não desenhou nada: o componente devolveu null?)

A causa real é pao.map is not a function: objeto não tem map. Para percorrer objeto, transforme-o em array primeiro — Object.keys(pao).map((chave) => ...) — ou percorra o array de objetos que veio antes. O terceiro tropeço é o da seção 5: chaves sem return, painel com a lista vazia e nenhuma mensagem de erro.

9. Cenários do dia a dia

Cenário 1: o croissant que não entrou

A vitrine tinha quatro pães escritos à mão quando o croissant chegou. A Ana acrescentou o pão ao array de dados e esqueceu de editar o componente — a tela ficou uma semana desatualizada. Depois do map, o array virou a única fonte: ela acrescenta o croissant no dado e a vitrine o mostra na mesma hora, sem tocar no JSX. O trabalho de “manter a tela” deixou de existir.

Cenário 2: o preço que mudava em nove lugares

O pão de queijo aparecia na vitrine, no carrinho e no recibo do dia — três componentes, cada um com o preço digitado. Quando o quilo subiu, a Ana esqueceu o recibo e cobrou um valor diferente do que a vitrine anunciava. Agora o preço vive num objeto só, e cada tela o percorre com map: mudou o dado, mudaram as três telas.

Cenário 3: a vitrine do fim do dia

Depois das seis, a padaria vende quase tudo e às vezes não sobra pão nenhum. Na primeira versão, a página ficava com um quadrado branco embaixo do título, e os clientes achavam que o site tinha caído. A condição paes.length === 0 com a mensagem “Nenhum pão na vitrine” resolveu — e a lista vazia continuou sendo desenhada, só que discretamente.

Exercício: a lista de ingredientes

O pão recheado tem uma lista de ingredientes que vem num array, e o componente precisa desenhar um ingrediente por linha. Complete o espaço com o método que transforma cada item num <li>:

const ingredientes = ["Queijo", "Presunto", "Orégano"]; function App() { return <ul className="ficha">{ingredientes.((item) => <li key={item}>{item}</li>)}</ul>; }

Dica: é o método que devolve um array novo, do mesmo tamanho do original. Se você escrever o método que só executa a função — o das listas de tutorial antigo —, o JSX recebe undefined e a lista sai vazia.

11. Resumo

Lista na tela é dado transformado. O map percorre o array e devolve um array novo do mesmo tamanho, com cada item virado no molde que você escreveu: {paes.map((pao) => <li key={pao}>{pao}</li>)}. As chaves dizem “aqui é JavaScript”; a arrow recebe um item por vez; o JSX depois da seta é o que se repete.

Se o molde ganha mais de uma linha, ou você usa parênteses (retorno implícito) ou usa chaves com return. Chaves sem return não dão erro: dão lista vazia. Item repetido pelo map pede uma key única — a aula seguinte é sobre ela. E lista vazia é caso normal: o map devolve vazio, o React não desenha nada, e a página diz o que fazer no lugar.

Para lembrar

  • map transforma: entra array, sai array do mesmo tamanho.
  • forEach não devolve nada; não serve para lista no JSX.
  • A expressão vai entre chaves: {lista.map(...)}.
  • O molde é o JSX depois da seta: (pao) => <li>{pao}</li>.
  • Com chaves, return é obrigatório; com parênteses, é implícito.
  • Objeto não tem map: use Object.keys(objeto).map(...).
  • key vai no elemento repetido, com valor único dentro da lista.
  • Lista vazia desenha nada; o 0 da contagem, esse aparece.
