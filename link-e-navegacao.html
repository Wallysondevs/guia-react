Link e Navegação

O menu da Ana funciona: clicar em "Pães" troca a tela e o endereço acompanha. Só que o menu é feito de botões, e botão não abre em nova aba, não tem "copiar endereço" e não aparece na lista de links do leitor de tela. Quando ela trocou por links de verdade, a página começou a piscar e o pedido em andamento se perdeu. Nesta aula ela acerta as duas coisas: a âncora que o navegador entende e o clique que não recarrega.

Você vai aprender
  • Por que navegação se escreve com <a href> e não com <button>.
  • O que o preventDefault faz e por que ele é obrigatório num link interno.
  • O componente Link: destino, rótulo e clique interceptado.
  • Como tratar links externos sem prendê-los no roteador.
  • O que fazer com mailto, tel e download.
  • Foco, rolagem e o item ativo depois da troca de tela.

1. A cena: o menu de botões

No fim da aula de rotas por hash, o site da Ana navegava. O menu, porém, era uma fileira de <button>, cada um chamando irPara. Funcionava no clique simples e falhava em tudo o mais: o Ctrl+clique não abria em nova aba, o botão do meio não fazia nada, o menu de contexto não oferecia "copiar endereço do link" e o leitor de tela anunciava "botão, Pães" — sem dizer que aquilo levava a outra página.

A cliente reclamou do detalhe mais caro: ela queria mandar o link dos pães para a filha. Não havia link para copiar; havia um botão. O endereço até mudava depois do clique, mas o botão em si não levava a lugar nenhum.

A correção parece pequena — trocar <button> por <a> — e mexe em três coisas ao mesmo tempo: semântica, comportamento do navegador e o roteador. É o que esta aula desmonta, peça por peça.

2. Por que âncora, e não botão

A regra é antiga e não tem a ver com React: link é para navegar, botão é para agir. Salvar, somar, abrir um modal — botão. Ir para outra tela, outro endereço — link. O navegador trata os dois de formas diferentes porque essa diferença é a base da web.

O que o cliente faz<a href><button>
Ctrl+clique ou botão do meioabre em outra abanada
Menu de contextocopiar endereço, abrir em nova janelasem opções de link
TecladoEnter navegaEnter e espaço disparam o clique
Leitor de telaanuncia "link, Pães"anuncia "botão, Pães"
Antes do JavaScript carregarjá naveganão faz nada

Esse último item é o mais subestimado. Um site com links funciona em conexão ruim, em navegador antigo e quando o JavaScript quebra. Um site com botões depende do JavaScript para tudo — inclusive para o cliente saber que aquilo era um link.

Então o menu passa a ser uma lista de âncoras com href de verdade: <a href="#/paes">Pães</a>. Se nada mais for feito, o navegador já troca o hash e o seu roteador, que escuta hashchange, desenha a tela nova. Meio caminho andado, sem uma linha de código.

3. O clique que recarrega a página

Se a âncora aponta para um caminho de verdade — <a href="/paes"> —, o navegador faz o que sabe: pede o documento ao servidor e recarrega tudo. O React é desmontado, o estado se perde, o carrinho esvazia e a tela pisca. Numa rota por hash o estrago é menor, mas o princípio é o mesmo: o clique padrão é uma navegação do navegador, não do seu roteador.

GET https://loja.test/padaria/ 200 (from cache)
documento recarregado — o estado do React foi perdido

Para uma aplicação de página única, o clique tem de ser interceptado: você cancela o comportamento padrão e faz a troca por conta própria. Isso é uma linha — e.preventDefault() — e é a diferença entre um site que pisca e um que desliza.

Vale entender o que o preventDefault não faz: ele não impede o seu código de rodar, não cancela o evento para outros handlers e não tem nada a ver com stopPropagation. Ele cancela apenas a ação padrão do navegador para aquele evento — no caso de uma âncora, ir para o endereço.

4. O componente Link

Com a âncora e o preventDefault na mão, o componente fica curto: recebe o destino, monta o href e intercepta o clique para chamar o roteador. O rótulo vem por children.

O Link do menu está renderizando um botão, então não há link nenhum para copiar. Troque por uma âncora com href e mantenha a troca de tela sem recarregar.

const janela = new EventTarget();
janela.hash = "#/inicio";

function irPara(hash) {
  janela.hash = hash;
  janela.dispatchEvent(new Event("hashchange"));
}

function useRota() {
  const [rota, setRota] = useState(janela.hash);

  useEffect(() => {
    const aoMudar = () => setRota(janela.hash);
    janela.addEventListener("hashchange", aoMudar);
    return () => janela.removeEventListener("hashchange", aoMudar);
  }, []);

  return rota.replace(/^#\/?/, "") || "inicio";
}

function Link({ para, children }) {
  return <button onClick={() => irPara(para)}>{children}</button>;
}

function App() {
  const rota = useRota();

  return (
    <div>
      <nav>
        <Link para="#/paes">Pães</Link>
        <Link para="#/contato">Contato</Link>
      </nav>
      <p>Tela: {rota}</p>
    </div>
  );
}

</div>

Repare no que o href faz e o clique não precisa fazer: ele dá ao navegador o endereço real daquela tela. É o que permite copiar, abrir em nova aba e funcionar antes do JavaScript. O onClick só evita a recarga quando o cliente está na mesma aba e o roteador pode responder mais rápido.

href
O endereço que a âncora representa. É o que o navegador mostra ao passar o mouse e o que o "copiar endereço" entrega.
preventDefault
Cancela a ação padrão do navegador naquele evento. Numa âncora, evita sair da página.
children
O conteúdo entre as tags do Link — o rótulo clicável. É por aqui que o texto aparece.
link interno
Um endereço do próprio site. É o que o roteador deve interceptar.
link externo
Um endereço de outro domínio. O roteador não tem o que fazer com ele: quem navega é o navegador.

O nome do componente é uma escolha infeliz da história: quase toda biblioteca de rotas chama o componente de Link, e o React tem uma tag interna chamada... link, de minúscula, que serve para carregar CSS. Como componente começa com maiúscula, não há confusão para o React; mas vale saber que <link> e <Link> não têm nada a ver.

5. Links externos, download e contato

Nem todo href é rota. Um link para o perfil no Instagram, um PDF do cardápio, um mailto: — nada disso deve passar pelo roteador. Se você interceptar todos os cliques, o cliente clica no Instagram e não acontece nada: o preventDefault cancelou a ida, e o seu irPara não conhece aquele destino.

O link do cardápio aponta para outro site, mas usa o Link do roteador: o clique é cancelado e nada abre. Crie um link externo que abra em outra aba com rel="noreferrer".

O target="_blank" abre em outra aba. O rel="noreferrer" acompanha por dois motivos: impede que a página de destino saiba de onde o cliente veio e evita uma falha de segurança conhecida em que a aba nova controla a antiga. Os navegadores modernos já protegem o caso comum, mas escrever o atributo é barato e explícito.

Para download, o atributo é download no próprio href. Para telefone, href="tel:+5511999990000"; para e-mail, href="mailto:ana@notebook". Nos três casos, nada de preventDefault: o navegador sabe o que fazer melhor do que o seu roteador.

6. O Link que discorda do href

Esquecer o preventDefault tem um sintoma conhecido: a página pisca e o estado some. Mas existe um irmão mais discreto desse bug: o href aponta para um lugar e o onClick manda para outro. O endereço que o cliente copia diz "pães"; a tela que abre diz "início".

Os dois valores saem de fontes diferentes: o href é a prop que veio do menu, e o destino do irPara é o que o handler escreveu. Se alguém troca um e esquece o outro — numa refatoração, num teste, num copiar e colar —, o link passa a mentir. E o pior: o F5 costuma "consertar", porque aí a tela é lida do endereço. Você recarrega, funciona, e conclui que era cache.

clique em Pães → href: #/paes | enviado: #/inicio
tela depois do clique: inicio

Essas duas linhas são um console.log dentro do handler, imprimindo a prop e o valor que vai para o roteador. Quando os dois aparecem na mesma linha, a discordância fica óbvia — e é o tipo de log que vale a pena deixar no código enquanto você mexe em navegação.

O link tem o href certo, mas o handler manda o roteador para a home: uma variável esquecida de um teste anterior. Faça o clique levar para onde o href diz.

No painel, a prova é direta: no código quebrado o clique não muda o texto; no consertado, a tela passa para paes. No navegador de verdade, o sintoma é o endereço que não muda quando deveria — ou o contrário, a tela que muda e o endereço que fica.

7. Depois do clique: foco, rolagem e item ativo

Trocar de tela sem recarregar tem um efeito colateral invisível: o foco do teclado fica onde estava. Quem navega com o teclado aperta Enter no link e continua com o foco num elemento da tela antiga, que acabou de sair da árvore; o próximo Tab começa do topo do documento. Para quem usa leitor de tela, a mudança de tela passa em silêncio.

A correção é mover o foco para o título da tela nova depois da troca. Como isso é efeito colateral, morre num useEffect que observa a rota:

const titulo = useRef(null);

useEffect(() => {
  if (titulo.current) titulo.current.focus();
}, [rota]);

return <h1 tabIndex={-1} ref={titulo}>{nomeDaTela}</h1>;

O tabIndex={-1} permite focar o elemento por código sem colocá-lo na ordem do Tab. A rolagem é o mesmo tipo de problema: o navegador mantém a posição e a tela nova pode abrir no meio. Rolar para o topo no mesmo efeito resolve os dois de uma vez.

O terceiro item é o mais simples: marcar o link da tela atual. Com âncoras, o atributo é aria-current="page" — e ele vale tanto para o leitor de tela quanto para o seu CSS, que pode usar a[aria-current="page"] para destacar sem precisar de classe extra.

Repare no último caso: #precos também é hash, e o seu roteador pode confundi-lo com uma rota. Uma regra simples resolve: rotas começam com #/, âncoras de página não. Quem normaliza a rota tirando #/ já separa os dois mundos sem esforço.

8. Um clique, três caminhos

Vale juntar tudo num parágrafo, porque é fácil se perder. Quando o cliente clica num link interno, a ordem é: o seu onClick roda, cancela a navegação padrão e pede a troca de rota; o roteador muda o endereço; o evento de mudança avisa o componente; a tela nova é desenhada. Nenhum documento é baixado.

Quando o cliente usa Ctrl+clique, o navegador abre em outra aba sem passar pelo seu onClick — e é assim que deve ser. Quando o link é externo, você nem registra handler: o navegador cuida de tudo. Três caminhos, um componente, e a diferença entre eles é justamente o que o href diz.

Essa é a razão pela qual as bibliotecas de rota expõem um <Link> em vez de ensinar "use onClick". Elas querem que o elemento continue sendo um link de verdade, com endereço, com histórico e com o comportamento nativo que ninguém precisa reimplementar.

9. Cenários do dia a dia

Cenário 1: o menu que não dava para copiar

O menu era de botões e a cliente queria mandar o link dos pães para a filha. Não havia link: só um botão que, quando clicado, mudava o endereço. Trocado por âncoras, o "copiar endereço" apareceu no menu de contexto, e o Ctrl+clique passou a abrir em outra aba, já na tela certa.

Cenário 2: o Instagram que não abria

Ela pôs o perfil da padaria no menu usando o mesmo Link do roteador. O clique não fazia nada: o preventDefault cancelava a ida ao Instagram e o roteador não conhecia aquele destino. Link externo pede âncora comum — sem interceptar, com target e rel.

Cenário 3: o pedido que se perdia ao trocar de tela

A cliente preenchia o pedido, clicava em "Pães" para conferir o preço e voltava: o formulário estava vazio. Faltava o preventDefault, então cada clique recarregava o documento e o estado do React nascia do zero. O sintoma — "a página pisca e perde tudo" — é a assinatura de um link não interceptado.

11. Resumo

Navegação se escreve com âncora, não com botão. O href é o que faz o link ser link: dá endereço para copiar, abre em nova aba com Ctrl, funciona no teclado, é anunciado como link e navega mesmo antes do JavaScript carregar. Botão é para ação, e o navegador trata os dois de forma diferente porque a diferença é real.

Num site de página única, o clique interno precisa ser interceptado: e.preventDefault() cancela a navegação do navegador e o seu roteador faz a troca. O componente Link junta as duas coisas — href de verdade e clique interceptado. Já os links externos, os downloads e os mailto: não se interceptam: quem navega ali é o próprio navegador.

Depois da troca, cuide do que ninguém vê: foco no título da tela nova, rolagem para o topo e aria-current no link ativo. Na próxima aula, o endereço ganha a última peça que falta para parecer um site de verdade: o pedaço que muda por item, como o número do pedido em parâmetros de rota.

Para lembrar

  • Link navega; botão age. Use <a href> para trocar de tela.
  • href dá nova aba, cópia do endereço, teclado e semântica de graça.
  • Sem preventDefault, o clique recarrega o documento e o estado se perde.
  • preventDefault cancela só a ação padrão; não é stopPropagation.
  • Link = âncora com href mais preventDefault e o roteador.
  • Link externo: âncora comum com target="_blank" e rel="noreferrer".
  • Download, mailto: e tel: não passam pelo roteador.
  • Rotas começam com #/; âncoras de página, com # e sem barra.
  • aria-current="page" marca o link da tela atual.
  • Depois da troca: foco no título e rolagem para o topo, num efeito.
