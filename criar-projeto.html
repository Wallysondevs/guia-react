Criar o Projeto

Até aqui, todo o código da Ana rodou dentro das caixas deste guia: ela escreve, clica em Rodar e vê o resultado. Isso serve para aprender, mas não é um site. Para o cardápio da padaria existir de verdade, ele precisa de uma pasta no computador dela, de um servidor que abra a página e de um comando que gere a versão final para publicar. Nesta aula ela cria esse projeto do zero, com Node, npm e Vite, e entende o papel de cada arquivo que aparece — inclusive os dois que fazem a ponte entre o HTML e o React.

Você vai aprender
  • O que são Node, npm e Vite, e por que você precisa dos três.
  • Criar o projeto com npm create vite@latest.
  • Instalar as dependências e entender a pasta node_modules.
  • Rodar com npm run dev e ver a página recarregar sozinha.
  • O papel de index.html, main.jsx e App.jsx.
  • Gerar a versão final com npm run build.

1. A cena: o site precisa sair do guia

O cardápio da Ana já tem componentes, props e expressões. Enquanto ele mora em uma caixa do guia, três coisas são verdade: o código vive só naquele quadro, ninguém consegue abrir a página num endereço e o navegador precisa do guia para compilar o JSX. Para virar site, o projeto precisa de um lugar fixo — uma pasta — e de ferramentas que transformem aquele código em arquivos que qualquer navegador entende.

É isso que a aula faz: monta o projeto de verdade. O caminho é o mesmo que qualquer pessoa percorre ao começar um site em React hoje: instalar o Node, criar o projeto com um modelo pronto, instalar as dependências, subir o servidor de desenvolvimento e, no fim, gerar a versão de produção. São cinco comandos e quatro arquivos que importam. O resto é paisagem.

Uma promessa honesta antes de começar: nada aqui é decorado. Você vai precisar lembrar de dois comandos — npm install e npm run dev — e do papel de um arquivo, App.jsx. O resto está na tabela desta aula e no README.md que o próprio Vite escreve na pasta do projeto.

2. Node e npm: o chão onde tudo roda

O React é uma biblioteca JavaScript, e JavaScript nasceu para rodar dentro do navegador. Só que as ferramentas que preparam o código — compilar JSX, juntar arquivos, recarregar a página — precisam rodar fora do navegador. Quem dá esse chão é o Node.js: um programa que executa JavaScript no computador, como se fosse um navegador sem tela.

Junto com o Node vem o npm, o gerenciador de pacotes. Ele baixa bibliotecas de um catálogo público, guarda na pasta do projeto e anota o que baixou. É por meio dele que o React chega ao seu computador — e não por um <script> no HTML, como era em 2015.

Confira se os dois estão instalados abrindo o terminal e pedindo a versão:

$ node -v
v22.14.0
$ npm -v
10.9.2

Duas linhas com número significam que está tudo pronto. Se aparecer "command not found" ou "não é reconhecido como um comando interno", o Node não está instalado: baixe a versão LTS no site oficial, instale e feche e abra o terminal de novo. A versão importa pouco para começar — qualquer Node 20 ou mais novo serve —, mas instalar pelo site oficial é mais simples do que tentar gerenciar versões antes de saber o que é uma versão.

Node.js
O programa que executa JavaScript fora do navegador. É o que roda as ferramentas do projeto.
npm
O gerenciador de pacotes que vem com o Node: baixa bibliotecas, guarda e anota.
Vite
A ferramenta que cria o projeto a partir de um modelo e serve a página durante o desenvolvimento.
dependência
Uma biblioteca que o seu projeto usa. Fica listada no package.json.
servidor de desenvolvimento
Um programa local que abre a página em um endereço e a atualiza quando o arquivo muda.
build
A versão final, otimizada, gerada em arquivos que você publica em qualquer hospedagem.

3. Criando o projeto com Vite

O Vite é a ferramenta que a comunidade React usa para começar um projeto. Ele faz duas coisas bem diferentes: um assistente que monta a pasta com os arquivos de partida, e um servidor que serve essa pasta enquanto você trabalha. A primeira é usada uma vez; a segunda, todo dia.

Abra o terminal, entre na pasta onde você guarda seus estudos e rode o comando, trocando padaria pelo nome que você quiser dar ao projeto:

$ npm create vite@latest padaria
> Select a framework:  › React
> Select a variant:    › JavaScript

Scaffolding project in /home/ana/estudos/padaria...

Done. Now run:

  cd padaria
  npm install
  npm run dev

As perguntas mudam um pouco de versão para versão — algumas trazem a opção de TypeScript, outras perguntam se você quer instalar e subir o servidor na hora. O que não muda são as duas escolhas: React como framework e JavaScript como variante. TypeScript é uma camada a mais que você não precisa agora; escolher "React + TypeScript" no começo significa conviver com erros de tipo antes de saber escrever um componente.

A última linha da resposta é um resumo do que fazer em seguida, e é literalmente a receita: entrar na pasta, instalar e rodar. Guarde esses três comandos — eles aparecem em todo projeto Vite do mundo, e o próprio Vite imprime isso para você não precisar lembrar.

Se o comando reclamar de permissão ou de rede, o problema é do npm, não do React: confira a conexão e, em último caso, rode npm config get registry para ver de onde ele está baixando. Nunca é necessário usar sudo — se algum tutorial mandar, desconfie.

4. npm install: baixando as dependências

O modelo que o Vite criou não traz as bibliotecas: ele traz a lista delas, no package.json. Instalar é o trabalho de baixar essa lista para dentro do projeto:

$ cd padaria
$ npm install

added 154 packages, and audited 155 packages in 12s

found 0 vulnerabilities

Em alguns segundos aparece uma pasta chamada node_modules, com centenas de pastas dentro. Não abra, não edite, não apague arquivo de lá: é depósito, não código seu. O React está lá dentro, junto com o Vite e mais um pacote para cada coisa que eles precisam. O tamanho assusta na primeira vez e é normal — quando o projeto é copiado para outro computador, essa pasta não vai junto; ela é refeita com npm install.

O package.json é a parte que importa e que você pode ler: ele lista as dependências e os scripts, que são atalhos de comando. Os scripts do modelo são sempre os mesmos quatro: dev, build, preview e lint. Cada um é uma linha de comando guardada com nome curto, e é por isso que se escreve npm run dev em vez de decorar a chamada comprida do Vite.

Junto com o package.json nasce o package-lock.json, que trava as versões exatas de tudo o que foi baixado. Ele existe para que outro computador instale exatamente as mesmas versões — se você instalar amanhã e a biblioteca tiver sido atualizada, o resultado é o mesmo. Os dois arquivos vão para o controle de versão; a pasta node_modules, não.

5. npm run dev: o servidor que recarrega

Com as dependências instaladas, o projeto pode rodar. O comando abaixo sobe o servidor de desenvolvimento:

$ npm run dev

  VITE v7.1.0  ready in 312 ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: use --host to expose
  ➜  press h + enter to show help

O endereço é o que você cola no navegador. localhost significa "este computador", e 5173 é a porta onde o servidor está escutando. Enquanto o terminal estiver com essa mensagem, o servidor está de pé: feche o terminal ou aperte Ctrl + C e a página para de responder. Abrir o arquivo HTML com dois cliques não substitui isso, porque o navegador não sabe compilar JSX sozinho.

O ganho grande é a recarga automática. Salve o App.jsx com um texto novo e, em menos de um segundo, o navegador já mostra a mudança — sem apertar F5. Essa troca cirúrgica se chama HMR (hot module replacement), e é o que torna o ciclo de trabalho rápido: você digita, salva, olha. No começo, esse ritmo dá a sensação de que o código está vivo; depois, vira hábito.

Se a porta estiver ocupada por outro projeto, o Vite avisa e escolhe a próxima livre — 5174, 5175 —, e o endereço mostrado é o que vale. E se a página abrir com uma sobreposição preta cheia de texto, é o erro do Vite: ele mostra a mensagem e a linha, o que costuma ser mais útil que o console do navegador.

6. Os arquivos que importam

Dentro da pasta do projeto, a maior parte do que existe é configuração. Quatro arquivos merecem sua atenção, e três deles ficam em src/. A pasta criada fica assim:

padaria/
├── index.html
├── package.json
├── vite.config.js
└── src/
    ├── main.jsx
    ├── App.jsx
    ├── App.css
    └── index.css

O index.html fica na raiz, fora de src/: ele é a porta de entrada. O src/main.jsx é o primeiro código que roda; ele encontra o elemento certo do HTML e monta o React ali dentro. O src/App.jsx é o componente principal — é nele que você vai escrever. E o src/index.css guarda os estilos globais, que valem para a página inteira.

ArquivoO que éVocê mexe?

src/main.jsxmonta o App dentro do #rootquase nunca
src/App.jsxo componente principal, o que aparece na telao tempo todo
src/index.cssestilos globais da páginaquando quiser

Nada de index.html com tags de componente, nada de <App /> dentro do HTML. O React não vive no HTML: ele vive no JavaScript, e o HTML só entrega um espaço vazio com um id para ele ocupar. Quem faz a ligação são as duas linhas do main.jsx, e é justamente aí que começa a confusão de quem está começando.

7. O id que liga index.html e main.jsx

O index.html do modelo tem um div vazio com id="root" e um script que carrega o main.jsx. O main.jsx, por sua vez, procura esse mesmo id para saber onde desenhar. Se os dois nomes não baterem, o React não acha o lugar e nada aparece.

Na caixa abaixo o código foi escrito como se o id fosse root, mas aqui a prévia monta o ponto de entrada com id="raiz" — é o mesmo mecanismo do seu projeto, com outro nome. A missão é acertar o nome, e o erro que aparece é justamente o de "container".

O código procura #root, e nesta prévia o elemento se chama raiz. Troque o nome no getElementById para que o título apareça.

function App() {
  return <h1>Padaria da Ana</h1>;
}

const raiz = document.getElementById("root");
const root = ReactDOM.createRoot(raiz);
root.render(<App />);
Erro: Minified React error #299; visit https://react.dev/errors/299 for the full message or use the non-minified dev environment for full errors and additional helpful warnings.

function App() {
  return <h1>Padaria da Ana</h1>;
}

const raiz = document.getElementById("raiz");
const root = ReactDOM.createRoot(raiz);
root.render(<App />);

No seu projeto o id é root, e é assim que o Vite escreve — não mude o HTML para raiz só porque a caixa do guia usa esse nome. A regra é a que vale sempre: o nome escrito no getElementById tem de ser idêntico ao id do HTML. Minúscula e maiúscula contam, e um hífen a mais derruba tudo.

Sobre a mensagem de erro: o painel desta prévia roda a versão de produção do React, que troca o texto por um número. É por isso que ele mostra "Minified React error #299" em vez de explicar o problema. Na versão de desenvolvimento — a que o Vite usa no seu computador —, a mesma falha aparece escrita assim:

Target container is not a DOM element.

Ou seja: "o alvo não é um elemento do DOM", porque o resultado de procurar um id que não existe é null. Guarde o número 299 e a tradução; quando aparecer um erro minificado, o endereço que vem na mensagem (react.dev/errors/299) leva à explicação completa. É o mesmo erro, em duas línguas.

8. App.jsx e as duas linhas da montagem

O main.jsx faz três coisas, sempre na mesma ordem: pega o elemento do HTML, cria a raiz do React nele e manda desenhar o componente. O App.jsx é o componente em si, e o modelo já traz um com contador, imagem e link — conteúdo de exemplo para provar que funciona. A primeira coisa que você faz num projeto novo é apagar esse conteúdo e escrever o seu.

Duas confusões são tão comuns que aparecem em qualquer fórum: passar a função em vez do elemento, e usar o comando antigo de montagem. As duas caixas abaixo mostram cada uma.

O render recebeu App, a função, em vez de <App />, o elemento. Corrija para que o título apareça.

function App() {
  return <h1>Padaria da Ana</h1>;
}

const raiz = document.getElementById("raiz");
const root = ReactDOM.createRoot(raiz);
root.render(App);
(o React não desenhou nada: o componente devolveu null?)

function App() {
  return <h1>Padaria da Ana</h1>;
}

const raiz = document.getElementById("raiz");
const root = ReactDOM.createRoot(raiz);
root.render(<App />);

Como o painel roda a build de produção, ele só mostra que nada foi desenhado — o React de produção é silencioso para esse tipo de erro. No modo de desenvolvimento, o console do navegador diz:

Functions are not valid as a React child. This may happen if you return
a Component instead of <Component />. Or maybe you meant to call
this function rather than return it.

A frase final é a dica: "talvez você quisesse chamar a função em vez de devolvê-la". Passar App entrega a função para o React desenhar, e função não é conteúdo. Passar <App /> entrega o elemento — o resultado de chamar a função —, e aí o React sabe o que fazer. A diferença é de duas teclas, < e />, e vale a tela inteira.

Este código veio de um tutorial antigo: ReactDOM.render não existe mais no React 19. Troque pela montagem atual, com createRoot e root.render.

function App() {
  return (
    <div>
      <h1>Padaria da Ana</h1>
      <p>Pão quentinho</p>
    </div>
  );
}

const raiz = document.getElementById("raiz");
ReactDOM.render(<App />, raiz);
Erro: ReactDOM.render is not a function

function App() {
  return (
    <div>
      <h1>Padaria da Ana</h1>
      <p>Pão quentinho</p>
    </div>
  );
}

const raiz = document.getElementById("raiz");
const root = ReactDOM.createRoot(raiz);
root.render(<App />);

A mensagem aqui é direta: ReactDOM.render is not a function — não é uma função porque foi removida. Tutoriais de 2019 usam essa forma, e é por isso que copiar código antigo sem conferir a versão custa caro em React: a biblioteca muda, e o que era padrão vira erro. Sempre que encontrar ReactDOM.render em um exemplo, traduza para createRoot mais root.render, que é o jeito atual.

9. Cenários do dia a dia

Cenário 1: "vite: command not found"

A Ana clonou o projeto em outro computador, entrou na pasta e rodou npm run dev. O terminal respondeu que não achava o comando. Motivo: sem node_modules, não existe Vite instalado para rodar, e o package.json só tem a lista. O conserto é um npm install e, depois, o dev de novo. É o primeiro passo em qualquer máquina nova — inclusive na sua, se você apagar a pasta sem querer.

Cenário 2: a página ficou preta com uma mensagem

Ela apagou o App.css para limpar o visual do exemplo e esqueceu de tirar o import "./App.css" do topo do App.jsx. Ao salvar, o Vite mostrou uma sobreposição escura com "Failed to resolve import". O erro não é do React: é da ferramenta avisando que o arquivo importado não existe. As duas saídas são apagar a linha do import ou recriar o arquivo — e vale ler a mensagem inteira, porque ela diz exatamente qual caminho não foi encontrado.

Cenário 3: o site pronto não abre com dois cliques

Depois do npm run build, ela abriu dist/index.html direto no navegador e a página ficou em branco. O motivo é que os arquivos gerados usam caminhos absolutos, que só funcionam quando existe um servidor servindo a pasta. Para conferir a versão final, o caminho é npm run preview, que sobe um servidor local em cima do dist/. Para publicar, o conteúdo de dist/ vai inteiro para a hospedagem — nunca só o HTML.

Exercício: o comando do dia a dia

Depois de instalar as dependências, o comando que sobe o servidor e recarrega a página a cada alteração é:

npm run

Dica: são três letras, o nome do script que o Vite escreve no package.json. O comando completo é npm run dev; para derrubar o servidor depois, Ctrl + C.

11. Resumo

Criar um projeto React hoje é instalar o Node, rodar npm create vite@latest, escolher React e JavaScript, entrar na pasta, rodar npm install e depois npm run dev. O servidor abre em http://localhost:5173/ e recarrega a página a cada arquivo salvo. Enquanto o terminal estiver aberto, o site está de pé; Ctrl + C derruba.

Dos arquivos, três importam. O index.html tem o div vazio com id="root". O src/main.jsx procura esse id e monta o React com createRoot e root.render(<App />). O src/App.jsx é o componente que você vai escrever — apague o exemplo do modelo e comece o seu. Os nomes do id precisam bater, e o elemento vai entre < e />, nunca a função solta.

Para publicar, npm run build gera a pasta dist/, que é o site pronto: arquivos comuns, que rodam em qualquer hospedagem. Antes de subir, npm run preview confere o resultado. E o hábito que evita a maior parte dos problemas: quando algo não funcionar, leia a mensagem do terminal ou da sobreposição do Vite antes de mexer no código — ela costuma dizer o arquivo e a linha.

Na próxima aula o projeto já está rodando, e o assunto volta para o React: as props, o mecanismo que permite configurar um componente com dados diferentes a cada uso.

Para lembrar

  • Node executa JavaScript fora do navegador; npm baixa as bibliotecas.
  • npm create vite@latest cria; escolha React e JavaScript.
  • npm install baixa para node_modules; não edite essa pasta.
  • npm run dev sobe o servidor e recarrega sozinho.
  • index.html tem o #root; main.jsx monta o React nele.
  • Escreva root.render(<App />), não root.render(App).
  • ReactDOM.render não existe no React 19: use createRoot.
  • npm run build gera dist/; npm run preview confere.
