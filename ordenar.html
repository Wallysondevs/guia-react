Ordenar

A Ana tem uma lista de pães com o preço de cada um, e a lista está na ordem em que ela digitou — o que não quer dizer nada para ninguém. O cliente quer ver do mais barato ao mais caro; ela quer ver os campeões de venda primeiro. Toda vez que muda a pergunta, muda a ordem, e a Ana não vai reescrever a lista à mão em cada uma delas. Nesta aula ela aprende a ordenar no React: quem compara o quê, como inverter, e por que o sort tem uma armadilha que estraga a lista original.

Você vai aprender
  • Por que sort sem função de comparação ordena errado.
  • Como escrever o comparador (a, b) => a.preco - b.preco e o que ele devolve.
  • Como ordenar texto com localeCompare, respeitando acentos.
  • Que o sort mexe no array original — e os dois jeitos de evitar isso.
  • Quando a ordem é um estado e quando ela é só uma conta feita na hora de desenhar.
  • Como alternar crescente e decrescente com um botão.
  • O que fazer quando dois itens empatam.

1. A cena: a lista que só sabe chegar

Na padaria, a lista dos pães nasce sempre na mesma ordem: a ordem em que a Ana digitou. Pão francês, sonho, brioche, croissant. Funciona até o primeiro cliente perguntar “qual é o mais barato?”. Aí ela percorre a lista com o dedo, compara preço por preço e responde. No dia seguinte, a pergunta é “quais vendem mais?” e o trabalho é o mesmo, com outro critério.

Ordenar é uma operação de dado, não de tela. A lista de pães continua sendo a mesma; o que muda é a sequência em que os itens aparecem. No React, isso significa duas coisas separadas: o array de dados, que não deve ser estragado, e a lista que aparece na tela, que é consequência de uma escolha — “por preço”, “por nome”, “do maior para o menor”.

O JavaScript já tem essa ferramenta pronta: o método sort, que existe em todo array. Ele recebe uma função que decide quem vem antes de quem e devolve o array ordenado. Parece simples, e é — mas tem três detalhes que derrubam quase todo mundo na primeira tentativa: sem função, ele compara texto; com função, ela precisa devolver número; e ele ordena no lugar, mexendo no array original.

Esses três detalhes são o roteiro da aula. Cada um aparece na tela de um jeito diferente, e o painel das caixas mostra o resultado exato para você conferir. Vamos começar pelo mais traiçoeiro, porque ele não dá erro: só devolve a ordem errada.

2. O sort sem comparador ordena como texto

Quem vem primeiro: 10 ou 2? Para uma pessoa, 2. Para o sort sem argumento, 10 — porque ele converte cada item em texto e compara letra por letra. “10” começa com “1”, que vem antes de “2”. O resultado é uma lista que parece ordenada e não está:

const precos = [10, 2, 1, 30];
console.log(precos.sort());
console.log(precos.sort((a, b) => a - b));
> [10, 2, 1].sort()
[1, 10, 2]
> [10, 2, 1].sort((a, b) => a - b)
[1, 2, 10]

A primeira linha imprime [1, 10, 2]. A segunda imprime [1, 2, 10]. A diferença é a função que você entrega. E note uma coisa importante: as duas chamadas mexeram no array precos. Depois da primeira, o array já estava na ordem errada; a segunda ordenou o que sobrou. Guarde essa observação, ela volta na seção 6.

O comportamento padrão do sort é, portanto, alfabético. Para textos ele até serve: nomes de pães ficam em ordem alfabética sem você escrever nada. Para números, ele é uma armadilha silenciosa — nenhuma mensagem, nenhum aviso, só a ordem trocada. E como o React desenha o que você mandar, a tela vai mostrar a lista errada com toda a confiança do mundo.

Uma dica de leitura para o resto da aula: quando o resultado de um sort parece “quase certo”, desconfie do comparador. Listas de número em que 1, 10 e 100 aparecem juntos quase sempre são texto comparado como texto.

3. O comparador: uma função que devolve número

A função que o sort recebe se chama comparador. Ela recebe dois itens — convencionalmente chamados de a e b — e devolve um número. O sinal desse número é a instrução:

O comparador devolveO que o sort entendeExemplo
número negativoa vem antes de ba - b com 2 e 8 devolve -6
zeroempate: a ordem entre os dois tanto faza - b com 5 e 5 devolve 0
número positivob vem antes de aa - b com 8 e 2 devolve 6
texto qualquero navegador tenta converter; o resultado não é confiávela.nome < b.nome não serve

Por isso (a, b) => a - b ordena do menor para o maior: quando a é menor, a subtração dá negativo e ele fica na frente. E (a, b) => b - a faz o contrário, do maior para o menor, porque agora é o maior que produz o negativo. Não precisa decorar: pense em “número menor primeiro” para a - b.

Com objetos, você escolhe o campo antes de subtrair: (a, b) => a.preco - b.preco. O comparador não recebe o array inteiro, recebe dois itens por vez — e o sort decide quantas vezes chamar. Você só responde à pergunta “entre estes dois, quem vem antes?”.

Uma observação sobre o JavaScript: comparar texto com < e > parece funcionar e devolve true ou false. O sort espera número, e true vira 1, false vira 0 — um comparador que nunca devolve negativo. A consequência é uma lista que ignora metade das comparações. A seção 4 mostra o jeito certo de comparar texto.

A caixa abaixo é o teste do que acabamos de ler. O ranking está na ordem em que os pães entraram no cadastro, e a posição aparece na frente de cada item para você ver a mudança acontecer:

O ranking mostra os pães na ordem de chegada. Ordene do mais vendido para o menos vendido, com um comparador que subtraia as quantidades na direção certa.

Quando acertar, o painel mostra o Sonho em primeiro e o pão francês em último. Se você escrever a.quantidade - b.quantidade, o ranking sai invertido — a lista continua ordenada, só que de trás para a frente. Esse é o erro mais comum da seção inteira, e ele não dá aviso: o sinal do comparador é a única pista.

4. Comparar texto com localeCompare

Para nomes, o comparador certo é o método localeCompare, que toda string tem. Ele compara duas strings com as regras do idioma e devolve exatamente o que o sort quer: negativo, zero ou positivo.

const paes = ["Sonho", "Água na boca", "Brioche"];

const emOrdem = [...paes].sort((a, b) => a.localeCompare(b, "pt-BR"));

O segundo argumento, "pt-BR", pede as regras do português do Brasil. Sem ele, o resultado costuma ser parecido, mas com ele os acentos e o ç entram no lugar esperado: “Água” fica antes de “Brioche”, porque a comparação considera a letra sem o acento na hora de decidir a posição. É esse detalhe que faz a lista parecer ordenada para quem lê, e não só correta para o computador.

Também é o localeCompare que resolve maiúsculas e minúsculas sem susto. Comparar "brioche" com "Brioche" usando < dá um resultado estranho, porque o código da letra maiúscula é menor. O localeCompare trata as duas formas como a mesma letra e devolve zero — empate —, que é o que uma pessoa espera.

Com objetos, a diferença é só o campo: (a, b) => a.nome.localeCompare(b.nome, "pt-BR"). E o mesmo raciocínio vale para ordenar por bairro, por cidade ou por qualquer texto que venha do banco de dados. Números usam subtração; textos usam localeCompare. Duas receitas, o resto é combinação.

5. Ordenar por um campo — e desempatar pelo outro

Na lista da Ana, cada pão tem nome e preço. Ordenar por preço é uma linha; o problema aparece quando dois pães custam o mesmo. Aí a ordem entre eles fica indefinida, e a lista pode mudar de aparência entre uma renderização e outra, o que assusta. A solução é um segundo critério, aplicado só no empate:

const lista = [...paes].sort((a, b) => {
  const pelaOrdem = a.preco - b.preco;
  if (pelaOrdem !== 0) return pelaOrdem;
  return a.nome.localeCompare(b.nome, "pt-BR");
});

Leia em voz alta: “compare pelo preço; se der diferente de zero, pronto; se empatar, compare pelo nome”. Essa estrutura — primeiro critério, empate, segundo critério — é a base de qualquer ordenação de tabela. Você pode acrescentar um terceiro nível se precisar, mas raramente vale a pena: dois critérios resolvem quase tudo e continuam legíveis.

Uma versão mais curta usa o operador ||, que devolve o primeiro valor “verdadeiro”. Como zero é falso em JavaScript, a.preco - b.preco || a.nome.localeCompare(b.nome) funciona: se a subtração der zero, cai no nome. É esperto e é difícil de ler. Em código de estudo, prefira a versão com if, que qualquer pessoa entende em cinco segundos.

E o que é “estável”? O sort do JavaScript é estável: itens que empatam mantêm a ordem relativa que tinham no array original. Isso significa que, se você já ordenou por nome e depois ordena por preço, os empates de preço continuam em ordem alfabética. É um recurso elegante, e é o que permite ordenar duas vezes em vez de escrever um comparador gigante.

sort
Método de array que ordena os itens segundo um comparador e devolve o mesmo array, já mexido.
comparador
A função (a, b) => … que o sort chama para decidir quem vem antes. Devolve negativo, zero ou positivo.
no lugar
Quando o método altera o array original em vez de criar outro. sort, reverse, push e splice trabalham no lugar.
localeCompare
Comparação de texto com as regras de um idioma: a.localeCompare(b, "pt-BR"). Resolve acentos e maiúsculas.
estável
Ordenação que preserva a ordem anterior dos itens empatados. O sort do JavaScript é estável.
derivado
Valor calculado a partir de outro na hora de desenhar, em vez de guardado. A lista ordenada é o exemplo clássico.

6. O sort estraga o array — e como evitar

Agora o tropeço que não dá erro e aparece longe. O sort ordena no lugar: ele embaralha o próprio array e devolve uma referência para ele. Se aquele array é o estado do componente, ou uma constante que outra parte da tela usa, o estrago já aconteceu. No React isso é pior do que em JavaScript comum, porque o React compara referências para decidir se redesenha: você mudou o conteúdo sem trocar o array, então ele pode nem perceber.

A caixa abaixo mostra o sintoma de um jeito direto. O componente imprime duas linhas: a ordem de chegada e a ordem de venda. Elas deveriam ser diferentes. Rode do jeito que está e veja as duas iguais:

A linha chegada deveria manter a ordem original e está saindo ordenada, porque o sort mexeu no array. Ordene uma cópia — [...paes] — e deixe o original em paz.

const paes = [
  { nome: "Pão francês", preco: 2 },
  { nome: "Brioche", preco: 8 },
  { nome: "Sonho", preco: 5 }
];

function App() {
  const ordenados = paes.sort((a, b) => b.preco - a.preco);
  return (
    <div>
      <p>chegada: {paes.map((p) => p.nome).join(", ")}</p>
      <p>ordem: {ordenados.map((p) => p.nome).join(", ")}</p>
    </div>
  );
}
<div>
  <p>chegada: Brioche, Sonho, Pão francês</p>
  <p>ordem: Brioche, Sonho, Pão francês</p>
</div>

O spread [...paes] cria um array novo, com os mesmos itens. O sort trabalha nessa cópia e o paes original continua na ordem em que a Ana digitou. É uma linha a mais e o fim de uma classe inteira de bugs.

antes:  ["Pão francês", "Brioche", "Sonho"]
ordem:  ["Brioche", "Pão francês", "Sonho"]
antes:  ["Brioche", "Pão francês", "Sonho"]   (o sort mexeu no original)

Leia a última linha com atenção: depois de imprimir a lista ordenada, o array antes não é mais o de antes. Esse é o tipo de efeito colateral que aparece três telas depois, num lugar onde ninguém suspeita. O spread elimina o problema na origem.

Existe um segundo jeito, mais curto: paes.toSorted((a, b) => …). O toSorted faz a mesma coisa que o sort, mas devolve um array novo e não encosta no original. É a preferência quando o navegador é recente — e os navegadores atuais são. O primeiro jeito funciona em qualquer lugar, o segundo é mais legível. Os dois estão certos.

Vale conhecer também o reverse, que inverte no lugar e tem o mesmo problema, e o slice() sem argumentos, que copia o array inteiro e serve como “spread com outro nome”. O importante é criar o hábito: antes de chamar um método de array dentro de um componente, pergunte se ele altera a lista. Se altera, copie primeiro.

7. A ordem é estado ou é conta?

Aqui está a decisão de projeto da aula. A Ana quer dois botões: “por nome” e “por preço”. Ela tem duas formas de fazer isso. A primeira é guardar no estado a lista já ordenada e trocá-la quando o botão é clicado. A segunda é guardar apenas qual ordem foi escolhida e ordenar dentro do render, a cada desenho.

A segunda costuma ser melhor. O estado fica pequeno — uma string "nome" ou "preco" — e a lista ordenada é sempre calculada a partir da lista original. Você não corre o risco de ter duas versões da verdade: uma lista guardada em ordem alfabética e outra guardada em ordem de preço, que se contradizem depois de um item novo. Quem manda continua sendo o array de dados.

Esse é o padrão de estado derivado: guarde o mínimo e calcule o resto. O guia tem uma aula inteira sobre isso em Estado Derivado, e a regra prática cabe em uma frase: se o valor pode ser calculado a partir de outro estado ou das props, ele não precisa de useState.

Há exceções. Se ordenar for caro — uma lista de dez mil itens, com comparação complicada —, calcular a cada tecla digitada pode pesar. Aí entram useMemo ou uma lista já ordenada no estado. Para a padaria, com sete pães, o cálculo é instantâneo e a simplicidade ganha de longe.

Repare que as três primeiras linhas guardam coisas diferentes: uma lista, uma escolha, duas escolhas. A última não guarda nada — e é justamente a mais simples de manter. Se a lista de dados é grande ou vem de uma API, o cálculo repetido pode ser otimizado depois; comece pela versão que não tem como ficar inconsistente.

8. Alternar crescente e decrescente

“Do mais barato ao mais caro” e “do mais caro ao mais barato” não são duas listas: são a mesma lista com a comparação invertida. Então o estado natural é um booleano, crescente, e o comparador muda de sinal conforme ele:

O botão “Inverter a ordem” já troca o estado crescente, mas a lista ignora esse estado e mostra sempre a mesma coisa. Faça o comparador respeitar crescente: quando ele for falso, o mais caro vem primeiro.

const paes = [
  { nome: "Pão francês", preco: 2 },
  { nome: "Brioche", preco: 8 },
  { nome: "Sonho", preco: 5 }
];

function App() {
  const [crescente, setCrescente] = useState(true);
  const lista = [...paes].sort((a, b) => a.preco - b.preco);
  return (
    <div>
      <button className="inverter" onClick={() => setCrescente(!crescente)}>
        Inverter a ordem
      </button>
      <ul>
        {lista.map((pao, i) => (
          <li key={pao.nome}>{i + 1}º {pao.nome} — R$ {pao.preco}</li>
        ))}
      </ul>
    </div>
  );
}
<div>
  <button class="inverter">Inverter a ordem</button>
  <ul>
    <li>1 º Pão francês — R$ 2</li>
    <li>2 º Sonho — R$ 5</li>
    <li>3 º Brioche — R$ 8</li>
  </ul>
</div>

const paes = [
  { nome: "Pão francês", preco: 2 },
  { nome: "Brioche", preco: 8 },
  { nome: "Sonho", preco: 5 }
];

function App() {
  const [crescente, setCrescente] = useState(true);
  const lista = [...paes].sort((a, b) =>
    crescente ? a.preco - b.preco : b.preco - a.preco
  );
  return (
    <div>
      <button className="inverter" onClick={() => setCrescente(!crescente)}>
        Inverter a ordem
      </button>
      <ul>
        {lista.map((pao, i) => (
          <li key={pao.nome}>{i + 1}º {pao.nome} — R$ {pao.preco}</li>
        ))}
      </ul>
    </div>
  );
}

O número na frente de cada item — “1º”, “2º”, “3º” — não é enfeite: é o que torna a ordem visível para quem olha e conferível para quem testa. Se você só desenhar nomes, a lista invertida continua parecendo “uma lista”; com a posição na frente, a mudança fica óbvia. Em produção, use a posição quando ela é informação (um ranking) e deixe o navegador numerar quando for só uma lista comum, com <ol>.

Três detalhes que evitam confusão. Primeiro, o texto do botão deve dizer o que ele faz: “Inverter a ordem” é melhor do que “Ordenar”, que não diz nada. Segundo, o estado inicial precisa ser explícito — comece em true e comente por quê. Terceiro, não crie dois arrays no estado; um booleano resolve.

Se preferir evitar o ternário dentro do comparador, dá para multiplicar por -1: (a.preco - b.preco) * (crescente ? 1 : -1). Funciona igual e é mais fácil de ler quando o comparador já é comprido. Escolha um estilo e mantenha: consistência vale mais do que esperteza.

9. Cenários do dia a dia

Cenário 1: a lista ordenada na hora mostra itens fora de ordem

A Ana ordenou por preço, mas dois pães de mesmo preço aparecem trocados cada vez que ela recarrega a página. É o empate: sem segundo critério, a ordem entre iguais fica indefinida. A solução é o comparador de dois níveis da seção 5 — preço e, no empate, nome. Depois disso, a lista é sempre a mesma para os mesmos dados.

Cenário 2: ordenar “funcionou” no console, mas a tela não mudou

Ela chamou pedidos.sort(...) dentro do estado e nada foi redesenhado. O React compara referências: o array é o mesmo objeto, então ele conclui que nada mudou. O conserto é criar um array novo com [...pedidos] e passar esse para o setter. A tela obedece à referência, não ao conteúdo.

Cenário 3: a ordem “volta” depois de digitar no filtro

A Ana guardou a lista ordenada num estado e a lista filtrada em outro. Ao digitar, o filtro recria a lista a partir da original, na ordem de chegada — e a tela “desordena”. Não é bug do filtro: são duas verdades concorrentes. Guardando só o critério e ordenando no fim do render, filtro e ordem passam a conviver sem briga.

11. Resumo

Ordenar no React é ordenar um array antes de desenhar. O sort recebe um comparador e chama esse comparador para cada par de itens; o sinal do número decide quem vem antes. Para números, subtraia: a - b crescente, b - a decrescente. Para textos, use localeCompare. Para empates, um segundo critério resolve e a ordenação estável cuida do resto.

O sort trabalha no lugar. Isso significa que ele altera o array original — o que quase nunca é o que você quer. Copie antes com [...lista] ou use toSorted. E lembre que o React decide redesenhar por referência: trocar o conteúdo de um array sem trocar o array pode significar uma tela que não atualiza.

Sobre onde guardar a ordem: prefira guardar a escolha — "nome", "preco", crescente — e calcular a lista no render. Estado pequeno, uma fonte da verdade, nenhuma sincronização manual. Quando o cálculo ficar caro de verdade, aí sim useMemo ou uma cópia ordenada no estado.

E o teste que sempre vale: ordene, inverta, digite no filtro e recarregue. Se a lista continuar fazendo sentido em todas as combinações, você acertou o desenho. Se em alguma delas a ordem “voltar sozinha”, há duas verdades concorrentes no seu estado — e a solução é tirar uma delas.

Para lembrar

  • sort sem argumento compara texto: 10 vem antes de 2.
  • O comparador devolve negativo, zero ou positivo; a - b é crescente.
  • Texto se compara com a.localeCompare(b, "pt-BR").
  • sort e reverse alteram o array original.
  • [...lista].sort(...) ou lista.toSorted(...) deixam o original intacto.
  • Empate se resolve com um segundo critério, não com sorte.
  • Guarde o critério da ordenação no estado e calcule a lista no render.
  • O React compara referência: array novo, tela nova.
  • Ordene antes do map; a key de cada item não muda com a ordem.
  • Posição na frente do item (“1º”) deixa a ordem visível e testável.
