Hooks Próprios

A Ana tem três balcões no site: pães, cafés e encomendas. Cada balcão tem um contador com botão de somar e botão de zerar, e cada um repete as mesmas cinco linhas de useState. Quando ela quis que o contador parasse em dez, precisou mudar três lugares — e esqueceu um. Nesta aula a Ana escreve o primeiro hook dela: uma função com nome de use que guarda o estado e devolve o que os componentes precisam, do mesmo jeito que o useState faz.

Você vai aprender
  • O que é um hook próprio e por que o nome começa com use.
  • Como extrair um contador repetido para useContador.
  • Por que cada componente que chama o hook ganha o seu próprio estado.
  • Como um hook recebe dados por parâmetro e devolve um objeto pronto para usar.
  • Por que o estado precisa morar dentro do hook, com useState.
  • O que devolver: tupla, objeto ou valor simples.
  • Como um hook próprio chama outro, e onde guardar o arquivo.

1. A cena: a mesma contagem em três balcões

O painel da padaria mostra quantos pedidos cada balcão atendeu no dia. São três blocos iguais, com um número e dois botões: somar e zerar. A Ana escreveu o primeiro com useState, copiou para o segundo e copiou para o terceiro. Funciona. O problema não é o código estar errado — é ele estar três vezes.

Repetição cobra caro de um jeito silencioso. Semana que vem ela quer que o número não passe de dez. Vai mexer nos três. Depois quer que o zerar peça confirmação. Nos três de novo. Na terceira vez, um dos blocos fica para trás e ninguém percebe, porque os três parecem iguais na tela.

A solução é a mesma que ela já usou para componentes: dar um nome à repetição. Só que, em vez de extrair um componente, a Ana vai extrair a lógica. O componente já existe e cada balcão tem o seu título. O que se repete é o par “valor + ações”. Em React, esse tipo de extração tem nome: hook próprio.

2. O que é um hook próprio

Um hook próprio é uma função JavaScript comum, com duas obrigações: o nome começa com use e, lá dentro, ela pode chamar outros hooks. É isso. Não existe API para registrar um hook, não existe arquivo especial, não existe classe. Você escreve uma função e o React a trata como parte do componente que a chamou.

hook próprio
Uma função cujo nome começa com use e que chama outros hooks por dentro. useContador, useCampo, useCliente.
prefixo use
A combinação que o React e o ESLint usam para saber que aquilo é um hook: useAlgumaCoisa. Sem o prefixo, as regras dos hooks não são verificadas e você perde o aviso.
chamada
O componente chama o hook uma vez, no topo, e recebe de volta o que ele devolveu: const contador = useContador().
parâmetros
O que o hook precisa de fora: um valor inicial, uma URL, um cliente. Chegam como argumentos, iguais aos de qualquer função.
retorno
O que o componente precisa para desenhar: um valor, uma tupla como a do useState ou um objeto com valores e funções.
estado por cópia
Cada chamada do hook dentro de um componente tem o seu próprio useState. Dois componentes que chamam useContador não compartilham número nenhum.

A comparação mais útil é com o próprio useState. Ele é uma função com nome de use que guarda um valor entre desenhos e devolve o valor e a função de troca. O seu useContador vai ser a mesma coisa, com uma camada a mais: por dentro ele usa useState e por fora devolve o que o seu componente precisa. Hook próprio é composição de hooks, não uma tecnologia nova.

Uma consequência importante desse desenho: o hook não é um lugar onde o estado mora. O estado mora na posição do componente que chamou o hook. O hook é o nome que você dá ao acesso. Guarde essa frase, porque é ela que explica o comportamento da caixa seguinte.

3. A caixa: nasce o useContador

O painel tem dois balcões, cada um com o seu useState, o botão de somar funcionando e um botão “Zerar” que não faz nada — porque ninguém escreveu o que ele faz. A missão é criar useContador, devolver valor, somar e zerar, e usar o hook nos dois balcões.

Crie function useContador() com um useState(0) dentro, devolvendo { valor, somar, zerar }. Depois troque o useState do Balcao por const { valor, somar, zerar } = useContador().

function Balcao({ id, nome }) {
  const [valor, setValor] = useState(0);

  return (
    <section id={id}>
      <h2>{nome}</h2>
      <p>{nome}: {valor}</p>
      <button className="mais" onClick={() => setValor(valor + 1)}>+1</button>
      <button className="zerar">Zerar</button>
    </section>
  );
}

function App() {
  return (
    <div>
      <Balcao id="paes" nome="Pães" />
      <Balcao id="cafes" nome="Cafés" />
    </div>
  );
}

function useContador() {
  const [valor, setValor] = useState(0);
  return {
    valor,
    somar: () => setValor(valor + 1),
    zerar: () => setValor(0),
  };
}

function Balcao({ id, nome }) {
  const { valor, somar, zerar } = useContador();

  return (
    <section id={id}>
      <h2>{nome}</h2>
      <p>{nome}: {valor}</p>
      <button className="mais" onClick={somar}>+1</button>
      <button className="zerar" onClick={zerar}>Zerar</button>
    </section>
  );
}

function App() {
  return (
    <div>
      <Balcao id="paes" nome="Pães" />
      <Balcao id="cafes" nome="Cafés" />
    </div>
  );
}

Clique em “+1” duas vezes no balcão dos pães e uma no dos cafés: os números ficam 2 e 1, cada um no seu lugar. Depois clique em “Zerar” nos pães e repare: os pães voltam a zero e os cafés continuam em 1. Duas chamadas do mesmo hook, dois estados independentes. É a prova de que o hook não guarda nada sozinho — ele guarda por componente.

Repare também no que o componente ficou: quatro linhas de leitura no lugar de um useState, uma função e um cálculo. Se amanhã o contador precisar parar em dez, o limite entra em um lugar só, dentro do hook. E os três balcões continuam ganhando a mudança de graça, porque os três chamam a mesma função.

4. Por que cada cópia tem o próprio estado

Essa é a dúvida que aparece no dia seguinte: se o useContador é uma função só, por que os dois balcões não mostram o mesmo número? A resposta está em como o React guarda o estado. Ele não guarda no hook nem em uma variável global: guarda em uma posição ligada ao componente que está sendo desenhado, na ordem das chamadas de hook daquele componente.

Quando o Balcao dos pães desenha, o React abre uma ficha para aquela instância e anota: “o primeiro hook desta ficha é um useState”. O useContador não tem ficha própria — o que ele chama cai na ficha de quem o chamou. É por isso que duas instâncias de Balcao têm duas fichas, dois números e dois conjuntos de funções.

Essa mecânica tem um efeito colateral que vale decorar: hooks são contados por ordem. Se o seu hook próprio chamar useState em um desenho e não chamar no seguinte, as posições escorregam e o React perde a conta. É a regra dos hooks, que tem aula própria em As Regras dos Hooks: nada de hook dentro de if, de laço ou depois de um return antecipado.

Outra consequência: o hook próprio não compartilha estado entre componentes. Se a Ana quisesse que os três balcões somassem no mesmo número, o contador teria de subir para o App e descer por prop, ou ir para um contexto — é o assunto de Introdução ao Contexto. Hook próprio é sobre reaproveitar lógica, não sobre compartilhar dado.

5. Um hook que recebe e devolve dados

O segundo hook da Ana é o de campo de formulário. Todo campo controlado repete o mesmo par: value mais onChange, mais um useState. Ela escreveu useCampo para receber o valor inicial e devolver o estado e um objeto pronto para espalhar no <input>.

O hook recebe inicial, mas o useState começa sempre vazio: o campo nasce em branco e a saudação mostra reticências. Troque por useState(inicial).

function useCampo(inicial) {
  const [valor, setValor] = useState("");
  return {
    valor,
    campo: {
      value: valor,
      onChange: (e) => setValor(e.target.value),
    },
  };
}

function App() {
  const nome = useCampo("Ana");
  return (
    <div>
      <label htmlFor="nome">Nome</label>
      <input id="nome" {...nome.campo} />
      <p>Bem-vindo, {nome.valor || "..."}</p>
    </div>
  );
}
<div>
  <label for="nome">Nome</label>
  <input id="nome" value="">
  <p>Bem-vindo, ...</p>
</div>

  return {

    campo: {

function App() {
  const nome = useCampo("Ana");
  return (
    <div>
      <label htmlFor="nome">Nome</label>
      <input id="nome" {...nome.campo} />
      <p>Bem-vindo, {nome.valor || "..."}</p>
    </div>
  );
}

Depois do conserto, o campo já nasce com “Ana” e a saudação acompanha. Digite outra coisa e veja o texto mudar: o hook devolve o valor atual e o objeto que alimenta o campo. O {...nome.campo} é o espalhamento que você já viu nas props — ele põe value e onChange no <input> sem escrever cada um.

Há um detalhe de projeto aqui. O parâmetro inicial só é usado na primeira vez, porque o argumento do useState só vale no primeiro desenho. Se a Ana chamar useCampo("Ana") e depois useCampo("Bento"), o valor não troca — para trocar o conteúdo depois, o caminho é o componente receber uma prop e chamar a função de troca dentro de um efeito, ou remontar o componente com uma key diferente. É a mesma regra do useState, agora vista por dentro do hook.

Uma decisão de gosto: devolver { valor, campo } deixa o componente legível, mas obriga quem chama a saber que campo é um objeto de props. A alternativa é devolver { valor, definir } e deixar o componente montar o onChange. As duas funcionam; a primeira tem menos código na tela, a segunda esconde menos.

6. O estado tem de morar no hook (com useState)

Quando a ideia de hook próprio chega, aparece a tentação de guardar o valor “no hook”, em uma variável fora da função. Parece mais simples: uma variável, uma função que soma. Só que uma variável fora do componente não avisa o React de nada, e ainda é uma só para todos os balcões.

O botão não muda nada na tela: o contador soma em uma variável de fora, que o React não acompanha. Ponha um useState(0) dentro do hook e devolva valor e somar a partir dele.

let total = 0;

function useContador() {
  function somar() {
    total = total + 1;
  }
  return { valor: total, somar };
}

function Balcao({ id, nome }) {
  const { valor, somar } = useContador();
  return (
    <section id={id}>
      <p>{nome}: {valor}</p>
      <button onClick={somar}>+1</button>
    </section>
  );
}

function App() {
  return (
    <div>
      <Balcao id="a" nome="Balcão A" />
      <Balcao id="b" nome="Balcão B" />
    </div>
  );
}
<div>
  <section id="a">
    <p>Balcão A : 0</p>
    <button>+1</button>
  </section>
  <section id="b">
    <p>Balcão B : 0</p>
    <button>+1</button>
  </section>
</div>

function useContador() {
  const [valor, setValor] = useState(0);
  return { valor, somar: () => setValor(valor + 1) };
}

function Balcao({ id, nome }) {
  const { valor, somar } = useContador();
  return (
    <section id={id}>
      <p>{nome}: {valor}</p>
      <button onClick={somar}>+1</button>
    </section>
  );
}

    <div>
      <Balcao id="a" nome="Balcão A" />
      <Balcao id="b" nome="Balcão B" />
    </div>
  );
}

Com o useState dentro do hook, clicar duas vezes no A e uma no B dá 2 e 1. Sem ele, o painel fica parado em zero para sempre: a variável até muda, mas o React não sabe que precisa desenhar de novo, e quem lê o valor é a função de desenho, que não foi chamada. É o mesmo motivo pelo qual você nunca altera estado “na mão” em React.

Existe uma exceção legítima para variáveis fora do componente: constantes que nunca mudam, como a tabela de preços ou a lista de bairros atendidos. Isso não é estado, é configuração. A regra prática é simples: se o valor aparece na tela e pode mudar com o uso, ele precisa de useState (ou useReducer) em algum lugar.

E há um terceiro caso, mais sutil: o hook pode guardar um valor entre desenhos sem disparar desenho novo, com useRef. Serve para coisas como “quantas vezes já busquei”, que não aparecem na tela. Se o número aparece, é estado; se é só um caderninho interno, é ref. A aula de Timers usa essa ideia na prática.

7. O que devolver, e o que um hook pode chamar

Não existe formato obrigatório de retorno. O que existe é convenção, e a convenção segue o que o componente precisa fazer com o resultado.

FormatoExemploQuando usar
tuplaconst [valor, somar] = useContador()dois ou três itens posicionais, como o useState
objetoconst { valor, somar, zerar } = useContador()várias coisas, com nomes que se explicam
valor simplesconst cliente = useCliente()uma coisa só, sem ação nenhuma
funçãoconst validar = useValidacao()o hook só prepara uma ação

Objeto é o formato mais comum quando o hook cresce, porque a ordem não importa e o nome aparece na hora de usar. Tupla é melhor quando o hook imita o useState e o leitor já conhece a posição. O que ninguém recomenda é devolver coisas demais: um hook que devolve quinze campos é um componente disfarçado, e provavelmente deveria ser dividido em dois.

Sobre o que um hook pode chamar: qualquer hook. Inclusive os seus. Um useEncomenda pode chamar useCampo para o nome do cliente e useTotal para o preço. Essa composição é o motivo de o prefixo use existir: ele avisa ao React (e ao ESLint) que aquela função pode conter hooks, então as regras precisam ser verificadas também lá dentro.

import { useState } from "react";
import { useCampo } from "./useCampo";

export function useEncomenda() {
  const cliente = useCampo("");
  const [pago, setPago] = useState(false);
  const total = 6 * 12;

  return {
    cliente,
    pago,
    total,
    marcarPago: () => setPago(true),
  };
}

Em um projeto de verdade, cada hook mora no seu arquivo, com export, e quem usa importa. Nas caixas deste guia não há import: as linhas de import são removidas pelo motor, e o que importa é a função. Se você levar o código daqui para um projeto, a primeira linha do arquivo passa a ser import { useState } from "react" — veja Criar o Projeto para o arquivo completo.

8. As armadilhas dos hooks próprios

Quatro problemas concentram quase tudo o que dá errado com hooks próprios. Dois deles aparecem no console; dois aparecem só como comportamento estranho.

O sintomaA causaO conserto
o valor não muda na telao hook guarda o valor em variável de fora, sem useStatemover o estado para dentro do hook
dois componentes mostram o mesmo númeroo estado está em uma variável do móduloum useState por chamada do hook
o hook funciona em um lugar e quebra em outroele é chamado dentro de um if ou de um laçochamar sempre no topo do componente
o ESLint reclama de “ordem dos hooks”há um return antes de algum hooktodos os hooks antes de qualquer condição

O terceiro caso é o mais chato de diagnosticar, porque o hook está certo e o uso está errado. Um hook chamado dentro de um if roda em alguns desenhos e não em outros; as posições escorregam e o React passa a entregar o estado de um hook para outro. O ESLint avisa antes de rodar, com uma mensagem comprida que vale reconhecer:

React Hook "useState" is called conditionally. React Hooks must be called in the exact same order in every component render.

A tradução é direta: “o useState está sendo chamado condicionalmente; hooks precisam ser chamados na mesma ordem em todo desenho do componente”. O conserto quase sempre é subir a chamada para o topo e usar o valor condicionalmente depois, no JSX.

O quarto caso aparece quando alguém chama o hook fora de um componente — dentro de um onClick, de um setTimeout ou de uma função auxiliar comum. No navegador, em modo de desenvolvimento, a mensagem é esta:

Uncaught Error: Invalid hook call. Hooks can only be called inside of the body of a function component.

“Chamada de hook inválida: hooks só podem ser chamados no corpo de um componente de função.” Se você vir essa mensagem, procure onde o hook foi chamado: quase sempre é um onClick que tentou usar useState para guardar um resultado. O caminho é declarar o estado no corpo e usá-lo no manipulador.

9. Cenários do dia a dia

Cenário 1: o limite que entrou em um lugar só

A Ana decidiu que nenhum balcão passa de dez pedidos. Antes, isso seria três if em três componentes. Com o useContador, ela mudou a função somar para setValor(Math.min(valor + 1, 10)) e os três balcões passaram a respeitar o limite. Nenhum componente soube que a regra mudou.

Cenário 2: o contador que compartilhava número

Na primeira versão, o total ficava fora do hook, e os dois balcões mostravam o mesmo número — e nenhum dos dois atualizava ao clicar. O sintoma parecia “o React não está funcionando”. A causa era uma variável de módulo onde deveria haver useState. Duas linhas de conserto, uma tarde de investigação.

Cenário 3: o hook que virou componente

O usePainel da Ana começou pequeno e terminou devolvendo doze coisas, incluindo o JSX de três blocos. Quando isso acontece, o nome está errado: aquilo é um componente que devolve tela. Ela dividiu em useContador, useCampo e um componente Painel que usa os dois. O código ficou maior em número de arquivos e bem menor em sustos.

function () { const [fornadas, setFornadas] = useState(0); return { fornadas, assar: () => setFornadas(fornadas + 1) }; }

11. Resumo

Hook próprio é uma função com nome de use que chama outros hooks e devolve o que o componente precisa. Ele não guarda estado: quem guarda é a instância do componente que o chamou, na ordem das chamadas. Por isso duas chamadas dão dois estados independentes, e por isso a regra “hooks sempre no topo” vale também dentro do seu hook.

A extração compensa quando a mesma lógica aparece em dois lugares e você já se pegou copiando as mesmas linhas. Comece pelo formato mais simples — um useState e duas funções — e devolva um objeto com nomes claros. Se o hook crescer a ponto de devolver tela ou doze campos, provavelmente é hora de dividir.

Um hook pode chamar outro hook, inclusive os seus, e é aí que a composição aparece: um useEncomenda junta useCampo e useTotal para entregar ao componente uma coisa só. Em projeto de verdade, cada hook mora no seu arquivo e é importado; nas caixas, o import é removido e a função fica no mesmo lugar.

E fica a advertência que vale mais que a sintaxe: se o valor aparece na tela e pode mudar, ele precisa de useState em algum lugar. Variável de módulo é a origem dos bugs mais silenciosos desta aula — não porque o JavaScript esteja errado, mas porque o React nunca fica sabendo que algo mudou.

Para lembrar

  • Hook próprio: função com nome use... que pode chamar hooks.
  • O estado mora na instância do componente, não no hook.
  • Duas chamadas do mesmo hook: dois estados independentes.
  • Parâmetros chegam como argumentos; o valor inicial do useState só vale no primeiro desenho.
  • Devolva objeto quando há vários itens; tupla quando imita o useState.
  • Nada de hook dentro de if, laço ou onClick.
  • Variável fora do componente não redesenha e é compartilhada por todos.
  • Hook pode chamar hook: useEncomenda usa useCampo e useTotal.
  • No projeto, cada hook mora no seu arquivo e é importado.
  • Hook que devolve JSX é componente disfarçado: divida.
