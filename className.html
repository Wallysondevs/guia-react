className e Estilo

O CSS da padaria da Ana já tem a classe .esgotado, pronta para pintar de cinza o pão que acabou. Ela escreveu o CSS, mas o selo nunca aparece. O problema não está no CSS: está no atributo que liga o JSX à folha de estilo. Nesta aula a Ana aprende a montar o className — uma classe fixa, duas classes juntas, uma classe que só entra quando o estoque acaba — e a ver no painel exatamente o que o React escreveu no HTML.

Você vai aprender
  • Por que o JSX usa className e o HTML usa class.
  • A montar o valor com uma classe fixa, com concatenação e com template string.
  • Como juntar várias classes sem sobrar espaço nem a palavra false.
  • Uma função de duas linhas que resolve o caso para sempre.
  • A ler o atributo class no painel da caixa e no DevTools.
  • Por que uma classe aparece no HTML e mesmo assim não pinta nada.
  • Um padrão de nomes para quando o site crescer.

1. A cena: o selo que não aparece

A Ana tem um site de padaria feito à mão, com uma folha de estilo de duzentas linhas. Nela existe a regra .esgotado, que deixa o texto cinza e riscado. Quando ela passou a lista de pães para o React, a regra deixou de funcionar. O pão sem estoque continua preto, bonito e vendável — o que, numa padaria, é propaganda enganosa.

O CSS está certo. O que mudou foi o lado do React: no JSX, o atributo que carrega as classes não se chama class. Chama-se className. Quem escreve class="esgotado" em um componente vê o atributo passar batido ou virar um aviso no console, e a regra .esgotado nunca encontra o elemento.

Não é capricho do React. O JSX é JavaScript, e em JavaScript class é uma palavra reservada — a que declara classes. Um atributo com esse nome dentro de um objeto literal seria ambíguo, então o React escolheu className, que é o nome da propriedade do DOM criada quando o navegador não podia usar class. O mesmo aconteceu com for, que virou htmlFor nos rótulos de formulário.

Com o nome certo no lugar, o assunto desta aula começa de verdade: className é uma string, e quase todo problema com classes vem de esquecer isso. Não é um objeto, não é uma lista, não é uma função. É texto — e, como todo texto em JSX, pode ser montado com uma conta antes de ir para a tela.

2. className é uma string

O valor de className vai direto para o atributo class do elemento. Se você escrever className="preco destaque", o HTML gerado tem class="preco destaque" e as duas regras de CSS valem ao mesmo tempo. Se escrever className="preco", só a primeira vale. O navegador não sabe nem se importa de onde veio o texto: pode ser uma string fixa, uma variável, uma conta com + ou um template com crase.

className
A prop do JSX que preenche o atributo class do elemento. Recebe texto.
class
O nome do mesmo atributo no HTML puro. Em JSX é className, porque class já significa outra coisa em JavaScript.
CSS
A folha onde cada classe ganha aparência: cor, tamanho, margem. O React não aplica estilo nenhum sozinho; ele só escreve o atributo.
seletor
O trecho do CSS que acha os elementos: .preco pega quem tem a classe preco.
classe condicional
Uma classe que entra ou sai conforme um estado. É o que transforma "pão" em "pão esgotado".

A tabela abaixo é o mapa dos valores que você vai escrever e do que sai do outro lado. Vale conferir cada linha no painel das caixas: o painel mostra o HTML gerado, com o atributo class e tudo.

className="preco destaque"class="preco destaque"as duas regras se aplicam
className={ativo && "destaque"}class="destaque" ou nenhum classcom false o React omite o atributo

Repare na terceira e na quarta linha: são quase iguais e se comportam de forma oposta. Quando o && está sozinho dentro das chaves, o React recebe false e simplesmente não escreve o atributo. Quando o && está no meio de uma concatenação, o false vira texto e entra na string. É a fonte do class="preco false" que aparece em tanto site por aí, e o assunto da seção 5.

Para ver o valor de verdade, o DevTools é o caminho mais rápido. O console mostra o atributo e a lista de classes do elemento, que é o que o CSS enxerga:

document.querySelector("p").className
'preco false'
document.querySelector("p").classList.contains("promocao")
false

3. Uma classe fixa e uma condicional

O caso mais comum do dia a dia é este: o elemento sempre tem a classe base e ganha uma segunda classe quando um estado muda. O preço do pão é sempre preco; quando o balcão está vazio, ele também é destaque. Duas classes, uma delas opcional, e a decisão sai do estado que já existe.

Note que a conta é feita na renderização, com o estado na mão, e não em um efeito. É o mesmo raciocínio da aula anterior: o texto do atributo é um valor derivado — paes === 0 decide, e o resultado é uma variável comum.

Quando não há pão no balcão, o preço precisa das classes preco e destaque; com pães, só preco. Monte o className a partir de paes === 0.

function App() {
  const [paes, setPaes] = useState(0);

  return (
    <div>
      <p className="preco">Pão francês — R$ 12,00</p>
      <p>{paes} pães no balcão</p>
      <button onClick={() => setPaes(paes + 1)}>Assar mais um</button>
    </div>
  );
}
<div>
  <p class="preco">Pão francês — R$ 12,00</p>
  <p>0 pães no balcão</p>
  <button>Assar mais um</button>
</div>

function App() {
  const [paes, setPaes] = useState(0);
  const classes = paes === 0 ? "preco destaque" : "preco";

  return (
    <div>
      <p className={classes}>Pão francês — R$ 12,00</p>
      <p>{paes} pães no balcão</p>
      <button onClick={() => setPaes(paes + 1)}>Assar mais um</button>
    </div>
  );
}

Na solução, o painel mostra <p class="preco destaque"> antes do clique e <p class="preco"> depois. O HTML muda de verdade, e é isso que o CSS lê. A variável classes poderia estar dentro do próprio atributo, em uma linha: className={paes === 0 ? "preco destaque" : "preco"}. Separar em uma variável com nome é melhor quando a condição é comprida, porque dá nome à decisão e deixa o JSX legível.

Duas versões equivalentes que você vai encontrar por aí. A primeira usa template string com crase, e serve quando parte do nome da classe vem de uma variável:

const classes = `preco ${paes === 0 ? "destaque" : ""}`;
const classes = `preco tamanho-${tamanho}`;   // "preco tamanho-grande"

A segunda usa && para a classe opcional, mas só quando não há classe base: className={esgotado && "esgotado"}. Quando esgotado é false, o React não escreve atributo nenhum — o que é o comportamento certo. O perigo é misturar os dois estilos na mesma linha, e é ali que nasce o false da próxima seção.

4. Juntando várias classes

Quando a lista de classes cresce — uma base, uma de estado, uma de tamanho — a concatenação com + fica ilegível e cheia de espaços para acertar. O caminho mais confiável é montar uma lista de verdade e colar com join(" "): o join coloca um espaço entre os itens e nenhum no começo nem no fim.

O filter(Boolean) no meio é o que remove os valores falsos — false, "", null — antes de colar. Sem ele, a lista com um false dentro viraria "item false", exatamente o problema que estamos tentando evitar.

A lista tem três pães, e os que custam mais de R$ 20 precisam também da classe item--caro. Monte o className de cada li com a classe base item mais a condicional.

const precos = [12, 24, 30];

function App() {
  return (
    <ul>
      {precos.map((preco) => (
        <li key={preco} className="item">{"R$ " + preco + ",00"}</li>
      ))}
    </ul>
  );
}
<ul>
  <li class="item">R$ 12,00</li>
  <li class="item">R$ 24,00</li>
  <li class="item">R$ 30,00</li>
</ul>

const precos = [12, 24, 30];

function App() {
  return (
    <ul>
      {precos.map((preco) => (
        <li key={preco} className={"item" + (preco > 20 ? " item--caro" : "")}>
          {"R$ " + preco + ",00"}
        </li>
      ))}
    </ul>
  );
}

Depois da solução, o painel mostra três li com class="item", class="item item--caro" e class="item item--caro". A conta preco > 20 decide, e o espaço do começo da segunda classe é o que separa os dois nomes. Esquecer esse espaço é o erro de digitação mais comum aqui: "itemitem--caro" é uma classe só, que não existe no CSS, e o sintoma é "a classe não funciona".

A versão com lista é mais fácil de ler quando há três ou mais classes: className={["item", preco > 20 && "item--caro"].filter(Boolean).join(" ")}. Ela não precisa de espaço manual, aceita quantos itens você quiser e ignora os falsos. Depois de escrever essa linha três vezes, vale extrair uma função — e ela cabe em duas linhas:

function classes(...nomes) {
  return nomes.filter(Boolean).join(" ");
}

<p className={classes("preco", esgotado && "esgotado")}>Pão francês</p>;

O ...nomes é o operador de descanso: ele junta todos os argumentos em uma lista. A função recebe quantos nomes você passar, descarta os falsos e devolve o texto pronto. Bibliotecas como clsx e classnames fazem exatamente isso e são populares em projetos grandes, mas para começar a sua versão de duas linhas resolve — e você entende cada pedaço dela.

5. O "false" que entrou na classe

Este é o bug que mais aparece em código de quem está começando, e ele é silencioso: a página não quebra, o console não reclama, e o atributo fica com uma classe a mais que não existe em CSS nenhum. A causa é sempre a mesma: uma concatenação em que o && devolve false em vez de string vazia.

"preco " + (promocao && "promocao") parece uma boa ideia. Quando promocao é true, o parêntese vale "promocao" e o resultado é "preco promocao". Quando é false, o parêntese vale o booleano false, e somar texto com booleano transforma o booleano em texto: o resultado é "preco false". O React escreve o atributo sem pensar duas vezes.

O className está montado com && dentro de uma concatenação, então fora da promoção ele vira class="preco false". Corrija para que o atributo seja preco ou preco promocao.

function App() {
  const [promocao, setPromocao] = useState(false);

  return (
    <div>
      <p className={"preco " + (promocao && "promocao")}>Pão francês — R$ 12,00</p>
      <button onClick={() => setPromocao(!promocao)}>Promoção</button>
    </div>
  );
}
<div>
  <p class="preco false">Pão francês — R$ 12,00</p>
  <button>Promoção</button>
</div>

function App() {
  const [promocao, setPromocao] = useState(false);

  return (
    <div>
      <p className={"preco" + (promocao ? " promocao" : "")}>Pão francês — R$ 12,00</p>
      <button onClick={() => setPromocao(!promocao)}>Promoção</button>
    </div>
  );
}

Repare no painel do código inicial: <p class="preco false">. Essa palavra false é o booleano que virou texto. O navegador aceita, o CSS ignora, e o atributo fica sujo para sempre. Depois do clique a classe promocao entra e o visual até funciona — o que esconde o problema enquanto a promoção está ligada. Desligou, o false volta.

Há três correções, todas boas. A primeira é trocar o && por um ternário que devolve espaço mais a classe, ou string vazia. A segunda é a lista com filter(Boolean), que descarta o booleano antes de colar. A terceira é a função classes(...) da seção anterior. O que não funciona é deixar o booleano entrar na concatenação e esperar que o React o remova: ele remove apenas quando o valor inteiro do className é false.

E o caso do objeto? className={{ preco: true }} vira class="[object Object]", porque o navegador converteu o objeto em texto do jeito dele. Esse formato é o mesmo que aparece quando você esquece de chamar uma função: className={meuEstilo} em vez de className={meuEstilo()}. Se você vir [object Object] em um atributo, a causa é sempre essa: um objeto onde o React esperava texto.

6. Nomes que escalam

Classe é texto livre, e é por isso que a bagunça cresce rápido. A Ana começou com preco, preco2, precoVermelho e, três semanas depois, não sabia qual delas estava em uso. O remédio é combinar um padrão de nomes antes que o site tenha cinquenta classes. Não é regra do React, é acordo de time — e o mais usado é o BEM, que separa bloco, elemento e modificador.

PeçaComo se escrevePara que serve

Com esse acordo, o className do card fica classes("cartao", destaque && "cartao--destaque"), e qualquer pessoa do time sabe que cartao--destaque é uma variação do bloco cartao, não um componente novo. O traço duplo e o sublinhado duplo são só convenção: o CSS trata cartao--destaque como um nome único, com dois hifens no meio. A vantagem é que o nome carrega a estrutura, e a busca no editor acha todos os usos.

Quando o projeto chega ao Vite, no Nível 3, aparece outra ferramenta: os CSS Modules. O arquivo Cartao.module.css exporta nomes de classe que o build renomeia para evitar colisão, e você escreve className={estilos.cartao}. A ideia é a mesma desta aula — uma string no atributo —, mas o nome passa a ser local ao componente. Até lá, o padrão de nomes resolve, e você não precisa de nenhuma ferramenta extra.

7. Por que a classe não fez nada

De vez em quando o painel mostra class="destaque" e o elemento continua sem estilo. O problema saiu do React e foi para o CSS, e vale ter um roteiro de conferência em vez de mexer no código às cegas. O console ajuda: getComputedStyle diz o valor que o navegador aplicou de verdade.

getComputedStyle(document.querySelector(".preco")).color
'rgb(17, 17, 17)'
document.styleSheets.length
1

A primeira linha mostra a cor final do elemento. Se ela não é a que a sua regra pede, alguma outra regra venceu, ou a sua não chegou. A segunda conta quantas folhas de estilo o documento carregou: zero significa que o arquivo de CSS não veio — import errado, caminho errado, ou, no caso das caixas deste guia, nenhum CSS carregado de propósito.

Vale dizer o óbvio que economiza meia hora: a caixa desta página não carrega o CSS do site. Ela roda o componente em um quadro isolado, com o estilo básico do navegador, e mostra o HTML gerado no painel. É por isso que as missões aqui conferem o atributo e a quantidade de elementos com cada classe, e não a cor. No projeto de verdade, com a folha carregada, o mesmo class que aparece no painel é o que pinta a tela.

8. className no resto do HTML

O className não é exclusividade de div e p. Todo elemento que aceita class no HTML aceita className no JSX: ul, li, button, input, form, table e até os elementos de SVG, como svg e path. A regra é a mesma: texto, com os nomes separados por espaço.

Os vizinhos de sempre continuam valendo dentro do JSX. for vira htmlFor nos rótulos; tabindex vira tabIndex; readonly vira readOnly. E há uma diferença que confunde: atributos personalizados com data- e aria- mantêm o nome exato, com hífen e tudo, porque o React não os converte. Então data-cy="preco" e aria-label="Preço do pão" funcionam como no HTML.

Uma dúvida frequente: dá para usar class no React 19? O atributo até chega ao HTML em muitos casos, mas não conte com isso. O JSX foi desenhado para className, as ferramentas esperam className, e a diferença de comportamento entre versões não vale a economia de quatro letras. Quando o código vem de um HTML antigo colado no JSX, a primeira coisa a fazer é trocar todos os class= por className=.

Por último: classe não é o único jeito de estilizar, e as duas ferramentas têm papéis diferentes. A classe é o lugar do estilo que pertence ao desenho do site — o card, o botão, a tabela — e que deve estar na folha de CSS, reaproveitável e cacheada. O atributo style, que vem na próxima aula, é para valores que nascem do estado e mudam a cada renderização: a largura de uma barra de progresso, a cor escolhida pela pessoa. Misturar os dois sem critério é o que transforma CSS em JavaScript e JavaScript em CSS.

9. Cenários do dia a dia

Cenário 1: o botão que deveria ficar cinza e continua azul

A Ana escreveu className={desabilitado && "botao-cinza"} e o botão ficou azul. Ao desabilitar, o atributo aparecia certo: class="botao-cinza". O problema era que a classe base tinha sumido — o botão perdeu a classe botao e ganhou só a de estado. Quando a classe condicional é um acréscimo, a base tem de estar sempre na string: className={"botao" + (desabilitado ? " botao-cinza" : "")}, ou com a função classes.

Cenário 2: a promoção aparece em todos os pães

Ela escreveu a condição uma vez, no componente da lista, e passou o resultado para todos os itens. O preço de cada pão precisa da sua própria condição, calculada dentro do map, com os dados daquele item. Regra geral: a classe condicional é decidida no lugar onde o dado daquele elemento está — não no pai, que não sabe qual pão está em promoção.

Cenário 3: a classe certa, o CSS certo, e nada muda

Ela conferiu o painel: class="esgotado". Conferiu o CSS: .esgotado existe. O problema estava em outra regra, mais específica, que também pintava aquele parágrafo — o DevTools mostra a regra vencedora e a riscada. O React fez a parte dele; o resto foi briga de especificidade no CSS, e a solução foi ajustar o seletor, não o componente.

Exercício: o preço com as duas classes

Complete as duas linhas. Na primeira, o parágrafo recebe a classe pelo atributo certo do JSX. Na segunda, as classes são montadas a partir de uma lista, coladas com o método que separa os nomes por espaço:

<p ="preco">Pão francês</p> <p className={["preco", "destaque"].(" ")}>Pão de queijo</p>

Dica: a primeira resposta é o nome que o JSX usa no lugar de class. A segunda é o método que transforma uma lista em texto, com o separador que você mandar entre os parênteses. Sem ele, a lista viraria uma string só, com vírgulas.

11. Resumo

className é uma string e vira o atributo class do elemento. Uma classe é texto, duas classes são dois textos separados por espaço, e a decisão de incluir uma delas sai do estado, calculada na renderização. Concatenação com + funciona, mas exige cuidado com espaços; lista com filter(Boolean).join(" ") é mais segura; a função classes(...) de duas linhas deixa o JSX limpo.

O erro que você vai reconhecer para sempre é o false dentro da string. O React remove o atributo quando o valor inteiro é false, mas não remove um booleano que já virou texto no meio de uma concatenação. Objeto no className também vira lixo: [object Object]. Os dois aparecem no painel do guia, e é para isso que ele serve — olhar o HTML gerado é mais rápido do que adivinhar.

E quando o atributo está certo e o estilo não vem, o problema é do CSS: folha que não carregou, regra mais específica vencendo, nome com typo. Aqui as caixas não carregam o CSS do site, então as missões conferem atributo e quantidade — no projeto de verdade, é o mesmo class que pinta a tela. Guardar essa separação ajuda: o React escreve o nome, o CSS decide a aparência, e cada um tem o seu lugar de depuração.

Falta o outro lado da estilização: valores que nascem do estado e não cabem em uma folha de estilo. É o assunto da próxima aula, e ele combina com esta — classe para o que é do desenho, estilo inline para o que é do dado.

Para lembrar

  • No JSX é className; no HTML gerado vira class.
  • O valor é uma string com nomes separados por espaço.
  • Classe condicional: ternário com " " ou string vazia, nunca && dentro de concatenação.
  • Várias classes: ["a", cond && "b"].filter(Boolean).join(" ").
  • Uma função classes(...nomes) resolve o caso para sempre.
  • className={cond && "x"} sozinho é seguro: com falso, o atributo nem aparece.
  • Objeto no className vira [object Object].
  • Classe no HTML e estilo ausente é problema de CSS, não de React.
  • Nomes com padrão (cartao__titulo, cartao--destaque) evitam colisão.
