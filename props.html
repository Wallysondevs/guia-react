As Props

A Ana já tem um componente Cartao que desenha um pão com nome e preço. Só que o cartão está com o nome escrito dentro dele, no código: “Pão francês”, “R$ 1,20”. Para mostrar o pão de queijo, ela copiou o componente inteiro e trocou as palavras — três vezes. Quando o preço do pão francês subiu, ela corrigiu dois cartões e esqueceu o terceiro, e o site passou a mentir. Nesta aula ela aprende a mandar os dados de fora para dentro: as props. Um componente, vários pães.

Você vai aprender
  • O que são props: os dados que o componente recebe na hora da chamada.
  • Como o atributo que você escreve vira uma chave dentro do objeto props.
  • Como ler esses valores no JSX com {props.nome}.
  • A diferença entre passar texto com aspas e passar JavaScript com chaves.
  • Como o mesmo componente desenha cartões diferentes.
  • Por que props são somente leitura e quem manda no valor é quem chama.
  • Como achar o problema quando a prop chega vazia.

1. A cena: três cartões copiados

A vitrine da padaria tem três pães. O componente que a Ana escreveu é este, e ele funciona — para um pão só:

function Cartao() {
  return (
    <div className="cartao">
      <h2>Pão francês</h2>
      <p>R$ 1,20</p>
    </div>
  );
}

Para o segundo pão, ela copiou o componente e trocou as duas palavras. Para o terceiro, copiou de novo. O site ficou pronto e a vida seguiu — até o dia em que o quilo da farinha subiu e ela precisou mudar todos os preços. Foi aí que o problema apareceu: três cópias do mesmo código, três lugares para editar, e uma garantia zero de que ela não esqueceria nenhum.

A ideia que resolve isso é a mesma que a aula anterior já plantou: componente é função. E função aceita argumento. Em vez de escrever o nome do pão dentro do componente, você deixa um espaço vazio e manda o nome na hora de chamar. Esse espaço, no React, tem nome: props, abreviação de properties, propriedades.

Vale dizer o que muda no seu dia a dia: um componente com props desenha qualquer pão, e o texto que aparece vem sempre de fora. Quem sabe o nome e o preço é a página, não o cartão. O cartão só sabe o formato — onde fica o título, onde fica o preço, como é a borda. É a separação entre a forma e o conteúdo, e é ela que permite reaproveitar.

2. O atributo que vira objeto

Quando você escreve <Cartao nome="Pão francês" />, o React faz duas coisas antes de chamar a sua função. Primeiro, junta todos os atributos num objeto. Segundo, passa esse objeto como o primeiro argumento da função. Ou seja: o que você escreveu como atributo chega do outro lado como propriedade de um objeto.

function Cartao(props) {
  return (
    <div className="cartao">
      <h2>{props.nome}</h2>
      <p>{props.preco}</p>
    </div>
  );
}

function App() {
  return <Cartao nome="Pão francês" preco="R$ 1,20" />;
}

O parâmetro props é esse objeto. Se a chamada tem dois atributos, o objeto tem duas chaves. Com um atributo, uma chave. Sem nenhum, um objeto vazio — e é por isso que um componente que lê props.nome sem receber nada mostra um espaço em branco em vez de explodir.

prop
Um dado que entra no componente. O nome vem de property, propriedade; no dia a dia, todo mundo fala “as props” no plural.
atributo
O que você escreve na chamada, no formato nome="valor" ou nome={valor}. nome é o nome do atributo, não da tag.
objeto props
O pacote que o React monta com todos os atributos daquela chamada e entrega como primeiro argumento: { nome: "Pão francês", preco: "R$ 1,20" }.
chave
O nome de uma propriedade dentro do objeto. O atributo nome vira a chave nome; para ler, props.nome.
somente leitura
A regra de ouro: o componente lê as props, mas não as altera. Quem manda no valor é sempre quem chama.

Repare que o componente mudou muito pouco: saiu o texto fixo, entrou {props.nome}. As chaves { } são a porta entre o JSX e o JavaScript — o mesmo recurso da aula de expressões. Dentro delas você escreve código; fora delas, texto comum. Se você esquecer as chaves e escrever props.nome direto, a tela mostra a palavra “props.nome”, porque sem chaves aquilo é só texto.

3. A primeira prop

Vamos ao primeiro caso de verdade. O componente já está pronto para receber um nome, mas a chamada está vazia:

A chamada <Cartao /> não manda nada, então o título sai vazio. Passe a prop nome com o texto Pão francês e clique em Rodar.

function Cartao(props) {
  return (
    <div className="cartao">
      <h2>{props.nome}</h2>
      <p>R$ 1,20</p>
    </div>
  );
}

function App() {
  return <Cartao />;
}
<div class="cartao">
  <h2></h2>
  <p>R$ 1,20</p>
</div>

function Cartao(props) {
  return (
    <div className="cartao">
      <h2>{props.nome}</h2>
      <p>R$ 1,20</p>
    </div>
  );
}

function App() {
  return <Cartao nome="Pão francês" />;
}

Antes de rodar, o painel mostra o h2 vazio. Depois, mostra o título com o texto. Nada mais mudou no componente: o mesmo código, uma informação a mais na chamada. É o gesto que você vai repetir mil vezes — o componente declara o que precisa, a página entrega.

Um detalhe de vocabulário que ajuda a conversar com outras pessoas: quando o componente declara props, ele está dizendo “eu aceito dados”; quando a página passa nome, está dizendo “aqui está um deles”. O nome da prop é um contrato. Se um lado escreve nome e o outro lê titulo, não há erro nenhum na tela — só um espaço em branco, que é o pior tipo de bug. Voltamos a isso na seção 9.

4. Texto entre aspas, JavaScript entre chaves

Todo atributo em JSX aceita duas formas de valor, e a diferença importa. Com aspas, o valor é texto, sempre — mesmo que pareça número. Com chaves, o valor é JavaScript: pode ser número, conta, variável, resultado de função. A tabela mostra o que chega em props em cada caso.

Na chamadaO que chega em propsPor quê
<Cartao nome="Pão francês" />props.nome é o texto "Pão francês"aspas delimitam texto
<Cartao preco={3.5} />props.preco é o número 3.5chaves entregam o valor como está
<Cartao preco={2 * 1.75} />props.preco é 3.5a conta é feita antes da chamada
<Cartao nome={pao.nome} />o valor que estiver na variávelchaves leem variáveis
<Cartao destaque />props.destaque é trueatributo sem valor vale verdadeiro
<Cartao preco="3.5" />props.preco é o texto "3.5"aspas nunca produzem número

Por que isso é problema? Porque texto e número se comportam diferente. Com o número 3.5 você consegue somar, multiplicar, formatar com duas casas. Com o texto "3.5", a soma vira concatenação: "3.5" + 1 dá "3.51", e não 4.5. Numa calculadora de encomenda, esse detalhe é a diferença entre cobrar certo e cobrar errado.

A regra prática é curta: texto entre aspas, todo o resto entre chaves. Preço em reais já formatado (“R$ 1,20”) é texto e vai entre aspas. Quantidade, peso, desconto, qualquer coisa que você queira calcular, vai entre chaves. E quando o valor vem de uma variável — pao.nome —, chaves sempre, mesmo que o conteúdo seja texto.

5. O objeto props inteiro

Você não precisa adivinhar o que chegou. O objeto props é um objeto comum e pode ser impresso no console. É o jeito mais rápido de descobrir por que uma prop não aparece: você vê a lista de chaves, com os valores, exatamente como o React montou.

function Cartao(props) {
  console.log(props);
  return <h2>{props.nome}</h2>;
}

Ao rodar esse componente com dois atributos, o painel mostra o HTML e, embaixo, a linha do console com o objeto. Os números entre chaves são a forma como um objeto é escrito em texto:

console: {"nome":"Pão francês","preco":"R$ 1,20"}

Leia com calma: duas chaves, nome e preco, cada uma com o seu valor entre aspas porque os dois são texto. Se você tivesse passado preco={1.2}, a linha sairia com 1.2 sem aspas — a diferença entre texto e número aparece até aqui. No DevTools do navegador, o mesmo objeto aparece com um triângulo para abrir e inspecionar; no painel do guia, ele vem achatado numa linha só.

Há um segundo uso para esse truque, mais direto: imprimir as chaves que chegaram. Se o objeto vier vazio, a chamada não passou nada; se vier com uma chave estranha, você descobre o erro de digitação na hora. Nesta página, a caixa 3 usa justamente esse raciocínio para achar um cartão em branco.

6. O mesmo componente, dois cartões

Chegou a hora do motivo de tudo. Com props, o mesmo Cartao desenha pães diferentes, sem copiar código nenhum. A página chama o componente duas vezes, cada chamada com os seus valores, e o React roda a função duas vezes.

A vitrine só tem um pão. Acrescente um segundo <Cartao /> com nome="Pão de queijo" e preco="R$ 3,50", para a vitrine ficar com dois cartões.

function Cartao(props) {
  return (
    <div className="cartao">
      <h2>{props.nome}</h2>
      <p>{props.preco}</p>
    </div>
  );
}

function App() {
  return (
    <div>
      <Cartao nome="Pão francês" preco="R$ 1,20" />
    </div>
  );
}
<div>
  <div class="cartao">
    <h2>Pão francês</h2>
    <p>R$ 1,20</p>
  </div>
</div>

function Cartao(props) {
  return (
    <div className="cartao">
      <h2>{props.nome}</h2>
      <p>{props.preco}</p>
    </div>
  );
}

function App() {
  return (
    <div>
      <Cartao nome="Pão francês" preco="R$ 1,20" />
      <Cartao nome="Pão de queijo" preco="R$ 3,50" />
    </div>
  );
}

O painel passa a mostrar dois div com a classe cartao, cada um com o seu título e o seu preço. Uma função, duas telas. Agora imagine vinte pães: a página fica com vinte linhas de chamada, e o componente continua com sete linhas. Mudar o desenho do cartão — a borda, a cor, o espaçamento — é mudar um lugar só.

É importante entender o que o React faz aqui, porque explica quase todo o resto. Ele não guarda um “cartão” na memória: ele chama a função Cartao uma vez para cada uso, com o objeto de props daquele uso. Duas chamadas, dois objetos diferentes, dois resultados diferentes. Se a sua função tem efeitos colaterais — um console.log, por exemplo —, eles acontecem uma vez por chamada, e isso é normal, não é bug.

7. Props são somente leitura

Uma regra que parece burocracia e é o que segura projetos grandes: dentro do componente, você não altera as props. Lê, usa, mostra — mas não escreve. O valor pertence a quem chamou.

O motivo é de organização. Se cada componente pudesse reescrever os dados que recebe, o valor na tela deixaria de corresponder ao valor guardado na página, e ninguém conseguiria responder “qual é o preço verdadeiro?”. Pior: quando a página fosse desenhada de novo — e ela é, a cada mudança de estado —, o componente receberia outra vez o valor original e a sua alteração sumiria, criando aquele tipo de bug que aparece, desaparece e ninguém consegue reproduzir.

No modo de desenvolvimento do React, esse objeto chega protegido, e a tentativa de escrever nele reclama no console. Mesmo quando a alteração passa em silêncio, ela não volta para quem chamou: o dado original continua intacto do lado de lá, e a próxima renderização desfaz o que você fez. Por isso a frase que resume tudo: props descem, nunca sobem. Quem quer mudar um valor precisa de estado, e o estado mora em quem é dono do dado.

Na prática, isso muda como você pensa a tela. Se o botão “+” da encomenda precisa aumentar a quantidade, o número não pode morar numa prop alterada pelo botão: ele mora no pai, e o pai passa o valor por prop junto com uma função para pedir a mudança. Essa função também é uma prop, e é o assunto de Props com Objetos mais adiante.

8. Quem manda no valor é quem chama

Da regra acima sai uma consequência que vale guardar em letra grande: o componente não escolhe o seu conteúdo. Se o cartão mostra “Pão francês”, é porque a página escreveu “Pão francês” na chamada. Trocar o texto do cartão, então, é editar a página — e não o componente.

Isso tem um efeito prático delicioso quando o dado vem de outro lugar. Se a lista de pães está numa variável, a chamada fica <Cartao nome={pao.nome} preco={pao.preco} />, e o cartão acompanha qualquer mudança na lista sem saber que a lista existe. O componente não precisa conhecer a padaria, o banco de dados nem o horário: ele precisa de um nome e de um preço, e alguém entrega.

É por isso que nomear bem as props economiza tempo. nome e preco dizem o que o componente espera. dado1 e dado2 dizem que quem escreveu tinha pressa. Quando o componente é seu e o uso é de outra pessoa — ou de você mesma daqui a dois meses —, o nome da prop é a documentação que ninguém esquece de atualizar, porque está no código que roda.

9. Cenários do dia a dia

O cartão em branco é o sintoma mais comum de quem está começando com props, e quase sempre a causa é o nome. Veja o caso: o componente lê props.nome, mas a página passou titulo. Nenhum erro aparece — o React entende que props.nome simplesmente não existe e desenha um título vazio.

O cartão aparece sem título: o componente lê props.nome, mas a chamada passou titulo. Acerte a chamada para o nome aparecer.

function Cartao(props) {
  return (
    <div className="cartao">
      <h2>{props.nome}</h2>
      <p>R$ 1,20</p>
    </div>
  );
}

function App() {
  return <Cartao titulo="Pão francês" />;
}
<div class="cartao">
  <h2></h2>
  <p>R$ 1,20</p>
</div>

function Cartao(props) {
  return (
    <div className="cartao">
      <h2>{props.nome}</h2>
      <p>R$ 1,20</p>
    </div>
  );
}

function App() {
  return <Cartao nome="Pão francês" />;
}

A correção pode ser dos dois lados: trocar titulo por nome na chamada, como na solução, ou trocar props.nome por props.titulo no componente. O importante é os dois lados usarem a mesma palavra. E note que não houve erro: o React não tem como saber que você queria outra coisa — para ele, faltou uma prop e pronto.

Cenário 1: o cartão em branco

A Ana chamou <Cartao nome="Pão francês" /> e o título não apareceu. O componente, porém, lia props.titulo. Nomes diferentes, tela vazia, console limpo. O conserto foi abrir o componente e conferir, letra por letra, o nome que ele lê. É o primeiro lugar para olhar sempre que uma prop “não chega”.

Cenário 2: o número que virou texto

Ela passou preco="3.5", com aspas, e o cálculo da encomenda deu errado: três pães custaram “3.53.53.5”. Com aspas o valor é texto, e texto soma colando. Trocou para preco={3.5}, sem aspas, e a conta passou a funcionar. Sempre que o valor for usado em conta, chaves.

Cenário 3: o aviso de atributo sem aspas

Com pressa, ela escreveu <Cartao nome=Pão francês />. O código nem compila: o compilador do JSX não aceita valor solto depois do sinal de igual. A mensagem fala em expressão ou texto entre aspas, e aponta a linha. Conserto: nome="Pão francês", ou nome={"Pão francês"}, se o valor vier de uma variável.

console: nome: undefined
/App.jsx: JSX value should be either an expression or a quoted JSX text. (6:22)

As duas linhas contam histórias diferentes, e reconhecer qual é qual economiza tempo. A primeira é do seu código rodando: você imprimiu uma prop que não existe, e o valor saiu undefined — a palavra que o JavaScript usa para “não existe”. A segunda é do compilador, antes de qualquer coisa rodar: o JSX está mal escrito e nem vira JavaScript.

11. Resumo

Props são os dados que entram num componente. Você escreve como atributos na chamada, o React junta tudo num objeto e entrega como primeiro argumento da função; dentro do componente, você lê com props.nome e mostra com {props.nome}. Texto vai entre aspas, todo o resto entre chaves.

Com props, um componente serve para muitos conteúdos: cada chamada é uma execução da função, com o seu próprio objeto. E o valor pertence a quem chama — o componente lê, mas não altera. Quando uma prop não aparece, o suspeito número um é o nome: o atributo e a leitura precisam usar exatamente a mesma palavra.

Para lembrar

  • Atributo na chamada vira chave no objeto props: nome="Pão" → props.nome.
  • O componente recebe props como primeiro parâmetro: function Cartao(props).
  • Para mostrar, chaves: <h2>{props.nome}</h2>.
  • Aspas entregam texto; chaves entregam JavaScript (número, conta, variável).
  • Uma chamada por cartão: duas chamadas, dois objetos, dois resultados.
  • Props são somente leitura; quem manda no valor é quem chama.
  • Prop que “não chega” quase sempre é nome diferente nos dois lados.
  • console.log(props) mostra as chaves que chegaram — o primeiro passo do diagnóstico.
  • Valor sem aspas não compila: nome=Pão é erro de sintaxe.
