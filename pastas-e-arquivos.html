Pastas e Arquivos

O projeto da Ana já roda: ela criou a pasta, o npm install passou e a página abre no navegador. Agora vem a pergunta que não é sobre React, mas decide se o projeto vai envelhecer bem: onde cada arquivo mora? Hoje o App.jsx dela tem seiscentas linhas, quatro componentes e uma foto do pão importada do lugar errado. Nesta aula ela organiza a casa — sem instalar nada e sem tocar no que já funciona.

Você vai aprender
  • O mapa de um projeto React: o que é index.html, src/ e public/.
  • O papel de cada arquivo: main.jsx, App.jsx e os componentes.
  • A regra de um componente por arquivo, com nome em maiúscula.
  • Como export e import ligam os arquivos.
  • Caminhos com ./ e ../, e o erro que aparece quando o caminho está errado.
  • A diferença entre components/ e pages/.
  • Por que o main.jsx existe e o que ele faz.

1. A cena: seiscentas linhas num arquivo só

O projeto da Ana nasceu do jeito mais comum: ela criou com o Vite, apagou o conteúdo de exemplo e começou a escrever. Cabeçalho, lista de pães, rodapé, formulário de encomenda, tudo no App.jsx. Funcionava. Até o dia em que ela quis mudar a borda do cartão e passou quarenta minutos rolando o arquivo para achar a linha certa.

O sintoma não é de React, é de casa bagunçada. Um arquivo de seiscentas linhas tem vinte assuntos dentro; para mexer em um, você atravessa os outros dezenove. A solução é a mesma de uma oficina: cada ferramenta na sua gaveta, e a gaveta com nome. A diferença é que, no React, a gaveta é uma pasta e a ferramenta é um arquivo com um componente.

Antes de abrir a primeira gaveta, um aviso: organizar não é criar vinte pastas. Um projeto pequeno com duas pastas bem usadas é melhor do que um projeto com quinze pastas quase vazias. O critério é sempre “onde eu procuraria isso daqui a três meses”.

2. O mapa da casa

Um projeto criado com Vite tem poucos arquivos no começo, e cada um tem um papel claro. Vale conhecer os cinco que você vai abrir todo dia.

index.html
A única página HTML do projeto. Não tem componente dentro; tem a div onde o React vai montar tudo — no Vite, <div id="root"></div>.
src/main.jsx
A porta de entrada. Importa o App, pega a div raiz e monta o componente com createRoot. É o único arquivo que fala com o HTML.
src/App.jsx
A raiz dos componentes: o que aparece na tela nasce aqui. É o arquivo que você abre para decidir quais telas e peças a página usa.
src/components/
As peças reaproveitáveis: Cabecalho.jsx, Cartao.jsx, Botao.jsx. Usadas por mais de uma tela ou por mais de um lugar.
src/pages/
As telas: Inicial.jsx, Paes.jsx, Contato.jsx. Cada uma monta as peças para um assunto da navegação.
public/
Arquivos servidos como estão, sem passar pelo build: favicon, foto grande, PDF de cardápio. O caminho começa na raiz do site.

Repare no que não está nessa lista: não existe pasta “utils” no dia um, nem “hooks”, nem “services”. Essas pastas nascem quando o projeto pede — quando há três funções de data para guardar, quando há um hook próprio, quando há chamadas de rede. Criar pasta vazia por simetria só atrapalha a busca.

Existe mais de uma escola de organização. A que este guia segue separa por tipo — componentes de um lado, telas do outro. A outra separa por assunto: uma pasta encomendas/ com a tela, os componentes e o CSS daquele assunto juntos. A segunda funciona melhor em projeto grande, com muitos times; a primeira é mais fácil de aprender e de navegar no começo. Escolha uma e seja consistente: o pior cenário é metade do projeto em cada estilo.

Uma diferença que confunde no começo: no projeto do Vite a div raiz se chama root; nas caixas deste guia ela se chama raiz. É só o id escolhido no HTML. O que importa é que exista uma, e que o main.jsx pegue exatamente essa.

3. O App chama o que mora em components/

Na caixa abaixo, os três componentes estão juntos no mesmo editor — é assim que você vê a ligação entre eles. Num projeto de verdade, cada um mora em src/components/, com o nome do componente no nome do arquivo. O App só usa o cabeçalho; a lista e o rodapé ficaram de fora.

No projeto, esse mesmo App.jsx começa com três importações. Elas não mudam o que aparece na tela: só dizem de qual arquivo cada nome vem.

import Cabecalho from "./components/Cabecalho";
import ListaDePaes from "./components/ListaDePaes";
import Rodape from "./components/Rodape";

function App() {
  return (
    <div>
      <Cabecalho />
      <ListaDePaes />
      <Rodape />
    </div>
  );
}

export default App;

O export default App na última linha é a outra metade do contrato: o arquivo oferece o componente para fora. Sem ele, o App.jsx existe, mas ninguém consegue importá-lo. As caixas deste guia apagam import e export default do seu código justamente porque tudo está no mesmo lugar — no projeto, eles são obrigatórios.

4. Um arquivo, um componente

A convenção é simples e vale a pena seguir sem invenção: cada arquivo exporta um componente, e o nome do arquivo é o nome do componente, com a primeira letra maiúscula. Cartao.jsx exporta Cartao. ListaDePaes.jsx exporta ListaDePaes.

function Cartao({ children }) {
  return <div className="cartao">{children}</div>;
}

export default Cartao;

O nome do arquivo não é o nome do componente para o React — o React só conhece o nome que você importa. Mas manter os dois iguais evita a caçada: quando o erro aponta Cartao.jsx, você sabe qual função abrir. E a maiúscula no arquivo acompanha a regra do JSX: o nome que você usa como componente começa com maiúscula; com minúscula, o React trataria como tag.

Duas escolhas que causam dúvida. A primeira: .jsx ou .js? Se o arquivo tem JSX dentro — e componente tem —, use .jsx. O Vite aceita as duas extensões, mas a extensão certa avisa ao editor que ali dentro tem marcação. A segunda: e quando o arquivo tem dois componentes pequenos que só existem juntos? Pode ficar num arquivo só, desde que um deles seja o exportado e o outro seja detalhe interno. Se o segundo começar a ser importado por outra tela, ele ganha o próprio arquivo.

Um hábito que economiza muito tempo: deixar o CSS do componente ao lado dele. Se Cartao.jsx tem uma classe .cartao, o arquivo Cartao.css mora na mesma pasta e é importado no topo do componente. Assim, apagar o componente é apagar a pasta dele, sem deixar estilo órfão no style.css global. O mesmo vale para o teste, quando existir: Cartao.test.jsx ao lado de Cartao.jsx. Quem abre a pasta vê tudo o que pertence àquela peça.

5. Duas telas, um cabeçalho

Agora a decisão que separa components/ de pages/. A tela inicial e a tela de pães precisam do mesmo cabeçalho. Se o cabeçalho mora dentro de uma das telas, a outra vai copiar — e a cópia envelhece. Ele é uma peça, então mora em components/ e as duas telas importam.

A segunda tela copiou o cabeçalho e ficou com outro horário. Troque as duas linhas por <Cabecalho /> para as duas telas usarem a mesma peça.

O painel agora mostra dois header iguais — e é isso que você quer: a peça aparece duas vezes, definida uma. Se amanhã o horário mudar, muda em components/Cabecalho.jsx e as duas telas acompanham. E a página de pães ficou menor, porque perdeu o cabeçalho copiado.

No projeto, as duas telas moram em src/pages/ e o cabeçalho em src/components/. O App.jsx importa as telas de ./pages/, e cada tela importa o cabeçalho de ../components/Cabecalho — com dois pontos, porque de dentro de pages/ é preciso subir um nível para chegar em components/.

6. Imports e caminhos

Todo import precisa de um caminho que exista. Existem três formas, e elas cobrem quase tudo:

Você escreveQuer dizerExemplo
./Cartaomesma pastaApp.jsx importando de src/
../Cartaouma pasta acimapages/Paes.jsx importando de components/
./components/Cartaouma subpastaApp.jsx importando a peça

A extensão é opcional: ./components/Cartao e ./components/Cartao.jsx funcionam igual, porque o Vite completa sozinho. O que não é opcional é a maiúscula do nome do arquivo — no Linux, cartao.jsx e Cartao.jsx são arquivos diferentes, e o erro de caminho aparece na hora de rodar.

Quando o caminho não existe, quem reclama é o Vite, no terminal, antes de a página abrir. A mensagem diz qual arquivo tentou importar o quê:

Failed to resolve import "./components/Cartao" from "src/App.jsx"

“Falha ao resolver o import” quer dizer: o caminho não apontou para nenhum arquivo. As causas comuns são três — a pasta não é a que você pensa, o nome do arquivo está com outra caixa, ou o arquivo está numa pasta acima e faltou o ../. Repare que o erro já entrega os dois lados: ./components/Cartao é o caminho escrito e src/App.jsx é o arquivo que escreveu. Comparando os dois, você acha a pasta certa.

Quando o projeto cresce, os caminhos com ../ começam a se repetir e a virar ../../../components/Cartao, que ninguém lê. O Vite permite criar um apelido no vite.config.js, normalmente @, apontando para src. Aí o import vira @/components/Cartao de qualquer lugar do projeto. É conveniência, não obrigação: em projeto pequeno, os caminhos relativos dizem mais sobre onde as coisas estão do que um apelido.

7. O main.jsx é a porta de entrada

Falta a peça que liga o React à página. O main.jsx é o único arquivo que conhece o HTML: ele pega a div raiz e entrega essa div ao React, dizendo qual componente desenhar dentro. É por isso que o App não aparece sozinho se você esquecer essa etapa.

Este é o main.jsx: ele já cria a raiz, mas está desenhando outra coisa. Troque o que está dentro do render por <App />.

function App() {
  return (
    <div>
      <h1>Padaria da Ana</h1>
      <p>Aberto das 6h às 18h</p>
    </div>
  );
}

const raiz = ReactDOM.createRoot(document.getElementById("raiz"));
raiz.render(<p>Carregando…</p>);
<p>Carregando…</p>

  return (
    <div>
      <h1>Padaria da Ana</h1>
      <p>Aberto das 6h às 18h</p>
    </div>
  );
}

const raiz = ReactDOM.createRoot(document.getElementById("raiz"));
raiz.render(<App />);

Três linhas e o projeto inteiro se explica. A primeira pega o elemento do HTML; a segunda cria a raiz do React em cima dele; a terceira diz o que desenhar. Como esse código roda uma vez, ele fica separado do App.jsx — misturar os dois é o tipo de bagunça que faz o componente depender de um id que só existe numa página.

Esse arquivo costuma ser o mais chato de depurar, porque roda fora dos componentes e qualquer erro dele derruba a página inteira. O caso mais comum é montar a raiz duas vezes — o que acontece quando alguém cola o trecho do main.jsx dentro de outro arquivo. A mensagem é curta e específica:

Warning: createRoot(): Target container is already passed to createRoot().

“O contêiner já foi entregue ao createRoot” — quer dizer que existe mais de uma chamada apontando para a mesma div. A div raiz pertence a um dono só: o main.jsx. Se você vir essa mensagem, procure o segundo createRoot no projeto.

No Vite, esse arquivo é gerado junto com o projeto e você quase nunca o edita. Nas caixas deste guia, quando a caixa tem data-modo="manual", é você quem monta a raiz; nas outras, o motor faz esse papel e por isso o seu componente precisa se chamar App. Saber qual dos dois está acontecendo evita a dúvida “por que a tela ficou vazia?”.

8. Onde cada coisa mora

Com as peças no lugar, a regra de decisão cabe numa tabela. Ela não é lei; é o consenso que economiza discussão.

O arquivo é…Mora emPorque
usado por duas ou mais telassrc/components/é peça, não assunto de uma tela
uma tela da navegaçãosrc/pages/monta peças para um assunto inteiro
a raiz que escolhe a telasrc/App.jsxé o primeiro componente do projeto
uma função de data ou preçosrc/utils/não é componente; nasce quando há a segunda
imagem, fonte, PDFpublic/é servido como está, sem build

A última linha tem uma pegadinha que a Ana viveu. Ela colocou a foto do pão em src/assets/ e escreveu <img src="/pao.jpg">; a imagem não apareceu, porque o caminho /pao.jpg procura na raiz do site, e o arquivo estava dentro de src. Duas saídas: mover a foto para public/pao.jpg e manter o caminho, ou deixar em src/assets/ e importar a imagem no arquivo, deixando o Vite cuidar do caminho.

O outro erro clássico de arquivo não é de caminho, é de export. Se o componente é exportado com nome (export function Cartao) e você importa como padrão (import Cartao from …), o nome chega undefined e o React reclama na hora de desenhar:

Warning: React.jsx: type is invalid -- expected a string or a class/function but got: undefined.

“Tipo inválido, esperava uma string ou uma classe/função, recebi undefined” — traduzindo: no lugar de um componente, chegou nada. Quase sempre é o par export/import desencontrado, e o conselho é escolher um estilo por projeto: ou todo mundo usa export default, ou todo mundo usa export com nome. Os dois funcionam; misturar é que gera esse aviso.

9. Cenários do dia a dia

Cenário 1: dois Cartao.jsx no projeto

Ela criou Cartao.jsx em components/ e depois outro em pages/, para a tela de encomendas. Os dois funcionavam, mas metade das telas usava um e metade usava o outro. A saída foi dar nome ao segundo pelo assunto: CartaoDeEncomenda.jsx, na mesma pasta components/, e apagar o duplicado. Nome de arquivo repetido em pastas diferentes é legal para o sistema e caro para a cabeça.

Cenário 2: a pasta utils com um arquivo

Ela criou src/utils/ para guardar uma função que formata preço em real. Um arquivo só, mas usado em quatro telas — a pasta se justificou no primeiro dia. O contrário também aconteceu: criou src/hooks/ antes de ter qualquer hook próprio, e a pasta ficou vazia por dois meses. Pasta vazia não é organização, é promessa.

Cenário 3: o componente que ficou grande demais

O App.jsx dela chegou a seiscentas linhas. Dividir em arquivos resolveu a leitura, mas não o problema de fundo: um componente que fazia coisa demais. Organizar pasta e quebrar componente são dois assuntos diferentes — o segundo é o da próxima aula, Quando Quebrar em Componentes.

11. Resumo

Um projeto React tem poucos lugares e cada um com um papel: index.html é a página, src/main.jsx é a porta de entrada, src/App.jsx é a raiz dos componentes, src/components/ guarda as peças e src/pages/ guarda as telas. public/ serve arquivos como estão.

Um arquivo, um componente, com o mesmo nome nos dois e a primeira letra maiúscula. O arquivo oferece o componente com export; quem usa pede com import e um caminho que exista: ./ para a pasta atual, ../ para subir um nível. Errou o caminho, o Vite avisa antes de abrir a página; desencontrou export e import, o React avisa com “type is invalid … got undefined”.

Organizar antes de precisar dá pasta vazia; organizar quando dói dá alívio. O critério é a pergunta “onde eu procuraria isso daqui a três meses”, e a resposta quase sempre é a pasta do assunto, não a pasta da moda. Com a casa arrumada, sobra o assunto seguinte: como decidir a hora de quebrar um componente grande em peças menores.

Para lembrar

  • index.html tem a div raiz; main.jsx monta o React nela.
  • App.jsx é a raiz dos componentes; components/ guarda peças; pages/ guarda telas.
  • Um componente por arquivo, nome igual ao do componente, primeira letra maiúscula, extensão .jsx.
  • export default oferece; import pede; os dois nomes precisam combinar.
  • ./ é a pasta atual; ../ sobe um nível.
  • A extensão no import é opcional; a maiúscula do arquivo não.
  • Caminho errado: erro do Vite, “Failed to resolve import”.
  • Export desencontrado: aviso do React, “type is invalid … got undefined”.
  • public/ para arquivos servidos como estão; src/assets/ para importar no código.
  • Pasta nasce quando o segundo arquivo do mesmo assunto aparece.
