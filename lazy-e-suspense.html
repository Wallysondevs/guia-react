lazy e Suspense

O site da Ana passou de 300 kB para 1,2 MB quando ela acrescentou a página de relatórios — e o cliente que só queria ver o pão da manhã passou a baixar o gráfico de vendas junto. Nesta aula ela aprende a mandar o React carregar um componente só quando ele for aparecer, com React.lazy, e o que mostrar enquanto o pedaço de código não chega, com Suspense.

Você vai aprender
  • O que é baixar código sob demanda e por que isso muda o primeiro acesso.
  • Como declarar um componente com React.lazy e o papel do import().
  • O que é o fallback do Suspense e o que mostrar nele.
  • Onde colocar a fronteira para não apagar a página inteira durante o carregamento.
  • Por que a rota é o melhor ponto de corte de uma aplicação.
  • Os tropeços: default faltando, erro de rede, fallback que pisca e lazy declarado no lugar errado.
  • Como medir o ganho no build e na aba Network.

1. A cena: o pacote que cresceu

O site da Ana começou com 300 kB de JavaScript: o React, o roteador e as quatro páginas. Um dia ela acrescentou a página de relatórios, com uma biblioteca de gráficos, e o pacote foi para 1,2 MB. O cliente que abre o site às seis da manhã para ver o cardápio baixa tudo — inclusive o gráfico que ele nunca vai ver.

O problema não é o tamanho do site, e sim o tamanho do primeiro arquivo. Em uma conexão de celular, 900 kB a mais significam segundos de tela branca. E segundos de tela branca custam visitas: a pessoa fecha antes de ver o pão.

A saída é dividir o código em pedaços e baixar cada um quando ele for aparecer. O React faz isso com duas peças que trabalham juntas: React.lazy, que declara um componente que ainda não está no pacote, e Suspense, que diz o que mostrar no lugar dele enquanto o arquivo não chega.

Vale saber o que acontece por baixo. O empacotador (o Vite, no projeto da padaria) vê um import() dinâmico e separa aquele módulo em um arquivo próprio, um chunk. Quando o componente aparece na tela pela primeira vez, o navegador baixa o chunk, o React espera a Promise e só então desenha. Da segunda vez em diante, o módulo já está na memória — o chunk não é baixado de novo.

2. As peças do carregamento sob demanda

Antes do código, os nomes. Eles aparecem nas mensagens de erro e no painel Network, e confundir um com outro atrapalha o diagnóstico: o lazy é do React, o import() é do JavaScript, o chunk é do empacotador e o Suspense é a fronteira que decide o que aparece na espera.

React.lazy
Uma função que recebe um carregador (função que devolve Promise) e devolve um componente que se comporta como os outros.
import()
O import dinâmico do JavaScript: em vez de carregar no topo do arquivo, carrega na hora em que for chamado, e devolve uma Promise.
chunk
O pedaço de código que o empacotador gerou para um import(). Um arquivo separado, baixado sob demanda.
Suspense
O componente que marca uma fronteira: se algo dentro dele ainda não está pronto, ele mostra o fallback.
fallback
O que aparece no lugar do conteúdo durante a espera: um texto, um esqueleto, um indicador.

Uma coisa importante: o lazy espera um módulo, não um componente. O carregador precisa devolver um objeto com a chave default — é o formato que o import() entrega, e é por isso que o componente do outro arquivo precisa ser exportado como export default. Esse detalhe é a causa do erro "element type is invalid" que aparece no primeiro dia de quem usa lazy.

Outro detalhe: o lazy tem de ser declarado no módulo, fora do componente. Declarado dentro, cada desenho cria um componente novo, e o React baixa e monta tudo outra vez. Voltamos a isso na seção dos tropeços.

3. O React.lazy no projeto de verdade

No projeto da Ana, a página de relatórios fica em um arquivo próprio. O import estático traria o arquivo para o pacote inicial; o dinâmico o deixa para depois. A diferença é uma palavra: o import() com parênteses devolve uma Promise, e é isso que o lazy consome.

// antes: entra no pacote inicial
import Relatorios from "./Relatorios.jsx";

// depois: vira um chunk, baixado quando aparecer
const Relatorios = React.lazy(() => import("./Relatorios.jsx"));

function App() {
  const [rota, setRota] = useState("/");

  return (
    <div>
      <Menu irPara={setRota} />
      <React.Suspense fallback={<p>carregando os relatórios…</p>}>
        {rota === "/relatorios" && <Relatorios />}
      </React.Suspense>
    </div>
  );
}

Neste guia não há rede dentro das caixas, então os exemplos trocam o import() por uma Promise que se resolve com um atraso — a mesma forma que o lazy espera. O comportamento que você observa é o mesmo; muda só a origem do arquivo. No projeto, quem resolve a Promise é o navegador baixando o chunk.

Vale notar que o lazy não é exclusivo de rotas: dá para usá-lo em um modal que só abre ao clicar, em uma tabela pesada que só aparece depois de um filtro, em um editor de texto de uma tela secundária. A pergunta é sempre a mesma: esse componente é necessário no primeiro desenho? Se não, ele pode chegar depois.

4. O que mostrar enquanto baixa

Na caixa, o cardápio é lazy e a fronteira existe — mas o fallback é null. Durante os primeiros instantes, a área do cardápio simplesmente não existe: o cliente vê o topo e um vazio. É o mesmo problema da rota 404, com outra causa: a tela não diz nada.

A fronteira tem fallback={null} e a espera fica invisível. Troque por um parágrafo com o texto assando o cardápio… e clique em Rodar.

const Cardapio = React.lazy(() => new Promise((ok) => {
  setTimeout(() => ok({ default: CardapioDoDia }), 200);
}));

function CardapioDoDia() {
  return <p>pão de queijo, croissant, sonho</p>;
}

function App() {
  return (
    <div>
      <h1>Padaria da Ana</h1>
      <React.Suspense fallback={null}>
        <Cardapio />
      </React.Suspense>
    </div>
  );
}

O painel do código inicial mostra só o título; o da solução mostra o título e o aviso. É o retrato dos primeiros instantes: em duzentos milissegundos o cardápio chega e o aviso sai de cena. Deixar o fallback nulo é aceitável quando o carregamento é quase instantâneo (um clique que já tem o chunk em cache); é ruim quando é a primeira visita.

Um bom fallback tem o tamanho aproximado do conteúdo que vai chegar. Um parágrafo de texto em uma área que vai virar uma tabela de dez linhas faz a página "pular" quando o conteúdo entra — o famoso deslocamento de layout. Um esqueleto cinza do tamanho certo evita o pulo e ainda dá a sensação de progresso.

5. Onde colocar a fronteira

O Suspense é uma fronteira: tudo o que está dentro dela fica escondido enquanto qualquer coisa ali dentro estiver esperando. Colocada no topo da árvore, ela esconde a página inteira — topo, menu, título — por causa de um pedaço que ainda não chegou. Colocada em volta do conteúdo, só o conteúdo desaparece.

A fronteira está envolvendo a página inteira, e o título desaparece durante o carregamento. Deixe o <h1> fora e envolva só o <Cardapio /> com o Suspense.

const Cardapio = React.lazy(() => new Promise((ok) => {
  setTimeout(() => ok({ default: CardapioDoDia }), 200);
}));

function CardapioDoDia() {
  return <p>pão de queijo, croissant, sonho</p>;
}

function App() {
  return (
    <React.Suspense fallback={<p>assando o cardápio…</p>}>
      <div>
        <h1>Padaria da Ana</h1>
        <Cardapio />
      </div>
    </React.Suspense>
  );
}

O painel do código inicial mostra apenas o aviso: o título foi engolido pela fronteira. Depois da missão, aparecem o título e o aviso, e é possível ler onde está o problema. Duas fronteiras — uma no topo para o que é essencial, outra por área — dão resultados melhores do que uma fronteira enorme.

Existe uma exceção que vale conhecer: em navegação, esconder a página inteira por um instante é pior do que manter a página antiga até a nova chegar. O React 19 faz isso quando a atualização vem de uma transição (o startTransition, ou o useTransition da aula de transições): a fronteira não mostra o fallback se já havia conteúdo na tela. O assunto é do nível de transições, mas o efeito prático é esse — a navegação não pisca.

6. A rota é o melhor ponto de corte

Onde cortar? A resposta mais rentável é a rota: cada página vira um chunk, e o cliente baixa a página que pediu. A página inicial continua pequena; a de relatórios chega só quando alguém abre relatórios. É a divisão que combina com o que o cliente faz — ele navega.

Na caixa, o cardápio é importado direto: ele entra no pacote inicial e aparece junto com o título. A missão é trocar a chamada direta por um lazy e mostrar o aviso da espera. Quando o aviso aparecer no painel, você acabou de provar que o cardápio deixou de vir no pacote inicial.

O cardápio entra no pacote inicial. Troque o uso direto de <CardapioDoDia /> por um componente criado com React.lazy (atraso de 200 ms) e envolva-o em Suspense com o fallback assando o cardápio….

function CardapioDoDia() {
  return <p>pão de queijo, croissant, sonho</p>;
}

function App() {
  return (
    <div>
      <h1>Padaria da Ana</h1>
      <CardapioDoDia />
    </div>
  );
}

Uma nota sobre expectativa: dividir por rota não deixa a primeira página mais leve se ela carrega tudo o que as outras precisam em comum. O ganho vem de tirar do pacote inicial o que só algumas rotas usam — gráficos, editores, mapas, tabelas grandes. Um projeto bem cortado costuma ter um pacote inicial pequeno e vários chunks médios.

7. Os tropeços do caminho

O primeiro é esquecer o default. O lazy espera um módulo com essa chave; um carregador que devolve o componente direto produz o erro "element type is invalid" na hora de desenhar. No projeto, isso acontece quando o arquivo exporta sem default — a correção é ajustar o export, e não o lazy.

O segundo é o erro de rede. O chunk é um arquivo como outro qualquer: se a conexão cair no meio, ou se uma publicação nova trocar o nome do arquivo, o download falha e a Promise é rejeitada. O Suspense não pega esse erro — quem pega é um error boundary, um componente que envolve a área e mostra uma mensagem quando algo quebra. Sem ele, a página inteira some.

GET https://loja.test/assets/Cardapio-3f9c1a.js net::ERR_ABORTED 404
Uncaught Error: Failed to fetch dynamically imported module: /assets/Cardapio-3f9c1a.js

O terceiro é o fallback que pisca. Se o chunk demora 40 ms e o seu aviso tem uma animação de meio segundo, o cliente vê um flash desagradável a cada navegação. Duas saídas: manter a página anterior até a nova chegar (transição) ou atrasar a exibição do aviso por um instante, mostrando-o só quando a espera passar de, digamos, 150 ms.

O quarto é o lazy declarado dentro do componente. Como ele é uma fábrica de componentes, declarar no corpo cria um tipo novo a cada desenho: o React descarta o anterior, pede o módulo de novo (do cache do navegador, mas ainda assim) e remonta. O sintoma é o aviso aparecendo a cada clique, mesmo com o código já baixado. Declare sempre no módulo, como as caixas fazem.

8. Medindo o ganho

O build mostra os chunks e o tamanho de cada um. Antes de dividir, havia um arquivo grande; depois, um arquivo inicial menor e alguns pedaços. O número que importa é o do primeiro — o resto só é baixado se o cliente pedir.

dist/assets/index-9a1c2f.js        312.44 kB │ gzip: 101.02 kB
dist/assets/Relatorios-7e4b9d.js   648.11 kB │ gzip: 198.30 kB
dist/assets/Cardapio-3f9c1a.js      12.08 kB │ gzip:   4.61 kB

Repare na coluna do gzip: é o que o navegador baixa de verdade. E repare que o chunk grande continua grande — a divisão não fez o código encolher, só mudou quando ele é baixado. Se o relatório é aberto por dez por cento dos clientes, a conta fecha; se todos abrem na primeira tela, dividir não ajuda em nada.

A aba Network do navegador mostra o mesmo na prática: um arquivo no primeiro acesso, outro quando você abre a rota. Vale olhar também o "cache": na segunda visita, o chunk vem do cache do navegador com uma resposta de poucos bytes. E vale desconfiar de chunks minúsculos demais — um arquivo por componente gera dezenas de requisições e o ganho vira custo de protocolo.

9. Cenários do dia a dia

Cenário 1: o site ficou mais lento depois de dividir

Acontece quando o corte é fino demais: vinte chunks de 3 kB e vinte requisições, cada uma com a sua latência. O primeiro acesso piora. O bom corte agrupa por área: uma rota inteira, um modal grande, uma biblioteca pesada. Se o chunk tem menos de 10 kB, provavelmente não valia a pena separar.

Cenário 2: o cliente atualizou o site no meio da navegação

A Ana publicou uma versão nova e os nomes dos chunks mudaram. Um cliente com a página aberta clicou em "relatórios" e o arquivo antigo já não existia: 404 no chunk e a página sumiu. A defesa é um error boundary com "recarregue a página" e manter os arquivos antigos no ar por um tempo após a publicação.

Cenário 3: o modal que demora na primeira abertura

O modal de pagamento é lazy e, na primeira vez, o cliente vê o esqueleto por meio segundo; na segunda, abre na hora. É o comportamento esperado — o chunk fica em memória. Se a primeira abertura for frequente e crítica, vale baixar o chunk antes, quando a página estiver ociosa, com um import() disparado por um efeito; o React 19 tem até uma função de pré-carregamento para isso.

11. Resumo

Baixar código sob demanda é dividir o pacote em chunks e carregar cada um quando ele for aparecer. No React, a declaração fica no módulo: const X = React.lazy(() => import("./X.jsx")). O componente se comporta como qualquer outro, com uma diferença: na primeira vez ele precisa esperar o arquivo, e durante essa espera o Suspense mostra o fallback.

A fronteira é a decisão de projeto mais importante. Envolver a página inteira apaga o topo e o menu por causa de um pedaço; envolver só a área que espera mantém o resto legível. Na navegação, a transição evita o pisca-pisca. E o melhor ponto de corte costuma ser a rota: o cliente baixa o que pediu.

Os tropeços são previsíveis: default faltando, erro de rede sem error boundary, fallback que pisca e lazy declarado dentro do componente. Com a medição no build e na aba Network, dá para saber se a divisão valeu — e vale lembrar que ela não deixa o código menor, só muda o momento em que ele chega.

Para lembrar

  • React.lazy recebe um carregador que devolve Promise com default.
  • O import() dinâmico é o que gera o chunk no build.
  • Declare o lazy no módulo, nunca dentro do componente.
  • Suspense mostra o fallback enquanto o conteúdo não está pronto.
  • A fronteira esconde tudo o que está dentro: coloque-a perto do que espera.
  • Na navegação, transição evita trocar a página pelo aviso.
  • fallback com o tamanho do conteúdo evita o pulo de layout.
  • Suspense não trata erro: para isso existe o error boundary.
  • O corte mais rentável é por rota; chunks minúsculos demais custam requisições.
  • Medir no build (tamanho + gzip) e na aba Network.
