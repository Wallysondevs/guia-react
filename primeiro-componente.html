O Primeiro Componente

A Ana tem um site de três páginas feito à mão, em HTML puro. Cada página repete o mesmo cabeçalho, a mesma lista de pães, o mesmo rodapé — e quando ela muda o horário de funcionamento, precisa editar três arquivos e rezar para não esquecer nenhum. Nesta aula ela escreve o primeiro componente React: uma função que devolve pedaços de tela, e que ela vai reaproveitar em todo lugar. Sem instalar nada, sem configuração: o componente roda aqui na caixa, com o React de verdade.

Você vai aprender
  • O que é um componente: uma função que devolve a tela.
  • Como se escreve a primeira função componente e o que o React faz com ela.
  • A ler o painel: o HTML que o React gerou a partir do seu JSX.
  • Por que um componente devolve um elemento só, e o que fazer quando precisa de vários.
  • Como chamar um componente dentro de outro.
  • Como o componente recebe dados de fora (as props), só para reconhecer o assunto.
  • Como usar console.log para espiar o que está acontecendo.

1. A cena: o mesmo cabeçalho em três arquivos

A padaria da Ana tem três páginas: a inicial, a lista de pães e o contato. Em cada uma delas, o topo da página é igual: o nome da padaria, o horário e um aviso. Ela copiou e colou esse topo três vezes, e é isso que dói. Mudou o horário de sábado? Três arquivos. Errou uma letra? Agora as páginas mostram coisas diferentes.

A ideia do React é simples e vale a aula inteira: em vez de escrever o topo em três lugares, escreva uma função que devolve o topo — e mande as três páginas chamarem essa função. Essa função que devolve um pedaço de tela se chama componente. Não é uma classe, não é um arquivo especial, não tem palavra mágica: é uma função.

Você talvez tenha visto React por aí com arquivos terminando em .jsx, com import e export default. Isso é o React num projeto de verdade, com ferramentas de build. Aqui na caixa, o componente é só a função — o resto chega no Nível 3, quando o assunto for montar o projeto. Por enquanto, o importante é entender o mecanismo.

2. O que é um componente, na prática

Um componente é uma função que devolve alguma coisa que o React sabe desenhar. Essa coisa é escrita numa linguagem chamada JSX, que parece HTML mas não é bem HTML — é uma forma mais curta de escrever "crie este elemento". Quando a função roda, o React pega o que ela devolveu e transforma em elementos de verdade na página.

componente
Uma função JavaScript que começa com letra maiúscula e devolve JSX. App, Cabecalho, ListaDePaes.
JSX
A escrita parecida com HTML que o React entende: <h1>Pão</h1> dentro do código JavaScript.
elemento
O que o JSX representa: uma peça da tela, com o nome da tag, os atributos e os filhos.
renderizar
O ato de o React pegar o que o componente devolveu e colocar na página de verdade.

Uma nota sobre a história, porque ela aparece em código antigo: até 2019, componente em React também podia ser escrito com class e um método render(). Hoje a forma normal é a função, e é só ela que você vai ver neste guia. Se cair num código com class extends React.Component, não se assuste: aquilo é um componente também, só escrito no estilo antigo.

Duas regras de ouro, que valem dor de cabeça se esquecidas. Primeira: o nome do componente começa com letra maiúscula. O React usa essa diferença para saber se <Cabecalho /> é um componente seu ou uma tag comum como <div>. Segunda: a função devolve uma coisa só. Um elemento, que pode ter vários filhos dentro — mas um na raiz.

3. O primeiro componente

Vamos ao menor componente possível. A função se chama App e devolve um título:

O título está escrito "Oi". Troque o texto para Pão quentinho e clique em Rodar.

function App() {
  return <h1>Oi</h1>;
}
<h1>Oi</h1>

function App() {
  return <h1>Pão quentinho</h1>;
}

Repare no painel: ele mostra <h1>Pão quentinho</h1>. Isso é o HTML que o React gerou. O seu código nunca escreveu esse HTML à mão — escreveu JSX, o React transformou em chamadas de função, rodou a função App e montou o elemento na página. Ver esse HTML é a melhor forma de entender o que está acontecendo: o JSX é a receita, o HTML é o bolo.

Uma coisa que confunde no começo: o return está numa linha e o JSX na outra, mas os dois são a mesma frase. Se você quebrar a linha logo depois de return, o JavaScript entende que a função terminou ali e devolve undefined — e aí nada aparece. Por isso a convenção de colocar o JSX entre parênteses quando ele ocupa várias linhas.

4. Lendo o painel (e o console)

O painel tem dois tipos de linha. As linhas de tags são o HTML gerado; as linhas que começam com console: são o que o seu código escreveu com console.log. O console é o jeito mais antigo e mais confiável de espiar o que está acontecendo: valores, cálculos, o que veio de um clique.

Dentro do componente, calcule 2 + 1 e escreva no console total de pães: 3. O texto do título continua o mesmo.

function App() {
  const total = 2 + 1;
  return <h1>Pão quentinho</h1>;
}
<h1>Pão quentinho</h1>

function App() {
  const total = 2 + 1;
  console.log("total de pães: " + total);
  return <h1>Pão quentinho</h1>;
}

Aqui o componente faz duas coisas: calcula e mostra. Rodar código antes do return é normal e é o que permite preparar os dados que a tela vai usar. O que não pode é esquecer o return: sem ele, a função devolve undefined e o React reclama que um componente precisa devolver algo.

No navegador de verdade esse console é a aba Console do DevTools, aberta com F12. Aqui ele aparece no painel, com o mesmo conteúdo e na mesma ordem:

5. Um elemento pai só

Agora o tropeço clássico. A Ana quer que o topo tenha o nome da padaria e o horário. Ela escreve os dois lado a lado, no mesmo return:

function App() {
  return (
    <h1>Padaria da Ana</h1>
    <p>Aberto das 6h às 18h</p>
  );
}

Isso não compila, e a mensagem do React fala em "adjacent JSX elements" — elementos JSX adjacentes, um do lado do outro. A razão é que o JSX é traduzido para uma chamada de função que cria um elemento; dois elementos soltos não cabem em um. A solução é embrulhar os dois em alguma coisa: uma <div> (que cria um nó de verdade) ou um Fragment (que não cria nó nenhum).

O componente devolve dois elementos soltos e não compila. Coloque os dois dentro de uma <div> para a página aparecer com o título e o horário.

function App() {
  return (
    <h1>Padaria da Ana</h1>
    <p>Aberto das 6h às 18h</p>
  );
}
Erro: não compilou: /App.jsx: Adjacent JSX elements must be wrapped in an enclosing tag. Did you want a JSX fragment <>...</>? (4:4)

  2 |   return (
  3 |     <h1>Padaria da Ana</h1>
> 4 |     <p>Aberto das 6h às 18h</p>
    |     ^
  5 |   );
  6 | }

function App() {
  return (
    <div>
      <h1>Padaria da Ana</h1>
      <p>Aberto das 6h às 18h</p>
    </div>
  );
}

Note também que a mensagem aponta a linha 3:4 — linha 3, coluna 4 — e sugere a saída: envolver os elementos num fragmento <>...</>, que é uma casca invisível. As duas soluções funcionam; a diferença é que a div aparece no HTML final e o fragmento não. Voltamos a isso na aula de composição.

Rodar o código quebrado de propósito é uma boa ideia: você vê a mensagem de verdade, com a linha onde o problema está, em vez de decorar um nome de erro. E note que o painel aceitou o erro sem quebrar a página — o React reclama, mas o resto do guia continua funcionando.

6. Um componente dentro do outro

Agora o motivo de tudo. A Ana separa o topo num componente chamado Cabecalho e usa esse componente dentro do App. JSX aceita componentes como se fossem tags: a diferença é a primeira letra maiúscula.

A função Cabecalho já existe, mas o App não a usa: só mostra a lista de pães. Chame <Cabecalho /> dentro do App.

function Cabecalho() {
  return (
    <div>
      <h1>Padaria da Ana</h1>
      <p>Aberto das 6h às 18h</p>
    </div>
  );
}

function App() {
  return (
    <div>
      <p>Pão saindo do forno</p>
    </div>
  );
}
<div>
  <p>Pão saindo do forno</p>
</div>

function Cabecalho() {
  return (
    <div>
      <h1>Padaria da Ana</h1>
      <p>Aberto das 6h às 18h</p>
    </div>
  );
}

function App() {
  return (
    <div>
      <Cabecalho />
      <p>Pão saindo do forno</p>
    </div>
  );
}

O painel mostra o resultado final: o div do App com o div do Cabecalho dentro, e o texto do topo. O React não "salva" o componente em lugar nenhum: ele chama a função Cabecalho na hora de montar a tela. Componente é função — chamou, apareceu. E é por isso que o reaproveitamento funciona: as três páginas do site da Ana podem chamar o mesmo Cabecalho, e mudar o horário passa a ser mudar uma linha.

7. O componente recebe dados: props

Um cabeçalho que só serve para a Ana não resolve muito. O mesmo componente precisa mostrar "Padaria da Ana" na padaria e "Livraria da Ana" na loja ao lado. A forma de mandar dados para dentro de um componente é por props — os atributos que você escreve na hora de chamar:

function Cabecalho(props) {
  return <h1>{props.nome}</h1>;
}

function App() {
  return (
    <div>
      <Cabecalho nome="Padaria da Ana" />
      <Cabecalho nome="Livraria da Ana" />
    </div>
  );
}

Props são somente leitura. O componente recebe os dados e usa, mas não os altera — quem manda no valor é quem chama. Essa restrição parece chata e é uma das melhores ideias do React: se cada componente pudesse mexer nas props dos outros, rastrear um bug viraria arqueologia. Quem precisa mudar dados ao longo do tempo usa estado, que é o assunto das próximas aulas.

Três detalhes que a aula de props vai destrinchar, mas que já aparecem aqui: o componente recebe um objeto chamado props; as chaves { } mostram um valor dentro do JSX; e um componente pode ser usado quantas vezes quiser, cada vez com props diferentes. O React chama a função uma vez por uso — dois <Cabecalho /> são duas chamadas.

8. Os tropeços de leitura do JSX

Quase todo erro de quem começa está em uma destas quatro linhas. Vale ler com calma, porque o sintoma de todos é parecido: a tela não mostra o que você esperava.

Há um jeito infalível de descobrir qual caso você tem em mãos: rode o código e leia o painel. Se aparecer Erro: não compilou:, é sintaxe — o componente nem chegou a rodar. Se o painel mostrar um HTML diferente do que você esperava, o componente rodou e devolveu outra coisa: aí o problema está no que você escreveu dentro do JSX, não na estrutura.

O terceiro caso é o mais confuso, porque o erro fala de "elementos adjacentes" e o arquivo parece certo. A causa é a tradução que o React faz: cada elemento do JSX vira uma chamada React.createElement, e uma função não pode devolver duas chamadas soltas. Embrulhar é dar à função uma coisa para devolver.

Já o primeiro caso engana por não reclamar. Um componente com nome minúsculo é lido como tag HTML — e o navegador aceita qualquer tag, mesmo inventada. Ele cria um elemento vazio e segue em frente. Na dúvida entre "meu componente não aparece" e "meu componente está errado", conferir a maiúscula resolve metade dos casos.

Adjacent JSX elements must be wrapped in an enclosing tag.
Warning: Invalid DOM property `class`. Did you mean `className`?

A primeira linha é do compilador, e impede a página de rodar: é um erro de sintaxe. A segunda é um aviso do React, e a página roda mesmo com ele — só o atributo não é aplicado. Guardar a diferença entre erro e aviso economiza tempo: erro impede, aviso reclama.

9. Cenários do dia a dia

Cenário 1: o componente aparece duas vezes e o texto é o mesmo

A Ana chamou <Cabecalho /> duas vezes e viu o mesmo texto nas duas. É o esperado: sem props, o componente devolve sempre a mesma coisa. O que muda de uma cópia para outra é o que você manda por atributo. E se o texto ficar grande demais para a tela, é CSS — o React não interfere no estilo, só nos elementos.

Cenário 2: a função não aparece na tela

Ela escreveu function cabecalho() com letra minúscula e usou <cabecalho />. O React entendeu que era uma tag HTML desconhecida e desenhou um elemento vazio. Letra maiúscula no nome do componente não é estilo, é regra: é assim que o React separa componente de tag. O sintoma é uma tela em branco sem erro nenhum.

Cenário 3: esqueceu o return

O componente calculava, escrevia no console e terminava. Sem return, a função devolve undefined, e o React avisa que nada foi devolvido. É um dos erros mais comuns de quem está começando, e o console do navegador aponta o componente. Na dúvida, olhe a última linha da função: tem um return com JSX?

Exercício: o rodapé da padaria

Crie um componente Rodape que devolve um parágrafo com o texto "Padaria da Ana — desde 1998" e chame esse componente dentro do App. Depois responda: qual é o nome da função que você criou?

function () { return <p>Padaria da Ana — desde 1998</p>; }

Dica: o nome começa com maiúscula, porque é um componente. Se você escrever rodape, o React trata como tag e nada aparece.

11. Resumo

Componente é uma função com nome maiúsculo que devolve JSX. O React chama essa função, transforma o JSX em elementos e monta a página — e o painel das caixas mostra exatamente esse resultado, o HTML gerado. Um componente devolve um elemento na raiz; para mostrar várias coisas lado a lado, embrulhe em uma div ou em um Fragment. E componentes chamam componentes: <Cabecalho /> dentro do App é o começo de qualquer aplicação React.

Vale reparar no que este guia está fazendo quando você clica em Rodar: o JSX é transformado em JavaScript pelo Babel, esse JavaScript roda com o React 19 dentro de um quadro isolado, e o painel lê o resultado. É o mesmo caminho de um projeto de verdade — a diferença é que lá o passo de transformar acontece antes de a página ir para o servidor, e aqui acontece no seu navegador, na hora. Entender isso agora evita a pergunta "onde está o HTML?" mais adiante.

E um último conselho prático: quando um componente pequeno não aparece, reduza. Apague tudo e deixe só return <p>oi</p>. Se aparecer, o problema está no que você apagou; se não aparecer, o problema está no nome do componente, no return ou na chamada. Reduzir até o osso acha o culpado mais rápido do que reler quarenta linhas.

Guardar esse desenho mental — função entra, JSX sai, React monta — resolve a maior parte da confusão inicial. As props entram nesse desenho como os dados que chegam de fora, e o estado (a próxima parada do nível) como os dados que nascem dentro do componente e mudam com o tempo.

Para lembrar

  • Componente é função; o nome começa com letra maiúscula.
  • A função devolve JSX, e o React transforma o JSX em HTML de verdade.
  • Um componente devolve um elemento raiz só; os filhos ficam dentro dele.
  • Para vários irmãos sem criar nó: Fragment ou <>...</>.
  • <Componente /> chama a função; quantas vezes aparecer, quantas vezes roda.
  • Props são os atributos que chegam ao componente: <Cabecalho nome="Ana" />.
  • className vira class e htmlFor vira for.
  • { } abre espaço para JavaScript dentro do JSX.
  • Sem return não há tela: a função devolve undefined.
  • console.log aparece no painel, prefixado com console:.
