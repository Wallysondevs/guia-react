style Inline

A cor do preço da Ana agora depende do estoque: vermelho quando o pão acabou, preto quando tem pão no balcão. Isso não cabe em uma folha de CSS, porque o valor nasce do estado e muda a cada clique. Nesta aula ela aprende a segunda forma de estilizar no React — a prop style, que recebe um objeto JavaScript — e a reconhecer o que ela faz bem e o que ela simplesmente não faz.

Você vai aprender
  • Por que o style tem chaves duplas.
  • A escrever as propriedades em camelCase e a entender o que o React faz com elas.
  • Por que fontSize: 20 vira 20px e opacity: 0.5 não.
  • Como deixar o estilo mudar com o estado, inclusive com o que a pessoa digita.
  • O que o style inline não faz: :hover, media query e animação.
  • Quando usar classe, quando usar estilo inline e quando usar os dois juntos.
  • Como ler o atributo style no painel e no DevTools.

1. A cena: a cor que o CSS não decide sozinha

Na aula anterior a Ana resolveu o selo de esgotado com uma classe: esgotado pinta o texto de cinza, e o componente decide se a classe entra. Funcionou. Agora ela quer mais: o preço deve ficar vermelho quando o balcão está vazio e voltar ao preto quando ela assa mais pão. Cinza não basta — ela quer um vermelho específico, que o cliente vê de longe.

Duas classes resolveriam: preco e preco--esgotado, cada uma com a sua cor. E essa continua sendo a melhor solução quando são dois ou três estados fixos. Mas a Ana quer mais um passo: uma barra que mostra quanto pão sobrou, preenchendo 20% quando tem dois pães e 100% quando tem dez. Uma porcentagem calculada não vira classe: não dá para escrever uma classe para cada número possível.

É aí que entra a segunda ferramenta. Todo elemento HTML aceita um atributo style, com declarações de CSS escritas ali mesmo. No React, esse atributo vira uma prop chamada style — com uma diferença importante: ele não recebe texto, recebe um objeto JavaScript. Quem vem do HTML estranha no começo; depois de três usos, parece natural.

A divisão de trabalho fica assim: a classe cuida do desenho que pertence ao site — cores, fontes, espaçamentos, tudo o que é igual em todos os pães. O style inline cuida do valor que vem do dado — a cor de hoje, a largura da barra, a ordem de um item. Uma regra prática: se o valor é o mesmo para todos os elementos daquele tipo, é CSS; se o valor sai de um estado, é style.

2. A prop style é um objeto

A sintaxe assusta por causa das duas chaves: style={{ color: "crimson" }}. Não é capricho. A primeira chave diz "aqui começa JavaScript dentro do JSX"; a segunda diz "aqui começa um objeto". Por dentro, são propriedades de CSS com o nome escrito em camelCase e o valor em texto ou número.

style
A prop que preenche o atributo style do elemento. Recebe um objeto, não uma string.
objeto de estilo
O mapa entre nome de propriedade e valor: { color: "crimson", fontSize: 20 }.
camelCase
O jeito de escrever nomes compostos: backgroundColor, fontSize, marginTop. No CSS eles têm hífen.
pixel automático
Quando o valor é número, o React acrescenta px — menos nas propriedades que não têm unidade.
variável CSS
Um nome que começa com -- e guarda um valor para ser usado com var(--nome). Funciona dentro do objeto, entre aspas.

Antes de escrever a primeira linha, vale ver o que o React produz. A tabela abaixo mostra o objeto, o atributo que sai no HTML e o efeito. Note que o painel das caixas mostra exatamente a segunda coluna: o atributo style com as declarações já normalizadas.

A sexta é o oposto: um nome com sublinhado em vez de maiúscula não quebra nada, só não aparece — e você perde vinte minutos procurando o erro no lugar errado.

No DevTools, a conferência é de duas linhas. A primeira mostra o que o React escreveu; a segunda, o valor que o navegador calculou depois de aplicar tudo:

document.querySelector("p").getAttribute("style")
'color: crimson; font-size: 20px;'
getComputedStyle(document.querySelector("p")).fontSize

3. O primeiro estilo

Hora de escrever. O preço do pão precisa de três coisas: vermelho-escuro (crimson), tamanho 20 e negrito. As três cabem em um objeto, e o objeto vai entre as chaves do JSX. Como a cor vem em texto e o tamanho vem em número, a mistura de aspas é normal: só o número dispensa aspas.

O preço está sem estilo nenhum. Dê a ele a cor crimson, o tamanho 20 e o peso "bold", usando a prop style.

function App() {
  return (
    <div>
      <p>Pão francês — R$ 12,00</p>
      <p>Pão de queijo — R$ 8,00</p>
    </div>
  );
}
<div>
  <p>Pão francês — R$ 12,00</p>
  <p>Pão de queijo — R$ 8,00</p>
</div>

function App() {
  return (
    <div>
      <p style={{ color: "crimson", fontSize: 20, fontWeight: "bold" }}>
        Pão francês — R$ 12,00
      </p>
      <p>Pão de queijo — R$ 8,00</p>
    </div>
  );
}

Depois da solução, o painel mostra <p style="color: crimson; font-size: 20px; font-weight: bold;">. Três declarações, exatamente na ordem em que você escreveu, com o px acrescentado no tamanho. Repare que 20 virou 20px porque o fontSize é uma medida; o mesmo aconteceria com margin, padding, width e borderRadius.

Se você quisesse 20 pontos em vez de pixels — o que quase nunca é o certo —, o valor precisaria ser texto: fontSize: "20pt". Sempre que a unidade não é pixel, escreva a unidade junto, entre aspas. E cuidado com a vírgula entre as propriedades: é um objeto JavaScript comum, então esquecer a vírgula quebra a compilação do JSX, com uma mensagem apontando a linha — o mesmo tipo de erro que você já viu nas aulas de JSX.

Um detalhe que confunde quem vem do CSS: font-weight aceita "bold" e também número, 700. Os dois funcionam, e o painel mostra font-weight: bold; no primeiro caso. O número é mais preciso quando você quer 600 ou 800; a palavra é mais legível. Em ambos, o resultado é o mesmo peso na tela.

4. Estilo que vem do estado

Aqui começa a parte que o CSS não faz. O valor da propriedade pode ser uma expressão que lê o estado, e o React recalcula o objeto a cada renderização. Quando o estado muda, o objeto muda, o atributo muda e a tela muda — sem nenhuma classe nova no CSS e sem nenhum efeito.

A Ana quer o preço vermelho quando não há pão. Ela já tem o estado paes e a variável esgotado, calculada na renderização. O estilo é só uma conta em cima disso, com um ternário.

O preço está sempre preto. Use o ternário com esgotado para que ele fique "red" quando não há pão e "black" quando há.

function App() {
  const [paes, setPaes] = useState(0);
  const esgotado = paes === 0;

  return (
    <div>
      <p className="preco" style={{ color: "black" }}>Pão francês — R$ 12,00</p>
      <p>{paes} pães no balcão</p>
      <button onClick={() => setPaes(paes + 1)}>Assar mais um</button>
    </div>
  );
}
<div>
  <p class="preco" style="color: black;">Pão francês — R$ 12,00</p>
  <p>0 pães no balcão</p>
  <button>Assar mais um</button>
</div>

function App() {
  const [paes, setPaes] = useState(0);
  const esgotado = paes === 0;

  return (
    <div>
      <p className="preco" style={{ color: esgotado ? "red" : "black" }}>
        Pão francês — R$ 12,00
      </p>
      <p>{paes} pães no balcão</p>
      <button onClick={() => setPaes(paes + 1)}>Assar mais um</button>
    </div>
  );
}

Na solução, o painel mostra style="color: red;" antes do clique e style="color: black;" depois — o atributo muda de verdade, e não é uma classe a mais. Se você quiser combinar com a aula anterior, dá para deixar a classe cuidar do resto: preco traz o tamanho e a margem, o style traz só a cor que depende do estoque. Duas ferramentas, cada uma com o seu pedaço.

Note também que o estado não guarda o estilo. Guardar const [cor, setCor] = useState("black") e mudar a cor em um efeito seria repetir o erro da aula de quando não usar efeito: a cor é derivada de paes. O objeto de estilo é uma conta feita na hora, como o total do pedido.

5. O valor que a pessoa escolhe

O caso mais direto de estilo inline é o valor que vem de um campo. A Ana quer testar cores no balcão: digita o nome de uma cor e vê o cartão mudar. O input guarda texto no estado; o style usa esse texto direto. Nada de classe, nada de efeito, nada de conversão.

O cartão está sempre branco. Pinte o fundo com a cor que estiver no estado cor, usando backgroundColor.

function App() {
  const [cor, setCor] = useState("white");

  return (
    <div>
      <input value={cor} onChange={(e) => setCor(e.target.value)} />
      <p style={{ backgroundColor: "white" }}>Pão francês — R$ 12,00</p>
    </div>
  );
}
<div>
  <input value="white">
  <p style="background-color: white;">Pão francês — R$ 12,00</p>
</div>

function App() {
  const [cor, setCor] = useState("white");

  return (
    <div>
      <input value={cor} onChange={(e) => setCor(e.target.value)} />
      <p style={{ backgroundColor: cor }}>Pão francês — R$ 12,00</p>
    </div>
  );
}

Digite "crimson" na solução e o painel passa a mostrar style="background-color: crimson;". Digite uma cor inválida, como "crimsonn", e o React escreve o atributo do mesmo jeito; é o navegador que descarta o valor e mantém o fundo anterior. Isso é importante: o React não valida CSS. Ele escreve o que você mandou, e o navegador decide o que fazer com aquilo.

Uma consequência prática: nunca construa uma string inteira de CSS, tipo style={"background-color: " + cor}. Vai virar string, e string não é objeto — o componente nem desenha. O objeto é a única forma, e ele já aceita expressões em cada valor, como você acabou de ver.

6. Números, unidades e o que não é pixel

O React acrescenta px nos valores numéricos porque isso resolve 95% dos casos. Mas existem propriedades em que px não faz sentido, e o React sabe quais são: ele mantém o número puro nas chamadas "sem unidade". As mais comuns são opacity, zIndex, flex, flexGrow, order, lineHeight e fontWeight.

Então opacity: 0.5 fica opacity: 0.5, e não 0.5px. Já lineHeight: 1.5 fica sem unidade, o que em CSS significa "uma vez e meia o tamanho da fonte". Se você quisesse 24 pixels de altura de linha, escreveria lineHeight: "24px" — com aspas, porque a unidade é parte do texto.

const estiloAviso = {
  opacity: 0.5,        // 0.5, sem px
  lineHeight: 1.5,     // 1.5, sem px
  zIndex: 3,           // 3, sem px
  marginTop: 12,       // 12px
  fontSize: "1.2rem"   // unidade escrita à mão
};

Quando o valor vem de uma conta, cuidado com o resultado. width: 100 / 3 vira 33.333333333333336px, o que é feio de ler no DevTools e inútil na prática. Arredonde antes de entregar: Math.round(100 / 3). O mesmo vale para porcentagens: se você quer 40%, o valor é "40%", com aspas — o React não sabe que aquele número deveria ser porcentagem.

Há uma exceção que vale conhecer: as variáveis CSS. Propriedades que começam com -- precisam de aspas no nome, porque têm hífen, e o valor é texto. Elas servem para passar um valor para o CSS a partir do JavaScript, sem repetir a propriedade em cada elemento:

function App() {
  const [cor, setCor] = useState("crimson");

  return (
    <div style={{ "--cor-destaque": cor }}>
      <p style={{ color: "var(--cor-destaque)" }}>Pão francês</p>
      <p style={{ borderColor: "var(--cor-destaque)", borderStyle: "solid" }}>Pão de queijo</p>
    </div>
  );
}

Trocar cor muda os dois parágrafos de uma vez, porque os dois leem a mesma variável. É o jeito mais limpo de fazer tema que muda com o estado sem repetir o valor em cada elemento — e o mesmo truque funciona para o tema claro e escuro que este guia usa.

7. O que o style inline não faz

O atributo style é poderoso e tem limites duros. Ele escreve declarações naquele elemento e só. Não tem seletor, então não existe :hover, não existe ::placeholder, não existe :focus, não existe media query e não existe @keyframes. Essas quatro coisas pertencem à folha de CSS, e não há como imitá-las com objeto.

Há ainda duas limitações menos citadas. A primeira: !important não funciona no objeto — o React escreve a declaração normal, e uma regra de CSS com !important vence. A segunda: o objeto é recriado a cada renderização, então o React reescreve o atributo mesmo quando os valores são iguais. Para um parágrafo, é imperceptível; em uma lista de mil linhas, aparece. É uma das razões pelas quais classe costuma ser a escolha padrão e estilo inline, a exceção.

Existe também o problema do estilo que some sem erro. Um nome com sublinhado (background_color), uma propriedade que não existe no navegador, um valor inválido para aquela propriedade: em todos, o React não reclama e o console não mostra nada. O jeito de descobrir é olhar o atributo gerado — se a declaração não está lá, o problema é no nome; se está lá e não pinta, o problema é no valor.

getComputedStyle(document.querySelector("p")).backgroundColor
'rgb(255, 255, 255)'
document.querySelector("p").getAttribute("style")
'font-size: 20px;'

A leitura acima conta a história inteira: o elemento não tem background-color no atributo, então o fundo continua o branco padrão. O background_color com sublinhado foi engolido pelo React, e nenhum aviso apareceu em lugar nenhum.

8. Classe e estilo, cada um no seu lugar

Depois de duas aulas, a Ana tem o critério completo. Classe é contrato com a folha de estilo: o desenho do card, o tamanho da fonte, o espaçamento entre seções, o estado de um botão. Estilo inline é valor que nasce do dado: a cor do dia, a largura da barra, a posição de um item em uma lista ordenada. Os dois convivem sem briga no mesmo elemento, e a ordem em que aparecem no JSX não importa.

Quando o estilo inline começa a crescer, o primeiro passo é dar nome ao objeto. Um const estiloBarra = { ... } fora do componente deixa o JSX legível e evita recriar o objeto a cada renderização — o que ajuda o memo a perceber que nada mudou. O segundo passo é perceber que aquele estilo não depende de estado nenhum e voltar para o CSS. Muita coisa que começa inline termina em uma classe bem nomeada.

E vale desconfiar quando o objeto tem mais de cinco propriedades. Nessa hora, o desenho pertence ao site, não ao dado: vira classe. O estilo inline fica com uma ou duas propriedades dinâmicas, e o resto vai para a folha — onde o navegador cacheia, onde o :hover existe e onde a pessoa que cuida do visual consegue mexer sem abrir o JavaScript.

9. Cenários do dia a dia

Cenário 1: a barra de estoque que não enche

A Ana escreveu style={{ width: paes * 10 }} e a barra ficou com 20 pixels em vez de 20%. O número virou pixel, como manda a regra. Para porcentagem, o valor precisa ser texto: width: (paes * 10) + "%". E para limitar em 100%, Math.min(paes * 10, 100) antes de montar a string — senão a barra vaza do card quando há mais de dez pães.

Cenário 2: o botão perdeu o estilo ao passar o mouse

Ela trocou a classe do botão por um objeto de estilo e o :hover parou de funcionar. Não é bug: :hover é um seletor, e o style inline não tem seletor. O conserto é voltar a classe para o que é interação e deixar o inline só com o valor dinâmico — por exemplo, a cor que vem do tema, enquanto o hover continua no CSS.

Cenário 3: o estilo apareceu no HTML e a tela não mudou

O painel mostrava style="background_color: red;" e o cartão continuava branco. O nome estava com sublinhado, e o navegador não conhece essa propriedade: descarta sem avisar. Trocado para backgroundColor, funcionou na hora. Sempre que um estilo inline "não pega", compare o nome com a lista de propriedades do CSS — o camelCase é a única diferença entre os dois mundos.

Exercício: a cor e o tamanho

Complete o objeto de estilo do preço. A primeira propriedade é a cor de fundo, escrita no padrão do React. A segunda é o tamanho da fonte, que deve chegar ao CSS como 20px:

<p style={{ : "crimson", fontSize: }}>Pão francês</p>

Dica: a primeira resposta é background-color em camelCase — sem hífen. A segunda é um número puro: o React acrescenta o px sozinho, então escrever "20px" também funciona, mas o número é o jeito mais comum.

11. Resumo

A prop style recebe um objeto JavaScript, e é por isso que são duas chaves: uma para entrar no JSX, outra para abrir o objeto. As propriedades vão em camelCase, os números ganham px automaticamente — menos nas que não têm unidade, como opacity, zIndex e lineHeight — e os valores dinâmicos saem direto do estado, com ternário ou variável.

O que o inline faz bem: valor que muda com o dado, cor escolhida pela pessoa, largura calculada, variável CSS para tema. O que ele não faz: :hover, :focus, media query, @keyframes e !important — nada que precise de seletor. E há dois erros para reconhecer de longe: passar string em vez de objeto, que faz o componente não desenhar, e escrever o nome com sublinhado, que o React ignora sem avisar.

A divisão com a aula anterior fica simples de guardar. Se o valor é do desenho e igual para todos, é classe. Se o valor vem do dado e muda a cada renderização, é style. Os dois juntos no mesmo elemento são o normal, não a exceção: a classe carrega o que é estável, o objeto carrega o que é dinâmico.

E fica uma vantagem honesta do inline, que às vezes é esquecida: ele não precisa de arquivo de CSS nenhum. Para um componente que precisa se virar sozinho — um card que recebe a cor por prop, um gráfico que calcula a altura da barra — o objeto resolve sem depender de uma folha externa. Só não peça a ele o que é trabalho de seletor.

Para lembrar

  • style recebe objeto: style={{ color: "crimson" }}.
  • Propriedades em camelCase: backgroundColor, fontSize, marginTop.
  • Número vira px; opacity, zIndex e lineHeight ficam sem unidade.
  • Outra unidade: escreva entre aspas — fontSize: "1.2rem".
  • Valor dinâmico: style={{ color: esgotado ? "red" : "black" }}.
  • String em vez de objeto faz o componente não desenhar.
  • Nome com sublinhado é ignorado sem erro: o painel é o lugar de conferir.
  • :hover, media query e animação são trabalho do CSS, não do inline.
  • Variável CSS no objeto: style={{ "--cor": cor }}, com aspas no nome.
