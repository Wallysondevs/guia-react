Checkbox

A padaria da Ana quer avisar o cliente quando o pão quentinho sai do forno, e quer perguntar se a encomenda vai embrulhada para presente. São perguntas de sim ou não — e a resposta certa para elas não é um texto, é um booleano. Nesta aula a Ana liga uma caixinha de marcar ao estado, aprende que o valor não vem em e.target.value e sim em e.target.checked, conta quantas caixas foram marcadas e faz um campo aparecer só quando o presente é escolhido.

Você vai aprender
  • O que um checkbox guarda: verdadeiro ou falso, não texto.
  • A diferença entre checked e value.
  • Como ler a marcação com e.target.checked.
  • Como ligar a caixa ao estado e mostrar o resultado na tela.
  • Como trabalhar com várias caixas ao mesmo tempo.
  • Como transformar booleano em número para contar extras.
  • Como mostrar um campo extra só quando a caixa está marcada.

1. A cena: perguntas de sim ou não

No formulário da padaria, nem toda pergunta quer um texto. "Aceita receber o aviso de pão quentinho?" tem duas respostas possíveis, e nenhuma delas é uma frase: ou aceita, ou não. "Embrulhar para presente?" é a mesma coisa. Para esses casos existe o checkbox, a caixinha que marca e desmarca. No estado, ela não guarda "sim" nem "não", guarda true e false — os dois valores booleanos do JavaScript.

A Ana começou guardando a resposta como texto, numa caixa de seleção com "sim" e "não". Funcionava, mas era mais clicque do que o necessário e mais difícil de validar: qualquer dia alguém escreveria "Sim" com maiúscula e a comparação quebrava. O checkbox resolve com um valor só, e o código fica com uma pergunta simples: está marcado ou não?

A diferença em relação ao input de texto aparece no evento. Num campo de texto, você lê e.target.value; numa caixa de marcar, o valor de value é fixo (por padrão, o texto "on") e quem diz se está marcada é a propriedade checked. É o primeiro lugar do guia em que o dado do campo não vem em e.target.value. Guarde isso, porque é a causa do clássico "o estado recebe on".

2. A caixa guarda verdadeiro ou falso

Um checkbox tem dois estados e uma propriedade que os representa: checked. Marcada, true; desmarcada, false. No JSX controlado, você passa checked={aviso} para a caixa mostrar o estado, e no onChange você lê e.target.checked para guardar o novo valor. Não existe conversão de texto no meio: é booleano entrando e booleano saindo.

checked
A propriedade que diz se a caixa está marcada. No JSX controlado, recebe o booleano do estado: checked={aviso}.
onChange
A função chamada a cada marcação e desmarcação. É onde você atualiza o estado.
e.target.checked
O booleano novo: true se a caixa acabou de ser marcada, false se foi desmarcada.
e.target.value
O atributo value da caixa, que por padrão é "on". Não serve para saber se está marcada.
label envolvendo
Quando o input fica dentro do label, clicar no texto também marca a caixa — e o leitor de tela anuncia os dois juntos.

A última peça é a que mais melhora a vida de quem usa o site. Uma caixinha sozinha é pequena; o texto ao lado é o alvo grande. Envolver o input com o label faz o texto inteiro ser clicável. A outra forma é dar um id à caixa e apontar o label com htmlFor — as duas funcionam, e a primeira é mais curta quando o texto é só uma frase.

3. O primeiro checkbox controlado

A missão é pequena e mostra o mecanismo inteiro: a caixa começa desmarcada, o parágrafo diz "desligado", e ao marcar o parágrafo passa a dizer "ligado". Repare que o estado é useState(false) — o valor inicial é booleano, não string vazia:

A caixa não está ligada a nada. Crie o estado aviso começando em false, passe checked={aviso}, atualize com e.target.checked e mostre Aviso: ligado quando estiver marcada.

function App() {
  return (
    <div>
      <label>
        <input type="checkbox" /> Aceito receber o aviso de pão quentinho
      </label>
      <p>Aviso: desligado</p>
    </div>
  );
}
<div>
  <label>
    <input type="checkbox">
    Aceito receber o aviso de pão quentinho
  </label>
  <p>Aviso: desligado</p>
</div>

function App() {
  const [aviso, setAviso] = useState(false);
  return (
    <div>
      <label>
        <input
          type="checkbox"
          checked={aviso}
          onChange={(e) => setAviso(e.target.checked)}
        /> Aceito receber o aviso de pão quentinho
      </label>
      <p>Aviso: {aviso ? "ligado" : "desligado"}</p>
    </div>
  );
}

Clique na caixa ou no texto: os dois marcam, porque o input está dentro do label. O parágrafo muda para "Aviso: ligado" e volta ao desmarcar. No painel, a caixa aparece como <input type="checkbox">, sem atributo checked: a marcação é propriedade viva, como o valor de um campo de texto. Quem quiser conferir o que o React desenhou olha o parágrafo; quem quiser conferir o estado olha o texto.

Note também que o parágrafo usa uma expressão condicional com ? e :. Ela poderia ser um && se o texto falso não importasse, mas aqui os dois casos têm texto próprio, então a condicional é mais honesta. Não existe regra de estilo: escolha a forma que deixa a intenção mais clara para quem ler depois.

4. checked, value e defaultChecked

Três atributos parecidos, três papéis diferentes. Quem vem do HTML costuma usar value para tudo e depois não entende por que o estado recebe "on". A tabela separa os casos:

O que você escreveuO que aconteceConserto
value={aviso}a caixa ignora esse valor para saber se está marcada; e.target.value devolve o texto do atributousar checked={aviso} e ler e.target.checked
checked sem onChangea caixa não marca: o React mantém o valor que você mandouacrescentar onChange que atualiza o estado
checked={true}marcada para sempre, sem desmarcarusar um estado que começa em true
defaultCheckedcomeça marcada e o navegador cuida do resto (não controlado)use só quando não precisa acompanhar a marcação

Uma confusão comum é achar que value e checked podem ser usados juntos como sinônimos. Não são: value é o dado que a caixa representa (útil quando várias caixas compartilham o mesmo name num formulário), e checked é o "está marcada?". Num formulário de extras, cada caixa tem um value — "geleia", "manteiga" — para o envio saber o que foi marcado; no estado controlado, quem manda é checked.

Para ver a diferença no console, marque uma caixa e observe os dois valores. O value continua o mesmo; o checked troca:

e.target.checked: true
e.target.value: "on"

É por isso que a leitura certa é sempre checked. Se você guardar value no estado, ele nunca muda, e a caixa parece "não funcionar" mesmo com o onChange no lugar.

5. Várias caixas, uma contagem

A encomenda da padaria tem extras: geleia, manteiga e queijo, cada um numa caixa. O cliente pode marcar quantas quiser, e a Ana quer mostrar no resumo quantos extras foram escolhidos. Como cada caixa tem o seu próprio sim ou não, o caminho mais direto é um estado booleano para cada uma e uma conta que soma os verdadeiros.

O truque da conta é que Number(true) é 1 e Number(false) é 0. Somar os três booleanos convertidos dá o total de marcados sem nenhum if:

Number(true): 1
Number(false): 0
Number(true) + Number(false) + Number(true): 2

As três caixas estão soltas e o resumo diz "0 extras". Ligue cada caixa ao seu estado (geleia, manteiga, queijo), some os marcados e mostre {total} extras.

function App() {
  return (
    <div>
      <p>Extras para a encomenda:</p>
      <label><input type="checkbox" id="geleia" /> Geleia</label>
      <label><input type="checkbox" id="manteiga" /> Manteiga</label>
      <label><input type="checkbox" id="queijo" /> Queijo</label>
      <p>0 extras</p>
    </div>
  );
}
<div>
  <p>Extras para a encomenda:</p>
  <label>
    <input id="geleia" type="checkbox">
    Geleia
  </label>
  <label>

    Manteiga
  </label>

function App() {
  const [geleia, setGeleia] = useState(false);
  const [manteiga, setManteiga] = useState(false);
  const [queijo, setQueijo] = useState(false);
  const total = Number(geleia) + Number(manteiga) + Number(queijo);
  return (
    <div>
      <p>Extras para a encomenda:</p>
      <label>
        <input
          type="checkbox"
          id="geleia"
          checked={geleia}
          onChange={(e) => setGeleia(e.target.checked)}
        /> Geleia
      </label>
      <label>
        <input
          type="checkbox"
          id="manteiga"
          checked={manteiga}
          onChange={(e) => setManteiga(e.target.checked)}
        /> Manteiga
      </label>
      <label>
        <input
          type="checkbox"
          id="queijo"
          checked={queijo}
          onChange={(e) => setQueijo(e.target.checked)}
        /> Queijo
      </label>
      <p>{total} extras</p>
    </div>
  );
}

Marque geleia e manteiga e o resumo mostra "2 extras". Desmarque uma e o total cai. O total é uma conta feita no desenho, não um quarto estado: se fosse um useState, você teria de atualizá-lo em cada um dos três onChange e um dia esqueceria um deles.

Três estados separados são ótimos para três caixas fixas. Quando a lista cresce ou vem de um array, dá para guardar um objeto ({ geleia: true, manteiga: false }) ou um array com os nomes marcados. A aula de estado com objeto e a de estado com array mostram os dois caminhos; a regra continua a mesma: cada caixa lê do estado e escreve no estado, e o resumo é derivado.

Vale um comentário sobre o id em cada caixa. Aqui os labels envolvem os inputs, então o id não é obrigatório para o clique funcionar — mas ele ajuda na hora de testar e de estilizar uma caixa específica, e é o que permite um label separado quando o layout exige. Escolha um nome estável e use o mesmo no CSS.

6. A caixa que libera um campo

Um uso muito comum do checkbox é ligar e desligar um pedaço da tela. "Embrulhar para presente" é o exemplo perfeito: enquanto a caixa não está marcada, não faz sentido pedir o nome que vai no cartão. Marcou, o campo aparece; desmarcou, some. É a renderização condicional com um booleano no comando.

O campo do cartão aparece sempre. Mostre-o só quando presente for verdadeiro — no começo deve existir um input só, e depois do clique, dois.

function App() {
  const [presente, setPresente] = useState(false);
  const [cartao, setCartao] = useState("");
  return (
    <div>
      <label>
        <input
          type="checkbox"
          id="presente"
          checked={presente}
          onChange={(e) => setPresente(e.target.checked)}
        /> Embrulhar para presente
      </label>
      <label htmlFor="cartao">Nome no cartão</label>
      <input
        id="cartao"
        type="text"
        value={cartao}
        onChange={(e) => setCartao(e.target.value)}
      />
    </div>
  );
}
<div>

    <input id="presente" type="checkbox">
    Embrulhar para presente
  </label>
  <label for="cartao">Nome no cartão</label>

function App() {
  const [presente, setPresente] = useState(false);
  const [cartao, setCartao] = useState("");
  return (
    <div>
      <label>
        <input
          type="checkbox"
          id="presente"
          checked={presente}
          onChange={(e) => setPresente(e.target.checked)}
        /> Embrulhar para presente
      </label>
      {presente && (
        <div>
          <label htmlFor="cartao">Nome no cartão</label>
          <input
            id="cartao"
            type="text"
            value={cartao}
            onChange={(e) => setCartao(e.target.value)}
          />
        </div>
      )}
    </div>
  );
}

O && lê assim: se presente for verdadeiro, desenhe o que vem depois; se for falso, não desenhe nada. Os parênteses em volta do div existem porque o bloco ocupa várias linhas — é a mesma convenção do return ( que você já viu. Sem eles, o JSX quebra na primeira linha.

Repare no conta:input=1 da missão: quando a caixa está desmarcada, o único input da tela é a própria caixa. Depois do clique, aparece o campo de texto e a conta vai para dois. Esse tipo de conferência é útil quando você quer provar que um elemento não está escondido por CSS, e sim ausente do HTML.

Um cuidado com o estado do campo que aparece e desaparece: quando o div sai da tela, o input é destruído, mas o estado cartao continua no componente. Se a pessoa desmarcar e marcar de novo, o texto volta. Isso pode ser bom (não perde o que foi digitado) ou ruim (o cliente desmarcou e o nome antigo vai junto no pedido). Se for ruim, limpe o estado ao desmarcar: setCartao("") dentro do onChange da caixa, quando e.target.checked for false.

7. Caixas que se parecem com escolhas únicas

Existe uma armadilha de interpretação: um grupo de checkbox com o mesmo name parece um grupo de escolha única, mas não é. O name só agrupa os valores no envio do formulário; marcar uma caixa não desmarca as outras. Quem faz escolha única é o radio, assunto da próxima aula, ou o select, que você já viu.

A pergunta na telaElementoO que o estado guarda
sim ou não, uma caixa sócheckboxum booleano
vários extras, pode marcar quantos quiserum checkbox por itemum booleano por item
uma escolha entre poucas, todas visíveisradioo value da escolhida, como texto
uma escolha entre muitas, em lista fechadaselecto value da opção escolhida

Então, quando usar cada um? Um teste rápido: a resposta pode ter mais de um "sim" ao mesmo tempo? Se sim, checkbox. Se só um pode valer — forma de pagamento, tamanho da camiseta, período de entrega —, use radio ou select. Errar essa escolha não quebra o código, mas confunde o cliente, que marca duas formas de pagamento e não entende por que o pedido não fecha.

Outro detalhe é o visual. Uma caixa marcada aparece com um sinal dentro; desmarcada, vazia. Em alguns navegadores, o estado "indeterminado" (aquele traço no lugar do sinal) existe para representar "alguns itens de um grupo estão marcados", mas ele não se define pelo JSX controlado: precisa de ref e de uma atribuição direta na propriedade. É um caso avançado, para uma lista com "marcar todos"; a aula de useRef é o lugar certo para ele.

8. O label e o alvo de clique

Uma caixa de marcar mede uns 16 pixels. Em celular, isso é um alvo pequeno e fácil de errar. O label resolve: envolver o input faz o texto inteiro ser clicável, e o navegador cuida de marcar a caixa quando o clique cai no texto. É acessibilidade de graça, sem uma linha de JavaScript.

As duas formas funcionam. A primeira é envolver:

<label>
  <input type="checkbox" checked={geleia} onChange={(e) => setGeleia(e.target.checked)} />
  Geleia
</label>

A segunda é apontar com htmlFor, que é útil quando o texto precisa ficar longe da caixa, em outra coluna do layout:

<input id="geleia" type="checkbox" checked={geleia} onChange={(e) => setGeleia(e.target.checked)} />
<label htmlFor="geleia">Geleia</label>

As duas exigem que o id seja único na página quando você usa htmlFor. Dois inputs com o mesmo id fazem o rótulo apontar para o primeiro, e o segundo fica sem nome acessível. Se o componente é reaproveitado várias vezes, isso acontece sem você perceber — e é um dos motivos pelos quais existe o hook useId, que gera identificadores únicos.

Por fim, um detalhe de teclado: com a caixa em foco, a barra de espaço marca e desmarca. O Tab leva até ela como leva a qualquer campo. Nada disso precisa de código; é comportamento nativo que você ganha por usar o elemento certo, e é mais um argumento para não substituir a caixa por um div com estilo de caixa.

9. Cenários do dia a dia

Cenário 1: o estado recebe "on"

A Ana guardou value no estado e recebeu "on" a cada clique, com a caixa nunca marcando. O value de um checkbox é fixo; quem muda é checked. A correção é passar checked={aviso} e ler e.target.checked no onChange. Se o valor "on" aparecer num estado seu, é sinal de que a leitura foi feita no lugar errado.

Cenário 2: a caixa marca e desmarca sozinha

Ela passou checked={aviso} mas esqueceu o onChange. O React redesenha a caixa com o valor do estado a cada render, então o clique parece não pegar. O sintoma é uma caixa que pisca e volta, ou que simplesmente não marca. Sempre que um campo controlado "não obedece", procure o onChange antes de qualquer outra coisa.

Cenário 3: o nome do cartão vai junto com um pedido sem presente

O cliente marcou presente, digitou o nome, desmarcou e fez o pedido. O campo sumiu da tela, mas o estado cartao continuou com o texto, e o resumo mostrou um cartão para um pedido sem embrulho. A correção foi limpar o estado ao desmarcar, ou só montar o resumo quando presente for verdadeiro. Esconder não é o mesmo que apagar.

Exercício: ler a marcação

Complete a função que guarda o novo valor da caixa no estado aviso. Escreva só a propriedade que falta, sem e.target.:

<input type="checkbox" checked={aviso} onChange={(e) => setAviso(e.target.)} />

Dica: é a mesma palavra que aparece no checked={aviso}, do lado esquerdo do sinal de igual. Se você escrever value, o estado recebe "on" e a caixa para de funcionar.

11. Resumo

O checkbox guarda um booleano. No JSX controlado, checked mostra o estado e onChange lê e.target.checked para atualizá-lo. value não serve para saber se a caixa está marcada: ele é o dado que a caixa representa no envio, e por padrão vale "on". Envolver o input com o label aumenta o alvo de clique e melhora a leitura por leitores de tela.

Várias caixas pedem vários booleanos — ou um objeto, ou um array, quando a lista é grande. A contagem de marcados sai de Number(booleano) somado, uma conta feita no desenho. E o mesmo booleano pode ligar um pedaço da tela: {presente && (...)} mostra o campo do cartão só quando faz sentido. Lembre que esconder um campo não apaga o estado dele; se o dado não vale mais, limpe o estado também.

Com isso, o formulário já sabe pedir texto curto, texto longo, uma escolha em lista e um sim ou não. Na próxima aula, a caixa vira escolha única — o radio —, e a diferença vai estar num atributo que agrupa as opções e num valor que é texto, não booleano. Se você entendeu por que o checkbox usa checked e o input usa value, a próxima aula vai parecer uma mistura dos dois, e é exatamente isso que ela é.

Para lembrar

  • Checkbox guarda true ou false; o estado começa em false.
  • Mostrar: checked={aviso}. Ler: e.target.checked.
  • e.target.value de um checkbox é "on" por padrão.
  • checked sem onChange deixa a caixa travada.
  • defaultChecked é para campo não controlado.
  • Várias caixas: um estado por caixa, ou um objeto/array para listas.
  • Contar marcados: Number(a) + Number(b).
  • {condicao && (<div>...</div>)} mostra um bloco só quando a caixa está marcada.
  • Esconder o campo não limpa o estado dele.
  • label envolvendo o input deixa o texto clicável.
