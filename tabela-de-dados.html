Tabela de Dados

A Ana precisa comparar os pedidos da semana: quem pediu, o que pediu e quanto vai pagar. Ela colocou tudo numa lista de parágrafos, e o resultado é aquela cena conhecida — os preços em escada, cada um começando num lugar diferente, impossível de somar com os olhos. Nesta aula ela monta uma tabela de verdade no React: cabeçalho, linhas geradas a partir do array, números alinhados e um cabeçalho que ordena quando é clicado.

Você vai aprender
  • As tags de uma tabela e o papel de cada uma: table, thead, tbody, tr, th, td.
  • Como gerar as linhas com map e onde fica a key.
  • Por que th não é “texto em negrito” e para que serve o scope.
  • O caption, que quase ninguém usa e os leitores de tela agradecem.
  • Como alinhar números à direita sem gambiarra.
  • O que mostrar quando a tabela não tem linhas.
  • Como ordenar clicando no cabeçalho, com aria-sort.

1. A cena: preços em escada

A lista de pedidos da Ana era assim: um parágrafo por pedido, com nome, produto e valor separados por travessão. No papel funciona. Na tela, vira uma escada: “R$ 8” começa numa coluna, “R$ 12” em outra, e o olho não consegue comparar nada. Para saber quanto a semana rendeu, ela soma com a calculadora — e erra.

Tabela existe exatamente para isso: alinhar informação em colunas, para que o olho compare na vertical. Não é um jeito antigo de diagramar página; é a estrutura certa para dados que têm as mesmas colunas em todas as linhas. Nome, produto, valor: três colunas, quantas linhas forem necessárias.

No React, a tabela é escrita com as mesmas tags do HTML — table, thead, tbody, tr, th, td — e ganha uma coisa a mais: as linhas vêm de um array, com map. Você não escreve três tr; escreve um molde de linha e deixa o React repetir.

É a mesma ideia da lista com map da aula Listas com map, dentro de uma estrutura mais exigente. E “mais exigente” aqui é bom: o navegador entende a tabela, os leitores de tela entendem a tabela, e o CSS alinha as colunas sozinho.

2. A anatomia de uma tabela

Antes de gerar linhas, vale conhecer as peças. Uma tabela tem um cabeçalho e um corpo, e os dois são listas de linhas:

<table>
  <caption>Pedidos da semana</caption>
  <thead>
    <tr>
      <th scope="col">Cliente</th>
      <th scope="col">Produto</th>
      <th scope="col">Valor</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Maria</td>
      <td>Brioche</td>
      <td>R$ 8</td>
    </tr>
  </tbody>
</table>

O caption é o título da tabela e precisa ser o primeiro filho do table. O thead guarda a linha de títulos; o tbody, as linhas de dados. Cada linha é um tr, e cada célula é um td — exceto no cabeçalho, onde é th. O navegador usa essa estrutura para navegar por célula com o teclado e para anunciar “coluna Valor, linha Maria” num leitor de tela.

Uma confusão comum: th não é uma célula com negrito. É uma célula de cabeçalho, e o negrito é só o estilo padrão. A diferença aparece quando alguém usa leitor de tela: o th vira a etiqueta das células da mesma coluna; o td é o dado. Trocar um pelo outro “funciona” visualmente e quebra a leitura.

O scope diz se aquele cabeçalho vale para a coluna ("col") ou para a linha ("row"). Em tabelas simples, é o suficiente para a acessibilidade funcionar sem nenhum atributo extra. Custa uma palavra por th e resolve o assunto.

3. Uma linha por item, com map

Com os dados num array, o tbody passa a ter um map só. O molde da linha é o tr com as células:

const pedidos = [
  { id: 1, cliente: "Maria", produto: "Brioche", valor: 8 },
  { id: 2, cliente: "João", produto: "Sonho", valor: 5 },
  { id: 3, cliente: "Bia", produto: "Croissant", valor: 7 }
];

<tbody>
  {pedidos.map((pedido) => (
    <tr key={pedido.id}>
      <td>{pedido.cliente}</td>
      <td>{pedido.produto}</td>
      <td>R$ {pedido.valor}</td>
    </tr>
  ))}
</tbody>

Três pedidos, três linhas. Se amanhã forem trinta, o código é o mesmo. O key fica no tr, o elemento que se repete — e não nas células, que são filhas de uma linha já identificada. Esse detalhe rende um aviso do React quando errado, e a aula A key explica o porquê.

O id é o melhor candidato a key: é único, estável e não muda quando o cliente corrige o nome. Usar o índice do map funciona enquanto a lista só cresce no fim; com remoção ou ordenação, o React passa a associar a linha errada ao item errado, e o foco do teclado salta. Se os dados vêm de um banco, use o id de lá.

A tabela tem cabeçalho e uma linha escrita à mão. Gere as linhas do tbody a partir do array pedidos, com key no tr.

Essas três linhas são o jeito mais rápido de conferir uma tabela no navegador, com o DevTools aberto: conte as linhas do corpo, conte as do cabeçalho e leia uma célula. Se o número de tr do corpo não bate com o tamanho do array, o map está no lugar errado ou o array mudou sem redesenhar.

table
O contêiner da tabela. Não deve ser usado para diagramar página; é para dados com colunas.
caption
Título da tabela, primeiro filho do table. Anunciado por leitores de tela.
thead / tbody
Cabeçalho e corpo. O primeiro guarda os títulos das colunas; o segundo, as linhas de dados.
tr
Uma linha. Recebe a key quando gerada por map.
th / td
Célula de cabeçalho e célula de dado. O th etiqueta a coluna; o td carrega o valor.
scope
Atributo do th que diz se ele vale para a coluna ("col") ou para a linha ("row").

4. Caption e scope: o que ninguém vê e todo mundo usa

Os dois atributos que fazem uma tabela ser compreensível para quem não enxerga custam quase nada. O caption dá nome à tabela; o scope liga cada célula ao seu cabeçalho. Numa loja, o caption pode ser “Pedidos da semana” — a mesma frase que você colocaria num h2, mas dentro da tabela, para não se perder quando ela é lida fora de contexto.

O scope="col" parece redundante quando a tabela tem uma linha de títulos no topo. E é, para quem vê. Para quem usa leitor de tela, é a diferença entre ouvir “R$ 8” e ouvir “Valor, R$ 8”. Multiplique por trinta linhas e você entende por que vale a linha extra.

A tabela já tem as três linhas, mas os cabeçalhos não dizem a que se referem e a tabela não tem título. Acrescente scope="col" em cada th e um <caption>Pedidos da semana</caption> logo depois da abertura do table.

5. Números à direita, texto à esquerda

Alinhamento não é capricho: é leitura. Números alinhados à direita fazem as unidades coincidirem na vertical, e a comparação de 8 com 12 fica imediata. Texto alinhado à esquerda é mais fácil de escanear. Numa tabela de pedidos, cliente e produto à esquerda, valor à direita.

.tabela th,
.tabela td {
  padding: 0.5rem;
  border-bottom: 1px solid #ddd;
}

.tabela .valor {
  text-align: right;
  font-variant-numeric: tabular-nums;
}

No React, aplique a classe na célula: <td className="valor">. O text-align: right alinha; o font-variant-numeric: tabular-nums faz todos os dígitos ocuparem a mesma largura, então os números ficam numa coluna perfeitamente reta. É CSS puro, não tem nada de React — e é a diferença entre uma tabela amadora e uma tabela que dá gosto de ler.

Cuidado com a tentação de alinhar pelo JSX, com espaços. Espaços colapsam no HTML e o resultado fica imprevisível. Alinhamento é trabalho do CSS; o React só entrega a estrutura com as classes certas.

6. A tabela sem linhas

Quando pedidos está vazio, o map devolve um array vazio e o tbody fica sem nenhuma linha. O navegador mostra só o cabeçalho flutuando — o que parece um bug. A solução é uma linha especial que ocupa todas as colunas:

<tbody>
  {pedidos.length === 0 ? (
    <tr>
      <td colSpan="3">Nenhum pedido nesta semana.</td>
    </tr>
  ) : (
    pedidos.map((pedido) => (
      <tr key={pedido.id}>
        <td>{pedido.cliente}</td>
        <td>{pedido.produto}</td>
        <td>R$ {pedido.valor}</td>
      </tr>
    ))
  )}
</tbody>

colSpan (com S maiúsculo no React) faz a célula atravessar três colunas. O número precisa bater com a quantidade de colunas da tabela; se você acrescentar uma coluna e esquecer de atualizar o colSpan, a mensagem fica torta. Em tabelas maiores, vale calcular: colSpan={colunas.length}.

E a mensagem precisa ser específica. “Nenhum pedido nesta semana” diz o que está vazio e delimita o tempo; “Nenhum resultado” não diz nada. Essa diferença entre vazio de verdade e vazio de filtro é a aula de Estados Vazios, e a tabela é onde ela aparece com mais força: o cabeçalho fica, o corpo recebe a explicação.

7. Ordenar pelo cabeçalho

Numa tabela, o lugar natural para ordenar é o título da coluna. A pessoa clica em “Valor” e as linhas se reordenam. Para isso, o th precisa conter um button — clicar em th não é acessível por teclado, enquanto um botão é.

<th scope="col" aria-sort={ordem === "valor" ? "descending" : "none"}>
  <button className="preco" onClick={() => setOrdem("valor")}>
    Valor
  </button>
</th>

O aria-sort vai no th, não no botão, e aceita "ascending", "descending" e "none". Ele é o que anuncia “coluna Valor, ordem decrescente” para quem usa leitor de tela. Sem ele, a mudança de ordem é invisível para uma parte das pessoas.

A ordenação em si é a da aula Ordenar: comparador, cópia com spread e critério no estado. O que a tabela acrescenta é o lugar do clique e o atributo que descreve o estado. E o cuidado de sempre: ordenar a lista antes do map, nunca mexendo no array original.

O botão “Valor” já troca o estado ordem, mas a tabela ignora. Ordene as linhas do maior valor para o menor, mostre a posição na primeira coluna e marque o th de Valor com aria-sort="descending".

const pedidos = [
  { id: 1, cliente: "Maria", produto: "Brioche", valor: 8 },
  { id: 2, cliente: "João", produto: "Sonho", valor: 5 },
  { id: 3, cliente: "Bia", produto: "Croissant", valor: 7 }
];

function App() {
  const [ordem, setOrdem] = useState("chegada");
  const linhas = pedidos;
  return (
    <table>
      <thead>
        <tr>
          <th scope="col">#</th>
          <th scope="col">Produto</th>
          <th scope="col">
            <button className="preco" onClick={() => setOrdem("valor")}>Valor</button>
          </th>
        </tr>
      </thead>
      <tbody>
        {linhas.map((pedido, i) => (
          <tr key={pedido.id}>
            <td>{i + 1}º</td>
            <td>{pedido.produto}</td>
            <td>R$ {pedido.valor}</td>
          </tr>
        ))}
      </tbody>
    </table>
  );
}

A meta confere três coisas: o clique no botão, o aria-sort no th e o texto “1º Brioche” na prévia. Se a ordem mudou mas a conferência falhou no atributo, falta o aria-sort; se o atributo está lá e o texto não, o sort não entrou. Um erro por vez, sempre.

8. Tabela ou lista de cartões?

Tabela não é a resposta para tudo. Ela brilha quando as linhas têm as mesmas colunas e a pessoa precisa comparar valores. Sofre quando cada item tem muita informação, imagens ou ações diferentes. No celular, uma tabela de seis colunas rola de lado — e rolagem lateral é o pior gesto possível.

Uma alternativa comum é esconder a tabela no celular e mostrar cartões. Isso duplica a marcação e costuma sair pela culatra. Para a padaria, com três colunas, a tabela funciona no celular se você deixar o nome do produto quebrar linha e reduzir o padding. O guia inteiro usa overflow-x nas tabelas de referência justamente por isso — e é o que o div.table-wrap faz nas páginas deste site.

Se a decisão for tabela, capriche no cabeçalho: ele é o mapa que a pessoa usa para entender as colunas. Se for cartão, cada cartão precisa repetir o nome do campo (“Valor: R$ 8”), porque não há cabeçalho para consultar.

9. Cenários do dia a dia

Cenário 1: a linha aparece fora do corpo

A Ana colocou o map envolvendo o table inteiro. O resultado são três tabelas de uma linha cada, com cabeçalho repetido, e o CSS alinha cada uma do seu jeito. O map vai dentro do tbody, gerando tr — nunca em volta da tabela.

Cenário 2: o cabeçalho não acompanha a ordenação

As linhas mudam de ordem, mas a seta e o anúncio continuam dizendo “ordem crescente”. Faltou ligar o aria-sort ao estado: quando o critério é aquele, o valor é "ascending" ou "descending"; nos outros, "none". O atributo não muda a ordem — só a descreve.

Cenário 3: a tabela vazia vira um cabeçalho solto

Sem linhas, sobra a faixa de títulos e nada embaixo. A correção é a linha com colSpan e uma mensagem que diga o que está vazio. E lembre de atualizar o número do colSpan quando acrescentar uma coluna, senão a mensagem ocupa menos espaço do que devia.

11. Resumo

Tabela é estrutura, não estilo. table contém caption, thead e tbody; cada linha é um tr, cada célula um td, e os títulos das colunas são th com scope="col". As linhas vêm do map sobre o array, com a key no tr — o id do dado, não o índice, quando possível.

O caption nomeia a tabela e o scope liga cada célula ao seu cabeçalho. São os dois detalhes que separam uma tabela que funciona de uma tabela que só parece funcionar. Números alinham à direita com text-align e tabular-nums; texto, à esquerda.

Sem linhas, o corpo recebe uma linha com colSpan e uma mensagem específica. Com muitas linhas, o cabeçalho ganha botões que ordenam — e o th ganha aria-sort para descrever a ordem atual. E lembre que a ordem se calcula antes do map, como na aula de Ordenar.

Para lembrar

  • thead para títulos, tbody para dados.
  • Uma linha por item: map dentro do tbody.
  • key no tr; use o id, não o índice.
  • th é cabeçalho, não negrito; scope="col" liga a coluna.
  • caption é o título da tabela e vem primeiro.
  • colSpan faz a célula atravessar colunas; case com o número de colunas.
  • aria-sort no th descreve a ordenação.
  • Clique de ordenação vai num button dentro do th.
  • Números à direita, texto à esquerda, dígitos de largura fixa.
  • Tabela no celular precisa de overflow-x; cartões são alternativa.
