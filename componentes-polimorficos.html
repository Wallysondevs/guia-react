Componentes Polimórficos

O botão do site da Ana tem o mesmo visual em todo lugar, mas às vezes precisa ser um link — para abrir a vitrine — e às vezes precisa ser um botão de verdade, que envia a encomenda. Ela quer um componente só, que escolha a tag na hora do uso. Nesta aula ela aprende a prop as, o truque de renomear na desestruturação e o cuidado de não perder o href no caminho.

Você vai aprender
  • O que é um componente polimórfico: um componente que escolhe a tag que vai desenhar.
  • Como criar a prop as e dar a ela um valor padrão.
  • Por que as: Tag precisa ser renomeado na desestruturação, e por que a maiúscula importa.
  • Como repassar as props para a tag escolhida sem perder href, onClick ou disabled.
  • Que as também aceita um componente, não só uma tag.
  • Como juntar a classe base do componente com a classe de quem chama.
  • Por que trocar de tag não é só visual: cada elemento tem uma semântica.

1. A cena: o mesmo botão que precisa ser link

Na padaria da Ana existem dois tipos de ação que parecem iguais na tela. "Encomendar" abre o formulário de encomenda dentro do próprio site — é uma ação, feita por um botão. "Ver a vitrine" leva para outra página, a vitrine de pães — é uma navegação, e o elemento certo para navegar é um link.

Visualmente as duas coisas são um retângulo com fundo escuro e texto claro. A Ana copiou o CSS em um componente Botao e, no dia em que precisou do link, escreveu <a className="botao"> na mão. Funcionou — até ela mudar a cor do botão e metade dos links ficar com a cor antiga.

Ela quer um componente só, com o visual em um lugar, que decida na hora do uso se vai desenhar um button, um a, um h2 ou o que for preciso. Um componente que pode assumir várias formas tem nome: polimórfico. A palavra vem do grego e significa "muitas formas"; aqui, muitas tags.

O caminho mais comum é uma prop chamada as — convenção da comunidade, não regra do React. Você poderia chamar de tag ou elemento; as pegou porque lê bem em inglês ("um botão como link"). O componente recebe esse valor e usa como nome da tag que vai desenhar.

2. O que é um componente polimórfico, na prática

A ideia é simples e o código tem três peças: uma prop com valor padrão, uma variável que começa com maiúscula e um JSX que usa essa variável no lugar do nome fixo da tag. O resto é repasse de props, que você já viu no HOC.

polimórfico
Componente que desenha uma tag escolhida por quem o usa, em vez de uma tag fixa no código. "Um botão que pode ser link".
as
A prop que carrega a escolha: as="a", as="h2", as={Destaque}. O nome é convenção; funciona igual com outro nome.
as: Tag
Desestruturação com renomeação: pega a prop as e guarda em uma variável chamada Tag, que começa com maiúscula.
tag dinâmica
Usar uma variável onde você usaria uma tag: <Tag {...props} />. O React olha o valor da variável para saber o que desenhar.
semântica
O significado que a tag carrega para o navegador e para leitores de tela. Link navega; botão executa uma ação.

A primeira decisão é o padrão. Se o uso mais comum do componente é ser um botão, o padrão é "button"; se é uma caixa de texto, o padrão é "div". Quem não passa as recebe o padrão, e o componente continua funcionando como antes. Padrão bom é o que deixa o código de quem chama mais curto no caso comum.

A segunda decisão é o que fazer com o resto das props. Um Botao que vira link precisa receber href; um que vira botão precisa receber type, disabled, onClick. Você não sabe de antemão, então repassa tudo. É o mesmo {...props} que a aula de Higher-Order Components usou para o componente de dentro continuar funcionando.

3. A prop as com valor padrão

Olhe o código. O Botao já declara as: Tag = "button", mas o JSX ainda desenha um <button> fixo — então o segundo uso, que pede um link, sai como botão. O conserto é usar a variável e espalhar as props.

Troque o <button> fixo pelo dinâmico <Tag>, mantendo a classe botao e espalhando as props. O segundo uso é um link e precisa sair como <a> com o href.

function Botao({ as: Tag = "button", texto, ...props }) {
  return <button className="botao">{texto}</button>;
}

function App() {
  return (
    <div>
      <Botao texto="Ver a vitrine" />
      <Botao as="a" href="https://loja.test/vitrine" texto="Encomendar" />
    </div>
  );
}
<div>
  <button class="botao">Ver a vitrine</button>
  <button class="botao">Encomendar</button>
</div>

function Botao({ as: Tag = "button", texto, ...props }) {
  return (
    <Tag className="botao" {...props}>
      {texto}
    </Tag>
  );
}

function App() {
  return (
    <div>
      <Botao texto="Ver a vitrine" />
      <Botao as="a" href="https://loja.test/vitrine" texto="Encomendar" />
    </div>
  );
}

O painel mostra um <button> e um <a href="https://loja.test/vitrine">, os dois com class="botao". O primeiro não recebeu as e usou o padrão; o segundo pediu a e recebeu o href pelo espalhamento. Uma classe, dois elementos, nenhuma cópia de CSS.

Repare na ordem dentro do <Tag>: primeiro a classe do componente, depois as props. Assim, se alguém passar className="grande", a prop sobrescreve a classe base e o botão perde o visual. A seção 6 resolve isso; por enquanto, guarde que a ordem do espalhamento é uma decisão, não um detalhe.

4. Por que as: Tag e por que a maiúscula

Três coisas acontecem nesse pedaço de código, e cada uma tem um motivo. A primeira é a renomeação: as: Tag diz "pegue a prop as e chame de Tag aqui dentro". Você não pode usar as direto no JSX porque <as> começa com minúscula e o React leria como uma tag HTML chamada "as" — desenharia um elemento vazio, sem erro.

A segunda é a maiúscula. O React decide entre tag e componente pela primeira letra do nome: minúscula é tag do navegador, maiúscula é variável. <Tag /> é "desenhe o que estiver na variável Tag"; <tag /> é "desenhe uma tag chamada tag". A convenção de chamar a variável de Tag com maiúscula não é estilo: é o que faz o JSX funcionar.

A terceira é o valor padrão. as: Tag = "button" significa que, quando a prop não vier, a variável vale a string "button". Como a string é minúscula, o React a trata como tag do navegador — e é isso que queremos. O padrão pode ser qualquer tag: "div", "span", "section".

Para ver o que chega na variável, um log com typeof mostra a diferença entre tag e componente:

function Texto({ as: Tag = "p", ...props }) {
  const nome = typeof Tag === "string" ? Tag : Tag.name;
  console.log("Tag: " + nome + " (" + typeof Tag + ")");
  return <Tag {...props} />;
}

function App() {
  return (
    <div>
      <Texto>Pão quentinho</Texto>
      <Texto as={Destaque}>Feito na hora</Texto>
    </div>
  );
}

Com essas duas chamadas, o console mostra:

console: Tag: p (string)
console: Tag: Destaque (function)

String é tag do navegador; função é componente. O mesmo componente aceita os dois porque o JSX aceita os dois no mesmo lugar. Essa é a razão de a prop as ser tão curta e tão poderosa: ela não guarda um texto, guarda o que o React deve desenhar.

5. as também aceita um componente

Até aqui a prop recebeu nomes de tag. Mas o valor pode ser um componente seu — e aí o polimorfismo fica mais útil: o Texto pode virar um parágrafo, um subtítulo ou o seu componente Destaque, com o visual que ele já tem, sem que ninguém saiba como ele é feito por dentro.

O Texto ignora a prop as e desenha sempre um <p>. Implemente a tag dinâmica com as: Tag = "p" e espalhe as props, para os três usos saírem diferentes.

function Destaque({ children }) {
  return <strong className="destaque">{children}</strong>;
}

function Texto({ children }) {
  return <p>{children}</p>;
}

function App() {
  return (
    <div>
      <Texto>Pão quentinho</Texto>
      <Texto as="h2">Encomendas</Texto>
      <Texto as={Destaque}>Feito na hora</Texto>
    </div>
  );
}
<div>
  <p>Pão quentinho</p>
  <p>Encomendas</p>
  <p>Feito na hora</p>
</div>

function Destaque({ children }) {
  return <strong className="destaque">{children}</strong>;
}

function Texto({ as: Tag = "p", ...props }) {
  return <Tag {...props} />;
}

function App() {
  return (
    <div>
      <Texto>Pão quentinho</Texto>
      <Texto as="h2">Encomendas</Texto>
      <Texto as={Destaque}>Feito na hora</Texto>
    </div>
  );
}

O painel mostra um <p>, um <h2> e um <strong class="destaque">. Repare que o Destaque recebeu o texto mesmo sem o Texto passar children explicitamente: children está dentro de props, e o espalhamento leva junto. Se você desestruturar children para usar em outro lugar, precisa passá-lo à mão.

Esse é o ponto mais delicado do componente polimórfico: ele não sabe quais props a tag escolhida aceita. Passar href para um <div> não navega nada — no React 19 vira só um atributo estranho no HTML; passar disabled para um <a> também não desabilita coisa nenhuma. Quem escolhe as precisa escolher as props que combinam — e é por isso que a documentação do componente precisa dizer quais combinações fazem sentido.

6. Juntando classes: o visual base não se perde

Um componente polimórfico costuma ter uma classe base — botao — que traz o visual. Quem chama, muitas vezes, quer acrescentar a sua: grande, link, perigo. Se o componente simplesmente repassa className, a classe base desaparece; se ignora, a classe de quem chama não entra. O certo é juntar as duas.

O componente está usando só a classe de quem chama, e o visual base se perde. Junte botao com a classe recebida, sem deixar espaço sobrando.

function Botao({ as: Tag = "button", className = "", children, ...props }) {
  return (
    <Tag className={className} {...props}>
      {children}
    </Tag>
  );
}

function App() {
  return (
    <div>
      <Botao className="grande">Comprar</Botao>
      <Botao as="a" href="https://loja.test/vitrine" className="link">
        Ver vitrine
      </Botao>
    </div>
  );
}
<div>
  <button class="grande">Comprar</button>
  <a class="link" href="https://loja.test/vitrine">Ver vitrine</a>
</div>

function Botao({ as: Tag = "button", className = "", children, ...props }) {
  return (
    <Tag className={("botao " + className).trim()} {...props}>
      {children}
    </Tag>
  );
}

function App() {
  return (
    <div>
      <Botao className="grande">Comprar</Botao>
      <Botao as="a" href="https://loja.test/vitrine" className="link">
        Ver vitrine
      </Botao>
    </div>
  );
}

O painel mostra class="botao grande" no button e class="botao link" no a. O trim() no fim existe para o caso em que ninguém passa classe: sem ele, sobraria um espaço solto no atributo — inofensivo para o navegador, mas sujo no DevTools e em testes que comparam texto.

Vale conferir no console quando a conta de classes é maior do que uma concatenação:

function Botao({ as: Tag = "button", className = "" }) {
  const classes = ("botao " + className).trim();
  console.log("classe final: " + classes);
  return <Tag className={classes} />;
}

Com <Botao className="grande">, o console mostra:

console: classe final: botao grande

Em código de verdade, essa junção costuma virar uma função auxiliar — algo como juntarClasses("botao", className, { grande: ehGrande }) — porque as condições se multiplicam. A ideia, porém, é sempre a mesma: o componente garante a base, quem chama acrescenta o que precisa.

7. Semântica: link é link, botão é ação

Aqui está a parte que separa um componente polimórfico bem feito de uma armadilha de acessibilidade. Se o "botão" que navega é desenhado como <button>, ele não pode ser aberto em outra aba, não aparece no menu de contexto como link, e leitores de tela anunciam "botão" onde deveria estar "link". Se o "link" que envia uma encomenda é desenhado como <a> sem href, ele nem recebe foco pelo teclado.

O que a ação fazTag certaPor quê
leva para outra página ou âncoraa com hrefnavegação, histórico, abrir em nova aba, foco por teclado

A regra prática: escolha a tag pelo comportamento, não pelo desenho. O CSS deixa qualquer elemento parecido com um botão; o que ele é vem da tag. Um componente polimórfico só é uma boa ideia quando as formas que ele assume compartilham o mesmo visual e o mesmo papel — ou quando quem chama sabe escolher a forma certa.

Dois cuidados pequenos e frequentes. O primeiro: dentro de um formulário, um <button> sem type envia o formulário ao ser clicado; se ele é só um botão de abrir detalhe, escreva type="button". O segundo: quando a ação é feita por um link, deixe o href de verdade — um onClick em um <a> sem href não é link nem botão, e o teclado não alcança.

No mundo TypeScript, componentes polimórficos pedem tipos generosos, e é comum ver bibliotecas com tipos assustadores para isso. Em JavaScript puro, o custo é só a disciplina de escolher a tag certa e documentar as combinações. Se o componente começa a acumular regras do tipo "se for link, não aceite disabled", talvez ele esteja tentando ser dois componentes ao mesmo tempo — e a saída é separar.

8. Quando não vale a pena

Polimorfismo tem custo de leitura. Quem vê <Botao as="a"> precisa saber que a tag mudou, que as props mudam junto e que a semântica mudou. Em um componente pequeno e estável, como a moldura de um cartão, isso é exagero: melhor ter Cartao e CartaoLink, ou um Cartao que recebe o conteúdo por children.

O critério que funciona: use as quando o componente é visual e a tag é uma escolha legítima de quem usa — botão, link, título. Evite as quando a tag faz parte da identidade do componente — uma linha de tabela que pode virar div deixa de ser linha de tabela. E evite quando o número de combinações passa de três ou quatro: aí o componente precisa de variantes, não de mais liberdade.

Eu preciso mudar…FerramentaExemplo

As três linhas convivem bem no mesmo componente. O erro comum é usar as para resolver aparência — as="a" porque o link é menor — e variante para resolver semântica. A escolha é sempre pelo significado, nunca pelo desenho.

9. Cenários do dia a dia

Cenário 1: a tag "tag" apareceu no HTML

A Ana escreveu <tag className="botao"> em vez de <Tag ...>. O navegador aceitou a tag inventada e desenhou um elemento vazio, do tamanho do texto que estava dentro. O sintoma é um botão sem estilo e sem clique. A causa é a primeira letra: minúscula vira tag literal, maiúscula vira variável. É a mesma regra do nome do componente, aplicada a uma variável.

Cenário 2: o link não recebe foco

Ela trocou o botão por as="a" e esqueceu de passar href. O elemento saiu como <a class="botao">, sem endereço: o clique não navega e o teclado não alcança o elemento. O conserto é passar o endereço de verdade — e, se não houver endereço nenhum, voltar para button, porque a ação é na mesma tela. Aparência igual, comportamento diferente.

Cenário 3: o texto sumiu ao virar componente

Ao usar as={Destaque}, o conteúdo desapareceu porque o Destaque não renderizava children — só um <strong> vazio. Um componente usado como tag precisa aceitar o conteúdo que chega. O conserto é receber children e desenhá-lo. Sem isso, o polimorfismo funciona, mas o texto fica pelo caminho.

11. Resumo

Componente polimórfico é o que escolhe a tag na hora do uso, por uma prop — na convenção da comunidade, as. Dentro do componente, a prop é renomeada para uma variável com maiúscula (as: Tag) e usada no JSX como <Tag {...props} />. O valor pode ser uma string ("a", "h2") ou um componente seu ({Destaque}), e o espalhamento leva as props e o children junto.

O padrão precisa de três cuidados. O primeiro: dar um valor padrão que corresponda ao uso mais comum. O segundo: repassar as props, senão href, disabled e onClick se perdem no caminho. O terceiro: juntar a classe base com a classe de quem chama, em vez de escolher uma das duas.

E a parte que não é de sintaxe: cada tag carrega um significado. Link navega, botão executa ação, título organiza a página. O componente polimórfico só ajuda se quem escolhe a tag escolher pelo comportamento — CSS deixa qualquer coisa parecida com botão, mas não muda o que o navegador e os leitores de tela entendem. Use as quando a forma é uma escolha legítima do uso; prefira variantes quando o que muda é só a aparência.

Por último, uma dose de realismo: se o componente começa a acumular exceções do tipo "se for link, não aceite disabled", é sinal de que duas coisas foram empacotadas em uma. Separar costuma ser mais barato do que ensinar o componente a ser esperto.

Para lembrar

  • Polimórfico: o componente escolhe a tag; a prop as é convenção, não API do React.
  • as: Tag = "button" renomeia e dá o padrão em uma linha.
  • A variável do JSX começa com maiúscula; <tag> vira tag literal vazia.
  • Espalhe as props: <Tag className="botao" {...props} />.
  • as aceita componente: as={Destaque}.
  • children viaja dentro de props; se desestruturar, passe à mão.
  • Junte classes: ("botao " + className).trim().
  • Escolha a tag pelo comportamento: link navega, botão executa.
  • <a> sem href não recebe foco; button em formulário pede type.
  • Mudança de aparência é variante; mudança de tag é as.
