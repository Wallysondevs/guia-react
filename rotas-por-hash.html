Rotas por Hash

A Ana quis mandar o link da lista de pães no grupo da padaria e percebeu o problema: o endereço era sempre o mesmo, e a cliente caía na vitrine. Na aula passada a tela morava dentro de um estado; agora ela vai morar no endereço. O caminho mais curto para isso é o hash — o pedaço que vem depois do # —, que muda sem recarregar a página, não pergunta nada ao servidor e sobrevive ao F5, ao voltar e ao link no grupo.

Você vai aprender
  • O que é o hash e por que ele não chega ao servidor.
  • Como ler o hash quando a página abre, para o link direto funcionar.
  • Como trocar de tela escrevendo em window.location.hash.
  • Como ouvir o evento hashchange num efeito, com limpeza.
  • Por que o estado pode ser só um espelho da URL.
  • Como normalizar a rota e tratar o endereço vazio.
  • O que muda — e o que ainda não muda — em relação à rota por estado.

1. A cena: o link que abre na vitrine

Na aula de rotas com estado, a Ana trocou de tela sem recarregar. O endereço, porém, continuava https://loja.test/ em qualquer tela. Mandar "o link dos pães" era mandar o link da vitrine: a cliente abria, via "Bem-vindo" e desistia.

A saída é colocar a tela no endereço. Existem dois jeitos clássicos: usar o caminho (https://loja.test/paes) ou usar o hash (https://loja.test/#/paes). O caminho é mais bonito e melhor para busca, mas exige que o servidor devolva o index.html em qualquer rota — a regra de rewrite da aula de publicando. O hash não exige nada: o navegador não manda o que vem depois do # para o servidor.

Começar pelo hash é bom por dois motivos. Ele funciona em qualquer host, inclusive no GitHub Pages, onde rewrite não existe. E ele obriga a entender a peça central de qualquer roteador: a URL guarda a rota, o componente lê a URL, e um evento avisa quando ela muda. Trocando hash por pathname mais uma biblioteca, é o mesmo desenho.

2. O que é o hash, exatamente

A URL tem partes. https é o esquema, loja.test é o domínio, /padaria é o caminho, #/paes é o fragmento (o hash) e ?destaque=1 é a query. O navegador envia ao servidor o esquema, o domínio, o caminho e a query. O fragmento fica no computador do cliente — ele nunca sai na requisição.

ParteExemploVai ao servidor?
esquema e domíniohttps://loja.testsim, é para onde o pedido vai
caminho/padaria/paessim, o servidor precisa achar o arquivo
query?ordem=precosim, chega junto com o caminho
fragmento (hash)#/paesnão: fica só no navegador

Duas consequências caem daí. A boa: mudar só o hash não recarrega a página nem gera pedido — é instantâneo e funciona offline. A ruim: o servidor não vê a rota, então buscadores e prévias de link não enxergam aquele conteúdo. Para a padaria, que quer o link funcionando no grupo, é um preço aceitável; para uma loja que vive de busca, o caminho é o caminho.

O navegador ainda faz um favor: toda vez que o hash muda, ele dispara um evento chamado hashchange na janela e registra a mudança no histórico. É esse par — propriedade e evento — que transforma o hash num roteador de verdade.

3. Lendo o hash quando a página abre

A primeira metade do roteador é ler. Quando alguém abre https://loja.test/#/contato, o navegador carrega o index.html e entrega o endereço completo para o JavaScript. A tela inicial tem de sair dali, e não de um valor fixo — senão o link direto abre sempre na vitrine.

function rotaDoEndereco() {
  const hash = window.location.hash;      // "#/contato"
  const semCerquilha = hash.replace(/^#\/?/, "");
  return semCerquilha || "inicio";
}

O replace tira a cerquilha e a barra; se sobrar vazio — caso de https://loja.test/ —, a rota é "inicio". Essa pequena normalização é o que impede a área em branco quando alguém abre o site sem hash nenhum.

Nas caixas desta aula, o motor roda o componente num quadro isolado, sem um endereço de verdade: um window.location.hash ali não sobrevive ao clique. Para você poder experimentar, as caixas usam uma janela de mentira que tem as mesmas peças — uma propriedade hash e o evento hashchange —, criada com new EventTarget(). O código de um projeto de verdade é o do bloco acima, com window no lugar de janela; a lógica é idêntica.

O site abriu direto em #/contato, mas a tela mostra a vitrine, porque o estado começa fixo em "inicio". Inicie o estado a partir do hash da janela.

const janela = new EventTarget();
janela.hash = "#/contato";

function App() {
  const [rota, setRota] = useState("inicio");

  return (
    <div>
      <p>Rota: {rota}</p>
      {rota === "contato" ? <p>Contato — 9999-0000</p> : <p>Vitrine</p>}
    </div>
  );
}
<div>
  <p>Rota: inicio</p>
  <p>Vitrine</p>
</div>

O valor inicial do useState é calculado uma vez, na montagem — que é exatamente o momento em que a página abriu. Ler o endereço ali é o que faz o link direto e o F5 funcionarem: não há estado antigo para restaurar, porque o endereço já diz tudo.

4. Escrevendo no hash para trocar de tela

A segunda metade é escrever. Em vez de chamar o setter, o botão muda o endereço; o evento avisa o componente; o componente lê o hash de novo. Quem manda é a URL, e o estado só repete o que ela diz.

function irPara(rota) {
  window.location.hash = "#/" + rota;
}

Atribuir a location.hash faz três coisas de uma vez: muda a barra de endereço, cria uma entrada no histórico e dispara o hashchange. Note que isso não recarrega a página — o navegador já tem o documento e só guarda o novo fragmento.

Se você escrever o mesmo hash duas vezes seguidas, nada acontece: o navegador compara o valor e não dispara evento quando o endereço não mudou. É o mesmo raciocínio do setState com valor igual — e a mesma surpresa de "cliquei e não aconteceu nada".

Tem um bônus importante aqui: um link comum, <a href="#/paes">Pães</a>, muda o hash sozinho, sem uma linha de JavaScript. O navegador troca o fragmento, entra no histórico e dispara o hashchange; o seu efeito faz o resto. Isso significa que a navegação por hash funciona mesmo antes do JavaScript carregar — o endereço muda e, quando o componente monta, ele lê o hash novo e desenha a tela certa. É a razão pela qual os roteadores por hash são tão robustos em conexão ruim.

O caminho inverso também é útil: history.back() e o botão do navegador só mexem no histórico. Como cada mudança de hash é uma entrada, voltar dispara hashchange e a tela acompanha sem que você escreva nada para isso.

5. Ouvindo o hashchange

Ler na montagem resolve o link direto. Falta o meio do caminho: quando o hash muda depois que a página abriu, alguém precisa avisar o componente. Esse alguém é o evento hashchange, e o lugar de assinar um evento da janela é dentro de um efeito.

O clique muda o hash da janela, mas a tela não acompanha: ninguém está escutando o hashchange. Assine o evento num efeito e atualize a rota. A missão clica em Pães e confere #/paes.

const janela = new EventTarget();
janela.hash = "#/inicio";

function irPara(hash) {
  janela.hash = hash;
  janela.dispatchEvent(new Event("hashchange"));
}

function App() {
  const [rota, setRota] = useState(janela.hash);

  return (
    <div>
      <nav>
        <button onClick={() => irPara("#/paes")}>Pães</button>
      </nav>
      <p>Rota atual: {rota}</p>
    </div>
  );
}
<div>
  <nav>
    <button>Pães</button>
  </nav>
  <p>Rota atual: #/inicio</p>
</div>

const janela = new EventTarget();
janela.hash = "#/inicio";

function irPara(hash) {
  janela.hash = hash;
  janela.dispatchEvent(new Event("hashchange"));
}

function App() {
  const [rota, setRota] = useState(janela.hash);

  useEffect(() => {
    function aoMudar() {
      setRota(janela.hash);
    }
    janela.addEventListener("hashchange", aoMudar);
    return () => janela.removeEventListener("hashchange", aoMudar);
  }, []);

  return (
    <div>
      <nav>
        <button onClick={() => irPara("#/paes")}>Pães</button>
      </nav>
      <p>Rota atual: {rota}</p>
    </div>
  );
}

O efeito tem as três partes que você já conhece: assina na entrada, atualiza o estado quando o evento chega e desassina na limpeza. A limpeza não é enfeite — ela roda quando o componente sai da tela e evita uma função pendurada em cada montagem, o que vira vazamento de memória e aviso de estado atualizado em componente desmontado.

A lista de dependências vazia ([]) está certa aqui: setRota é estável e janela nasce fora do componente. O efeito assina uma vez só na vida do componente, o que é exatamente o comportamento desejado para um evento global.

hashchange → "#/paes"
hashchange → "#/contato"

Cada linha é um console.log dentro do aoMudar, mostrando o valor novo. Se você clicar nos dois botões e não ver nenhuma linha, o problema não é o desenho: é a assinatura do evento, que não foi feita, foi feita fora do efeito ou foi desfeita cedo demais.

6. A URL é a fonte, o estado é o espelho

Junte as duas metades e o desenho fica claro: a URL guarda a rota, o componente lê a URL para desenhar e escreve na URL para trocar. O estado não decide nada — ele copia o endereço para o React ter algo para comparar e redesenhar.

hash (fragmento)
O trecho depois do #, que não vai ao servidor. Aqui ele carrega a rota: #/paes.
window.location.hash
A propriedade que lê e escreve o fragmento. Atribuir muda o endereço, cria histórico e dispara o evento.
hashchange
O evento da janela avisando que o fragmento mudou. É o que mantém a tela em sincronia com a barra.
fonte da verdade
O lugar onde a informação mora. Numa rota por hash, é a URL; o estado é cópia para desenhar.
link direto (deep link)
Um endereço que abre o site já numa tela interna. É o que o hash entrega de graça.

O ciclo completo, em uma frase: o cliente clica, o hash muda, o navegador dispara o evento, o efeito lê o hash e chama setRota, o componente desenha a tela nova. São dois passos em vez de um — e é por isso que existe um desenho extra. O custo é irrelevante e a vantagem é grande: o mesmo caminho funciona quando a mudança vem do link, do botão voltar ou do endereço digitado à mão.

Há um detalhe de nomenclatura que ajuda: chame o estado de rota e a função de irPara. Quando alguém lê setRota no código, precisa ficar óbvio que aquilo acontece em resposta ao evento, e não uma decisão futura. Espelho é espelho.

E se a URL for a fonte, o que acontece se o estado divergir? O componente desenha a tela errada até o próximo hashchange. Por isso a regra: nunca chame setRota com um valor inventado — sempre com o que o endereço diz. Quem quer trocar de tela muda o endereço.

7. Normalizar a rota

O hash é texto livre: #/paes, #/Paes, #paes, #/paes/ e # são cinco endereços diferentes. O roteador precisa de um padrão — uma função que transforme qualquer um deles no nome que as telas conhecem.

A função que lê a rota devolve o hash cru, com cerquilha e barra, e nenhuma tela casa. Normalize: tire #/, devolva inicio quando estiver vazio. A missão confere "Tela: paes".

function nomeDaRota(hash) {
  return hash;
}

function App() {
  const [rota] = useState("#/paes");
  const nome = nomeDaRota(rota);

  return (
    <div>
      <p>Tela: {nome}</p>
      <button onClick={() => {}}>Ver pães</button>
    </div>
  );
}
<div>
  <p>Tela: #/paes</p>
  <button>Ver pães</button>
</div>

function nomeDaRota(hash) {
  return hash.replace(/^#\/?/, "") || "inicio";
}

function App() {
  const [rota] = useState("#/paes");
  const nome = nomeDaRota(rota);

  return (
    <div>
      <p>Tela: {nome}</p>
      <button onClick={() => {}}>Ver pães</button>
    </div>
  );
}

A expressão regular /^#\/?/ lê assim: no começo do texto, uma cerquilha e, se existir, uma barra. As duas saem. O || "inicio" cobre o resto: se a string ficou vazia, a rota é a vitrine.

Uma decisão que vale tomar de uma vez: guarde a rota sempre em minúsculas e sem barra no fim. Se você aceitar #/Pães, vai precisar comparar com cuidado em cada lugar — ou normalizar na entrada, numa função só, e usar o resultado em todo o resto. Uma função de normalização bem feita evita uma classe inteira de bugs de rota.

8. O que muda em relação à rota por estado

Com o hash no lugar, as três limitações da aula passada caem. O F5 abre a tela certa, porque a tela está no endereço. O botão voltar do navegador volta uma tela, porque cada mudança de hash entrou no histórico. E o link do grupo abre na tela que a Ana queria mandar.

PerguntaRota por estadoRota por hash

Recarregar mantém a tela?nãosim, se você lê o hash na montagem
O voltar do navegador funciona?nãosim: cada mudança é uma entrada no histórico
Dá para mandar o link de uma tela?nãosim: o hash vai junto no link
Precisa de configuração no host?nãonão: o hash nem chega ao servidor
Buscadores e prévias veem a tela?nãonão: o fragmento não é enviado

As duas linhas resumem o preço e a vantagem: o servidor não sabe da rota (por isso nenhuma configuração é necessária) e o navegador sabe (por isso o link funciona). Quem precisa das duas coisas — link bonito, busca e nenhuma configuração — usa um roteador de verdade, que combina caminhos no servidor com rewrite e um pouco mais de código no cliente.

Vale conhecer também o history.pushState, que muda o caminho sem recarregar e sem o #. Ele resolve a estética, mas traz de volta o problema do F5: o caminho novo precisa existir no servidor. É por isso que a escolha entre hash e caminho é, no fundo, uma escolha sobre quem vai responder ao pedido.

9. Cenários do dia a dia

Cenário 1: o link do grupo abria a vitrine

A Ana mandou https://loja.test/#/paes e a cliente viu a vitrine. O componente lia o hash, mas o useState começava com o texto "inicio" fixo, e a leitura só acontecia num efeito posterior — tarde demais para o primeiro desenho. Passar a leitura para o valor inicial resolveu: o primeiro desenho já nasce na tela certa.

Cenário 2: o endereço mudou e a tela não

Ela escreveu a função que troca o hash e o link passou a mudar na barra. Só que a tela continuava a mesma até recarregar. Faltava o outro lado: ouvir o hashchange. Sem a assinatura no efeito, o React não tem por que redesenhar — ninguém avisou que o mundo mudou.

Cenário 3: o endereço vazio deixou a área em branco

Quem abria https://loja.test/ via a página sem conteúdo. O hash era "", a normalização devolvia "" e nenhuma tela casava. O || "inicio" no fim da função é a linha que evita esse silêncio — e vale para todo endereço inesperado que alguém colar no navegador.

11. Resumo

O hash é a parte do endereço que o navegador guarda sem mandar ao servidor. Isso o torna o roteador mais barato que existe: muda de tela sem recarregar, funciona em qualquer host estático e não precisa de rewrite. O preço é que buscadores e prévias de link não veem a rota.

O desenho tem duas metades. Na montagem, leia window.location.hash e normalize numa função só — tirando #/ e caindo em "inicio" quando estiver vazio. Depois, assine hashchange num efeito com limpeza, para a tela acompanhar cada mudança; e troque de tela escrevendo em location.hash, não chamando o setter. A URL é a fonte da verdade; o estado é espelho.

Com isso, F5, voltar e link compartilhado passam a funcionar. Falta o que o cliente realmente usa: um link de verdade na tela, com o comportamento que ele espera — abrir na mesma aba, abrir em nova aba com o Ctrl, funcionar no teclado. É o assunto da próxima aula, sobre o componente de link e navegação.

Para lembrar

  • O hash (fragmento) não vai ao servidor: funciona em qualquer host.
  • A URL é a fonte da verdade; o estado é só um espelho para desenhar.
  • Leia o hash no valor inicial do useState: o link direto nasce certo.
  • Trocar de tela é window.location.hash = "#/paes", não setRota.
  • Atribuir ao hash muda o endereço, cria histórico e dispara hashchange.
  • Assine hashchange num efeito com lista vazia e remova na limpeza.
  • Normalize: tire #/, use minúsculas e caia em "inicio" quando vazio.
  • Endereço vazio sem fallback = área em branco, sem erro.
  • Repetir o mesmo hash não dispara evento: o endereço não mudou.
  • Buscadores não veem o fragmento; para eles, só com caminho e rewrite.
