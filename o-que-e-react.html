O que é React

A Ana tem um site de padaria com três páginas escritas à mão: a inicial, a lista de pães e o contato. Funciona. Só que cada página repete o mesmo cabeçalho, e quando o horário de sábado mudou ela editou três arquivos, esqueceu um e passou duas semanas com o site se contradizendo. Nesta primeira aula ela não vai instalar nada nem escrever código complicado: vai entender o que é React, que problema ele resolve e por que tanta gente usa. As caixas rodam React de verdade, então você já pode mexer no código e ver o resultado na hora.

Você vai aprender
  • O que é React, em uma frase que caiba na cabeça.
  • Que problema ele resolve (e qual ele não resolve).
  • O que é um componente e por que ele muda a forma de escrever a tela.
  • A diferença entre montar a tela passo a passo e descrever o resultado.
  • O que é JSX, essa escrita que parece HTML.
  • O que o painel das caixas mostra e de onde vem aquele HTML.
  • Onde o React roda e onde ele não é necessário.

1. A cena: o horário em três arquivos

A Ana está com o notebook na mesa da padaria, entre uma fornada e outra. No site dela, o topo de cada página tem o nome da padaria, o horário e uma frase de aviso. As três páginas foram escritas copiando e colando esse topo. É rápido de fazer e é uma armadilha: no dia em que o horário mudou, ela abriu index.html, trocou, salvou; abriu paes.html, trocou, salvou; esqueceu contato.html.

O problema não é digitação. O problema é que a mesma informação existe em três lugares, e nada no site avisa quando os três discordam. Quem programa chama isso de duplicação, e é a fonte da maior parte dos erros chatos: não os difíceis, mas os bobos, que ficam meses no ar.

Todo o resto desta aula é uma resposta a essa cena. O React nasceu para permitir escrever o topo uma vez e usá-lo em quantas páginas quiser. E, como consequência, ele acaba mudando um pouco a forma de pensar: em vez de você mandar o navegador trocar um pedaço de texto, você descreve como a tela deve ficar e deixa que ele descubra o que precisa mudar.

2. O que é React, em uma frase

React é uma biblioteca de JavaScript para montar telas. Biblioteca, aqui, quer dizer um conjunto de funções prontas que você chama no seu código — não é um programa que você instala e abre, nem uma linguagem nova. É código JavaScript, do mesmo jeito que o seu.

A versão que este guia usa é a React 19, a atual. Ela é mantida pela Meta e por uma comunidade grande, é de código aberto e roda no navegador de qualquer pessoa. Você não paga nada e não precisa de servidor para começar.

A frase inteira, então: React é uma biblioteca que recebe componentes — pedaços de tela descritos no código — e cuida de transformá-los nos elementos que o navegador sabe desenhar. O trabalho chato de criar elemento por elemento, dizer onde cada um entra e trocar o que mudou fica com ele. O trabalho de decidir o que a tela mostra fica com você.

Vale saber de onde vem o nome. A ideia original era reagir a mudanças: quando os dados mudam, a tela reage. Essa é a diferença central em relação ao jeito antigo, em que você mesmo tinha de lembrar de atualizar cada pedacinho da página depois de cada mudança.

3. Um pedaço de tela com nome: o componente

Pense no topo da padaria. Ele tem um nome, um horário e um aviso. É um pedaço de tela que faz sentido sozinho. No React, esse pedaço ganha um nome: vira um componente. Em vez de copiar o HTML três vezes, você escreve uma função chamada Cabecalho e usa essa função nas três páginas.

Componente, na prática, é uma função que devolve o que deve aparecer. Não é classe, não é arquivo especial, não tem configuração: é função. Essa simplicidade é a razão de o React ter pegado tanto — e é o assunto da aula seguinte, quando você escreve o primeiro.

componente
Uma função que devolve um pedaço de tela. O nome começa com maiúscula: Cabecalho, ListaDePaes.
JSX
A escrita parecida com HTML usada dentro do JavaScript: <h1>Padaria</h1>. O React transforma isso em código de verdade.
DOM
A árvore de elementos que o navegador desenha na tela. É o alvo final do React: ele cria e atualiza esses elementos por você.
renderizar
O ato de transformar o componente em elementos na página. Quando você clica em Rodar, é isso que acontece.
props
Os dados que um componente recebe de fora, como o horário que muda de página para página. Tem aula própria mais adiante.

Repare que o componente resolve a cena da Ana de um jeito que o HTML não resolve: o horário passa a existir em um lugar só. Mudar o sábado vira mudar uma linha. E, como o componente é código, ele pode decidir coisas — mostrar "fechado" quando são oito da noite, por exemplo —, o que o HTML copiado nunca vai saber fazer.

O componente Cabecalho já existe e aparece na primeira página. Na segunda, o topo foi copiado à mão e ficou sem título. Troque a cópia por <Cabecalho /> e veja o HTML sair igual nos dois lugares.

O painel mostra dois blocos <header> idênticos no HTML final, e nenhum <header> escrito à mão: os dois vieram da mesma função. Isso é reúso de verdade, diferente de copiar e colar. Se amanhã o horário mudar, muda a função, e as duas cópias mudam junto.

E tem um detalhe que você já deve ter notado no código acima: escrevemos <Cabecalho /> como se fosse uma tag. O React entende que aquilo é o seu componente, não uma tag do HTML, por causa da letra maiúscula. Minúsculo seria uma tag desconhecida; maiúsculo é o seu pedaço de tela entrando ali.

4. A ideia que muda tudo: descrever em vez de mandar

Existem duas formas de chegar a uma tela. A primeira é a que o site da Ana usa hoje: você escreve cada elemento, na ordem, e depois, se algo muda, procura o elemento na página e troca. A segunda é a do React: você descreve como a tela deve ficar para os dados que tem, e o React se encarrega de chegar lá.

A primeira forma tem nome: imperativa, do jeito que você dá ordens, passo a passo. A segunda é a declarativa, do jeito que você declara o resultado. O exemplo clássico é uma lista de compras: no modo imperativo você diz "pegue o papel, escreva pão, escreva queijo, risque o que já tem"; no declarativo você entrega a lista pronta e pronto.

SituaçãoEm HTML puroEm React
Mostrar o mesmo topo em três páginascopiar e colar o bloco nas trêsum componente usado três vezes
Mudar o horário de funcionamentoeditar três arquivos e torcereditar uma função
Acrescentar um pão à listaescrever mais um <li> à mãoacrescentar o pão na lista de dados
Atualizar a tela depois de um cliqueachar o elemento e trocar o texto delemudar o dado; o React atualiza
Mostrar uma mensagem quando não há pãouma condição no JavaScript, mexendo no DOMuma condição dentro da descrição da tela

Essa mudança de postura é o que se chama de programação declarativa, e ela assusta um pouco no começo porque parece mágica. Não é: por baixo, o React faz exatamente o trabalho braçal que você fazia. A diferença é que ele faz isso sempre igual, sem esquecer um canto da tela, e você escreve só a parte que decide.

Tem uma consequência prática que vale guardar desde já: no React, você quase nunca mexe no HTML diretamente. Nada de document.querySelector para trocar um texto. Você muda o dado e descreve a tela de novo — e o React calcula a diferença. Essa regra vale para todo o guia.

5. A tela é o resultado, não o arquivo

Aqui está a mudança de cabeça mais importante da aula. Em HTML puro, o arquivo é a tela: o que está escrito é o que aparece. Em React, o arquivo é a receita; a tela é o que sai dela depois que o React executa o componente.

Por isso o painel das caixas mostra o HTML gerado, e não o seu código. Ele é a prova do que o navegador recebeu. Vamos mexer no texto e ver o HTML acompanhar:

O sábado agora fecha às 19h. Troque o horário do parágrafo e clique em Rodar para ver o HTML gerado mudar.

function App() {
  return (
    <div>
      <h1>Padaria da Ana</h1>
      <p>Aberto das 6h às 18h</p>
    </div>
  );
}

  <p>Aberto das 6h às 19h</p>

Repare que o painel não mostra o seu código, e sim o resultado dele. Se você apagar o <div> de fora, o painel vai reclamar de elementos adjacentes; se você trocar <h1> por <h2>, o painel acompanha. O painel é um espelho do DOM, e é assim que você vai descobrir o que o React realmente fez — não pelo que você achou que escreveu.

Essa separação entre receita e bolo é o que permite ao React atualizar só o que mudou. Quando o dado muda, ele compara a descrição nova com a antiga e mexe na página apenas nas diferenças. Você não precisa saber como; precisa saber que é por isso que a tela não pisca inteira a cada clique.

6. Descrever uma lista inteira

Uma lista é o melhor exemplo de por que descrever é melhor do que mandar. No HTML puro, seis pães são seis <li> escritos à mão, e cada pão novo é mais um bloco copiado. No React, a lista inteira é a descrição de uma repetição.

Nesta primeira aula você ainda não vai escrever a repetição — ela tem aula própria, quando falarmos de listas e de map. Mas já dá para sentir o gosto: acrescente um pão ao código e veja o painel ganhar uma linha. É literalmente isso que vai acontecer na tela do site.

A lista tem dois pães. Acrescente um terceiro, Sonho de creme, do mesmo jeito que os outros, e rode.

Nada de especial, e é aí que está o ponto: no React você vai aprender a escrever a lista uma vez, a partir de uma lista de dados, e o número de itens na tela passa a ser consequência do que está nos dados. Se a padaria criar um pão novo, é uma linha na lista de dados — a tela se ajusta.

Esse é o mesmo raciocínio do cabeçalho, um passo adiante: primeiro você aprendeu a dar nome a um pedaço fixo, agora a descrever um pedaço que se repete. Componentes fazem as duas coisas, e é por isso que a biblioteca inteira cabe em uma ideia só.

7. Onde o React roda

React roda no navegador, como qualquer JavaScript. O site que a Ana já tem poderia ganhar um pedaço em React sem ser reescrito inteiro — dá para colocar um componente em uma página HTML comum e ir conversando. É assim que muita gente entra: primeiro um trecho, depois outro.

Também roda fora do navegador. Com React Native, o mesmo jeito de escrever componentes vira aplicativo de celular; com renderização no servidor, o React pode gerar o HTML antes de a página chegar ao navegador, o que ajuda no primeiro carregamento. São assuntos de níveis mais adiante, mas vale saber que existem porque explicam por que o React aparece em tantos lugares diferentes.

Aqui no guia, todas as caixas rodam do mesmo jeito: seu componente é transformado em JavaScript, executado com o React 19 de verdade e montado em um pedacinho de página dentro de um quadro isolado. O painel lê o que apareceu naquele quadro. É o mesmo caminho de um site real, só que sem servidor e sem instalação — e é por isso que você pode aprender React antes de aprender a montar um projeto.

8. O React não é tudo: o que ele não faz

Uma das maiores fontes de confusão de quem começa é esperar do React coisas que ele não faz. Ele é uma biblioteca, não um pacote completo. Esta tabela separa as responsabilidades:

AssuntoÉ do React?Quem cuida
Montar e atualizar a telasimreact e react-dom
Aparência: cor, espaço, tamanhonãoCSS, ou Tailwind se você quiser
Endereços e páginas do sitenãobiblioteca de rotas, como o React Router
Buscar dados de um servidornãofetch, ou uma biblioteca de dados
Guardar dados que mudam na telasimestado, com useState
Lógica de JavaScript puronãoo próprio JavaScript
Testes automatizadosnãoferramentas de teste

Duas linhas dessa tabela merecem comentário. A primeira é o CSS: o React não tem opinião sobre aparência. Ele cria os elementos e coloca as classes; o desenho continua sendo CSS. Quem promete "React deixa bonito" está vendendo outra coisa.

A segunda é o roteamento. Um site de três páginas em React normalmente continua sendo um site com endereços diferentes — e quem cuida disso é uma biblioteca separada ou, em projetos pequenos, um controle manual do que mostrar. O React sozinho não sabe o que é "/contato".

E há o que ele não substitui: você ainda vai precisar de HTML para saber quais elementos existem, de CSS para o desenho e de JavaScript para a lógica. O React é uma camada em cima disso, não um atalho que dispensa as outras.

9. Cenários do dia a dia

Cenário 1: "vou ter que jogar meu site fora?"

Não. O React entra por partes: uma página, um trecho, um formulário. A Ana poderia começar só pelo cabeçalho — o resto do site continuaria HTML comum. Reescrever tudo é uma decisão de projeto, não uma exigência da biblioteca. Na prática, quem tem um site que funciona raramente ganha algo reescrevendo por reescrever.

Cenário 2: "site de padaria precisa de React?"

Depende do que o site faz. Se é só uma vitrine com horário e endereço, HTML e CSS resolvem, e ponto. O React começa a valer a pena quando a página reage: carrinho de encomendas, lista que filtra, formulário que valida enquanto a pessoa digita, painel de pedidos do dia. A pergunta certa não é "é moderno?", e sim "tem coisa mudando na tela sozinha?".

Cenário 3: "preciso saber JavaScript antes?"

Precisa do básico: variáveis, funções, listas e objetos. O React usa essas quatro coisas o tempo todo, e o guia introduz cada uma conforme elas aparecem. Mas não espere dominar JavaScript inteiro para começar: o caminho contrário — aprender React e JavaScript juntos, com exemplos concretos — funciona bem melhor para quem está começando.

11. Resumo

React é uma biblioteca de JavaScript para montar telas. Ela não substitui HTML, CSS nem JavaScript: é uma camada em cima deles, que organiza a tela em componentes — pedaços com nome, que podem ser usados quantas vezes você quiser. O componente é uma função que devolve JSX, e o React transforma esse JSX nos elementos que o navegador desenha.

A ideia que sustenta tudo é a passagem de "mandar" para "descrever". Em vez de procurar elementos na página e trocar o que mudou, você escreve como a tela deve ficar para os dados que tem. Quando os dados mudam, o React compara a descrição nova com a anterior e atualiza só o que é diferente. É por isso que a palavra-chave do React é reagir.

O painel das caixas mostra o HTML gerado, e não o seu código. Isso é proposital: no React, o arquivo é a receita e a tela é o bolo. Ler o HTML gerado é como você confere o que realmente aconteceu — e vai ser o seu hábito em toda aula deste guia.

Por último, o bom senso: React não é obrigatório. Um site parado, com horário e endereço, vive bem sem ele. Ele entra quando a tela precisa reagir — e aí economiza o trabalho que você faria a mão, lembrando de cada canto da página que mudou. A próxima aula mostra o caminho que o componente percorre até virar tela.

Para lembrar

  • React é biblioteca de JavaScript para interfaces, não uma linguagem nova.
  • Componente é uma função com nome maiúsculo que devolve um pedaço de tela.
  • Um componente usado em três lugares existe uma vez só no código.
  • Declarativo é descrever o resultado; imperativo é mandar passo a passo.
  • O painel mostra o HTML gerado, mais as linhas de console.
  • Sem document.querySelector: você muda o dado e o React atualiza a tela.
  • React não cuida de CSS, de rotas nem de buscar dados: cada assunto tem sua ferramenta.
  • Um site estático não precisa de React; uma tela que reage, sim.
